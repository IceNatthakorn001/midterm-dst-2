1. Ethernet คืออะไร & ประวัติ ⭐

  • data-link + physical layer มีโปรโตคอลมากเกินไป สร้างปัญหาและความสับสน → กำหนด มาตรฐานโดยพฤตินัย (de facto standard) ชื่อ Ethernet
  • ⭐ Ethernet ครอบคลุมทั้ง data-link layer และ physical layer ในมาตรฐานเดียว
  • ยุคเก่า: bus network (มี terminator สองปลาย), ring, star ที่ใช้ hub | ปัจจุบัน: LAN แบบ star ใช้ switch, home network ใช้ wireless router + Cat 5/Cat 6
ปี เหตุการณ์
1973–1974 พัฒนาที่ Xerox PARC ได้แรงบันดาลใจจาก ALOHAnet โดย Robert Metcalfe
1978 Metcalfe ออกจาก Xerox ตั้ง 3Com
— ชักชวน DEC, Intel, Xerox (DIX) ผลักดันเป็นมาตรฐาน; แข่งกับ IBM Token Ring ที่แพง; ใช้ 10BASE2 (thin coax ราคาถูก)
1983 เป็นมาตรฐาน IEEE 802.3
1990 เปลี่ยนเป็น twisted pair — 10BASE-T (UTP)
1995+ ฆ่า Token Ring และโปรโตคอล proprietary ในตลาด PC ได้สมบูรณ์

ทำไม Ethernet ชนะ: วิวัฒนาการตามความต้องการความเร็วได้ / เปิดให้ทุกคน (ใครก็ผลิตได้ถ้าทำตาม IEEE 802.3) / ราคาถูกกว่า

2. IEEE Project 802 & Ethernet ใน OSI

Project 802 เริ่มเพื่อรวมหน้าที่และข้อกำหนดของ physical + data-link layer ของ LAN เพราะมีโปรโตคอลมากเกินไป และสองชั้นต้องทำงานใกล้ชิดกัน

  • Data-link layer = LLC (ร่วมกัน) + MAC เฉพาะเทคโนโลยี (Ethernet MAC, Token Ring MAC, …)
  • ⚠️ LLC (IEEE 802.2) ไม่ได้เป็นส่วนหนึ่งของ Ethernet
  • Ethernet == IEEE 802.3 กำหนดโดยโปรโตคอลชั้น data link (MAC) และ physical
  • LLC sublayer จัดการการสื่อสารระหว่างชั้นบนกับชั้นล่าง — รับข้อมูลโปรโตคอลเครือข่าย (มักเป็น IPv4 packet) แล้วเพิ่ม control information

3. วิวัฒนาการ 4 รุ่น ⭐

รุ่น ความเร็ว การเข้าถึงสื่อ
Standard Ethernet 10 Mbps ใช้ CSMA/CD (bus หรือ hub)
Fast Ethernet 100 Mbps CSMA/CD เป็น optional (เฉพาะเมื่อใช้ hub)
Gigabit Ethernet 1 Gbps ไม่ใช้ CSMA/CD (switch)

ปัจจุบันรองรับถึง 40 Gbps และ 100 Gbps

4. Flow Control & Error Control ⭐

Flow Control — Ethernet ไม่มี:

  • ให้บริการแบบ connectionless — แต่ละ frame อิสระ, ไม่มีขั้นตอนสร้างหรือปิด connection
  • เพราะ Ethernet ไม่มี LLC ผู้ส่งจึงส่งทันทีที่มี → อาจส่งท่วมผู้รับ → frame ถูกทิ้งและผู้ส่งไม่รู้
  • ต้องพึ่งชั้นสูง: IP (L3) ก็ connectionless ไม่รู้ว่า frame หาย → ถ้า transport เป็น UDP frame หายไปเลย ต้องพึ่ง application layer / ถ้าเป็น TCP ผู้ส่งไม่ได้ ACK → ส่งใหม่

Error Control:

  • Ethernet unreliable เหมือน IP และ UDP — ในทางปฏิบัติใช้ Ethernet โดยไม่มี flow control แล้วปล่อยให้ transport จัดการ เพื่อความเร็ว
  • มี CRC-32 ตรวจ error → ถ้าเสียและตรวจพบ → ทิ้ง frame เงียบ ๆ (drop silently)

💡 Ethernet ตรวจ error ได้ (CRC-32) แต่ไม่แก้และไม่แจ้ง — ทิ้งเงียบ ๆ แล้วให้ TCP ส่งใหม่

5. Ethernet Frame Format ⭐⭐

Preamble SFD DA SA Type Data + padding CRC
7 bytes 1 byte 6 bytes 6 bytes 2 bytes 46–1500 bytes 4 bytes
Field หน้าที่
Preamble (7 B = 56 bits) บิต 0 และ 1 สลับกัน เตือนว่า frame กำลังมา + synchronize clock — เพิ่มที่ physical layer ไม่ใช่ส่วนของ frame อย่างเป็นทางการ
SFD (1 B = 10101011) บอกจุดเริ่มต้นของ frame, โอกาสสุดท้ายในการ synchronize, จริง ๆ คือ flag — เพิ่มที่ physical layer
Destination address (DA) link-layer address ของปลายทาง
Source address (SA) link-layer address ของผู้ส่ง
Type (2 B) ระบุโปรโตคอลชั้นบน เช่น IP, ARP, OSPF
Data (46–1500 B) ต้องมีความยาวขั้นต่ำเพราะ CSMA/CD ต้องฟัง frame ที่เข้ามา; สั้นเกินใส่ 0-padding
CRC (4 B) CRC-32 คำนวณจาก addresses, type และ data

⚠️ Wireshark ปกติไม่แสดง preamble, SFD และ FCS

6. Frame Length ⭐

frame payload
ต่ำสุด 64 bytes (512 bits) 46 bytes
สูงสุด 1518 bytes (12,144 bits) 1500 bytes
  • header + trailer = 18 bytes (6 SA + 6 DA + 2 type + 4 CRC) → 64 − 18 = 46
  • ทำไม min 64 bytes? เพื่อรองรับ CSMA/CD
  • ทำไม max 1518? 1. สมัยออกแบบ หน่วยความจำแพงมาก → ลดขนาด buffer 2. ป้องกันสถานีเดียวผูกขาดสื่อกลางที่แชร์

7. MAC Address ⭐⭐

  • ทุกสถานีมี NIC (Network Interface Card) ที่ให้ link-layer address
  • Ethernet address = 6 bytes (48 bits) เขียนเป็นเลขฐาน 16 คั่นด้วย colon เช่น 4A:30:10:21:10:1A
  • 24 บิตแรก = OUI (Organizationally Unique Identifier) กำหนดโดย IEEE ให้ผู้ผลิต | 24 บิตหลัง = vendor กำหนด
  • ⚠️ MAC ซ้ำกันได้ จากความผิดพลาดตอนผลิตหรือ virtual machine

การส่ง address บนสาย: ส่ง ซ้ายไปขวาทีละไบต์ แต่ ในแต่ละไบต์ส่ง LSB ก่อน → ⭐ บิตที่บอก unicast/multicast มาถึงผู้รับก่อน (Unicast = 0, Multicast = 1)

ชนิดของ MAC address ⭐⭐ — ดูเลขฐาน 16 หลักที่ 2 จากซ้าย:

Address หลักที่ 2 ชนิด
4A:30:10:21:10:1A A = 1010 (คู่) Unicast
47:20:1B:2E:08:EE 7 = 0111 (คี่) Multicast
FF:FF:FF:FF:FF:FF ทั้งหมดเป็น F Broadcast

💡 ทำไมดูหลักที่ 2? เพราะเป็น 4 บิตล่างของไบต์แรก บิต LSB ของมันเป็นตัวบอก unicast/multicast — เลขคู่ LSB = 0, เลขคี่ LSB = 1

8. Unicast / Multicast / Broadcast ⭐

บน shared medium (Standard Ethernet) ทุกการส่งถูก broadcast อยู่แล้ว ต่างกันที่ผู้รับทำอะไร:

ชนิด ใครได้รับ ใครเก็บไว้ประมวลผล
Unicast ทุกสถานี เฉพาะผู้รับที่ตั้งใจ ที่เหลือทิ้ง
Multicast ทุกสถานี เฉพาะสมาชิกของกลุ่ม ที่เหลือทิ้ง
Broadcast ทุกสถานี (ยกเว้นผู้ส่ง) ทุกสถานี (ยกเว้นผู้ส่ง)
ชนิด Dest MAC Dest IP
Unicast 00-07-E9-42-AC-28 192.168.1.200
Broadcast FF-FF-FF-FF-FF-FF 192.168.1.255
Multicast 01-00-5E-00-00-C8 224.0.0.200
  • Broadcast ใช้กับโปรโตคอลที่ต้อง broadcast เพื่อหาข้อมูล เช่น DHCP และ ARP
  • Multicast: IPv4 = 224.0.0.0 – 239.255.255.255 | IPv6 = FF00::/8 | แทน กลุ่ม (host group) → ⭐ ใช้ได้เฉพาะเป็น destination — source เป็น unicast เสมอ | host สมัครเข้ากลุ่มด้วย IGMP | ช่วยผู้ส่งลดจำนวน frame (router/switch ช่วยทำสำเนา) | ใช้ใน เกมออนไลน์หลายผู้เล่น และ distance learning

9. MAC vs IP Address ⭐⭐

  • MAC address ใช้ route และ forward frames | IP address ใช้ route และ forward packets
  • ⭐ IP ต้นทางและปลายทางไม่เปลี่ยน แต่ MAC address เปลี่ยนทุก hop!

ตัวอย่าง A → Router B → Router C → Server D:

ช่วง MAC IP
A → B From A, To B From A, To D
B → C From B, To C From A, To D
C → D From C, To D From A, To D
  • Local Network: A (192.168.1.110, MAC 00-0A) ส่งถึง Server (192.168.1.50, MAC 00-0B) → Destination MAC = 00-0B (ของ server โดยตรง)
  • Remote Network: A ส่งถึง Server (172.16.1.99) คนละเครือข่าย → Destination MAC = 00-0C (NIC ของ router = default gateway) แต่ Destination IP = 172.16.1.99 (ปลายทางจริง) 💡 IP = ที่อยู่ปลายทางบนซองจดหมาย (ไม่เปลี่ยน) / MAC = ชื่อคนส่งต่อคนถัดไป (เปลี่ยนทุกช่วง)

10. Standard Ethernet: CSMA/CD ⭐

  • เฉพาะ Standard Ethernet ที่ต้องใช้ CSMA/CD — เลือกแบบ 1-persistent (ผู้ส่งฟังต่อระหว่างส่ง)
  • ส่ง frame ขนาดต่ำสุด 64 bytes (512 bits)

เหตุผลของ 512 bits:

  • Ethernet 10 Mbps → ส่ง 512 bits ใช้ 512/10M = 51.2 µs
  • ความเร็วสัญญาณ 2 × 10⁸ m/s → บิตแรกไปได้ 10,240 m (ขาเดียว) = 5,120 m (ไป-กลับ)
  • ถ้าจะเกิด collision ต้องเกิดก่อนผู้ส่งส่งครบ 512 bits
  • ในทางปฏิบัติ ความยาวสายสูงสุด 2,500 m เพื่อชดเชย delay ในสื่อ 💡 ถ้า frame สั้นเกินไป ผู้ส่งจะส่งจบก่อนสัญญาณชนย้อนกลับมา → ไม่รู้ว่าชน

11. Switched, Fast, Gigabit Ethernet

Switched Ethernet ⭐: switch สร้าง collision domain แยกให้แต่ละพอร์ต → บน full-duplex point-to-point link ทั้งสองฝั่งส่งพร้อมกันได้ → ไม่มี collision และไม่ใช้ CSMA/CD (half-duplex shared Ethernet ยังชนได้ แต่เป็น legacy)

Fast Ethernet (100 Mbps):

  • Hub-based: min frame ยัง 64 bytes แต่เร็วขึ้น 10 เท่า → ความยาวสายลดจาก 2,500 m เหลือ 250 m (ใช้จริง 100 m)
  • Switched: ไม่ต้องใช้ CSMA/CD — switch รับ frame เก็บใน buffer (queue) → ตรวจ destination → ส่งออกพอร์ตที่ตรง | การเชื่อมต่อเป็น full-duplex | สื่อที่แชร์เปลี่ยนเป็น point-to-point หลายเส้น
  • Backward Compatibility: มี autonegotiation ให้อุปกรณ์ตกลงความเร็ว (มักใช้ตัวที่ช้ากว่า)

Gigabit Ethernet ⭐ (IEEE 802.3z):

  • 1 Gbps | ใช้ร่วมกับ Standard/Fast ได้ด้วย autonegotiation | ใช้ framing specification เดิม
  • ⭐ เพิ่ม min frame เป็น 512 bytes (4096 bits) จาก 64 bytes → เรียกว่า Carrier Extension (ถ้าไม่ถึงใส่ padding)
  • ⭐ รวมหลาย frame เป็น frame ใหญ่ได้ = Frame Bursting
  • ไม่มี collision เพราะใช้ switch + full-duplex — ไม่มี Gigabit Ethernet hub
Implementation Medium Length Wires Encoding
1000Base-SX Fiber short-wave 550 m 2 8B/10B + NRZ
1000Base-LX Fiber long-wave 5000 m 2 8B/10B + NRZ
1000Base-CX STP 25 m 2 8B/10B + NRZ
1000Base-T4 UTP 100 m 4 4D-PAM5

Standards สรุป: 10BASE-5 (Coax 50Ω, 500 m) | 10BASE-2 (Coax BNC, 185 m) | 10BASE-T / 100BASE-TX / 1000BASE-T (UTP RJ-45, 100 m) | 1000BASE-CX (STP, 25 m) | 1000BASE-ST (MM Fiber, 220–550 m) | 1000BASE-LX (MM/SM Fiber, 550–5000 m) 💡 อ่านชื่อ: 10BASE-T = 10 Mbps, BASEband, Twisted pair / 10BASE-5 = สาย 500 m

12. Ethernet Switch ⭐⭐

Learning: switch สร้าง MAC address table แบบ dynamic โดยดู source MAC ของ frame ที่เข้าแต่ละพอร์ต

  • source MAC ยังไม่มี → เพิ่มพร้อมหมายเลขพอร์ตขาเข้า | เก็บ entry ไว้ 5 นาที | มีอยู่แล้วแต่คนละพอร์ต → แทนที่ด้วยพอร์ตล่าสุด

Forwarding:

กรณี switch ทำอะไร ชื่อเรียก
destination MAC อยู่ในตาราง ส่งออกพอร์ตที่ระบุเท่านั้น frame filtering
destination MAC ไม่อยู่ในตาราง ส่งออกทุกพอร์ตยกเว้นพอร์ตขาเข้า unknown unicast (flooding)
broadcast หรือ multicast flood ทุกพอร์ตยกเว้นพอร์ตขาเข้า

💡 จำ: Learn จาก source, Forward ตาม destination

Connected Switches: ⭐ 1 พอร์ตมีหลาย MAC address ได้ — เกิดบ่อยเมื่อ switch ต่อกับ switch (switch มี entry แยกสำหรับแต่ละ source MAC ที่ได้รับ) Sending Frame outside LAN: IP ปลายทางคนละเครือข่าย → ส่ง frame ไปที่ MAC address ของ default gateway (router) — อุปกรณ์รู้ MAC ของ default gateway ผ่าน DHCP

13. ประเภท Switch & Auto-MDIX ⭐

Store-and-forward Cut-through
วิธีทำงาน รับ frame ทั้งหมด → ตรวจ CRC → ส่งต่อถ้า CRC ถูก ส่งต่อก่อนรับครบ โดยดู destination address ก่อน
ความเร็ว ช้ากว่า เร็วกว่า
ตรวจ error ✅ ❌
QoS จำเป็นสำหรับ QoS เหมาะกับงานที่ไม่ต้องการ QoS

Cut-through 2 แบบ: Fast forwarding (ดู destination แล้วส่งเลย) | Fragment-free (ตรวจ 64 bytes แรกก่อนส่ง เพราะ collision ตาม CSMA/CD มักเกิดใน 64 bytes แรก)

Auto-MDIX = automatic medium-dependent interface crossover — switch ตรวจชนิดสายที่ต่ออัตโนมัติ → ใช้ สาย crossover หรือ straight-through ก็ได้ (ค่าเริ่มต้นบน Cisco IOS 12.2(18)SE ขึ้นไป)

สายแบบดั้งเดิม: switch–switch = crossover | switch–router = straight-through | switch–PC = straight-through | router–PC = crossover 💡 อุปกรณ์ชนิดเดียวกัน → crossover / ต่างชนิดกัน → straight-through (router กับ PC ถือเป็นกลุ่มเดียวกัน) ⚠️ Auto-MDIX (ตรวจชนิดสาย) ≠ Autonegotiation (ตกลงความเร็วและ duplex)

จุดที่มักออกสอบ

  1. Ethernet = IEEE 802.3 (data link MAC + physical); LLC (802.2) ไม่ใช่ส่วนของ Ethernet
  2. ประวัติ: Xerox PARC 1973–74 (ALOHAnet, Metcalfe), 3Com 1978, IEEE 802.3 ปี 1983, 10BASE-T ปี 1990
  3. 4 รุ่น: Standard 10M (CSMA/CD), Fast 100M (optional/hub), Gigabit + 10G ไม่มี CSMA/CD
  4. Ethernet connectionless, ไม่มี flow control, unreliable — CRC-32 ผิดแล้วทิ้งเงียบ ให้ TCP ส่งใหม่
  5. Frame: Preamble 7 | SFD 1 (10101011) | DA 6 | SA 6 | Type 2 | Data 46–1500 | CRC 4
  6. Min 64 bytes (payload 46) / Max 1518 (payload 1500) — และเหตุผลของทั้งคู่
  7. MAC 48 บิต: 24 บิตแรก OUI (IEEE), 24 บิตหลัง vendor; ส่ง LSB ก่อน
  8. ⭐ ชนิด MAC: หลักฐาน 16 ที่ 2 — คู่ = unicast, คี่ = multicast, FF ทั้งหมด = broadcast
  9. Broadcast: DHCP, ARP | Multicast: IPv4 224.0.0.0–239.255.255.255, IPv6 FF00::/8, เป็น destination เท่านั้น, IGMP
  10. ⭐ MAC เปลี่ยนทุก hop / IP ไม่เปลี่ยน; ส่งต่างเครือข่าย → dest MAC = default gateway
  11. ทำไม 512 bits: 10 Mbps → 51.2 µs → 10,240 m (ไป-กลับ 5,120 m); ใช้จริงสายยาวสุด 2,500 m
  12. Fast Ethernet hub → สาย 250 m (ใช้จริง 100 m); autonegotiation ใช้ความเร็วที่ช้ากว่า
  13. Gigabit (802.3z): min frame 512 bytes = Carrier Extension, Frame Bursting, ไม่มี hub
  14. Switch: learn จาก source MAC (เก็บ 5 นาที) / forward ตาม destination — filtering / unknown unicast flood / broadcast flood
  15. Store-and-forward (ตรวจ CRC, รองรับ QoS) vs Cut-through (fast forwarding, fragment-free ตรวจ 64 bytes แรก)
  16. Auto-MDIX ≠ Autonegotiation
