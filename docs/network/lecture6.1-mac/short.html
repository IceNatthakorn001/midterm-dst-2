📖 อ่านฉบับเต็ม📝 ทำแบบทดสอบ

ตอบคำถาม "ใครมีสิทธิ์ส่งบนสื่อกลางที่แชร์กัน?"

1. Topology & Transmission Mode ⭐

Topology = การจัดวางและความสัมพันธ์ของอุปกรณ์เครือข่ายและการเชื่อมต่อ

  • Physical topology = การเชื่อมต่อทางกายภาพ | Logical topology = การเชื่อมต่อเสมือน ใช้ interface และ IP addressing scheme
โหมด ลักษณะ ตัวอย่าง
Simplex ทางเดียว (unidirectional) TV, วิทยุ (รับ), รีโมต (ส่ง)
Half-duplex ส่งหรือรับได้ทีละฝั่ง บนสื่อที่แชร์ WLANs, legacy bus + Ethernet hubs
Full-duplex ทั้งสองฝั่งส่งและรับพร้อมกัน Ethernet switches

💡 Simplex = วิทยุ FM / Half-duplex = walkie-talkie / Full-duplex = โทรศัพท์

2. Multiple Access Control & Collision

  • Multiple Access Control = ชุดขั้นตอนจำกัดการส่งบน shared channel/broadcast link เพื่อลดการชนกัน
  • LAN ดั้งเดิมทุกสถานีต่อกับสื่อกลางที่แชร์ (bus หรือ star ที่ใช้ hub) → หลายสถานีเข้าถึงพร้อมกัน → collision
  • ⚠️ อย่าสับสน: MAC method = วิธีคุมการเข้าถึงสื่อ / MAC address = ที่อยู่ฮาร์ดแวร์
  • Collision เกิดในอากาศได้ และไม่จำเป็นต้องอยู่เครือข่ายเดียวกัน ขอแค่สัญญาณใช้ความถี่เดียวกัน → สัญญาณรวมกันมี ระดับที่อ่านไม่ได้ (undefined levels)

4. ALOHA ⭐

วิธี random-access แรกสุด พัฒนา ต้นทศวรรษ 1970 ออกแบบสำหรับ radio (wireless) LAN ที่ 9600 bps (มหาวิทยาลัยฮาวาย)

ลักษณะ ความหมาย
Multiple Access สถานีใดก็ได้ ส่งทันทีเมื่อมี frame
No Carrier Sense ไม่ตรวจว่ามีใครกำลังส่งหรือสื่อว่างไหม
No Checking for Collision หลังส่งไม่ฟังว่าชนไหม
Acknowledgement หลังส่ง รอ ACK — ไม่ได้ในเวลาที่กำหนด → ส่งใหม่
  • เวลารอ ACK = 2 เท่าของ maximum propagation delay | ไม่ได้ ACK → ถือว่าหาย → ส่งใหม่หลังรอเวลาสุ่ม
  • Propagation time = d / propagation speed

Vulnerable time ⭐ = ช่วงเวลาที่มีโอกาสเกิด collision

  • Pure ALOHA = 2 × T_fr (ถ้า A เริ่มตั้งแต่ t − T_fr ปลายของ A ชนต้นของ B; ถ้า C เริ่มก่อน t + T_fr ปลายของ B ชนต้นของ C)
  • Slotted ALOHA = T_fr — แบ่งเวลาเป็น slot ขนาดเท่ากับ 1 frame สถานีส่งได้เฉพาะตอนต้น slot → ชนกันเฉพาะเมื่อเริ่มใน slot เดียวกัน ⚠️ slotted ลดโอกาสชนลงครึ่งหนึ่ง

5. CSMA ⭐

  • "Sense before transmit" — ฟังสื่อก่อนส่ง
  • ⭐ CSMA ลดโอกาสชนได้ แต่กำจัดไม่ได้ เพราะ propagation delay — สถานีอาจฟังแล้วพบว่าว่าง เพียงเพราะสัญญาณของอีกสถานียังเดินทางมาไม่ถึง

Persistence Strategies ⭐ = กำหนดว่าควรทำอะไรเมื่อฟังแล้วพบว่าช่อง busy

Strategy ถ้าช่อง ว่าง ถ้าช่อง ไม่ว่าง
Non-persistent ส่งทันที รอเวลาสุ่ม แล้วค่อยฟังใหม่
1-persistent ส่งทันที (ความน่าจะเป็น 1) ไม่รอเวลาสุ่ม ฟังต่อเนื่องจนว่างแล้วส่งเลย
p-persistent ส่งด้วยความน่าจะเป็น p ฟังต่อจนว่าง

ตัวอย่าง p-persistent (p = 0.2): สุ่มเลข 1–100 → น้อยกว่า 20 จึงส่ง (ไม่งั้นรอ slot ถัดไป) 💡 Non-persistent = เห็นห้องน้ำไม่ว่าง เดินไปทำอย่างอื่นก่อน (ชนน้อย แต่เสียเวลา) / 1-persistent = ยืนรอหน้าประตู ว่างปุ๊บเข้าปั๊บ (เร็ว แต่แย่งกันเข้าชน) / p-persistent = ว่างแล้วโยนเหรียญก่อน

6. CSMA/CD ⭐⭐

  • ⚠️ CSMA ไม่เคยถูกใช้จริงโดยลำพัง เพราะไม่ได้กำหนดขั้นตอนเมื่อเกิด collision
  • CSMA/CD: สถานีเฝ้าดูสื่อว่าส่งสำเร็จไหม → มี collision → back off แล้วส่งใหม่
  • ⭐ Exponential backoff: รอสุ่มระหว่าง 0 ถึง (2^N − 1) × propagation_time (N = ครั้งที่พยายาม)

Collision of the First Bit: A เริ่มที่ t₁, C เริ่มที่ t₂ (ยังไม่ได้ยิน A) → บิตแรกชนกันกลางทาง → C ตรวจพบก่อนที่ t₃ → abort → A ตรวจพบที่ t₄ → abort ⚠️ frame ต้องยาวพอ ที่ผู้ส่งยังส่งไม่จบตอนสัญญาณชนย้อนมาถึง ไม่งั้นตรวจจับไม่ได้ (= เหตุผลของ minimum frame size ใน Ethernet)

Energy Level: Idle = ศูนย์ | Normal transmission = ปกติ | Collision = สูงกว่าปกติ (~2 เท่า) → ตรวจ collision ได้จากพลังงานสูงผิดปกติ

7. CSMA/CA ⭐⭐

  • ⚠️ ต่างจาก CSMA/CD: ไม่มี collision detection! (ในไร้สายตรวจจับการชนยาก เช่นปัญหา hidden terminal)
  • ขั้นตอน: 1. ใช้ persistence strategy ฟังช่อง → 2. พบว่าว่าง รอ IFG (InterFrame Gap) → 3. รอเวลาสุ่มอีกช่วง (contention window) → 4. ส่ง frame แล้วรอ ACK

IFS & Contention Window ⭐ ลำดับ: Continuously sense (busy) → Found idle → รอ IFS → Contention window (แบ่งเป็น slot) → Send frame → Time-out (รอ ACK)

  • ⭐ IFS ใช้กำหนด priority — IFG ที่มีค่าสูงกว่า = priority ต่ำกว่า
  • ⭐ ถ้าพบว่าช่องไม่ว่างระหว่าง contention window: ไม่เริ่มนับใหม่ แต่หยุด timer ไว้ แล้วนับต่อเมื่อช่องว่าง
  • จำนวน slot เปลี่ยนตาม binary exponential backoff: ครั้งแรก 1 slot แล้วเพิ่มเป็นสองเท่าทุกครั้งที่ตรวจไม่พบช่องว่างหลัง IFS

RTS/CTS และ NAV ⭐

ย่อ เต็ม
DCF Distributed Coordination Function
DIFS DCF Interframe Spacing
SIFS Short Inter-Frame Space
NAV Network Allocation Vector
RTS / CTS Request to Send / Clear to Send

ขั้นตอน (A → B, สถานีอื่น C, D):

  1. A backoff แล้วรอ DIFS → 2. A ส่ง RTS → 3. B รอ SIFS ตอบ CTS → 4. C, D ได้ยิน CTS → ตั้ง NAV → 5. A รอ SIFS ส่ง Data → 6. B รอ SIFS ส่ง ACK → 7. NAV หมดเวลาหลัง ACK

NAV: เมื่อสถานีส่ง RTS จะแนบระยะเวลาที่ต้องใช้ช่อง → สถานีที่ได้รับผลกระทบสร้าง timer NAV ว่าต้องรอนานเท่าไหร่ → ก่อนฟังสื่อจริง สถานีเช็ค NAV ก่อนว่าหมดเวลาหรือยัง 💡 NAV = ป้าย "ห้องประชุมไม่ว่าง ใช้ถึง 15:00" ไม่ต้องเคาะประตูถามจนกว่าจะถึงเวลา

8. Controlled Access ⭐

หลักการ: สถานีปรึกษากันหาว่าใครมีสิทธิ์ส่ง — ส่งไม่ได้จนกว่าจะได้รับอนุญาต

(1) Reservation: สถานีต้องจองก่อน | แต่ละช่วงมี reservation frame นำหน้า data frames | N สถานี → N reservation minislots | สถานีที่ต้องการส่งจองใน minislot ของตัวเอง แล้วส่งหลัง reservation frame ตัวอย่าง (5 สถานี): รอบแรก 0 0 0 0 1 → สถานี 1 จอง → ส่ง Data station 1 | รอบถัดไป 0 1 1 0 1 → สถานี 1, 3, 4 จอง → ส่ง Data station 4, 3, 1

(2) Polling: มี primary station (master) 1 เครื่อง + secondary stations (slaves) | การแลกเปลี่ยนข้อมูลทั้งหมดต้องผ่าน primary (primary คุมลิงก์, secondary ทำตามคำสั่ง)

  • Select = primary จะส่งข้อมูลให้ secondary | Poll = primary ถาม secondary ว่ามีข้อมูลจะส่งไหม 💡 เหมือนครูในห้องเรียน: นักเรียนพูดได้เฉพาะตอนครูเรียกชื่อ

(3) Token Passing: สถานีจัดเป็น ring แต่ละสถานีมี successor และ predecessor | ส่งข้อมูลได้เมื่อได้รับ frame พิเศษชื่อ token Flowchart: รอ token → capture token → มี data frame จะส่งไหม? (Yes → ส่ง → หมดเวลาที่จัดสรรหรือยัง? No: ส่งต่อ / Yes: ไปปล่อย) → release token

  • Physical ring = วงเดียว token วนทางเดียว | Dual ring = มีวงแหวนสำรองวนทิศตรงข้าม ถ้าวงหลักขาดใช้วงสำรองได้ 💡 Token = ไมค์ในวงประชุม

9. Channelization ⭐

แบ่ง bandwidth ของลิงก์ ให้สถานีใช้ร่วมกัน

วิธี ชื่อเต็ม หลักการ
FDMA Frequency-Division Multiple Access แต่ละสถานีได้ย่านความถี่ (band) ของตัวเอง คั่นด้วย guard bands — โปรโตคอล data link layer ที่ใช้ FDM ที่ physical layer — ใช้ใน มือถือและเครือข่ายดาวเทียม
TDMA Time-Division Multiple Access bandwidth ทั้งหมดเป็นช่องเดียว แบ่งกันใช้ตามเวลา (time slots) — ใช้ TDM ที่ physical layer
CDMA Code-Division Multiple Access แบ่งด้วยรหัส
OFDMA Orthogonal Frequency Division Multiple Access

💡 FDMA = แต่ละคู่คุยคนละห้อง / TDMA = ห้องเดียวผลัดกันคุย / CDMA = ห้องเดียวคุยพร้อมกันแต่คนละภาษา (FDMA: ถ้า Station 3 เงียบ ย่านของมันก็ว่างเปล่า)

จุดที่มักออกสอบ

  1. Simplex / half-duplex (WLAN, hubs) / full-duplex (Ethernet switches)
  2. Collision เกิดได้แม้ต่างเครือข่ายถ้าความถี่เดียวกัน
  3. 3 กลุ่ม และตัวอย่างแต่ละกลุ่ม
  4. Access method จริง: Fast Ethernet = CSMA/CD / Gigabit Ethernet = Switched / WLAN = CSMA/Polling
  5. ALOHA: early 1970s, 9600 bps; no carrier sense, no collision check, ACK timeout = 2 × max propagation delay
  6. ⭐ Vulnerable time: pure ALOHA = 2 × T_fr, slotted ALOHA = T_fr
  7. CSMA ลดแต่กำจัดการชนไม่ได้ เพราะ propagation delay
  8. Persistence 3 แบบ (p = 0.2 → สุ่ม 1–100 น้อยกว่า 20 ส่ง)
  9. CSMA/CD: exponential backoff 0 ถึง (2^N − 1) × propagation time; ตรวจจาก energy level; CSMA เปล่า ๆ ไม่ใช้จริง
  10. CSMA/CA: ไม่มี collision detection; IFS ยาว = priority ต่ำ; contention window binary exponential; ช่องไม่ว่าง → หยุด timer ไม่ restart
  11. RTS/CTS/NAV: DIFS → RTS → SIFS → CTS → SIFS → Data → SIFS → ACK
  12. Reservation: N สถานี N minislots | Polling: ทุกการสื่อสารผ่าน primary (select & poll) | Token passing: ring, ถือ token จึงส่งได้, หมดเวลาต้องปล่อย
  13. Channelization: FDMA (ความถี่ + guard bands, ใช้ FDM) / TDMA (ช่องเดียวแบ่งเวลา, ใช้ TDM) / CDMA / OFDMA
