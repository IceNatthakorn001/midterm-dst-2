Lecture 6.1 — Media Access Control Protocols

⚡ อ่านสรุปสั้น📝 ทำแบบทดสอบ

บทนี้ตอบคำถาม "ใครมีสิทธิ์ส่งบนสื่อกลางที่แชร์กัน?" (Medium Access)

เมื่อหลายสถานีใช้ช่องสัญญาณเดียวกัน ถ้าส่งพร้อมกันจะ ชนกัน (collision) — บทนี้เรียนวิธีจัดการ 3 กลุ่ม: (1) Contention-based / Random access — ALOHA, CSMA, CSMA/CD, CSMA/CA (2) Controlled access — Reservation, Polling, Token passing (3) Channelization — FDMA, TDMA, CDMA (OFDMA)

ต่อจาก Lecture 5.x (framing, error, flow control บนลิงก์) และเป็นพื้นฐานของ Lecture 6.2 Ethernet (CSMA/CD) และ Wi-Fi (CSMA/CA)

1. Review: Physical และ Logical Topologies

Topology = การจัดวางและความสัมพันธ์ของอุปกรณ์เครือข่ายและการเชื่อมต่อระหว่างกัน [Cisco NetAcad ITN7.0]

Physical topology Logical topology
แสดง การเชื่อมต่อทางกายภาพ และอุปกรณ์ต่อกันอย่างไร ระบุ การเชื่อมต่อเสมือน ระหว่างอุปกรณ์ โดยใช้ interface และ IP addressing scheme

2. Transmission Mode ⭐

โหมด ลักษณะ ตัวอย่าง
Simplex สื่อสาร ทางเดียว (unidirectional) — อุปกรณ์เป็นผู้รับอย่างเดียวหรือผู้ส่งอย่างเดียว TV, วิทยุ (รับ), รีโมตคอนโทรล (ส่ง)
Half-duplex ส่งหรือรับได้ทีละฝั่ง บนสื่อกลางที่แชร์ WLANs, legacy bus topology กับ Ethernet hubs
Full-duplex ทั้งสองฝั่งส่งและรับพร้อมกันได้ Ethernet switches

💡 Simplex = วิทยุ FM, Half-duplex = วิทยุสื่อสาร (walkie-talkie กดพูดทีละคน), Full-duplex = โทรศัพท์

3. Multiple Access Control และ Collision

3.1 Multiple Access Control

  • Multiple Access Control = ชุดขั้นตอน ที่ใช้จำกัดการส่งข้อมูลของผู้ส่งบน shared channel หรือ broadcast link เพื่อ ลดการชนกันของข้อมูล
  • Multiple Access Protocols = โปรโตคอลที่ควบคุมการเข้าถึงลิงก์ (เป็นหน้าที่ "Media access control" ใน data link layer)

ทำไมต้องมี?

  • LAN แบบดั้งเดิม ทุกสถานีต่อกับ สื่อกลางที่แชร์ (bus topology หรือ star topology ที่ใช้ hub)
  • มีโอกาสสูงที่หลายสถานีพยายามเข้าถึงสื่อพร้อมกัน
  • ถ้า 2 สถานีขึ้นไปส่งพร้อมกัน → collision
  • ดังนั้นทุกโปรโตคอลใน data link layer ต้องมีวิธี Medium Access Control (MAC) ป้องกันความขัดแย้ง

⚠️ อย่าสับสน: MAC (Media Access Control) method = วิธีคุมการเข้าถึงสื่อ / MAC address = ที่อยู่ฮาร์ดแวร์ (Lecture 6.2)

3.2 Collision

  • ถ้า 2 เครื่องขึ้นไปส่งพร้อมกัน → เกิด collision ได้
  • collision เกิดในอากาศได้ และ ไม่จำเป็นต้องอยู่เครือข่ายเดียวกัน ขอแค่ สัญญาณใช้ความถี่เดียวกัน
  • ผลคือสัญญาณรวมกันมี ระดับที่อ่านไม่ได้ (undefined levels) — เทียบ (a) สัญญาณจากโหนดเดียวที่ชัดเจน กับ (b) สัญญาณจากสองโหนดที่ชนกัน

4. ภาพรวมวิธี Multiple Access ⭐⭐

เป้าหมาย: ป้องกันสัญญาณชนกัน → ต้อง ควบคุมว่าผู้ส่งแต่ละรายจะ "พูด" อย่างไรและเมื่อไหร่

Random-access protocols (Contention-based) Controlled-access protocols Channelization protocols
ไม่มี carrier sense: ALOHA (MA) Reservation FDMA
มี carrier sense: CSMA, CSMA/CD, CSMA/CA Polling TDMA
Token passing CDMA
  • CS = Carrier Sense (ฟังก่อนว่าช่องว่างไหม), MA = Multiple/Media Access

4.1 รายละเอียดแต่ละกลุ่ม

Contention-based access

  • Performance: ดีที่สุดสำหรับ traffic แบบ bursty และโหลด เบาถึงปานกลาง
    • (+) implement ง่าย
    • (−) ประสิทธิภาพแย่เมื่อ traffic หนาแน่น
  • ทุกโหนดทำงาน half-duplex แย่งกันใช้สื่อ เช่น:
    • CSMA/CD — legacy bus-topology Ethernet
    • CSMA/CA — Wireless LANs

Controlled access

  • Deterministic access — แต่ละโหนดมี เวลาของตัวเอง บนสื่อ
  • ใช้ใน legacy network เช่น Token Ring และ ARCNET
  • Round Robin-based: Polling (Centralized), Token Passing (Decentralized)
  • Reservation-based: BRAP — Broadcast Recognition with Alternating Priorities (Centralized), DQDB (IEEE 802.6), DAMA (Decentralized)

5. Contention-Based: ภาพรวม

5.1 CSMA/CD (LAN)

  • ใช้ใน legacy Ethernet LANs
  • ทำงาน half-duplex (ส่งหรือรับทีละเครื่อง)
  • ใช้กระบวนการ ตรวจจับการชน (collision detection) กำหนดว่าเมื่อไหร่ส่งได้ และทำอะไรถ้าส่งพร้อมกัน
  • Random Access Method:
    • ทุกสถานีมี สิทธิ์ใช้สื่อเท่ากัน ไม่มีสถานีใดควบคุม
    • ถ้ามีมากกว่า 1 สถานีส่ง → access conflict = collision! frame จะถูกทำลายหรือถูกแก้ไข
    • ไม่มี scheduler ไม่มีกฎ — แข่งขัน (contention) กับสถานีอื่น

กระบวนการตรวจจับการชน:

  1. อุปกรณ์ที่ส่งพร้อมกันทำให้เกิด signal collision บนสื่อที่แชร์
  2. อุปกรณ์ ตรวจพบการชน (สื่อไม่ว่าง)
  3. อุปกรณ์ รอเวลาสุ่ม แล้วส่งใหม่

วิวัฒนาการ: MA → CSMA → แตกเป็น CSMA/CD และ CSMA/CA

5.2 CSMA/CA (WLAN)

  • ใช้ใน IEEE 802.11 WLANs
  • ทำงาน half-duplex
  • ใช้กระบวนการ หลีกเลี่ยงการชน (collision avoidance)

กระบวนการหลีกเลี่ยงการชน:

  • ตอนส่ง อุปกรณ์ แนบระยะเวลาที่ต้องใช้ในการส่ง (time duration) ไปด้วย
  • อุปกรณ์อื่นบนสื่อได้รับข้อมูลนี้ จึง รู้ว่าสื่อจะไม่ว่างนานเท่าไหร่

6. ALOHA ⭐

6.1 ประวัติ

  • ALOHA = วิธี random-access แรกสุด พัฒนาช่วง ต้นทศวรรษ 1970
  • ออกแบบสำหรับ radio (wireless) LAN ที่ 9600 bps (มหาวิทยาลัยฮาวาย)

6.2 หลักการ

ลักษณะ ความหมาย
Multiple Access สถานีใดก็ได้ ส่งทันทีเมื่อมี frame
No Carrier Sense ไม่ตรวจ ว่ามีสถานีอื่นกำลังส่งหรือสื่อว่างไหม — สำหรับสื่อไร้สาย สถานีอาจอยู่ไกลกันจนไม่ได้ยินกันอยู่แล้ว
No Checking for Collision หลังส่ง ไม่ฟัง สื่อว่าชนไหม
Acknowledgement หลังส่งแล้ว รอ ACK (explicit หรือ implicit) ถ้าไม่ได้ในเวลาที่กำหนด → ส่งใหม่

รายละเอียด ACK:

  • เวลาที่รอ ACK = 2 เท่าของ maximum propagation delay
  • ถ้าไม่ได้ ACK → ถือว่า frame หาย → ส่งใหม่หลังรอเวลาสุ่ม (random)
  • Propagation time = t₂ − t₁ = d / propagation speed — ความเร็วสัญญาณขึ้นกับสื่อและความถี่

6.3 Pure ALOHA: Vulnerable Time ⭐

  • Vulnerable time = ช่วงเวลาที่มีโอกาสเกิด collision
  • frame B ส่งที่เวลา t ใช้เวลา T_fr:
    • ถ้า A เริ่มส่งตั้งแต่ t − T_fr → ปลายของ A ชนกับต้นของ B
    • ถ้า C เริ่มส่งก่อน t + T_fr → ปลายของ B ชนกับต้นของ C
  • Pure ALOHA vulnerable time = 2 × T_fr

6.4 Slotted ALOHA ⭐

  • แบ่งเวลาเป็น slot ขนาดเท่ากับ 1 frame; สถานี ส่งได้เฉพาะตอนต้น slot
  • ถ้ามี 2 สถานีส่งใน slot เดียวกัน → ชนทั้ง slot (collision duration = 1 slot)
  • ตัวอย่างในภาพ: Slot 2 — Frame 2.1 และ 3.1 ชน; Slot 3 — Frame 1.2 และ 4.1 ชน; Slot 1, 4, 5, 6 ส่งสำเร็จ

  • Slotted ALOHA vulnerable time = T_frame (A และ B ชนกันเฉพาะเมื่อเริ่มใน slot เดียวกัน)

⚠️ Pure ALOHA = 2 × T_fr / Slotted ALOHA = T_fr → slotted ลดโอกาสชนลงครึ่งหนึ่ง

7. CSMA (Carrier Sense Multiple Access) ⭐

7.1 หลักการ

  • เพื่อลดโอกาสชน สถานีควร ฟังสื่อก่อนส่ง → "Sense before transmit"
  • CSMA ลดโอกาสชนได้ แต่กำจัดไม่ได้
  • เพราะ propagation delay — สถานีอาจฟังแล้วพบว่าว่าง เพียงเพราะสัญญาณของอีกสถานีที่ส่งไปแล้ว ยังเดินทางมาไม่ถึง

7.2 Collision ใน CSMA

  • A ส่ง frame ที่ t₁, Z ฟังแล้วยังไม่ได้ยิน A จึงส่งที่ t₂ → สัญญาณชนกันกลางทาง → collision signal ย้อนกลับไปหาทั้งสองฝั่ง
  • Space/Time model: B เริ่มส่งที่ t₁, C เริ่มที่ t₂ → มีพื้นที่ที่สัญญาณ A (B) และ C ซ้อนทับกัน (area where both signals exist)

7.3 Persistence Strategies ⭐

Persistence strategy = กำหนดว่าสถานี ควรทำอะไรเมื่อฟังแล้วพบว่าช่องไม่ว่าง (busy)

  • Nonpersistent
  • Persistent
    • 1-persistent
    • p-persistent
Strategy ถ้าช่อง ว่าง ถ้าช่อง ไม่ว่าง
Non-persistent ส่งทันที รอเวลาสุ่ม แล้วค่อยฟังใหม่
1-persistent ส่งทันที (ความน่าจะเป็น 1) ไม่รอเวลาสุ่ม — ฟังต่อเนื่องจนกว่าว่างแล้วส่งเลย
p-persistent ส่งด้วย ความน่าจะเป็น p ฟังต่อจนว่าง

ตัวอย่าง p-persistent (p = 0.2): สุ่มเลข 1 ถึง 100 → ถ้าน้อยกว่า 20 สถานีจะส่ง (ไม่งั้นรอ slot ถัดไปแล้วลองใหม่)

Persistence strategy Non-persistent vs 1-persistent

💡 Non-persistent = เห็นห้องน้ำไม่ว่าง เดินไปทำอย่างอื่นก่อนแล้วค่อยกลับมาดู (ชนน้อย แต่อาจเสียเวลา) 1-persistent = ยืนรอหน้าประตู ว่างปุ๊บเข้าปั๊บ (เร็ว แต่ถ้ามีคนรอหลายคนจะแย่งกันเข้าชน) p-persistent = ว่างแล้วโยนเหรียญก่อนว่าจะเข้าไหม (สมดุลระหว่างสองแบบ)

8. CSMA/CD (Collision Detection) ⭐⭐

8.1 หลักการ

  • CSMA ไม่เคยถูกใช้จริงโดยลำพัง เพราะ ไม่ได้กำหนดขั้นตอนเมื่อเกิด collision
  • CSMA/CD เพิ่มขั้นตอนจัดการ collision:
    • สถานี เฝ้าดูสื่อ ว่าส่งสำเร็จไหม
    • ถ้า มี collision → back off (รอ) ช่วงเวลาหนึ่งแล้วส่งใหม่
  • เวลารอสุ่มระหว่าง 0 ถึง (2^N − 1) × propagation_time (N = ครั้งที่พยายาม) → เรียกว่า exponential back off

💡 ยิ่งชนบ่อย ช่วงสุ่มยิ่งกว้างขึ้นเท่าตัว (1, 3, 7, 15, … ช่อง) → โอกาสสุ่มได้เวลาซ้ำกันลดลง

8.2 Collision of the First Bit

  • A เริ่มส่งที่ t₁, C เริ่มส่งที่ t₂ (ยังไม่ได้ยิน A)
  • บิตแรกของ A และ C ชนกันกลางทาง (collision occurs)
  • C ตรวจพบ collision ก่อน ที่ t₃ → abort (หยุดส่ง)
  • A ตรวจพบ ที่ t₄ → abort
  • ช่วง t₁–t₄ = transmission time ของ A, t₂–t₃ = transmission time ของ C

⚠️ สำหรับ CSMA/CD ต้องให้ frame ยาวพอ ที่ผู้ส่งยังส่งไม่จบตอนที่สัญญาณชนย้อนมาถึง ไม่อย่างนั้นจะตรวจจับการชนไม่ได้ (เป็นเหตุผลของ minimum frame size ใน Ethernet)

8.3 Energy Level

ระดับพลังงานบนสาย 3 สถานะ:

สถานะ ระดับพลังงาน
Idle (ว่าง) ศูนย์
Normal frame transmission ปกติ
Collision สูงกว่าปกติ (สัญญาณรวมกัน ประมาณ 2 เท่า)

→ สถานีตรวจ collision ได้โดยดูว่า พลังงานสูงผิดปกติ

9. CSMA/CA (Collision Avoidance) ⭐⭐

9.1 หลักการ

  • ต่างจาก CSMA/CD: ไม่มี collision detection! (ในไร้สายตรวจจับการชนยาก — เช่นปัญหา hidden terminal)
  • ขั้นตอน:
    1. ใช้ persistence strategy อย่างใดอย่างหนึ่งในการฟังช่อง
    2. เมื่อพบว่าช่องว่าง → รอ IFG (InterFrame Gap) ระยะหนึ่ง
    3. รอเวลาสุ่มอีกช่วง (contention window)
    4. ส่ง frame แล้วรอ ACK
  • CSMA/CA ใช้ใน wireless LAN

9.2 IFG (IFS) และ Contention Window ⭐

ลำดับเวลา: Continuously sense (busy) → Found idle → รอ IFS → Contention window (แบ่งเป็น slot, ขนาดแบบ binary exponential) → Send frame → Time-out (รอ ACK)

  • IFS ใช้กำหนด priority ของสถานีหรือ frame ได้ → IFG ที่มีค่าสูงกว่าจะมี priority ต่ำกว่า
  • ถ้าพบว่าช่องไม่ว่างระหว่าง contention window: ไม่เริ่มนับใหม่ แต่ หยุด timer ไว้ แล้ว นับต่อเมื่อช่องว่าง
  • Contention window = ช่วงเวลาที่แบ่งเป็น slots — สถานีที่พร้อมส่ง สุ่มจำนวน slot เป็นเวลารอ
  • จำนวน slot เปลี่ยนตาม binary exponential backoff: ครั้งแรก 1 slot แล้ว เพิ่มเป็นสองเท่า ทุกครั้งที่สถานีตรวจไม่พบช่องว่างหลังเวลา IFS

สรุปเป็นภาษาไทย (สไลด์): หากช่องสัญญาณว่าง จะรอ IFG แล้วรอเวลาอีกจำนวนหนึ่งตามจำนวน slot ที่สุ่ม แล้วจึงส่ง frame ออกไป และตั้ง timer รอ ACK จากผู้รับ แล้วค่อยส่ง frame ที่ 2

9.3 Procedure with RTS/CTS และ NAV ⭐

ศัพท์:

ย่อ เต็ม
DCF Distributed Coordination Function
DIFS DCF Interframe Spacing
SIFS Short Inter-Frame Space
NAV Network Allocation Vector
RTS Request to Send
CTS Clear to Send

ขั้นตอน (Source A → Destination B, สถานีอื่น C, D):

  1. A backoff แล้วรอ DIFS
  2. A ส่ง RTS ไป B
  3. B รอ SIFS แล้วตอบ CTS
  4. สถานีอื่น (C, D) ได้ยิน CTS → ตั้ง NAV (งดส่งตามเวลาที่ระบุ)
  5. A รอ SIFS แล้วส่ง Data
  6. B รอ SIFS แล้วส่ง ACK
  7. NAV ของสถานีอื่นหมดเวลาหลัง ACK

9.4 NAV ทำงานอย่างไร

  • คำถาม: เมื่อสถานีหนึ่งได้สิทธิ์ใช้ช่อง สถานีอื่นจะเลื่อนการส่งอย่างไร? → คำตอบ: NAV
  • เมื่อสถานีส่ง RTS จะ แนบระยะเวลาที่ต้องใช้ช่อง ไปด้วย
  • สถานีที่ได้รับผลกระทบจะสร้าง timer ชื่อ NAV แสดงว่าต้อง รอนานเท่าไหร่ก่อนจะตรวจว่าช่องว่างได้
  • ทุกครั้งที่มีสถานีส่ง RTS สถานีอื่นเริ่ม NAV
  • ก่อนฟังสื่อจริง สถานีจะเช็ค NAV ก่อนว่าหมดเวลาหรือยัง

💡 NAV เหมือนป้าย "ห้องประชุมไม่ว่าง ใช้ถึง 15:00" — ไม่ต้องเคาะประตูถามจนกว่าจะถึงเวลานั้น

10. Controlled Access ⭐

หลักการ: สถานี ปรึกษากัน เพื่อหาว่าใครมีสิทธิ์ส่ง — สถานีส่งไม่ได้ จนกว่าจะได้รับอนุญาต จากสถานีอื่น

3 วิธี: Reservation, Polling (round-robin), Token Passing (round-robin) — สถานีได้ "รอบ" ส่งตามช่วงเวลาสูงสุดที่กำหนด

10.1 Reservation

  • สถานีต้อง จองก่อน จะส่งข้อมูล
  • ในแต่ละช่วง จะมี reservation frame นำหน้า data frames ของช่วงนั้น
  • ถ้ามี N สถานี จะมี N reservation minislots ใน reservation frame
  • สถานีที่ต้องการส่งจะ จองใน minislot ของตัวเอง
  • สถานีที่จองแล้ว ส่งข้อมูลได้หลัง reservation frame

ตัวอย่าง (5 สถานี, minislot เรียง 5 4 3 2 1):

  • รอบแรก minislot = 0 0 0 0 1 → สถานี 1 จอง → ส่ง Data station 1
  • รอบถัดไป minislot = 0 1 1 0 1 → สถานี 1, 3, 4 จอง → ส่ง Data station 4, 3, 1

10.2 Polling (Select and Poll)

  • ใช้กับ topology ที่มี primary station (master) 1 เครื่อง และ secondary stations (slaves)
  • การแลกเปลี่ยนข้อมูลทั้งหมดต้องผ่าน primary
    • primary ควบคุมลิงก์ และกำหนดว่าใครใช้ช่องได้เมื่อไหร่
    • secondary ทำตามคำสั่ง
  • Select = primary จะส่งข้อมูลให้ secondary / Poll = primary ถาม secondary ว่ามีข้อมูลจะส่งไหม

💡 เหมือนครูในห้องเรียน: นักเรียนพูดได้เฉพาะตอนครูเรียกชื่อ (poll) หรือครูพูดกับนักเรียนคนนั้น (select)

10.3 Token Passing

  • สถานีจัดเรียงเป็น วงแหวน (ring) แต่ละสถานีมี successor (ถัดไป) และ predecessor (ก่อนหน้า)
  • สถานี ส่งข้อมูลได้เมื่อได้รับ frame พิเศษชื่อ token

Flowchart:

  1. Start → รอ token
  2. จับ (capture) token
  3. มี data frame จะส่งไหม?
    • Yes → ส่ง frame → หมดเวลาที่ได้รับจัดสรรหรือยัง? → No: กลับไปเช็คว่ามี frame อีกไหม / Yes: ไปข้อ 4
    • No → ไปข้อ 4
  4. ปล่อย (release) token → Stop

Physical และ Logical Ring Topology:

a. Physical ring b. Dual ring
สถานีต่อกันเป็นวงเดียว token วนทางเดียว มี วงแหวนสำรองวงที่สอง วนทิศตรงข้าม — ถ้าวงหลักขาด ใช้วงสำรองได้

💡 Token = ไมค์ในวงประชุม: ใครถือไมค์คนนั้นพูด พูดเสร็จหรือหมดเวลาก็ส่งต่อคนข้าง ๆ

11. Channelization ⭐

Channelization = วิธี multiple-access ที่ แบ่ง bandwidth ของลิงก์ ให้สถานีต่าง ๆ ใช้ร่วมกัน

วิธี ชื่อเต็ม
FDMA Frequency-Division Multiple Access
TDMA Time-Division Multiple Access
CDMA Code-Division Multiple Access
OFDMA Orthogonal Frequency Division Multiple Access

11.1 FDMA

  • bandwidth ที่มีแบ่งกันใช้ทุกสถานี — แต่ละสถานีได้ ย่านความถี่ (band) ของตัวเอง
  • FDMA = โปรโตคอล data link layer ที่ใช้ FDM ที่ physical layer
  • ใช้ใน โทรศัพท์มือถือและเครือข่ายดาวเทียม
  • bandwidth ของ common channel ถูกแบ่งเป็น bands ที่คั่นด้วย guard bands (ช่องว่างกันสัญญาณรบกวนกัน)
  • ตัวอย่างในภาพ: Station 1, 2, 4 ส่งข้อมูลในย่านของตัวเอง Station 3 เงียบ (silent) ย่านของมันก็ว่างเปล่า

11.2 TDMA

  • bandwidth ทั้งหมดเป็นช่องเดียว
  • สถานี แบ่งกันใช้ตามเวลา (time slots)
  • TDMA = โปรโตคอล data link layer ที่ใช้ TDM ที่ physical layer
  • bandwidth เป็นช่องเดียวที่ time-share ระหว่างสถานี

💡 เปรียบกับห้องที่มีคนคุยกันหลายคู่: FDMA = แต่ละคู่คุยคนละห้อง (แบ่งความถี่) TDMA = ทุกคู่ใช้ห้องเดียว ผลัดกันคุยตามเวลา (แบ่งเวลา) CDMA = ทุกคู่คุยพร้อมกันในห้องเดียว แต่ใช้คนละภาษา (แบ่งด้วยรหัส) — สไลด์ระบุเฉพาะชื่อ

14. สรุปท้ายบท / จุดที่มักออกสอบ

  1. Physical vs logical topology
  2. Simplex / half-duplex (WLAN, hubs) / full-duplex (Ethernet switches)
  3. Multiple access control ลดการชนบน shared/broadcast link; collision เกิดได้แม้ต่างเครือข่ายถ้าความถี่เดียวกัน
  4. 3 กลุ่ม: random access (ALOHA, CSMA, CSMA/CD, CSMA/CA), controlled access (reservation, polling, token passing), channelization (FDMA, TDMA, CDMA)
  5. Contention-based: เหมาะ bursty/โหลดเบา-กลาง, ง่าย, แย่เมื่อโหลดหนัก, half-duplex
  6. Controlled access: deterministic; round-robin (polling = centralized, token = decentralized); reservation (BRAP centralized, DQDB/DAMA decentralized); Token Ring, ARCNET
  7. Access method จริง: Fast Ethernet = CSMA/CD, Gigabit Ethernet = switched, Wireless LAN = CSMA/Polling
  8. ALOHA: early 1970s, radio LAN 9600 bps; no carrier sense, no collision check, ACK timeout = 2 × max propagation delay แล้วสุ่มส่งใหม่
  9. Vulnerable time: pure ALOHA = 2 × T_fr, slotted ALOHA = T_fr
  10. CSMA: sense before transmit; ลดแต่กำจัดการชนไม่ได้เพราะ propagation delay
  11. Persistence: non-persistent (สุ่มรอ), 1-persistent (รอจนว่างแล้วส่งทันที), p-persistent (p = 0.2 → สุ่ม 1–100 น้อยกว่า 20 ส่ง)
  12. CSMA/CD: ตรวจการชน → abort → exponential backoff 0 ถึง (2^N − 1) × propagation time; ตรวจจาก energy level; CSMA เปล่า ๆ ไม่ใช้จริงเพราะไม่มีขั้นตอนจัดการ collision
  13. CSMA/CA: ไม่มี collision detection; persistence → IFG → random contention window → ส่ง → รอ ACK; ใช้ใน WLAN
  14. IFS ยาว = priority ต่ำ; contention window ใช้ binary exponential backoff (เริ่ม 1 slot แล้วคูณ 2); ช่องไม่ว่าง → หยุด timer ไม่ restart
  15. RTS/CTS/NAV: DIFS → RTS → SIFS → CTS → SIFS → Data → SIFS → ACK; สถานีอื่นตั้ง NAV ตามเวลาที่ระบุ; เช็ค NAV ก่อนฟังสื่อ
  16. Reservation: N สถานี N minislots, จองก่อนแล้วส่งหลัง reservation frame
  17. Polling: primary/secondary, ทุกการสื่อสารผ่าน primary (select & poll)
  18. Token passing: ring, successor/predecessor, ส่งได้เมื่อถือ token, หมดเวลาต้องปล่อย; physical ring vs dual ring
  19. Channelization: FDMA (แบ่งความถี่ + guard bands, มือถือ/ดาวเทียม, ใช้ FDM), TDMA (ช่องเดียวแบ่งเวลา, ใช้ TDM), CDMA, OFDMA
