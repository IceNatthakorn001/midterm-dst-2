1. อินเทอร์เน็ตคืออะไร — 2 มุมมอง

(ก) Nuts and Bolts:

ชิ้นส่วน คืออะไร
Hosts = End systems อุปกรณ์ปลายทางที่รันแอปเครือข่าย อยู่ที่ edge
Packet switches routers และ switches
Communication links fiber, copper, radio, satellite — ความเร็ว = transmission rate = bandwidth

2. Protocol ⭐

นิยาม: โปรโตคอลกำหนด รูปแบบ (format) + ลำดับ (order) ของข้อความที่ส่ง-รับ และ การกระทำ (actions) เมื่อส่งหรือได้รับข้อความ 💡 จำ Format – Order – Action | เทียบคน: Hi → Hi → Got the time? → 2:00 / เครื่อง: TCP connection request → response → GET url → <file>

3. Network Edge

โครงสร้าง: Network edge (hosts = clients + servers; servers มักอยู่ data center) | Access networks + physical media | Network core (router เชื่อมกัน)

Access Networks (3 กลุ่ม: residential / institutional / mobile)

เทคโนโลยี จุดสำคัญ
Cable (HFC = Hybrid Fiber Coax) ใช้ระบบ cable TV เดิม ส่ง data + TV ที่ความถี่ต่างกัน ด้วย FDM | Asymmetric (down 40 Mbps–1.2 Gbps, up 30–100 Mbps) | บ้านหลายหลังแชร์ | cable modem + splitter → CMTS ที่ cable headend
DSL ใช้สายโทรศัพท์เดิม → central office → DSLAM | voice/data คนละความถี่ | dedicated (ไม่แชร์) down 24–52 Mbps, up 3.5–16 Mbps
Home network อุปกรณ์ → WiFi AP (54, 450 Mbps) หรือ Ethernet (1 Gbps) → router + firewall + NAT → modem (มักรวมกล่องเดียว)
Wireless access WLAN (802.11 WiFi) ~100 ft, 11/54/450 Mbps | Wide-area cellular (4G/5G) สิบ ๆ km, สิบ ๆ Mbps
Enterprise ผสมมีสาย+ไร้สาย, Ethernet 100M/1G/10 Gbps, WiFi 11/54/450 Mbps
Data center ลิงก์ 10s–100s Gbps เชื่อมเซิร์ฟเวอร์หลักร้อย-พันเครื่อง

⚠️ Cable = shared / DSL = dedicated (ออกสอบบ่อย) ตารางสรุป: FTTH (ใยแก้ว, dedicated, เร็วมาก) | Cable/HFC (coax, shared, ไม่สม่ำเสมอ) | DSL (สายโทรศัพท์, dedicated, จำกัดตามระยะทางจากชุมสาย) | 5G (คลื่นวิทยุ, shared, เน้น mobility)

Host ส่งข้อมูลอย่างไร: รับ application message → หั่นเป็น packets ยาว L bits → ส่งเข้า access network ด้วยอัตรา R bps $$d_{trans} = \frac{L\ \text{(bits)}}{R\ \text{(bits/sec)}}$$ 💡 ลิงก์ 1 Mbps ใช้ 1 µs/บิต, 10 Mbps ใช้ 100 ns/บิต → bandwidth สูง = บิตสั้นลง ไม่ใช่วิ่งเร็วขึ้น

Physical Media

Guided media = สัญญาณวิ่งในสื่อของแข็ง / Unguided media = กระจายอิสระ (radio)

สื่อ จุดเด่น/ตัวเลข
Twisted pair (TP) Cat 5: 100 Mbps, 1 Gbps / Cat 6: 10 Gbps
Coaxial ตัวนำ 2 ชั้นมีจุดศูนย์กลางร่วมกัน | bidirectional, broadband (หลายช่องความถี่บนสายเดียว) หลายร้อย Mbps ต่อช่อง
Fiber optic ส่งพัลส์แสง (1 พัลส์ = 1 บิต) | 10s–100s Gbps, error ต่ำ, repeater ห่างกันได้, ไม่ถูกรบกวนจากคลื่นแม่เหล็กไฟฟ้า
Wireless radio broadcast, half-duplex, โดน reflection/obstruction/interference

Radio links: WiFi 10–100s Mbps สิบ ๆ เมตร | 4G/5G สิบ ๆ Mbps ~10 km | Bluetooth ระยะสั้น | Terrestrial microwave point-to-point ช่องละ 45 Mbps | Satellite down < 100 Mbps (Starlink), delay 270 ms (geostationary)

4. Network Core ⭐⭐

Forwarding vs Routing

Forwarding (switching) Routing
ขอบเขต Local — ที่ router ตัวเดียว Global — ทั้งเครือข่าย
ทำอะไร ย้ายแพ็กเก็ตจาก input link → output link ที่ถูก หาเส้นทางต้นทาง → ปลายทาง
ใช้อะไร ดู destination address ใน header → local forwarding table routing algorithms (ตัวสร้าง forwarding table)

💡 Routing = วางแผนทั้งทริปด้วย Google Maps / Forwarding = ถึงแยกแล้วดูป้ายเลี้ยวซ้ายหรือขวา

Packet Switching

  • Store-and-forward: router ต้องได้รับแพ็กเก็ต ครบทั้งก้อน ก่อนจึงส่งต่อ | ส่ง L บิตบนลิงก์ R bps ใช้ L/R วินาที ตัวอย่าง: L = 10 Kbits, R = 100 Mbps → 10,000/100,000,000 = 0.1 msec (ผ่าน N ลิงก์ ≈ N·L/R)
  • Queueing & Loss: เกิดเมื่องานเข้าเร็วกว่าที่ให้บริการได้ → แพ็กเก็ตต่อคิว → ถ้า buffer ของ router เต็ม → drop (สูญหาย)

Circuit Switching

  • จองทรัพยากรตลอดเส้นทาง ให้ "call" — dedicated ไม่แชร์ → ประสิทธิภาพรับประกัน | ถ้าไม่ส่งข้อมูล circuit ว่างเปล่าเสียเปล่า | ใช้ในเครือข่ายโทรศัพท์แบบดั้งเดิม
FDM (Frequency Division Multiplexing) TDM (Time Division Multiplexing)
แบ่งอะไร แบ่งความถี่เป็นแถบแคบ ๆ แบ่งเวลาเป็น slot
ผู้ใช้ได้อะไร ได้ band ของตัวเอง ส่งได้ตลอดเวลา ที่ความเร็วของ band แคบ ได้ slot เป็นระยะ ส่งที่ความเร็วของ band กว้างทั้งหมด แต่เฉพาะช่วง slot ตัวเอง
เทียบ ถนนแบ่งเลน ถนนเลนเดียวผลัดกันวิ่ง

Packet vs Circuit Switching ⭐

ตัวอย่างคำนวณ: ลิงก์ 1 Gb/s, ผู้ใช้ใช้ 100 Mb/s ตอน active, active 10% ของเวลา

  • Circuit switching: 10 users (ต้องจองเต็มให้ทุกคน)
  • Packet switching: 35 users โดยโอกาสที่ active พร้อมกันเกิน 10 คน < 0.0004
ข้อดี packet switching ข้อเสีย
เหมาะกับข้อมูล bursty อาจเกิด congestion → delay และ loss จาก buffer overflow
แชร์ทรัพยากรคุ้มค่า ต้องมีโปรโตคอลช่วย reliable data transfer + congestion control
ไม่ต้อง call setup ทำให้เหมือน circuit (รับประกันคุณภาพ) ได้ยาก

💡 Circuit = จองโต๊ะร้านอาหาร (ไม่มาโต๊ะก็ว่างเสียเปล่า) / Packet = ทางด่วนที่รถแชร์กัน ใช้เต็มประสิทธิภาพแต่ รถติด (queueing delay)

โครงสร้าง "Network of Networks"

ขั้นวิวัฒนาการ: 1. ต่อทุก access ISP ตรง ๆ → ไม่ scale ต้อง O(N²) ❌ → 2. ต่อเข้า global transit ISP ตัวเดียว (มีข้อตกลงทางเศรษฐกิจ) → 3. มีคู่แข่ง (ISP A, B, C) → 4. เชื่อมกันผ่าน peering link + IXP → 5. เกิด regional ISP → 6. เกิด content provider networks (Google, Microsoft, Akamai)

ระดับ ลักษณะ
Tier-1 ISPs ระดับโลก (Level 3, Sprint, AT&T, NTT) — เชื่อมต่อกันเอง ไม่คิดค่าบริการ (settlement-free)
Regional ISPs เชื่อมเครือข่ายท้องถิ่นเข้ากับ Tier 1
Access ISPs ระดับท้องถิ่น (บ้าน องค์กร)
  • เงินไหลจากชั้นล่างขึ้นชั้นบน ข้อมูลไหลทั้งสองทาง
  • POP (Point of Presence) = จุดที่ลูกค้า/ISP ย่อยนำ router มาเชื่อมกับ ISP ใหญ่
  • IXP (Internet Exchange Point) = อาคารศูนย์กลางที่ผู้ให้บริการหลายรายมาเชื่อมกัน → Peering แลกข้อมูลโดยตรง → ลด latency + ประหยัดค่าใช้จ่าย
  • Content Provider Network = private network ทั่วโลก ข้ามลำดับชั้น (bypass) วางเซิร์ฟเวอร์ใกล้ผู้ใช้ → คุมคุณภาพได้ 100%

💡 เทียบถนน: Access ISP = ซอยหน้าบ้าน / Regional = ถนนสายหลัก / Tier-1 = ทางหลวงข้ามประเทศ / IXP = ทางแยกต่างระดับ / Content provider = ทางด่วนส่วนตัว

3 หลักคิด (The Invisible Infrastructure): 1. Intelligence is at the Edge (ความฉลาดอยู่ที่ปลายทาง แกนกลางแค่ส่งให้เร็ว) 2. Network of Networks (กระจายศูนย์ เชื่อมด้วยข้อตกลงธุรกิจและ IXP) 3. The Spanning Layer (IP) (IP เรียบง่าย เป็นกาวผสานฮาร์ดแวร์ทุกยุค)

5. Performance: Delay, Loss, Throughput ⭐⭐

4 แหล่งของ delay

$$d_{nodal} = d_{proc} + d_{queue} + d_{trans} + d_{prop}$$

ชนิด คืออะไร ขึ้นกับ
d_proc ตรวจ bit errors, เลือก output link ความเร็ว router (< microsecs)
d_queue เวลารอที่ output link ก่อนได้ส่ง ระดับ congestion (ไม่แน่นอน)
d_trans เวลา "ดัน" ทุกบิตขึ้นลิงก์ L/R (ขนาดแพ็กเก็ต / link rate)
d_prop เวลาสัญญาณเดินทางจากต้นถึงปลายลิงก์ d/s (ระยะทาง / ความเร็วสัญญาณ ≈ 2×10⁸ m/s)

⚠️ d_trans ขึ้นกับขนาดแพ็กเก็ตและ bandwidth ไม่เกี่ยวระยะทาง / d_prop ขึ้นกับระยะทาง ไม่เกี่ยวขนาดแพ็กเก็ต

Caravan analogy ⭐ (รถ = bit, ขบวน = packet, ด่าน = link transmission)

กรณี 1: 10 คัน, ด่าน 12 วินาที/คัน, รถวิ่ง 100 km/hr, ด่านห่าง 100 km → d_trans = 12 × 10 = 120 s = 2 นาที + d_prop = 100/100 = 1 ชม. = 62 นาที กรณี 2: รถ 1000 km/hr, ด่าน 1 นาที/คัน — รถถึงด่าน 2 ก่อนด่าน 1 เสร็จไหม? → ใช่! คันแรกออกนาทีที่ 1 วิ่ง 100 km ใช้ 6 นาที → ถึงด่าน 2 นาทีที่ 7 ขณะนั้นยังเหลือ 3 คัน ที่ด่าน 1 (= บิตแรกอาจถึง router ถัดไปแล้ว ขณะที่บิตหลังยังส่งไม่เสร็จ เมื่อ d_trans > d_prop)

Traffic Intensity

$$\text{traffic intensity} = \frac{L \cdot a}{R}$$ (a = อัตราแพ็กเก็ตมาถึงเฉลี่ย, L = ความยาวแพ็กเก็ต, R = bandwidth)

ค่า La/R queueing delay เฉลี่ย
≈ 0 delay น้อย
→ 1 delay พุ่งสูงมาก
> 1 delay เฉลี่ยอนันต์!

traceroute

วัด delay จากต้นทางไปยังแต่ละ router — สำหรับทุก i: ส่ง 3 แพ็กเก็ต ที่จะไปถึง router ที่ i (ตั้ง TTL = i) → router ที่ i ส่งกลับ → ผู้ส่งวัดเวลา ตัวอย่าง gaia.cs.umass.edu → www.eurecom.fr (19 hops): hop 1–7 = 1–22 ms → hop 7→8 กระโดดเป็น ~104 ms = trans-oceanic link | * * * = ไม่ตอบ | delay "ลดลง" ได้เพราะแต่ละ probe เป็นแพ็กเก็ตแยกกัน เจอ queueing delay ไม่เท่ากัน

Packet Loss & Throughput

  • Loss: queue มีความจุจำกัด → แพ็กเก็ตที่มาตอนคิวเต็มถูก drop → อาจส่งใหม่โดย node ก่อนหน้า / source end system / ไม่ส่งใหม่เลย
  • Throughput = อัตราที่บิตถูกส่งถึงผู้รับ | instantaneous (ณ เวลาหนึ่ง) vs average (เฉลี่ยช่วงยาว)
  • throughput = min(Rs, Rc) — ลิงก์ช้าที่สุด = bottleneck link
  • แชร์ backbone 10 connections: per-connection throughput = min(Rc, Rs, R/10) — ในทางปฏิบัติ access link (Rc หรือ Rs) มักเป็นคอขวด ไม่ใช่ backbone

6. Network Security

อินเทอร์เน็ตแต่แรกไม่ได้ออกแบบมาเพื่อความปลอดภัย (วิสัยทัศน์เดิม: กลุ่มผู้ใช้ที่ไว้ใจกัน) → ผู้ออกแบบต้อง "ไล่ตามแก้" และคำนึงถึงความปลอดภัยทุก layer

การโจมตี อธิบาย
Packet sniffing บน broadcast media (shared Ethernet, wireless) network interface แบบ promiscuous อ่าน/บันทึกทุกแพ็กเก็ตที่ผ่าน (รวมรหัสผ่าน) — Wireshark ก็เป็น packet sniffer
IP spoofing ใส่แพ็กเก็ตที่มี source address ปลอม เพื่อหลอกว่ามาจากแหล่งที่น่าเชื่อถือ
DoS ถล่มด้วย traffic ปลอมจนใช้งานไม่ได้ — จาก เครื่องเดียว/แหล่งเดียว
DDoS โจมตีจาก หลายเครื่องพร้อมกัน ใช้เครื่องติดมัลแวร์ (botnet) — รับมือยากกว่ามาก

ขั้นตอน DDoS: เลือกเป้าหมาย → เจาะเข้าเครื่องต่าง ๆ (สร้าง botnet) → สั่งถล่มเป้าหมาย แนวป้องกัน: Authentication (SIM card เป็น hardware identity ในมือถือ แต่อินเทอร์เน็ตดั้งเดิมไม่มี) | Confidentiality (encryption) | Integrity checks (digital signatures) | Access restrictions (VPN) | Firewalls ("middlebox", off-by-default, กรองแพ็กเก็ตขาเข้า, ตรวจจับ DoS)

7. Protocol Layers & Encapsulation ⭐⭐

ทำไมต้องแบ่ง layer: 1. โครงสร้างชัดเจน (reference model) 2. Modularization — เปลี่ยนวิธีทำงานภายใน layer หนึ่ง ไม่กระทบส่วนอื่น (อุปมา: ระบบการเดินทางทางอากาศ — แต่ละ layer ทำบริการหนึ่งอย่าง และพึ่งบริการของ layer ข้างล่าง)

Internet protocol stack (TCP/IP 5 layers)

Layer หน้าที่ โปรโตคอล หน่วยข้อมูล
5. Application รองรับแอปเครือข่าย HTTP, IMAP, SMTP, DNS message
4. Transport process ↔ process TCP, UDP segment
3. Network ต้นทาง → ปลายทาง (host-to-host) IP, routing protocols datagram
2. Link อุปกรณ์เพื่อนบ้าน (node-to-node) Ethernet, 802.11, PPP frame
1. Physical บิต "บนสาย" — bits

⚠️ Transport = process-to-process / Network = host-to-host / Link = neighbor-to-neighbor

Encapsulation

Layer ได้ ประกอบด้วย
Application message M
Transport segment Ht + M
Network datagram Hn + Ht + M
Link frame Hl + Hn + Ht + M
  • ฝั่งรับทำกลับกัน = Decapsulation | 💡 เหมือน ตุ๊กตาแม่ลูกดก (Matryoshka)
  • Switch (L2) ดูแค่ Hl | Router (L3) แกะถึง Hn เพื่อดู IP ปลายทางแล้วห่อ Hl ใหม่ | มีแค่ host ปลายทางที่แกะถึง application
  • สรุป: Application สร้าง Message → Transport ใส่ port ต้นทาง/ปลายทาง → Network แปะ IP address (เหมือนจ่าหน้าซอง) → Link บรรจุลงกรอบส่งผ่านสายสัญญาณเฉพาะหน้า
  • Link layer เปลี่ยนไปตามสภาพแวดล้อมทางกายภาพแต่ละช่วง (มือถือ →WiFi→ router บ้าน →Fiber→ ISP core switch)

OSI Reference Model (7 layers)

ปี เหตุการณ์

1964 Baran — packet switching ในเครือข่ายทหาร
1967 ARPAnet ถูกคิดขึ้น
1969 ARPAnet node แรกเริ่มใช้งาน
1972 ARPAnet สาธิตต่อสาธารณะ, NCP (host-host protocol แรก), โปรแกรม e-mail แรก, 15 nodes
1970 ALOHAnet (ดาวเทียมในฮาวาย)
1974 Cerf and Kahn — สถาปัตยกรรมเชื่อมต่อเครือข่าย
1976 Ethernet ที่ Xerox PARC
1979 ARPAnet 200 nodes
1982 กำหนด SMTP
1983 ใช้งาน TCP/IP, กำหนด DNS
1985 กำหนด FTP
1988 TCP congestion control
1990s ARPAnet ปลดระวาง, 1991 NSF ยกเลิกข้อจำกัดเชิงพาณิชย์, Web (HTML, HTTP: Berners-Lee), 1994 Mosaic → Netscape
ปลาย 90s–2000s instant messaging, P2P file sharing, network security สำคัญ, ~50 ล้าน host
2008 SDN (software-defined networking)
2017 อุปกรณ์ mobile มากกว่า fixed
2023 ~15B อุปกรณ์ ต่ออินเทอร์เน็ต

หลักการ internetworking ของ Cerf & Kahn (กำหนดสถาปัตยกรรมทุกวันนี้): minimalism, autonomy (ไม่ต้องเปลี่ยนภายในเครือข่ายเพื่อเชื่อมกัน) | best-effort service model | stateless routing | decentralized control

9. สไลด์เสริม

Network Scale

ประเภท ระยะ ตัวอย่าง
PAN 1–10 m Bluetooth
LAN 10 m–1 km Wi-Fi (อาคาร/วิทยาเขต)
MAN ~10 km WiMAX (เมือง)
WAN 100 km–ทั้งโลก Internet

วิวัฒนาการของ Ethernet

  1. Classic Ethernet — สาย Coaxial ร่วมกัน → การชนกัน (collisions)
  2. Hubs — Twisted Pair รวมศูนย์ที่ Hub แต่ยังแชร์แบนด์วิดท์และชนกันได้
  3. Switches — แต่ละพอร์ตมี dedicated lane → ขจัดการชนกันสมบูรณ์

Switched Ethernet: Independent Collision Domains (แต่ละพอร์ตแยกกัน ส่งขนานได้) | Full-Duplex (ส่งและรับพร้อมกัน) | High-Speed Backplane (store-and-forward ระดับ Gbps) | plug-and-play, ถูก, ประสิทธิภาพสูง

Wireless LANs (IEEE 802.11)

  • BSS (Basic Service Set): Access Point (AP) = base station เชื่อมไร้สายกับใช้สาย | Wireless Hosts ในรัศมี | Infrastructure Mode = การสื่อสารวิ่งผ่าน AP เป็นศูนย์กลาง | Association = อุปกรณ์ต้องลงทะเบียนกับ AP ก่อน
  • Hidden Terminal Problem: A ส่งให้ B → C อยากส่งให้ B → C ไม่ได้ยินสัญญาณของ A (นอกระยะ) จึงคิดว่าว่างและส่ง → ชนกันที่ B โดย A และ C ไม่รู้ตัว
  • ⭐ Key insight: เครือข่ายไร้สายใช้ CSMA/CD แบบ LAN มีสายไม่ได้ ต้องใช้กลไกหลีกเลี่ยง (avoidance) และยืนยันการรับส่งแทน

จุดที่มักออกสอบ (สรุปเร็ว)

  1. Internet = network of networks (2 มุม: nuts & bolts / services)
  2. Protocol = format + order + actions
  3. Cable (HFC) = shared, asymmetric, FDM vs DSL = dedicated, สายโทรศัพท์ → DSLAM
  4. Forwarding (local, forwarding table) vs Routing (global, routing algorithm)
  5. Store-and-forward d = L/R (10 Kb / 100 Mbps = 0.1 ms)
  6. Packet vs Circuit: 1 Gbps, 100 Mbps, active 10% → circuit 10 users, packet 35 users
  7. 4 delays: d_nodal = d_proc + d_queue + d_trans (L/R) + d_prop (d/s)
  8. Caravan: 62 นาที / กรณี 2 → นาทีที่ 7 เหลือ 3 คัน
  9. Traffic intensity La/R: >1 = อนันต์
  10. Throughput = min(Rs, Rc) / แชร์ backbone = min(Rc, Rs, R/10)
  11. TCP/IP 5 layers + หน่วยข้อมูล M-S-D-F | OSI ขาด Presentation + Session
  12. Encapsulation: Ht → Hn → Hl; switch ดูถึง L2, router ดูถึง L3
  13. ประวัติ: 1961 Kleinrock, 1969 ARPAnet node แรก, 1972 NCP+email, 1974 Cerf & Kahn, 1976 Ethernet, 1982 SMTP, 1983 TCP/IP+DNS, 1985 FTP, 1988 TCP congestion control, 2008 SDN, 2017 mobile > fixed
  14. Hidden terminal ทำให้ Wi-Fi ใช้ CSMA/CD ไม่ได้
