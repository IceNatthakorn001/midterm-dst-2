⚡ สรุปสั้น · Lecture 5.2 — Flow Control, ARQ, and HDLC

📖 อ่านฉบับเต็ม📝 ทำแบบทดสอบ

ตอบคำถาม "ผู้ส่งกับผู้รับประสานงานกันได้ไหม?" (Delivery Control)

1. Flow Control

ทำไมต้องมี: ส่งเร็วเกินไป → ผู้รับรับไม่ทัน buffer overflow / frame loss | ส่งช้าเกินไป → ผู้รับเสียเวลารอ ประสิทธิภาพลดลง

  • Sender buffer = เก็บ frame ที่รอส่ง/รอส่งใหม่ | Receiver buffer = เก็บ frame จนชั้นบนพร้อมประมวลผล
  • Feedback: ACK (ยืนยันรับสำเร็จ) / NAK หรือ retransmission request (ขอส่งใหม่) — ใช้ทั้ง flow control และ error recovery
For noiseless channel For noisy channel
Simplest / Stop-and-Wait Stop-and-Wait ARQ / Go-Back-N ARQ / Selective Repeat ARQ

Simple Protocol: ไม่มีทั้ง flow control และ error control — packet จาก network layer → ทำเป็น frame แล้วส่ง

2. Stop-and-Wait ARQ ⭐

หลักการ: ผู้ส่ง ส่งทีละ 1 frame แล้วรอ ACK ก่อนส่งตัวถัดไป | เก็บสำเนา frame ล่าสุดไว้จนได้ ACK

  • frame ถูกต้อง → ผู้รับส่ง ACK | frame มี error → ผู้รับไม่ส่ง ACK + ทิ้ง frame → timer หมดเวลา → ส่งใหม่ ⚠️ ไม่มีประสิทธิภาพบนลิงก์ bandwidth สูงหรือ delay ยาว

Sequence & ACK Numbers:

  • ต้องมี sequence number เพื่อแยก frame ใหม่จาก frame ซ้ำ — Stop-and-Wait ใช้แค่ 0 และ 1 สลับกัน
  • S = seq ของ frame ที่กำลังส่ง (ฝั่งส่ง) | R = seq ของ frame ถัดไปที่คาดหวัง (ฝั่งรับ)
  • ผู้รับส่งเฉพาะ positive ACK — ⭐ ACK number = frame ถัดไปที่คาดหวัง → ACK 1 = รับ frame 0 สำเร็จแล้ว รอ frame 1

4 สถานการณ์ ⭐

กรณี สิ่งที่เกิด
(ก) Normal S=0 ส่ง F0 → ACK 1 → S=1 ส่ง F1 → ACK 0 → …
(ข) Lost Frame F1 หาย → ไม่มี ACK → Time-out → ส่ง F1 ใหม่ → ACK 0
(ค) Lost ACK ผู้รับได้ F1 ส่ง ACK 0 แต่ ACK หาย → timeout → ส่ง F1 ซ้ำ → ผู้รับคาดหวัง F0 แต่ได้ F1 → รู้ว่าซ้ำ ทิ้ง F1 + ส่ง ACK 0 อีกครั้ง
(ง) Delayed ACK ACK 1 มาช้า → timeout ส่ง F0 ซ้ำ → ผู้รับคาดหวัง F1 → ทิ้ง F0 แล้วส่ง ACK 1 อีกรอบ → ผู้ส่งทิ้ง ACK 1 ตัวที่สอง (ACK เก่า)

💡 Sequence number → ตรวจ frame ซ้ำ / ACK number → ตรวจ ACK เก่าหรือที่มาช้า เมื่อผู้รับได้ frame ซ้ำ: 1. รู้จาก seq no. ว่าซ้ำ 2. ทิ้ง frame ซ้ำ 3. ส่ง ACK ที่เหมาะสมอีกครั้ง

3. Pipelining

Pipelining = ผู้ส่ง ส่งหลาย frame ก่อนรอ ACK → หลาย frame อยู่ระหว่างทางพร้อมกัน → เพิ่ม link utilization

  • มีใน Go-Back-N และ Selective Repeat | ⚠️ Stop-and-Wait ไม่มี pipelining

4. Go-Back-N ARQ ⭐⭐

Sequence numbers: m บิต → 2^m เลข (0 ถึง 2^m − 1) แล้ววนซ้ำ (m=3 → 0–7, 0, 1, …)

Send Window:

  • ส่งได้สูงสุด W frames โดยไม่รอ ACK ทีละตัว | frame ที่ส่งแล้วยังไม่ได้ ACK = outstanding frames (ต้องเก็บสำเนาทั้งหมด)
  • ⭐ ขนาด send window สูงสุด W ≤ 2^m − 1
ส่วน (S_f = first outstanding, S_n = next to send) สถานะ
ซ้ายของ S_f sent, acknowledged, purged
S_f ถึงก่อน S_n outstanding
S_n ถึงขอบขวา ส่งได้เมื่อ process ส่งข้อมูลมา
ขวาของ window ยังส่งไม่ได้

Sliding: window เลื่อนเมื่อได้ ACK ที่ไม่มี error (ackNo ≥ S_f และ < S_n) — ตัวอย่าง: S_f = 4, ได้ ACK 6 → S_f = 6 (frame 4, 5 ถูก ACK แล้วแบบ cumulative)

Receive Window: ⭐ ขนาด 1 เสมอ — รับเฉพาะ frame ถัดไปที่คาดหวัง (R_n) → ถูกต้อง = รับไว้ เลื่อน R_n ส่ง cumulative ACK | frame ที่มาผิดลำดับถูกทิ้ง

Timers & ACK:

  • ผู้ส่งมี timer ตัวเดียว สำหรับ outstanding frame ที่เก่าที่สุด | ผู้รับไม่มี retransmission timer
  • timer หมด → ส่งใหม่ตั้งแต่ frame เก่าสุดที่ยังไม่ได้ ACK และทุก outstanding frame ถัดไป ("go back N")
  • Cumulative ACK: ACK n = ทุก frame ก่อน n ได้รับแล้ว และรอ frame n

ทำไม send window ต้อง < 2^m ⭐ (ตัวอย่าง m = 2, เลข 0–3)

Window = 3 (< 2^m) ✅ Window = 4 (= 2^m) ❌
ส่ง F0,1,2 → ACK หายหมด → timeout ส่ง F0 ซ้ำ ส่ง F0,1,2,3 → ACK หายหมด → timeout ส่ง F0 ซ้ำ
ผู้รับรอ frame 3 → ได้ F0 → Correctly discarded ผู้รับรอ frame 0 ของรอบใหม่พอดี → Erroneously accepted

สถานการณ์ Lost Frame: ส่ง F0,1 → ACK 2 → ส่ง F2 หาย → ส่ง F3 → ผู้รับรอ F2 → F3 discarded, not in the window → Time-out → ส่งใหม่ทั้ง F2 และ F3 ACK เสีย/หาย/มาช้า: เพราะ cumulative ACK ถ้า ACK2 หายแต่ ACK3 มาก่อน timeout → ไม่ต้องส่งใหม่ (ACK3 ยืนยัน frame 0,1,2 แบบสะสม) | Delayed ACK ไม่จำเป็นต้องทำให้ส่งใหม่

GBN vs Stop-and-Wait: ⭐ Stop-and-Wait = กรณีพิเศษของ GBN ที่ใช้ seq แค่ 0,1 และ send window = 1 Piggybacking: ใส่ ACK ไปใน data frame ที่เดินทางสวนทาง (Data + ACK ใน frame เดียว) 💡 "ขี่หลังหมู"

ข้อดี/ข้อเสีย GBN: ✅ receiver ง่าย (window = 1, ไม่ต้อง buffer frame ผิดลำดับ) | ❌ ไม่มีประสิทธิภาพเมื่อ frame หาย/เสียบ่อย — frame เดียวหายต้องส่งใหม่ทั้งชุด, บาง frame ที่ผู้รับได้ถูกต้องแล้วกลับถูกทิ้ง → เปลือง bandwidth, เพิ่ม delay, congestion แย่ลง

5. Selective Repeat ARQ ⭐⭐

  • sliding-window protocol รองรับ pipelined transmission
  • ⭐ ต่างจาก GBN: ผู้รับ รับและ buffer frame ที่ถูกต้องแต่มาผิดลำดับได้ → frame หาย/เสีย → ส่งใหม่เฉพาะ frame นั้น

Window size: เพื่อไม่ให้สับสนเมื่อเลขวนรอบ ต้อง ไม่เกินครึ่งของ sequence-number space $$W_S \le 2^{m-1}, \quad W_R \le 2^{m-1}$$ ตัวอย่าง: seq 3 บิต (0–7), receive window = 4 รอช่วง 0,1,2,3 → ได้ F0, F2, F3 (F1 ยังไม่มา) → SR: รับทั้ง 3 เก็บ buffer รอ F1 / GBN: F2, F3 ถูกทิ้ง

  • ผู้รับอาจใช้ NAK (negative acknowledgement) / selective reject ระบุ frame ที่หาย เพื่อขอส่งใหม่ก่อน timeout

SR: Lost Frame: ส่ง F0,1 → ACK 2 → F2 หาย → ส่ง F3 → ผู้รับรับไว้ใน buffer + ส่ง NAK 2 → ผู้ส่งส่งใหม่เฉพาะ F2 → ผู้รับได้ F2 → ส่ง frame 2, 3 ขึ้นชั้นบนพร้อมกัน

ทำไม window ≤ 2^(m−1) ⭐ (ตัวอย่าง m = 2 → window ครึ่ง = 2)

Window = 2 ✅ Window = 3 ❌
ส่ง F0,1 → ACK หาย → timeout ส่ง F0 ซ้ำ ส่ง F0,1,2 → ACK หาย → timeout ส่ง F0 ซ้ำ
receive window = {2, 3} → F0 ไม่อยู่ → Correctly discarded receive window = {3, 0, 1} → F0 อยู่ใน window → Erroneously accepted

Timer & ACK: timer แยกสำหรับแต่ละ outstanding frame → timer ของ frame ไหนหมด ส่งใหม่เฉพาะ frame นั้น | individual acknowledgments (ACK ได้แม้มาผิดลำดับ ถ้า seq อยู่ใน receive window)

💡 GBN: frames treated as a group / SR: frames treated individually

Time sequence: ส่ง F0 → delivered → ACK 1 → F1 หาย → F2 buffer → F3 buffer + ส่ง NAK 1 → ส่งซ้ำเฉพาะ F1 → Frames 1, 2, 3 delivered พร้อมกัน → ACK 4

7. HDLC

โปรโตคอล data-link แบบ bit-oriented มาตรฐาน สำหรับลิงก์ serial point-to-point และ multipoint

  • Core concepts: flag-based framing + bit stuffing | flow & error control ด้วย sequence numbers, ACKs, ARQ | ทำงานได้ทั้ง half-duplex และ full-duplex
  • Operating modes: Unacknowledged Connectionless Mode | Connection Oriented: NRM (Normal Response Mode — primary สั่ง secondary ตอบ) และ ABM (Asynchronous Balanced Mode — ทั้งสองฝั่งเท่าเทียม)
Connectionless Connection-oriented
แต่ละ frame จัดการแยกกัน, ไม่มี session สร้าง logical link ก่อนส่ง และ ปิด หลังจบ
frame อาจหาย ซ้ำ ไม่เรียงลำดับ (เว้นแต่ชั้นอื่นจัดการ) เก็บ sequence numbers, ACKs, flow-control state

HDLC Frame Format ⭐: Flag | Address | Control | Information | FCS | Flag

  • Control field: 1 หรือ 2 ไบต์ สำหรับ flow และ error control
  • Information field: ข้อมูลผู้ใช้/จัดการเครือข่าย (มีเฉพาะใน I- และ U-frames) ความยาวคงที่ภายในแต่ละเครือข่าย
  • FCS: ITU-T CRC ขนาด 2 หรือ 4 ไบต์
Format โครงสร้าง
HDLC Flag (0x7E) | Address | Control | Information | FCS | Flag
PPP + Protocol field ระบุโปรโตคอลชั้นบน, มาตรฐานเปิด (Address = 0xFF, Control = 0x03)
Cisco HDLC + Type/Protocol field, proprietary ของ Cisco
LAPB HDLC-based สำหรับ X.25
Frame Relay Flag | Q.922 Address / DLCI | Information | FCS | Flag — มีบิต FECN, BECN, DE
ATM Header 5 bytes + Payload 48 bytes = fixed 53-byte cell — ไม่ใช้ flag คั่น

HDLC Frame Types ⭐

ชนิด ใช้ทำอะไร Control field
I-frames (Information) ส่งข้อมูลผู้ใช้ + ข้อมูลควบคุม (piggybacking) บิตแรก 0 | N(S) 3 บิต | P/F | N(R) 3 บิต
S-frames (Supervisory) เฉพาะข้อมูลควบคุม 2 บิตแรก 10 | Code 2 บิต | P/F | N(R)
U-frames (Unnumbered) system management 2 บิตแรก 11
  • P/F (Poll/Final): 0 = Poll (primary → secondary), 1 = Final (secondary → primary)
  • N(S) = seq ของ frame ที่กำลังส่ง | N(R) = ค่า ACK เมื่อ piggybacking

S-Frame Codes ⭐

Code ชื่อ ความหมาย
00 RR — Receiver Ready ACK รับได้สมบูรณ์
01 RNR — Receiver Not Ready ACK แต่ผู้รับยุ่งอยู่ (ช่วยให้ส่งช้าลง)
10 REJ — Reject NAK ใช้ใน Go-Back-N
11 SREJ — Selective Reject NAK ใช้ใน Selective Repeat

💡 REJ ↔ GBN / SREJ ↔ SR

U-Frame codes: SABM (set asynchronous balanced mode), SABME, SNRM (set normal response mode), SNRME, UP, UI, UA (unnumbered acknowledgment), RD, DISC (disconnect), DM, RIM, SIM, RSET, XID, FRMR

Connection Establishment/Release ⭐: A ส่ง U-frame (SABM) → B ตอบ U-frame (UA) → Data transfer → A ส่ง U-frame (DISC) → B ตอบ UA

Piggybacking ตัวอย่าง (GBN): A ส่ง I-frame N(S)=0, N(R)=0 → A ส่ง N(S)=1, N(R)=0 → B ส่ง N(S)=0, N(R)=2 = "Send my 0, wants your 2!" → B ส่ง N(S)=1, N(R)=2 → N(S)=2, N(R)=2 → A ไม่มีข้อมูล จึงตอบ S-frame RR, N(R)=3 = "Wants your 3, Receiver Ready"

8. Performance ⭐⭐

ตัวอย่าง: ระยะทาง 1000 m, propagation 500 m/s, frame 100 bits, ข้อมูลรวม 1000 bits

  • round trip ต่อ frame = 2 × 1000 / 500 = 4 วินาที | จำนวน frame = 1000/100 = 10 frames
  • Stop-and-Wait: 10 × 4 = 40 วินาที
  • Go-Back-N (N = 2): 10/2 = 5 รอบ × 4 = 20 วินาที

Bandwidth-Delay Product = bandwidth (bps) × round-trip delay (s) = จำนวนบิตที่ระบบส่งออกได้ระหว่างรอ ACK ตัวอย่าง utilization: bandwidth 1 Mbps, round trip 20 ms, frame 1000 bits

  • Bandwidth-delay product = 1×10⁶ × 20×10⁻³ = 20,000 bits
  • Stop-and-Wait: ส่งได้แค่ 1,000 บิต → Utilization = 1,000/20,000 = 5%
  • Go-Back-N (15-frame): 15 × 1000 = 15,000 บิต → Utilization = 15,000/20,000 = 75% (ถ้ามี frame เสียจะน้อยกว่านี้มาก)

9. Summary: ขนาด Window ⭐

m บิต จำนวนเลข GBN send GBN recv SR send = recv
1 2 1 1 1
2 4 3 1 2
3 8 7 1 4
4 16 15 (คี่) 1 8 (คู่)

ทั้งสอง ARQ ถ้าส่ง 20 packets ไม่มีหาย (m=4): 0, 1, …, 15, 0, 1, 2, 3

จุดที่มักออกสอบ

  1. Flow control กัน buffer overflow; Noiseless (Simplest, Stop-and-Wait) / Noisy (S&W ARQ, GBN, SR)
  2. Stop-and-Wait: seq 0/1, ACK n = รอ frame n, 4 สถานการณ์ (normal, lost frame, lost ACK, delayed ACK)
  3. Pipelining มีใน GBN และ SR ไม่มีใน Stop-and-Wait
  4. GBN: send ≤ 2^m − 1, receive = 1, cumulative ACK, timer เดียว, timeout ส่งใหม่ทั้งชุด, frame ผิดลำดับทิ้ง
  5. ทำไม GBN window < 2^m: frame 0 เก่าจะถูกรับผิดเป็น frame 0 ใหม่
  6. GBN ACK หาย: ACK ตัวถัดไปยืนยันแทนได้ (cumulative)
  7. Stop-and-Wait = GBN ที่ window = 1; piggybacking = ACK ใน data frame
  8. SR: send = receive ≤ 2^(m−1), buffer ผิดลำดับ, individual ACK, timer ต่อ frame, NAK/SREJ, ส่งใหม่เฉพาะตัว
  9. ทำไม SR ≤ 2^(m−1): window ใหญ่กว่านั้น frame 0 เก่าตกใน receive window ใหม่
  10. 4 บิต: SR window 8 (คู่), GBN send 15 (คี่) receive 1
  11. HDLC frame: Flag | Address | Control (1–2 bytes) | Information | FCS (CRC 2/4) | Flag; modes connectionless, NRM, ABM
  12. PPP เพิ่ม Protocol field (open, 0xFF/0x03) / Cisco HDLC เพิ่ม Type field (proprietary) / ATM = fixed 53-byte cell
  13. Frame types: I (0), S (10), U (11); S-frame: 00 RR, 01 RNR, 10 REJ (GBN), 11 SREJ (SR)
  14. Connection: SABM → UA → data → DISC → UA
  15. Performance: round trip 4 s, 10 frames → S&W 40 s, GBN(N=2) 20 s
  16. Bandwidth-delay product 1 Mbps × 20 ms = 20,000 bits → S&W 5%, GBN 15 frames 75%
