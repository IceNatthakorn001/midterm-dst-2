Go-Back-N ARQ Animation

ดูการทำงานของ Go-Back-N ทุกกรณีที่เกิดได้ — เฟรมหาย, เฟรมเสีย, ACK หาย, ACK มาช้า, หายซ้ำ, REJ และขนาดหน้าต่างผิด (Lecture 5.2)

กด ▶ เล่น เพื่อเริ่ม
ได้ ACK แล้ว / รับแล้ว ส่งแล้ว รอ ACK (outstanding) ในหน้าต่าง ยังไม่ส่ง หาย ⚡ เสีย (CRC ผิด) REJ (NAK) กรอบเส้นประ = ช้า

💡 แตะเฟรมหรือ ACK ที่กำลังวิ่งอยู่ เพื่อทำให้มันหายเองได้ทุกกรณี (ลองในโหมด “ทดลองเอง”)

บันทึกเหตุการณ์

    กติกาของ Go-Back-N ที่ใช้ในแอนิเมชัน

    • Sequence number m บิต → เลข 0 ถึง 2m − 1 แล้ววนซ้ำ (m = 3 → 0–7, 0, 1, …)
    • Send window ≤ 2m − 1 ส่งได้หลายเฟรมโดยไม่ต้องรอ ACK · ตัวชี้ S_f = เฟรมเก่าสุดที่ยังไม่ได้ ACK, S_n = เฟรมถัดไปที่จะส่ง
    • Receive window = 1 ผู้รับรับเฉพาะเฟรม R_n ที่คาดหวัง เฟรมที่มาผิดลำดับถูกทิ้ง
    • Cumulative ACK: ACK n = รับทุกเฟรมก่อน n แล้ว และรอเฟรม n → ACK ตัวหลังยืนยันแทนตัวที่หายได้
    • Timer ตัวเดียว สำหรับเฟรมเก่าสุด (S_f) เริ่มใหม่ทุกครั้งที่หน้าต่างเลื่อน · หมดเวลา → ส่งใหม่ตั้งแต่ S_f ทุกเฟรมที่ค้าง (go back N)
    • ผู้ส่งทิ้ง ACK ที่ซ้ำหรือเก่า (ไม่อยู่ในช่วง S_f+1 ถึง S_n)
    • REJ (กรณี 9): ผู้รับบอกทันทีว่าต้องการเฟรมไหน ผู้ส่งไม่ต้องรอ timeout (HDLC S-frame code 10)
    ⚠️ (อธิบายเพิ่ม) ตามสไลด์ ผู้รับ ACK เฉพาะเฟรมที่มาถูกลำดับ และเงียบเมื่อได้เฟรมที่มาก่อนเวลา (ช่วงหลังเฟรมหาย) · แต่ถ้าได้เฟรมซ้ำที่เคยรับแล้ว (ผู้ส่งส่งซ้ำเพราะ ACK หาย) ผู้รับต้องส่ง ACK R_n ซ้ำ ไม่อย่างนั้นผู้ส่งจะไม่มีวันรู้ว่าเฟรมไปถึงแล้ว · บางตำรา (Kurose) ส่ง ACK ซ้ำทุกครั้งที่ได้เฟรมผิดลำดับ

    สรุปทุกกรณี

    กรณีเกิดอะไรขึ้นผลลัพธ์
    จำง่าย ๆ: ถ้ามี ACK ตัวหลังมาทันก่อน timeout → ไม่ต้องส่งใหม่ · ถ้าไม่มี → หมดเวลาแล้วย้อนส่งใหม่ตั้งแต่ S_f ทั้งชุด · เฟรมเสีย (CRC ผิด) ผลเหมือนเฟรมหาย · REJ ช่วยให้ไม่ต้องรอ timeout · หน้าต่างต้อง < 2m ไม่งั้นผู้รับแยกเฟรมเก่ากับเฟรมใหม่ไม่ออก
