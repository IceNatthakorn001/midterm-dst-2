1. VLAN คืออะไร ⭐

VLAN = การเชื่อมต่อแบบ logical กับอุปกรณ์อื่นที่มีลักษณะคล้ายกัน:

  • แบ่งกลุ่มอุปกรณ์ (segmentation) แม้อยู่บน switch เดียวกัน
  • broadcast, multicast และ unicast ถูกแยกอยู่ภายในแต่ละ VLAN
  • แต่ละ VLAN มีช่วง IP address ของตัวเอง
  • broadcast domain เล็กลง

ตัวอย่าง: ตึก 3 ชั้น แบ่ง VLAN ตามแผนกข้ามชั้นได้ — VLAN 2 IT (10.0.2.0/24), VLAN 3 HR (10.0.3.0/24), VLAN 4 Sales (10.0.4.0/24) ⚠️ อุปกรณ์ต่าง VLAN คุยกันตรง ๆ ไม่ได้ที่ layer 2 — ต้องผ่านอุปกรณ์ layer 3 (router) 💡 VLAN = "ห้องแชทกลุ่ม" ในบริษัท — นั่งคนละชั้นก็อยู่กลุ่มเดียวกันได้ ประกาศในกลุ่มหนึ่งไม่รบกวนกลุ่มอื่น

ประโยชน์ 6 ข้อ ⭐

ประโยชน์ คำอธิบาย
Smaller Broadcast Domains ลดจำนวนอุปกรณ์ที่ได้รับ broadcast แต่ละครั้ง
Improved Security เฉพาะผู้ใช้ใน VLAN เดียวกันสื่อสารกันได้
Improved IT Efficiency จัดกลุ่มอุปกรณ์ที่ต้องการคล้ายกัน (อาจารย์ vs นักศึกษา)
Reduced Cost switch ตัวเดียวรองรับหลายกลุ่ม/หลาย VLAN
Better Performance broadcast domain เล็ก → traffic น้อย → bandwidth ดีขึ้น
Simpler Management กลุ่มคล้ายกันใช้แอปและทรัพยากรคล้ายกัน

ถ้าไม่มี VLAN: อุปกรณ์ทุกเครื่องที่ต่อ switch จะได้รับ traffic unicast, multicast, broadcast ทั้งหมด (PC1 ส่ง broadcast → switch ส่งออกทุกพอร์ต → ทุกเครื่องได้รับหมด)

2. Types of VLANs ⭐

Default VLAN = VLAN 1 มีสถานะเป็น: Default VLAN (ทุกพอร์ตอยู่ VLAN 1 ตั้งแต่แรก) + Default Native VLAN + Default Management VLAN — ⭐ ลบหรือเปลี่ยนชื่อไม่ได้

Cisco แนะนำให้ย้ายหน้าที่ default เหล่านี้ไปไว้ VLAN อื่น (เพื่อความปลอดภัย)

show vlan brief บน switch ใหม่: VLAN 1 default (active) Fa0/1–Fa0/24, Gi0/1–2 + VLAN 1002 fddi-default, 1003 token-ring-default, 1004 fddinet-default, 1005 trnet-default (act/unsup)

ชนิด หน้าที่
Data VLAN traffic ที่ผู้ใช้สร้าง (email, web) — VLAN 1 เป็น default data VLAN
Native VLAN ใช้กับ trunk link เท่านั้น — บน 802.1Q trunk ทุก frame ถูกติด tag ยกเว้น frame ของ native VLAN
Management VLAN SSH/Telnet VTY traffic — ไม่ควรปนกับ traffic ผู้ใช้ — โดยทั่วไปคือ VLAN ที่เป็น SVI (Switched Virtual Interface)
Voice VLAN traffic เสียง VoIP

3. VLAN ข้ามหลาย Switch ⭐⭐

Trunk = ลิงก์ point-to-point ระหว่างอุปกรณ์เครือข่าย 2 ตัว

  • ส่ง traffic ได้มากกว่า 1 VLAN | ขยาย VLAN ข้ามทั้งเครือข่าย | ค่าเริ่มต้นรองรับทุก VLAN | รองรับ 802.1Q trunking

IEEE 802.1Q Tag ⭐⭐

  • 802.1Q header (tag) ขนาด 4 bytes แทรกใน Ethernet frame ระหว่าง Source MAC กับ Type/Length
  • ⭐ เมื่อใส่ tag → ต้องคำนวณ FCS ใหม่ (FCS1 ≠ FCS2) | เมื่อส่งไป end device → ต้องถอด tag ออกและคำนวณ FCS กลับเป็นค่าเดิม
  • ⭐ tag ใช้เฉพาะระหว่าง VLAN switch — ผู้ส่ง/ผู้รับปลายทางเห็น frame ปกติ

Frame ปกติ: Dst MAC | Src MAC | Type/Length | Data | FCS Frame ติด tag: Dst MAC | Src MAC | Tag | Type/Length | Data | FCS

Tag Field ขนาด หน้าที่
Type 2 bytes ค่า 0x8100 = Tag Protocol ID (TPID)
User Priority 3 bits ลำดับความสำคัญ (CoS/QoS)
CFI (Canonical Format Identifier) 1 bit รองรับ token ring frame บน Ethernet
VLAN ID (VID) 12 bits รองรับถึง 4096 VLANs (2¹²)

💡 รวม: 16 + 3 + 1 + 12 = 32 bits = 4 bytes

4. Voice VLAN

  • ⭐ โทรศัพท์ VoIP เป็น switch 3 พอร์ต (P1 ต่อ switch, P2 ต่อ phone ASIC ภายใน, P3 = access port ต่อ PC)
  • switch ใช้ CDP (Cisco Discovery Protocol) แจ้งโทรศัพท์ว่า Voice VLAN คืออะไร
  • โทรศัพท์ติด tag traffic เสียงของตัวเองและตั้ง CoS (Class of Service) ได้ — ⭐ CoS = QoS ของ layer 2
  • โทรศัพท์อาจหรืออาจไม่ติด tag ให้ frame จาก PC
Traffic Tagging
Voice VLAN ติด tag พร้อม Layer 2 CoS priority ที่เหมาะสม
Access VLAN อาจติด tag พร้อม CoS priority หรือไม่ติด tag (ไม่มี CoS)

ตรวจสอบ show interfaces fa0/18 switchport: Administrative/Operational Mode: static access | Access Mode VLAN: 20 (student) | Trunking Native Mode VLAN: 1 | Voice VLAN: 150 (voice)

5. VLAN Configuration

VLAN Ranges ⭐ (Catalyst 2960/3650 รองรับ มากกว่า 4000 VLANs)

Normal Range: VLAN 1 – 1005 Extended Range: VLAN 1006 – 4095
ธุรกิจ ขนาดเล็กถึงกลาง ใช้โดย Service Providers
1002–1005 สงวนไว้สำหรับ legacy VLANs (FDDI, Token Ring) อยู่ใน running-config
1, 1002–1005 สร้างอัตโนมัติและลบไม่ได้ รองรับ feature ของ VLAN น้อยกว่า
เก็บในไฟล์ vlan.dat ใน flash ต้องตั้งค่า VTP
VTP ซิงก์ข้อมูลระหว่าง switch ได้

สร้าง VLAN + กำหนดพอร์ต:

S1# configure terminal
S1(config)# vlan 20
S1(config-vlan)# name student
S1(config-vlan)# end
S1# configure terminal
S1(config)# interface fa0/18
S1(config-if)# switchport mode access
S1(config-if)# switchport access vlan 20
S1(config-if)# end

⭐ access port กำหนดได้เพียง 1 data VLAN แต่เพิ่ม Voice VLAN ได้อีก 1 (กรณีโทรศัพท์และ PC ต่อผ่านพอร์ตเดียวกัน)

ตรวจสอบ show vlan [brief | id vlan-id | name vlan-name | summary]

  • brief = ชื่อ, สถานะ, พอร์ต บรรทัดละ 1 VLAN | id = ตามหมายเลข | name = ตามชื่อ (ASCII 1–32 ตัว) | summary = สรุป (จำนวน VLAN, VTP VLANs, extended VLANs)
  • show interface vlan 20 → สถานะ SVI ("Vlan20 is up, line protocol is up", Hardware is EtherSVI, MTU 1500)

ลบ VLAN:

  • ทีละอัน: no vlan vlan-id — ⚠️ ก่อนลบให้ย้ายพอร์ตสมาชิกทั้งหมดไป VLAN อื่นก่อน (ไม่งั้นพอร์ตใช้งานไม่ได้)
  • ทุกอัน: delete flash:vlan.dat แล้ว reload switch
  • คืนค่าโรงงาน: ถอดสาย data → ลบ startup-configuration → ลบ vlan.dat → reload

6. VLAN Trunks ⭐

Trunk เป็น layer 2 และส่ง traffic ของทุก VLAN

S1(config)# interface fa0/1
S1(config-if)# switchport mode trunk
S1(config-if)# switchport trunk native vlan 99
S1(config-if)# switchport trunk allowed vlan 10,20,30,99
S1(config-if)# end

ตัวอย่าง subnet: VLAN 10 Faculty/Staff 172.17.10.0/24 | 20 Students 172.17.20.0/24 | 30 Guests 172.17.30.0/24 | 99 Native 172.17.99.0/24

Note: ตัวอย่างนี้เป็น switch 2960 ที่ใช้ 802.1Q — Layer 3 switch ต้องตั้ง encapsulation ก่อนตั้ง trunk mode

ตรวจสอบ show interfaces fa0/1 switchport: Administrative Mode: trunk (ตั้งค่าไว้) | Operational Mode: trunk (ทำงานจริง) | Encapsulation: dot1q | Trunking Native Mode VLAN: 99 | Trunking VLANs Enabled: ALL

Reset Trunk:

(1) คืนค่า trunk เริ่มต้น → ทุก VLAN ผ่านได้ (ALL), Native VLAN = 1
S1(config-if)# no switchport trunk allowed vlan
S1(config-if)# no switchport trunk native vlan

(2) เปลี่ยนกลับเป็น access mode → Administrative/Operational = static access, Access VLAN = 1
S1(config-if)# switchport mode access

7. สรุปคำสั่ง ⭐

ทำอะไร คำสั่ง
สร้าง VLAN vlan 10 → name faculty
พอร์ตเป็น access switchport mode access
พอร์ตเข้า VLAN switchport access vlan 10
ตั้ง voice VLAN switchport voice vlan 150
ดู VLAN show vlan brief / id / name / summary
ดูพอร์ต show interfaces fa0/18 switchport
ลบ VLAN no vlan 10 (ย้ายพอร์ตก่อน!)
ลบทุก VLAN delete flash:vlan.dat แล้ว reload
ตั้ง trunk switchport mode trunk
native VLAN switchport trunk native vlan 99
VLAN ที่ผ่าน trunk switchport trunk allowed vlan 10,20,30,99
reset trunk no switchport trunk allowed vlan + no switchport trunk native vlan
trunk → access switchport mode access

จุดที่มักออกสอบ

  1. VLAN = logical segmentation — แยก unicast/multicast/broadcast, แต่ละ VLAN มี IP range ของตัวเอง, broadcast domain เล็กลง
  2. ประโยชน์ 6 ข้อ | ไม่มี VLAN → ทุกเครื่องได้รับ broadcast ทั้งหมด
  3. VLAN 1 = default + native + management, ลบ/เปลี่ยนชื่อไม่ได้ — Cisco แนะนำย้ายหน้าที่ไป VLAN อื่น
  4. 4 ชนิด: Data / Native (trunk เท่านั้น, frame ไม่ติด tag) / Management (SSH/Telnet, SVI) / Voice
  5. Trunk: point-to-point, หลาย VLAN, ขยาย VLAN ทั้งเครือข่าย, default รองรับทุก VLAN, 802.1Q
  6. ⭐ 802.1Q tag 4 bytes: TPID 0x8100 (2 bytes) + priority 3 bits + CFI 1 bit + VID 12 bits = 4096 VLANs; แทรกระหว่าง Source MAC กับ Type; ใส่/ถอด tag → คำนวณ FCS ใหม่; ใช้เฉพาะระหว่าง switch
  7. Voice VLAN: VoIP phone = switch 3 พอร์ต, switch บอก voice VLAN ด้วย CDP, CoS = QoS layer 2, access port มี 1 data VLAN + 1 voice VLAN
  8. VLAN ranges: normal 1–1005 (vlan.dat, 1002–1005 legacy, 1 และ 1002–1005 ลบไม่ได้) / extended 1006–4095 (running-config, service provider, ต้องใช้ VTP)
  9. ลบ VLAN ต้องย้ายพอร์ตก่อน! | factory reset = ถอดสาย + erase startup-config + ลบ vlan.dat + reload
  10. Verify trunk: administrative/operational = trunk, encapsulation dot1q, native VLAN 99, trunking VLANs enabled ALL
