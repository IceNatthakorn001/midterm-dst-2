1. End Systems และ Protocols

  • End System / Host = อุปกรณ์ทุกชนิดที่เชื่อมต่ออินเทอร์เน็ต ตั้งแต่เซิร์ฟเวอร์ใหญ่ถึง IoT
  • Protocol (HTTP, TCP) = ธรรมเนียมปฏิบัติทางการทูต — ถ้าไม่มี Standards ที่กำหนดลำดับและรูปแบบ อุปกรณ์ต่างค่ายจะสื่อสารกันไม่ได้ = Interoperability
  • ขั้นตอนใน TCP/IP stack: alignment sequence → handshake (SYN/ACK) → data exchange → security checkpoint → synchronization

2. Access Networks Matrix ⭐

เทคโนโลยี ประเภท สื่อกลาง แบนด์วิดท์ ความเร็ว
FTTH Home Fiber Optic Dedicated 100 Mbps – 1 Gbps+
HFC (Cable) Home Coaxial Shared 10s – 100s Mbps
DSL Home Copper Wire Dedicated <10 – 10s Mbps
Ethernet Enterprise Copper / Fiber Dedicated 10 Mbps – 100 Gbps
Wi-Fi Home / Enterprise Wireless (Unlicensed) Shared เร็ว ระยะสั้น
4G / 5G Wide-Area Wireless (Licensed) Shared ปานกลาง, high mobility

⚠️ Shared = HFC, Wi-Fi, 4G/5G / Dedicated = FTTH, DSL, Ethernet 💡 Wi-Fi = unlicensed (ใครก็ใช้ได้) / 4G/5G = licensed (ค่ายมือถือประมูลมา)

3. Circuit vs Packet Switching ⭐

Circuit Switching Packet Switching
รับประกัน bandwidth คงที่ตลอดการเชื่อมต่อ (dedicated path, TDM slots) แชร์ทรัพยากร (store-and-forward) เหมาะกับข้อมูล bursty
ประสิทธิภาพ คาดการณ์ได้ แต่ สูญเปล่าหากไม่ส่งข้อมูล รองรับผู้ใช้ มากกว่า แต่เสี่ยง queuing delay
ตัวอย่าง: ลิงก์ 2 Mbps, คนละ 1 Mbps → รับได้สูงสุด 2 คนถ้วน ตัวอย่าง: ลิงก์ 2 Mbps → รับได้มากกว่า 3 คน (ถ้าไม่ส่งพร้อมกันตลอด)

4. Internet Backbone

พีระมิด: Tier-1 ISP → Regional ISP → Access ISP

  • Peering: ISP ระดับเดียวกันเชื่อมกันเอง หรือผ่าน IXP เพื่อหลีกเลี่ยง transit fee ให้ ISP ระดับบน
  • Content Provider Network (Google's Private Network): ผู้ให้บริการเนื้อหารายใหญ่สร้างโครงข่ายส่วนตัวเชื่อม data center ทั่วโลก เพื่อลดต้นทุน transit และนำข้อมูลเข้าใกล้ผู้ใช้ปลายทาง — ข้ามลำดับชั้น (bypass)

5. ความหน่วง 4 ประเภท ⭐

$$d_{end\text{-}to\text{-}end} = d_{proc} + d_{queue} + d_{trans} + d_{prop}$$

ประเภท คงที่/แปรผัน ความหมาย
d_proc คงที่ ตรวจ header + ตัดสินใจหาเส้นทาง
d_queue แปรผัน รอในคิวหากทราฟฟิกหนาแน่น
d_trans คงที่ ดันบิตทั้งหมดของแพ็กเก็ตลงสู่สาย
d_prop คงที่ สัญญาณเดินทางตามฟิสิกส์ของสื่อกลาง

⚠️ queuing delay เป็นตัวเดียวที่แปรผัน

6. Transmission vs Propagation ⭐

d_trans = L / R d_prop = d / s
L = ความยาวแพ็กเก็ต (bits), R = แบนด์วิดท์ (bps) d = ระยะทาง (m), s = ความเร็วสัญญาณ (~2.5×10⁸ ในสไลด์นี้; โจทย์ใช้ 2×10⁸ m/s)
เทียบ: ด่านเก็บเงินปล่อยรถทีละคันจนครบขบวน เทียบ: รถแข่งวิ่งจาก A ไป B
ขึ้นกับ ขนาดแพ็กเก็ต + แบนด์วิดท์ ⭐ กฎเหล็ก: ไม่ขึ้นกับ L หรือ R ขึ้นกับระยะทางฟิสิกส์ล้วน ๆ

💡 ซื้อเน็ตแรงขึ้นลด d_trans ได้ แต่ ลด d_prop ไม่ได้

7. Throughput & Bottleneck ⭐

$$\text{Throughput} = \min(R_1, R_2, R_3)$$ ตัวอย่าง: Server → R1 = 2 Mbps → R2 = 100 kbps → R3 = 1 Mbps → Client → แม้มีเน็ตแรง 2 Mbps แต่คอขวดที่ 100 kbps จำกัดความเร็วรวมไว้ที่ 100 kbps

8. Queuing & Packet Loss ⭐

$$I = \frac{La}{R}$$

  • queuing delay ต่ำเมื่อ I ≈ 0 → เพิ่มช้า ๆ ถึง 0.5 → พุ่งขึ้นชันเมื่อ I เข้าใกล้ 1 → I ≥ 1 = Unstable Region
  • I > 1: ข้อมูลไหลเข้าเร็วกว่าที่ router ระบายออก → คิวยาวขึ้นเรื่อย ๆ → router buffer เต็ม → แพ็กเก็ตใหม่ ถูกทิ้ง (dropped) = Packet Loss

9. โจทย์คำนวณ Delay ⭐⭐

⚠️ แปลงหน่วยก่อนเสมอ: Bytes → bits × 8 | Mbps → bps × 10⁶ | MB → bytes × 10⁶ | km → m × 1,000

ข้อ 1: Packet 4,000 บิต ผ่านสาย 2 Mbps หา Transmission Delay → R = 2 × 10⁶ bps → 4,000 / 2,000,000 = 0.002 s = 2 ms

ข้อ 2: ไฟล์ 5 MB ผ่าน HFC upstream 10 Mbps ใช้เวลาผลักข้อมูลลงสายเท่าใด → L = 5 × 10⁶ × 8 = 40,000,000 bits | R = 10,000,000 bps → 40,000,000 / 10,000,000 = 4 วินาที

ข้อ 3: ข้อมูล 1,000 Bytes ผ่านสายยาว 2,000 km, bandwidth 10 Mbps, ความเร็วสัญญาณ 2 × 10⁸ m/s

  • d_trans: L = 1,000 × 8 = 8,000 bits → 8,000 / 10,000,000 = 0.0008 s = 0.8 ms
  • d_prop: 2,000 km = 2,000,000 m → 2,000,000 / 2×10⁸ = 0.01 s = 10 ms
  • ต่างกัน: d_prop (10 ms) มากกว่า d_trans (0.8 ms) ถึง 12.5 เท่า เพราะสายยาวมากแต่แพ็กเก็ตเล็กและแบนด์วิดท์สูง
ข้อ L R / d สูตร คำตอบ
1 4,000 bits 2 Mbps L/R 2 ms
2 5 MB = 40,000,000 bits 10 Mbps L/R 4 s
3 (trans) 1,000 B = 8,000 bits 10 Mbps L/R 0.8 ms
3 (prop) — 2,000 km, 2×10⁸ m/s d/s 10 ms

10. สถาปัตยกรรม 5 เลเยอร์ ⭐

Layer หน้าที่ หน่วยข้อมูล
5. Application รองรับแอปเครือข่าย (HTTP, SMTP, DNS) Message
4. Transport โพรเซส-ต่อ-โพรเซส (TCP, UDP) Segment
3. Network กำหนดเส้นทางต้นทาง → ปลายทาง (IP) Datagram
2. Link เคลื่อนย้ายระหว่างโหนดที่ติดกัน Frame
1. Physical ส่งสัญญาณแต่ละบิตลงสื่อกลาง Bits

11. Encapsulation

  • Host A ห่อ payload ด้วย header ทีละชั้น (H4 transport → H3 network → H2 link)
  • Link-layer Switch: แกะถึงแค่ L2 (ดูแค่ H2) | Router: แกะถึง L3 (ดู H3 หา IP ปลายทาง) แล้วห่อ H2 ใหม่ | Host B แกะครบทุกชั้น 💡 เทียบการเดินทางด้วยเครื่องบิน: ป้ายกระเป๋า (Header 1), Boarding Pass ที่ประตู (Header 2) — อุปกรณ์แกนกลางดูเฉพาะป้ายที่ตัวเองรับผิดชอบ

12. พลังของการแบ่งแพ็กเก็ต (Segmentation) ⭐

ส่งข้อความ 10⁶ บิต ผ่าน 3 ลิงก์ (ลิงก์ละ 5 Mbps)

กรณี A — ไม่แบ่ง (store-and-forward ทั้งก้อน):

  • 1 ลิงก์ใช้ 10⁶ / (5×10⁶) = 0.2 s → ต้องรอรับครบก่อนส่งต่อ → Link1 + Link2 + Link3 = 0.6 วินาที

กรณี B — แบ่ง 100 แพ็กเก็ต (แพ็กเก็ตละ 10⁴ บิต) = pipelining:

  • แต่ละแพ็กเก็ต 10⁴ / (5×10⁶) = 0.002 s ต่อลิงก์
  • แพ็กเก็ตแรกถึงปลายทางหลัง 3 × 0.002 = 0.006 s แล้วตัวถัดไปตามมาทีละ 0.002 s
  • รวม = 0.006 + 99 × 0.002 = 0.204 วินาที → เร็วขึ้นเกือบ 3 เท่า

💡 เหมือนย้ายหนังสือผ่านคน 3 คนยืนต่อแถว — ยกทีละลังใหญ่ คนที่ 2-3 ต้องยืนรอ / ส่งทีละเล่ม ทุกคนทำงานพร้อมกัน

13. Network Security Threats ⭐

ภัยคุกคาม ลักษณะ
1. Self-Replicating Malware Worms — แพร่กระจายและคัดลอกตัวเองไปยัง Host อื่นที่มีช่องโหว่โดยอัตโนมัติ ไม่ต้องพึ่งการกระทำของผู้ใช้
2. Botnets & DDoS มัลแวร์ยึด Host จำนวนมากเป็น Bot รอคำสั่งจากศูนย์กลาง ส่งทราฟฟิกขยะมหาศาลถล่มเป้าหมายเดียวพร้อมกัน
3. Man-in-the-Middle (MITM) Trudy แทรกตัวระหว่างการสื่อสาร (Alice ↔ Bob) เพื่อดักอ่าน ปลอมแปลง หรือแก้ไขข้อมูล

💡 ชื่อในตำรา security: Alice กับ Bob = คู่สื่อสารที่ดี, Trudy = ผู้บุกรุก

14. บทสรุป — The Internet Blueprint

  1. ขับเคลื่อนโดย HOSTS ที่ขอบข่าย (edge) → 2. เชื่อมด้วย PROTOCOLS มาตรฐานสากล → 3. ข้อมูลถูกหั่นและห่อหุ้มผ่าน 5 LAYERS → 4. เดินทางแบบ PACKET SWITCHING ผ่าน router ที่ต่อสู้กับ 4 DELAYS → 5. นำส่งจากมุมหนึ่งของโลกไปอีกมุมในเสี้ยววินาที

สูตรที่ต้องท่อง

d_end-to-end = d_proc + d_queue + d_trans + d_prop   (queue แปรผันตัวเดียว)
d_trans = L / R          (ขนาดแพ็กเก็ต / แบนด์วิดท์)
d_prop  = d / s          (ระยะทาง / ความเร็วสัญญาณ)
Throughput = min(R1, R2, …)          (คอขวด)
I = La / R               (Traffic intensity; > 1 = unstable, loss)
