Selective Repeat ARQ Animation

ดูการทำงานของ Selective Repeat (SR) ทุกกรณี — ผู้รับเก็บเฟรมที่มาผิดลำดับไว้ใน buffer และผู้ส่งส่งใหม่ เฉพาะเฟรมที่หาย (Lecture 5.2)

กด ▶ เล่น เพื่อเริ่ม
ได้ ACK แล้ว / ส่งขึ้นชั้นบนแล้ว ได้ ACK แล้วแต่ยังเลื่อนหน้าต่างไม่ได้ ผู้ส่ง: รอ ACK · ผู้รับ: เก็บใน buffer ในหน้าต่าง ยังว่าง หาย ⚡ เสีย (CRC ผิด) NAK (SREJ) กรอบเส้นประ = ช้า

⏱ แถบสีส้มใต้เฟรมผู้ส่ง = timer ของเฟรมนั้น (SR มี timer แยกทุกเฟรม) · 💡 แตะเฟรมหรือ ACK ที่กำลังวิ่งเพื่อทำให้หายได้ทุกกรณี

บันทึกเหตุการณ์

    กติกาของ Selective Repeat ที่ใช้ในแอนิเมชัน

    • Send window = Receive window ≤ 2m−1 (ครึ่งหนึ่งของเลขทั้งหมด) เช่น m = 3 → หน้าต่างได้สูงสุด 4
    • ผู้รับรับได้เป็นช่วง (receive window) เฟรมที่ถูกต้องแต่มาผิดลำดับเก็บใน buffer รอเฟรมที่ขาด แล้วค่อยส่งขึ้นชั้นบนพร้อมกันตามลำดับ
    • Individual ACK: ACK k = ยืนยันว่าได้เฟรม k (ACK ได้แม้มาผิดลำดับ) · ผู้ส่งเลื่อนหน้าต่างเมื่อเฟรมแรกสุด (S_f) ได้ ACK
    • Timer แยกทุกเฟรม: timer ของเฟรมไหนหมด → ส่งใหม่เฉพาะเฟรมนั้น
    • NAK / SREJ (กรณี 3): ผู้รับขอเฟรมที่ขาดได้ทันทีโดยไม่ต้องรอ timeout (HDLC S-frame code 11)
    • ผู้รับได้เฟรมเก่าที่ส่งแล้ว (ซ้ำ) → ทิ้งและส่ง ACK ของเฟรมนั้นซ้ำ ให้ผู้ส่งเลื่อนต่อได้
    ⚠️ (อธิบายเพิ่ม) ในภาพสไลด์ SR บางรูปเขียน ACK แบบ “ACK n = รอเฟรม n” (สะสม) หลังส่งเฟรมขึ้นชั้นบน · แอนิเมชันนี้ใช้ individual ACK ตามหัวข้อ Timer and Acknowledgment ของสไลด์ จึงเห็นชัดว่าแต่ละเฟรมได้ ACK ของตัวเอง
