2. TCP/IP Communication Model ⭐

Encapsulation ที่ผู้ส่ง: Application → Message → Transport (+TCP header) → Segment → Network (+IP header) → Packet → Data Link (+Frame header/trailer) → Frame → Physical → Bits

Layer ประเภทการเชื่อมต่อ
Application / Transport logical, end-to-end
Network logical, host-to-host
Data Link hop-by-hop (Alice↔R1, R1↔R2, R2↔Bob)
Physical physical connections (point-to-point)

ที่แต่ละ router: รับ frame → ถอด data link header & trailer ออก → เหลือ IP packet → ใส่ header & trailer ใหม่ → ส่งเป็น bits

⭐ Takeaway: layer บนสื่อสารแบบ logical end-to-end / data-link frames และ physical signals ทำงาน hop by hop

3. Frame Study with Wireshark

  1. Framing ห่อหุ้ม network-layer packet เพื่อส่งบนลิงก์ท้องถิ่น 1 ลิงก์
  2. Frame header มี source และ destination link-layer addresses
  3. Trailer มี FCS (frame check sequence) ตรวจจับข้อผิดพลาด
  4. ที่ทุก router frame ขาเข้าถูกถอด และสร้าง frame ใหม่สำหรับลิงก์ถัดไป
  • ใน Wireshark เห็น Ethernet II, Src: …, Dst: … ตามด้วย IPv4, TCP, TLS
  • ⚠️ Wireshark ปกติไม่แสดง preamble, SFD (Start Frame Delimiter), FCS (การ์ดเครือข่ายตัดออกก่อน)

4. Hop-by-Hop & Reframing ⭐

มุมมอง ลักษณะ
End-to-end (แอปมองเห็น) เส้นทางเดียว Node–Link–Node–Link–Node
Hop-by-hop (ความจริง) LAN → point-to-point → LAN → point-to-point → LAN ทีละช่วง แต่ละช่วงเป็นเทคโนโลยีต่างกัน

A Packet Is Reframed at Every Hop: network layer ส่ง IP packet ลงมา → ผู้ส่งห่อด้วย frame ที่เหมาะกับลิงก์ปัจจุบัน → ที่ router ถัดไป frame ถูกถอดและสร้าง frame ใหม่ → physical layer ส่งเป็นสัญญาณ ⚠️ IP packet (datagram) ไม่เปลี่ยนตลอดทาง (IP ต้นทาง/ปลายทางเดิม) แต่ frame และ MAC address เปลี่ยนทุก hop 💡 เหมือนส่งพัสดุข้ามจังหวัด: ลูกค้าเห็น "กรุงเทพ→เชียงใหม่" แต่จริง ๆ ผ่านมอเตอร์ไซค์ → รถบรรทุก → รถกระบะ ทีละช่วง

5. Core Services และ Sublayers ⭐

Physical layer ขนส่งบิต / Data link layer จัดระเบียบการส่งข้ามลิงก์ท้องถิ่น 1 ลิงก์

บริการ ใครทำ คำอธิบาย
Network-layer interface LLC multiplex โปรโตคอลชั้นบน (IPv4, IPv6, ARP)
Framing MAC ใน IEEE 802; ทำโดยตรงใน PPP/HDLC จัดบิตเป็น frame
Link addressing MAC ระบุอุปกรณ์บนลิงก์ท้องถิ่น
Error detection FCS/CRC ตรวจว่าบิตเสียไหม
Error recovery (optional) — ACKs + retransmission
Flow control (optional) — ควบคุมอัตราการส่ง
Medium access MAC ประสานสถานีที่ใช้สื่อกลางร่วมกัน

2 Sublayers: LLC (Logical Link Control) = network-layer interface + protocol multiplexing (อยู่บน ติด network layer) | MAC (Media Access Control) = frame format, MAC addressing, medium access, FCS (อยู่ล่าง ติด physical layer)

Dedicated / full-duplex link Shared medium
ไม่มีการแย่งช่องสัญญาณ (no contention) แต่ยังต้อง framing MAC ต้องประสานการเข้าถึงช่องสัญญาณ
มีแค่ data link control sublayer มี data link control + media access control sublayer

6. Data Link Protocols

Link type Example Architecture Key function
Shared LAN Ethernet 802.3 LLC/SNAP + MAC Framing, addressing, FCS
Wireless LAN Wi-Fi 802.11 LLC/SNAP + MAC Access, ACK, retransmission
Token LAN Token Ring 802.5 LLC + MAC Token access (legacy)
Low-power WPAN IEEE 802.15.4 Adaptation + MAC Low-power framing/access
Point-to-point PPP Single data-link protocol Framing, LCP/NCP, FCS
Point-to-point HDLC Single data-link protocol Framing, link control
X.25 WAN LAPB Single protocol Reliable HDLC-derived link
Cellular LTE / 5G System-specific PDCP, RLC, MAC
IEEE 802 LAN/WLAN PPP และ HDLC
LLC/SNAP (interface + multiplexing) + MAC (framing, addressing, FCS, medium access) data-link protocol point-to-point ที่ครบในตัว ทำ framing โดยตรง ไม่มีการแบ่ง LLC/MAC

💡 PPP/HDLC ไม่ต้องมี MAC sublayer เพราะเป็นลิงก์ point-to-point มีแค่ 2 ฝั่ง ไม่มีใครมาแย่งใช้สื่อ

7. Dedicated vs Shared Links & Multiple Access

Dedicated Links Shared Links
Full-duplex switch — Star topology Bus topology / Wireless

Multiple Access: หลายอุปกรณ์ใช้ช่องสัญญาณเดียวกัน อาจมี มากกว่า 1 สถานีส่งพร้อมกัน ตัวอย่างสื่อที่แชร์: shared wire (Ethernet เก่า), shared wireless (Wavelan), satellite, cocktail party ⭐ คำถามหลัก: สถานีจะแชร์สื่อกลางอย่าง ยุติธรรม (fairly) / มีประสิทธิภาพ (efficiently) / ชนกันน้อยลง (fewer collisions) ได้อย่างไร? Preview MAC: การส่งพร้อมกันอาจ ชนกัน (collide) — ปลายของ B ชนต้นของ A และปลายของ A ชนต้นของ C → Vulnerable time = 2 × T_fr

8. Framing ⭐

  • Physical layer ส่งบิต / Data-link layer จัดกลุ่ม bit stream เป็น frames
  • แต่ละ frame ต้องบอกขอบเขตของตัวเอง เพื่อให้ผู้รับแยก frame ได้
  • โครงสร้างทั่วไป: Flag | Address | Control | Data (information) | FCS | Flag 💡 frame = ซองจดหมาย (ซองแยกจดหมายฉบับหนึ่งจากอีกฉบับ, header = ที่อยู่, FCS = ตรวจว่าของข้างในเสียไหม)
Character-oriented (byte-oriented) Bit-oriented
ข้อมูลเป็น ตัวอักษร 8 บิต (ASCII) ข้อมูลเป็น ลำดับบิต ที่ชั้นบนตีความเป็น text/graphic/audio/video
UART, PPP, Modbus, Bisync HDLC, SDLC, CAN, Frame Relay, ATM, X.25

9. Byte Stuffing (PPP) ⭐

ข้อจำกัดของ byte-oriented framing 3 ข้อ:

  1. ส่งข้อมูลรูปแบบอื่น (graphics, audio, video) มีปัญหา
  2. ถ้า แพทเทิร์นเดียวกับ flag โผล่ในข้อมูล ต้องใช้ escape character (ESC) → byte stuffing
  3. Unicode มีตัวอักษร 16 และ 32 บิต ซึ่งขัดกับตัวอักษร 8 บิต

นิยาม: Byte stuffing = เพิ่ม 1 ไบต์พิเศษ (ESC) ทุกครั้งที่มี flag หรือ escape character อยู่ในข้อความ ขั้นตอน:

  1. Data from upper layer: … Flag … ESC …
  2. Stuffed (Sent): Flag | Header | … ESC Flag … ESC ESC … | Trailer | Flag (extra byte 2 ตัว)
  3. Received frame: เหมือนที่ส่ง
  4. Unstuffed: ผู้รับลบ ESC ที่ใส่เพิ่ม → ได้ … Flag … ESC … เหมือนเดิม

⚠️ ต้อง stuff ESC ที่อยู่ในข้อมูลด้วย ไม่งั้นผู้รับจะเข้าใจว่า ESC นั้นเป็นตัว escape ของไบต์ถัดไปแล้วลบผิด PPP ปัจจุบัน: PPPoE (broadband/DSL, บาง fiber access), router และ WAN บางระบบ, ระบบเดิมที่ใช้ point-to-point serial links

10. Bit Stuffing (HDLC) ⭐

HDLC Flag = 0x7E = 01111110 นิยาม: Bit stuffing = เพิ่ม 0 หนึ่งตัว ทุกครั้งที่มี 1 ติดกัน 5 ตัว ตามหลัง 0

ตัวอย่าง:

ขั้นตอน บิต
Data from upper layer 0001111111001111101000
Stuffed (Frame sent) 000111110110011111001000 (เพิ่ม 2 บิต)
Frame received เหมือน frame sent
Unstuffed 0001111111001111101000

ไล่: 000 11111 1100 11111 01000 → เจอ 1 ติดกัน 5 ตัวครั้งแรก แทรก 0 → เจออีกครั้ง แทรก 0 อีกตัว ผู้รับ: เมื่อเจอ 0 + 11111 แล้วตามด้วย 0 → ลบ 0 นั้นทิ้ง 💡 ทำไมเลข 5? flag มี 1 ติดกัน 6 ตัว ถ้าไม่ยอมให้ข้อมูลมี 1 ติดกันเกิน 5 ตัว ข้อมูลก็จะไม่มีวันหน้าตาเหมือน flag HDLC ปัจจุบัน: synchronous serial WAN (T1/E1, T3/E3, SONET/SDH), ระบบโทรคมนาคม, อุปกรณ์อุตสาหกรรม/ระบบเดิม, Cisco HDLC

11. เปรียบเทียบวิธี Framing ⭐

Feature Byte-Oriented Bit-Oriented Length/Fixed-Size
Frame boundary delimiter bytes flag bit pattern length field / fixed size / PHY sync
Data transparency byte stuffing bit stuffing ไม่ต้อง stuff
Protocols BISYNC, SLIP, asynchronous PPP HDLC, synchronous PPP, Frame Relay, CAN Ethernet, IEEE 802.11, ATM cells
Stuffing rule escape special bytes แทรก 0 หลัง 1 ติดกันตามจำนวน ไม่ stuff; อาจต้อง padding
Overhead escape bytes ขึ้นกับข้อมูล stuffed bits ขึ้นกับข้อมูล คาดการณ์ได้เกือบทั้งหมด
Key advantage ประมวลผลง่ายบนลิงก์แบบ byte ไม่ขึ้นกับ character encoding มีประสิทธิภาพ เหมาะกับ LAN ความเร็วสูง

หมายเหตุ: UART ใช้ start/stop bits | I²C ใช้ START/STOP conditions | SPI ไม่มีรูปแบบ frame มาตรฐานเดียว ⚠️ Ethernet padding ≠ stuffing — padding ทำให้ frame มีขนาดขั้นต่ำ ไม่ได้ป้องกันไม่ให้ payload ถูกเข้าใจว่าเป็น delimiter

จุดที่มักออกสอบ

  1. Layer บน = logical end-to-end / data link + physical = hop-by-hop
  2. Encapsulation units: Message → Segment → Packet → Frame → Bits
  3. ทุก router ถอด frame เดิมแล้วสร้าง frame ใหม่ — IP packet เดิม, frame เปลี่ยนตามชนิดลิงก์
  4. Header มี source/dest link-layer address / trailer มี FCS; Wireshark ไม่แสดง preamble, SFD, FCS
  5. บริการ data link 7 อย่าง และ LLC vs MAC ทำอะไร
  6. IEEE 802 แบ่ง LLC/SNAP + MAC / PPP-HDLC ทำ framing เอง ไม่แบ่ง
  7. Dedicated (star, full-duplex switch) ไม่มี contention / Shared (bus, wireless) ต้องมี MAC
  8. Multiple access: fair, efficient, fewer collisions; Vulnerable time = 2 × T_fr
  9. Generic frame: Flag | Address | Control | Data | FCS | Flag
  10. Byte stuffing: เพิ่ม ESC ทุกครั้งที่เจอ flag หรือ ESC ในข้อมูล
  11. Bit stuffing: HDLC flag = 01111110, แทรก 0 หลัง 1 ติดกัน 5 ตัว — ฝึกโจทย์ stuff/unstuff
  12. ตารางเปรียบเทียบ 3 แบบ และ Ethernet padding ≠ stuffing
