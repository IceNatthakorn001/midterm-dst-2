Stop-and-Wait ARQ Animation

ดูการทำงานของ Stop-and-Wait ARQ ทุกกรณี — ส่งทีละ 1 เฟรมแล้วรอ ACK · เฟรมหาย, เฟรมเสีย, ACK หาย, ACK มาช้า และถ้าไม่มี sequence number (Lecture 5.2)

กด ▶ เล่น เพื่อเริ่ม
ได้ ACK แล้ว / รับแล้ว ส่งแล้ว รอ ACK (outstanding) ในหน้าต่าง ยังไม่ส่ง หาย ⚡ เสีย (CRC ผิด) กรอบเส้นประ = ช้า

💡 แตะเฟรมหรือ ACK ที่กำลังวิ่งอยู่ เพื่อทำให้มันหายเองได้ทุกกรณี · ⏱ แถบสีส้มใต้เฟรม = timer

บันทึกเหตุการณ์

    กติกาของ Stop-and-Wait ที่ใช้ในแอนิเมชัน

    • ผู้ส่งส่งทีละ 1 เฟรม แล้วรอ ACK ก่อนส่งเฟรมถัดไป · เก็บสำเนาเฟรมล่าสุดไว้จนได้ ACK · มี timer 1 ตัว
    • ใช้ sequence number แค่ 0 และ 1 สลับกัน · ผู้ส่งมีตัวแปร S = เฟรมที่กำลังส่ง · ผู้รับมี R = เฟรมถัดไปที่คาดหวัง
    • ACK n = เฟรมถัดไปที่ผู้รับคาดหวัง → ACK 1 หมายถึง รับเฟรม 0 แล้ว รอเฟรม 1
    • เฟรมเสีย → ผู้รับทิ้งเงียบ ๆ ไม่ส่ง ACK → timeout → ส่งใหม่
    • ผู้รับได้เฟรมซ้ำ → รู้จาก sequence number → ทิ้ง แล้วส่ง ACK ที่เหมาะสมอีกครั้ง
    • ผู้ส่งได้ ACK เก่า (มาช้า) → ทิ้ง · 💡 sequence number ใช้ตรวจเฟรมซ้ำ, ACK number ใช้ตรวจ ACK เก่า
    💡 Stop-and-Wait = Go-Back-N ที่หน้าต่างส่ง = 1 และใช้เลขแค่ 0, 1 · ข้อเสีย: ไม่มี pipelining เวลาส่วนใหญ่หมดไปกับการรอ ACK จึงไม่มีประสิทธิภาพบนลิงก์ bandwidth สูงหรือ delay ยาว — utilization = เวลาส่ง 1 เฟรม ÷ round-trip time

    สรุปทุกกรณี

    กรณีเกิดอะไรขึ้นผลลัพธ์
    จำง่าย ๆ: ไม่ได้ ACK ก่อน timeout → ส่งเฟรมเดิมซ้ำ · ผู้รับทิ้งเฟรมซ้ำแต่ต้องส่ง ACK ซ้ำ · ผู้ส่งทิ้ง ACK เก่า · ถ้าไม่มี sequence number ผู้รับจะแยกเฟรมซ้ำไม่ออก
