Chapter 06 — Storage Systems (External Memory)

ภาพรวมบทนี้: หน่วยเก็บข้อมูลภายนอกที่อยู่ล่างสุดของ memory hierarchy: Magnetic disk (โครงสร้าง, การอ่านเขียน, รูปแบบข้อมูล, เวลาเข้าถึง), RAID 7 ระดับ (0–6), SSD (เทียบกับ HDD และปัญหาเฉพาะ), Optical memory (CD, DVD, Blu-ray) และ Magnetic tape

2. Magnetic Disk (สไลด์ 4–9)

2.1 วัสดุ (สไลด์ 4)

  • disk คือ จานกลม (platter) ทำจากวัสดุที่ไม่เป็นแม่เหล็ก เรียกว่า substrate เคลือบด้วยวัสดุที่ทำให้เป็นแม่เหล็กได้
  • แบบดั้งเดิม substrate เป็น aluminium หรือ aluminium alloy
  • ช่วงหลังเริ่มใช้ glass substrate — ข้อดี:
    • ผิว magnetic film สม่ำเสมอขึ้น → disk เชื่อถือได้มากขึ้น
    • ข้อบกพร่องบนผิวลดลงมาก → ลด read-write errors
    • รองรับ fly height ที่ต่ำลง
    • แข็งกว่า (stiffness) → ลด disk dynamics
    • ทนแรงกระแทกและความเสียหายได้ดีกว่า

2.2 Read / Write Process (สไลด์ 5–6)

  • ทิศทางของอนุภาคแม่เหล็กบนผิวจานแทนค่า "0" และ "1"
การเขียน (write) การอ่าน (read)
1. กระแสไฟฟ้าไหลผ่านขดลวด 1. ทิศทางแม่เหล็กบนผิวจาน
2. เกิดสนามแม่เหล็กจากขดลวด 2. เหนี่ยวนำสัญญาณไฟฟ้าที่หัวอ่าน
3. จัดเรียงทิศทางบนผิวจาน 3. แปลงเป็นข้อมูล bit 0 และ 1
  • Figure 6.1 Inductive Write / Magnetoresistive Read Head: หัวเขียนเป็น inductive write element (ใช้ write current), หัวอ่านเป็น MR (magnetoresistive) sensor (ใช้ read current), มี shield คั่น, บันทึกบน recording medium ตามความกว้าง track (track width)

2.3 Disk Data Layout (สไลด์ 7)

  • Platter หลายแผ่นซ้อนบน spindle หมุน (rotation)
  • Read-write head 1 หัวต่อ 1 surface ติดบน boom ที่ขยับได้ (direction of arm motion)
  • ผิวจานแบ่งเป็น track (วงซ้อน) คั่นด้วย inter-track gap
  • แต่ละ track แบ่งเป็น sector (S1, S2, … SN) คั่นด้วย inter-sector gap
  • track ที่ตำแหน่งเดียวกันทุก platter รวมกันเป็น cylinder

2.5 Winchester Disk Format — Seagate ST506 (สไลด์ 9)

  • 1 track มี 30 physical sectors (0–29), 600 bytes/sector
  • แต่ละ sector: Gap 1 (17 bytes) | ID field (7) | Gap 2 (41) | Data field (515) | Gap 3 (20) → รวม 600
  • ID field (7 bytes): synch byte (1), track # (2), head # (1), sector # (1), CRC (2)
  • Data field (515 bytes): synch byte (1), data (512), CRC (2)
  • มี index บอกจุดเริ่ม track

3.2 Characteristics (สไลด์ 11)

  • Fixed-head disk: 1 หัวต่อ 1 track, หัวติดบนแขนแข็งที่ยื่นข้ามทุก track
  • Movable-head disk: หัวเดียว ติดบนแขนที่ยืดหรือหดได้
  • Non-removable disk: ติดถาวรใน drive — เช่น hard disk ใน PC
  • Removable disk: ถอดเปลี่ยนได้ — ข้อดี: มีข้อมูลได้ไม่จำกัดด้วยระบบ disk จำนวนจำกัด, ย้าย disk ไปเครื่องอื่นได้ — ตัวอย่าง: floppy disk, ZIP cartridge
  • Double sided disk: เคลือบสารแม่เหล็กทั้งสองด้านของ platter

3.3 Disk Classification ตาม Head Mechanism (สไลด์ 12)

  • หัวต้องสร้างหรือรับรู้สนามแม่เหล็กที่แรงพอจะอ่าน/เขียนได้
  • หัวยิ่งแคบ ต้องยิ่งอยู่ใกล้ผิวจาน → หัวแคบ = track แคบ = ความหนาแน่นข้อมูลสูง
  • แต่ หัวยิ่งใกล้จาน ความเสี่ยงต่อ error จากสิ่งสกปรกหรือตำหนิยิ่งมาก
  • Winchester Heads:
    • ใช้ใน sealed drive assemblies ที่แทบไม่มีสิ่งปนเปื้อน
    • ออกแบบให้ทำงาน ใกล้ผิวจานกว่า หัวของ rigid disk ทั่วไป → ความหนาแน่นสูงกว่า
    • จริง ๆ แล้วเป็น aerodynamic foil ที่วางเบา ๆ บนผิวจานตอนจานหยุด
    • แรงดันอากาศ จากการหมุนของจานพอจะยกหัวขึ้นเหนือผิว

  • จะอ่าน/เขียน หัวต้องอยู่ที่ track ที่ต้องการ และที่ จุดเริ่มของ sector ที่ต้องการ
    • เลือก track: ขยับหัว (movable-head) หรือเลือกหัวด้วยไฟฟ้า (fixed-head)

Parameter ความหมาย

5. RAID (สไลด์ 16–20)

5.1 หลักการ (สไลด์ 16)

RAID = Redundant Array of Independent Disks — เทคนิคนำ HD หลายตัวมารวมกันทำงานเป็นกลุ่มเดียว

  • มี 7 ระดับ (0–6) — ระดับ ไม่ได้หมายถึงลำดับชั้น แต่เป็นสถาปัตยกรรมต่างกันที่มี 3 ลักษณะร่วม:
    1. ชุด physical disk drives ที่ OS มองเห็นเป็น logical drive เดียว
    2. ข้อมูลกระจายไปบน physical drives ด้วยวิธี striping
    3. ใช้ความจุส่วนเกินเก็บ parity เพื่อกู้ข้อมูลได้เมื่อ disk เสีย

คำอธิบายภาษาไทยในสไลด์:

  • Striping: แบ่งข้อมูลเป็นชิ้นเล็ก ๆ กระจายเขียนลงหลายดิสก์พร้อมกัน
  • Mirroring: เขียนข้อมูลชุดเดียวกันซ้ำลงดิสก์สองตัว → ปลอดภัยแต่เปลือง
  • Parity: คำนวณค่าตรวจสอบ (parity bit) เก็บแยกไว้ เพื่อใช้กู้คืนข้อมูลหากดิสก์ตัวใดตัวหนึ่งเสีย โดยไม่ต้องสำรองข้อมูลเต็มรูปแบบ

6. RAID แต่ละระดับ (สไลด์ 21–28)

RAID 0 (สไลด์ 21)

RAID 0 for High Data Transfer Capacity — ต้องมี 2 เงื่อนไข:

  1. ต้องมี transfer capacity สูงตลอดเส้นทางระหว่าง host memory กับ disk drives แต่ละตัว
  2. application ต้องส่ง I/O request ที่ใช้ disk array ได้อย่างมีประสิทธิภาพ

RAID 0 for High I/O Request Rate:

  • ดูที่รูปแบบ request ของ host และการวางข้อมูล (ผลของ redundancy ไม่รบกวนการวิเคราะห์)
  • I/O request เล็ก ๆ → เวลาถูกครอบงำด้วย seek time และ rotational latency
  • disk array ให้ I/O execution rate สูงได้โดย กระจาย I/O load ไปหลาย disk
  • ถ้า strip size ค่อนข้างใหญ่ → request ที่รออยู่หลายตัวทำขนานกันได้ → ลด queuing time

RAID 1 — Mirroring เขียนข้อมูลซ้ำ (สไลด์ 22)

Characteristics:

  • ต่างจาก RAID 2–6 ในวิธีสร้าง redundancy — ทำสำเนาข้อมูลทั้งหมด
  • ใช้ striping แต่ละ logical strip map ไป 2 physical disks → ทุก disk มี mirror disk ที่มีข้อมูลเหมือนกัน
  • ทำแบบไม่มี striping ก็ได้ (พบน้อยกว่า)

Positive aspects:

  • read request ให้บริการได้จาก disk ตัวใดก็ได้ ใน 2 ตัว
  • ไม่มี "write penalty"
  • กู้คืนง่าย — drive เสียก็อ่านจากตัวที่สอง
  • ได้สำเนาข้อมูลแบบ real-time
  • I/O request rate สูงได้ ถ้า request ส่วนใหญ่เป็น read
  • ข้อเสียหลักคือ ราคา

RAID 2 (สไลด์ 23)

Bit-level striping + Hamming code (ECC) เก็บแยกในดิสก์ต่างหาก — ซับซ้อนที่สุด และแทบไม่มีใช้งานจริงในปัจจุบัน

  • ใช้ parallel access: ทุก disk ร่วมทำทุก I/O request
  • spindles ของทุก drive synchronized → หัวทุก disk อยู่ตำแหน่งเดียวกันเสมอ
  • strip เล็กมาก มักเท่า 1 byte หรือ 1 word
  • คำนวณ error-correcting code ข้าม bit ที่ตรงกันของทุก data disk แล้วเก็บใน หลาย parity disks
  • มักใช้ Hamming code — แก้ error 1 bit, ตรวจจับ error 2 bit
  • จำนวน redundant disks ∝ log ของจำนวน data disks
  • เหมาะเฉพาะสภาพแวดล้อมที่ disk error เกิดบ่อย

RAID 3 (สไลด์ 24)

Byte-level striping + parity ดิสก์เดียว

  • ใช้ redundant disk แค่ 1 ตัว ไม่ว่า array ใหญ่แค่ไหน
  • parallel access, data กระจายเป็น strip เล็ก
  • ใช้ parity bit ธรรมดา คำนวณจาก bit ตำแหน่งเดียวกันในทุก data disk (แทน ECC)
  • Redundancy: drive เสีย → อ่าน parity drive แล้วสร้างข้อมูลจาก devices ที่เหลือ; เปลี่ยน drive แล้วกู้ข้อมูลลง drive ใหม่ได้
  • Performance:
    • transfer rate สูงมาก
    • เมื่อ disk เสีย ข้อมูลยังใช้ได้ใน reduced mode
    • จะกลับ full operation ต้องเปลี่ยน disk และสร้างข้อมูลทั้งหมดใหม่
    • ใน transaction-oriented environment performance แย่

RAID 4 (สไลด์ 25)

Block-level striping + parity disk แยกต่างหากเพียง 1 ตัว → parity disk เป็นคอขวด → RAID 5 จึงมาแก้ปัญหา

  • ใช้ independent access: แต่ละ disk ทำงานอิสระ → request ต่างกันทำขนานกันได้
  • strip ค่อนข้างใหญ่
  • Write penalty เมื่อเขียนข้อมูลขนาดเล็ก:
    • ทุกครั้งที่เขียน ต้อง update ทั้ง user data และ parity
    • คำนวณ parity ใหม่ต้องอ่าน old user strip และ old parity strip
    • → การเขียน 1 strip = 2 reads + 2 writes

RAID 5 (สไลด์ 26)

Block-level striping + parity หมุนเวียน

  • จัดคล้าย RAID 4
  • ต่างกันที่ กระจาย parity strips ไปทุก disk — มักใช้แบบ round-robin
  • การกระจาย parity หลีกเลี่ยงคอขวด I/O ที่เกิดใน RAID 4

RAID 6 (สไลด์ 26)

เหมือน RAID 5 แต่ parity 2 ชุด

  • คำนวณ parity 2 แบบ เก็บในคนละ block บนคนละ disk
  • ข้อดี: data availability สูงมาก — ต้องมี 3 disks เสียภายในช่วง MTTR ข้อมูลจึงจะหาย
  • ข้อเสีย: write penalty มาก เพราะการเขียนแต่ละครั้งกระทบ parity 2 blocks

7. SSD — Solid State Drive (สไลด์ 29–32)

7.1 SSD เทียบกับ HDD (สไลด์ 29)

ข้อดีของ SSD:

  • IOPS (input/output operations per second) สูง
  • ทนทาน (durability)
  • อายุการใช้งานยาวกว่า
  • ใช้พลังงานน้อยกว่า
  • เงียบกว่าและเย็นกว่า
  • access time และ latency ต่ำกว่า

7.4 Practical Issues — ปัญหาเฉพาะของ SSD ที่ HDD ไม่มี (สไลด์ 32)

ปัญหาที่ 1: performance ช้าลงเมื่อใช้ไปนาน ๆ เพราะการเขียนต้อง:

  1. อ่านทั้ง block จาก flash ไปไว้ใน RAM buffer
  2. ลบ (erase) ทั้ง block ของ flash ก่อนเขียนกลับ
  3. เขียนทั้ง block จาก buffer กลับไปที่ flash

ปัญหาที่ 2: flash ใช้ไม่ได้หลังเขียนครบจำนวนครั้งหนึ่ง — เทคนิคยืดอายุ:

  • ใช้ cache ด้านหน้า flash เพื่อหน่วงและรวม write operations
  • wear-leveling algorithms กระจายการเขียนให้ทั่ว block ของ cells
  • bad-block management
  • flash ส่วนใหญ่ ประเมินอายุที่เหลือของตัวเอง ได้ ทำให้ระบบคาดการณ์ความเสียหายและป้องกันล่วงหน้าได้

สรุปท้ายบท / จุดที่มักออกสอบ

  • Glass substrate ดีกว่า aluminium: ผิวสม่ำเสมอ, defect น้อย, fly height ต่ำได้, แข็งกว่า, ทนแรงกระแทก
  • เขียน: กระแส → สนามแม่เหล็ก → จัดทิศบนจาน | อ่าน: ทิศแม่เหล็ก → เหนี่ยวนำไฟฟ้า → bit
  • CAV (sector เท่ากันทุก track, วงในแน่น, ง่าย, พบน้อย) vs Multi-zone (วงนอก sector มาก, ความจุสูง, ซับซ้อน, ใช้ส่วนใหญ่)
  • ST506: 30 sectors × 600 bytes, data 512 bytes ต่อ sector
  • หัวแคบ = ความหนาแน่นสูง แต่ต้องใกล้จาน = เสี่ยง error → Winchester (sealed, aerodynamic foil)
  • Access time = Seek + Rotational delay | Transfer time แยกต่างหาก | Timing: wait device → wait channel → seek → rotational → transfer
  • RAID 3 ลักษณะร่วม: OS เห็นเป็น logical drive เดียว, striping, parity เพื่อกู้ข้อมูล
  • RAID: 0 = striping (N, ไม่มี redundancy, เสียตัวเดียวหายหมด) | 1 = mirror (2N, overhead 100%, ไม่มี write penalty) | 2 = bit + Hamming (N+m, ไม่มีใช้จริง) | 3 = byte + parity disk เดียว (N+1, transfer สูง, reduced mode) | 4 = block + parity disk เดียว (N+1, parity disk คอขวด, write = 2R+2W) | 5 = block + parity หมุนเวียน (N+1, หลากหลายที่สุด) | 6 = parity 2 ชุด P+Q (N+2, ต้องเสีย 3 ตัวใน MTTR ถึงหาย, write penalty มาก)
  • RAID ที่ "ไม่มีใช้เชิงพาณิชย์" ตามตาราง: 2 และ 4
  • SSD: IOPS สูง, ทน, อายุยาว, ประหยัดไฟ, เงียบเย็น, latency ต่ำ | แต่แพงกว่า ($0.50 vs $0.15/GB)
  • SSD practical issues: ช้าลงเมื่อใช้นาน (read block → erase → write back) + flash สึก (cache, wear leveling, bad-block management, ประเมินอายุตัวเอง)
  • CD-ROM > 650 MB (682 MB ในภาพ), block 2352 bytes (data 2048), DVD double-sided dual-layer 17 GB, Blu-ray 25 GB/layer, laser 780 / 650 / 405 nm
  • CD-R = write once (dye layer) | CD-RW = phase change (amorphous ↔ crystalline)
  • Tape: polyester, parallel tracks, serial recording, physical records, inter-record gaps, serpentine | LTO-1 200 GB (2000) → LTO-8 32 TB
