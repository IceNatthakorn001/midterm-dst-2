1. Magnetic Disk — วัสดุและการอ่านเขียน

  • disk = จาน (platter) ทำจากวัสดุไม่เป็นแม่เหล็ก = substrate แล้วเคลือบวัสดุที่ทำให้เป็นแม่เหล็กได้ | เดิมใช้ อะลูมิเนียม → ช่วงหลังใช้ แก้ว (glass)
  • ข้อดีของ glass substrate 5 ข้อ: ผิวฟิล์มแม่เหล็กสม่ำเสมอขึ้น / ตำหนิบนผิวลดลงมาก / รองรับ fly height ต่ำลง / แข็งแรงกว่า ลดการสั่นไหว / ทนแรงกระแทกได้ดีกว่า
  • เขียน: กระแสไฟฟ้าไหลผ่านขดลวด → เกิดสนามแม่เหล็ก → จัดเรียงทิศทางอนุภาคแม่เหล็กบนผิวจาน
  • อ่าน: อ่านทิศทางแม่เหล็ก → เหนี่ยวนำสัญญาณไฟฟ้าที่หัวอ่าน → แปลงเป็นบิต 0/1
  • ทิศทางของอนุภาคแม่เหล็กใช้แทนค่า 0 และ 1
  • หัว: Inductive write element (Write current) + MR (magnetoresistive) sensor (Read current, ความต้านทานเปลี่ยนตามทิศทางแม่เหล็ก) มี Shield กั้นระหว่างกัน

2. Data Organization & Formatting

ส่วน ความหมาย
Platter จานแต่ละแผ่น หมุนรอบ Spindle
Track วงกลมซ้อนกันบนผิวจาน
Sector ส่วนย่อยของ track
Cylinder track ตำแหน่งเดียวกันของทุก platter
Inter-track / Inter-sector gap ช่องว่างกันสัญญาณแม่เหล็กรบกวนกัน
Read-write head 1 หัวต่อ 1 ผิวจาน ติดกับ Boom
วิธีจัด layout ลักษณะ
(a) Constant angular velocity (CAV) ทุก track มีจำนวน sector เท่ากัน — sector นอกกว้างกว่าใน (ควบคุมง่าย แต่ track นอกเก็บไม่เต็มที่)
(b) Multiple zone recording แบ่งเป็น zone — zone นอกมี sector มากกว่า (จุมากขึ้น แต่วงจรซับซ้อน)

Winchester Disk Format (Seagate ST506): สัญญาณ index บอกจุดเริ่ม track, สัญญาณ sector บอกจุดเริ่มแต่ละ sector, 30 physical sectors ต่อ track (0–29) 1 sector = 600 bytes: gap1 17 + ID field 7 + gap2 41 + data field 515 + gap3 20

  • ID field (7): synch byte 1 + track# 2 + head# 1 + sector# 1 + CRC 2
  • Data field (515): synch byte 1 + data 512 + CRC 2

  • Removable disk ข้อดี: มีที่เก็บได้ไม่จำกัดโดยใช้ drive จำนวนจำกัด + ย้ายไปเครื่องอื่นได้ (floppy disk, ZIP cartridge)

4. Disk Performance Parameters ⭐⭐

ลำดับเวลาของ disk I/O transfer: Wait for Device → Wait for Channel → Seek → Rotational Delay → Data Transfer (ช่วง Seek → Rotational Delay → Data Transfer = Device Busy)

ค่า ความหมาย
Seek time เวลาเลื่อนหัวไปยัง track (ระบบ movable-head; fixed-head ใช้เลือกหัวทางอิเล็กทรอนิกส์)
Rotational delay (latency) เวลารอให้จุดเริ่มของ sector หมุนมาถึงหัว
Access time Seek time + Rotational delay
Transfer time ช่วงอ่าน/เขียนจริงขณะ sector เคลื่อนผ่านหัว

⚠️ Access time ไม่รวม transfer time

5. RAID ⭐⭐

RAID = Redundant Array of Independent Disks — เทคนิคนำ HD หลายตัวรวมกันให้ทำงานเป็นกลุ่มเดียว | มี 7 levels (0–6) — level ไม่ได้บอกว่าอันไหนดีกว่า เป็นแค่สถาปัตยกรรมที่ต่างกัน

ลักษณะร่วม 3 ข้อ:

  1. OS มองเห็น disk จริงหลายลูกเป็น logical drive ลูกเดียว
  2. ข้อมูลกระจายไปบน disk หลายลูกด้วย striping
  3. ใช้พื้นที่ส่วนเกิน (redundant) เก็บ parity เพื่อกู้ข้อมูลเมื่อ disk เสีย ⚠️ ข้อ 3 ไม่จริงกับ RAID 0 (ไม่มี redundancy) และ RAID 1 ใช้สำเนาแทน parity
  • Striping: แบ่งข้อมูลเป็นชิ้นเล็ก ๆ กระจายเขียนลงหลาย disk พร้อมกัน
  • Mirroring: เขียนข้อมูลชุดเดียวกันซ้ำลง 2 disk — ปลอดภัยแต่เปลือง
  • Parity: คำนวณค่าตรวจสอบเก็บแยก ใช้กู้เมื่อ disk ตัวใดตัวหนึ่งเสีย โดยไม่ต้องสำรองเต็มรูปแบบ
Category Lv Description Disks Data Availability Large I/O Transfer Small I/O Request Rate
Striping 0 Nonredundant N ต่ำกว่า disk เดี่ยว Very high Very high ทั้งอ่านเขียน
Mirroring 1 Mirrored 2N สูงกว่า 2,3,4,5 แต่ต่ำกว่า 6 อ่านเร็วกว่า เขียนใกล้เคียง disk เดี่ยว อ่านได้ถึง 2 เท่า เขียนใกล้เคียง
Parallel access 2 Redundant via Hamming code N + m สูงกว่า disk เดี่ยวมาก สูงที่สุด ~2 เท่าของ disk เดี่ยว
Parallel access 3 Bit-interleaved parity N + 1 สูงกว่า disk เดี่ยวมาก สูงที่สุด ~2 เท่าของ disk เดี่ยว
Independent access 4 Block-interleaved parity N + 1 สูงกว่า disk เดี่ยวมาก อ่านใกล้ RAID 0 เขียนต่ำกว่า disk เดี่ยวมาก อ่านใกล้ RAID 0 เขียนต่ำมาก
Independent access 5 Block-interleaved distributed parity N + 1 สูงกว่า disk เดี่ยวมาก อ่านใกล้ RAID 0 เขียนต่ำกว่า disk เดี่ยว อ่านใกล้ RAID 0 เขียนต่ำกว่า
Independent access 6 Block-interleaved dual distributed parity N + 2 สูงที่สุด อ่านใกล้ RAID 0 เขียนต่ำกว่า RAID 5 เขียนต่ำกว่า RAID 5 มาก

(N = จำนวน data disks, m ∝ log N)

รายละเอียดแต่ละ level

  • RAID 0: Array Management Software กระจาย strip แบบวนรอบ (disk 0 ได้ strip 0,4,8,12 …) | High transfer capacity ต้อง 2 เงื่อนไข: ทุกช่วงทางระหว่าง host memory กับ disk รองรับ transfer สูง + แอปส่ง I/O request ในแบบที่ใช้ array ได้มีประสิทธิภาพ | High I/O request rate: request เล็กเสียเวลาไปกับ seek + rotational latency เป็นหลัก → array ช่วยเพราะกระจายภาระ; strip ใหญ่ → request หลายตัวทำขนานกัน → ลดเวลารอคิว
  • RAID 1 (Mirroring): ยังใช้ striping แต่แต่ละ logical strip เขียนลง disk จริง 2 ลูก (ทำโดยไม่ striping ก็ได้แต่ไม่นิยม) | ข้อดี: อ่านจากลูกไหนก็ได้, ไม่มี write penalty, กู้คืนง่าย (อ่านจากอีกลูกได้เลย), มีสำเนา real-time, เร็วถ้างานส่วนใหญ่เป็นการอ่าน | ข้อเสียหลัก: แพง
  • RAID 2: parallel access (ทุก disk ช่วยทุก request, spindle ทุก drive หมุน synchronized) + strip เล็กมาก (1 byte หรือ 1 word) | คำนวณ ECC จากบิตที่ตรงกันของทุก data disk มักใช้ Hamming code (แก้ single-bit, ตรวจ double-bit) | จำนวน redundant disk แปรตาม log ของ data disk | คุ้มเฉพาะที่ disk error เกิดบ่อย — ซับซ้อนที่สุด แทบไม่มีใครใช้จริง
  • RAID 3: redundant disk ลูกเดียว ไม่ว่า array ใหญ่แค่ไหน | parallel access + strip เล็ก | ไม่ใช้ ECC ใช้ parity bit ธรรมดา | drive เสีย → ใช้ parity drive สร้างข้อมูลคืน → ทำงานต่อใน reduced mode | transfer rate สูงมาก แต่ งาน transaction แย่ (ทุก request ต้องใช้ทุก disk)
  • RAID 4: independent access (disk ทำงานอิสระ ทำหลาย request ขนานกันได้) + strip ค่อนข้างใหญ่ | มี write penalty: เขียน 1 strip ต้อง อ่าน user strip เดิม + parity strip เดิม แล้วเขียนกลับ = 2 reads + 2 writes (P' = P ⊕ D_old ⊕ D_new) | parity disk เป็นคอขวด → RAID 5 มาแก้
  • RAID 5: คล้าย RAID 4 แต่ กระจาย parity strip ไปทุก disk แบบ round-robin → เลี่ยงคอขวด I/O ของ RAID 4
  • RAID 6: คำนวณ parity 2 แบบ (P และ Q) เก็บคนละ block บน disk คนละลูก | ข้อมูลหายก็ต่อเมื่อ disk เสีย 3 ลูกภายใน MTTR | write penalty สูงมาก (กระทบ parity 2 block)

Lv ข้อดี ข้อเสีย Applications

6. SSD

ข้อดีเทียบ HDD 6 ข้อ: IOPS สูง / ทนทาน / อายุยาวกว่า / กินไฟน้อยกว่า / เงียบและเย็นกว่า / access time และ latency ต่ำกว่า

NAND Flash (SSD) HDD (Seagate Laptop)
File copy/write 200–550 Mbps 50–120 Mbps
Power 2–3 watts (แบตอยู่นานขึ้น 30+ นาที) 6–7 watts
Capacity notebook ≤ 512 GB, desktop ≤ 1 TB notebook ~500 GB สูงสุด 2 TB, desktop สูงสุด 4 TB
Cost $0.50/GB (1 TB) $0.15/GB (4 TB)

สถาปัตยกรรม: Host System (OS Software → File System Software → I/O Driver Software → Interface) ⇄ SSD (Interface → Controller → Addressing, Data buffer/cache, Error correction → Flash memory components)

Practical Issues ⭐ (2 ปัญหาที่ HDD ไม่มี):

  1. ประสิทธิภาพลดลงเมื่อใช้ไปนาน ๆ — การแก้ข้อมูลต้องทำทั้ง block: อ่านทั้ง block มาไว้ RAM buffer → erase ทั้ง block ของ flash → เขียนทั้ง block กลับ
  2. flash ใช้ไม่ได้หลังเขียนครบจำนวนครั้งหนึ่ง — ยืดอายุด้วย cache ข้างหน้า flash (หน่วงและรวบการเขียนเป็นชุด), wear-leveling algorithms (กระจายการเขียนทั่วทุก block), bad-block management | flash ส่วนใหญ่ประเมินอายุที่เหลือของตัวเองได้ ระบบจึงเตรียมรับมือก่อนเสีย

CD-R CD-RW

8. Magnetic Tape

  • อ่านเขียนด้วยเทคนิคเดียวกับ disk | ตัวกลาง = เทป polyester ยืดหยุ่น เคลือบวัสดุแม่เหล็ก (อนุภาคโลหะบริสุทธิ์ใน binder หรือ ฟิล์มโลหะแบบ vapor-plated)
  • ข้อมูลเรียงเป็น track ขนานกันหลายเส้นตามความยาวเทป | Serial recording = ข้อมูลเรียงเป็นลำดับบิตตามแต่ละ track | อ่านเขียนเป็นก้อนต่อเนื่อง = physical records | ระหว่าง block มี inter-record gaps
  • Serpentine recording: เขียน Track 0 ไปทางหนึ่ง → สุดเทป กลับทิศ เขียน Track 1 → Track 2 … วนไปมาแบบงู
