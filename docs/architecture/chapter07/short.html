⭐ Pipelining basics

  • Laundry analogy: overlapping execution | 4 loads speedup = 8/3.5 = 2.3 | non-stop = 2n/(0.5n+1.5) ≈ 4 = #stages
  • 5 ขั้น: IF (fetch) → ID (decode + register read) → EX (execute / address) → MEM (memory) → WB (write back)
Instr IF Reg read ALU MEM Reg write Total
ld 200 100 200 200 100 800
sd 200 100 200 200 — 700
R 200 100 200 — 100 600
beq 200 100 200 — — 500
  • Single-cycle Tc = 800ps | Pipelined Tc = 200ps
  • RISC-V เหมาะกับ pipeline: คำสั่ง 32 bit ทั้งหมด (x86 1–17 bytes), format น้อยสม่ำเสมอ, load/store (address ขั้น 3, memory ขั้น 4)
  • ⭐ เพิ่ม throughput แต่ latency เท่าเดิม | ISA design กระทบความซับซ้อน

⭐ Hazards

Hazard สาเหตุ แก้
Structure ทรัพยากรไม่ว่าง (memory เดียว → bubble) แยก I/D memory หรือ cache
Data รอข้อมูลคำสั่งก่อน forwarding, stall, code scheduling
Control การตัดสินใจขึ้นกับคำสั่งก่อน (branch) stall, prediction, ตัดสินใน ID

Data hazards

  • add x19,x0,x1 → sub x2,x19,x3: ไม่ forward ต้อง bubble 2 รอบ
  • Forwarding (bypassing): ใช้ผลทันทีที่คำนวณเสร็จ ไม่ต้องรอเขียน register (ต้องมีสายเพิ่ม)
  • Load-use: ld แล้วใช้ทันที → stall 1 รอบ แล้วค่อย forward ("can't forward backward in time")
  • ⭐ Code scheduling a = b + e; c = b + f: ย้าย ld x4 ขึ้นก่อน → 13 → 11 cycles

Control hazards

  • ต้องเทียบ register + คำนวณ target เร็ว → เพิ่ม hardware ในขั้น ID
  • Stall on branch: รอผล branch (ตัวอย่างเสีย 400ps)
  • Branch prediction: stall เฉพาะเมื่อทายผิด | RISC-V ทาย not taken
  • Static: backward = taken, forward = not taken | Dynamic: hardware เก็บประวัติ, ผิดแล้ว stall + update history

Datapath

  • Right-to-left flow (MEM → PC, WB → register) ทำให้เกิด hazards
  • Pipeline registers: IF/ID, ID/EX, EX/MEM, MEM/WB — เก็บข้อมูลจากขั้นก่อน
  • Load: IF → ID → EX (address) → MEM (อ่าน) → WB | "Wrong register number" → ต้องส่ง rd ไปตาม pipeline (corrected datapath)
  • Store: EX address → MEM เขียน → WB ไม่มีงาน
  • Multi-cycle diagram (ตามเวลา, resource หรือ traditional) vs single-cycle diagram (สถานะในรอบเดียว)
  • Control signals: PCSrc, Branch, RegWrite, ALUSrc, ALUOp, MemWrite, MemRead, MemtoReg

⭐ Forwarding detection

  • ตัวอย่าง: sub x2 → and, or, add, sd ใช้ x2 (x2 = 10 → −20 ที่ CC5)
  • Hazard เมื่อ: 1a/1b EX/MEM.Rd = ID/EX.Rs1/Rs2 (fwd จาก EX/MEM) | 2a/2b MEM/WB.Rd = ID/EX.Rs1/Rs2 (fwd จาก MEM/WB)
  • เฉพาะเมื่อ RegWrite = 1 และ Rd ≠ x0
Mux Source
00 ID/EX (register file)
10 EX/MEM (ALU result ก่อนหน้า)
01 MEM/WB (data memory / ALU ก่อนหน้านั้น)
  • Double data hazard (add x1 ×3): ใช้ค่าใหม่สุด → forward จาก MEM/WB เฉพาะเมื่อ EX hazard ไม่จริง (⚠️ สไลด์ 42 เขียน ≠ ใน not(...) — ดูฉบับเต็ม)

⭐ Load-use detection & stall

  • ตรวจในขั้น ID: ID/EX.MemRead and (ID/EX.Rd = IF/ID.Rs1 or Rs2) (สไลด์พิมพ์ Rs1 ซ้ำ)
  • Stall: control ใน ID/EX = 0 (EX/MEM/WB เป็น nop) + ไม่ update PC และ IF/ID (decode/fetch ใหม่) → 1 รอบแล้ว forward
  • Hazard detection unit คุม PCWrite, IF/IDWrite
  • Stall ลด performance แต่จำเป็น | compiler จัดโค้ดเลี่ยงได้

⭐ Branch hazards

  • ตัดสินใน MEM → flush 3 คำสั่ง (control = 0)
  • ย้ายไป ID: target address adder + register comparator → เสีย 1 bubble (IF.Flush)
  • 40: beq x1, x3, 16 → target = 40 + 16×2 = 72 (ld x4, 50(x7))
