ส่วน A — Data Representation

1. พื้นฐาน

  • ข้อมูลเก็บใน registers ซึ่งมีจำนวนและขนาดจำกัด | register n บิต unsigned: min = 0, max = 2ⁿ − 1
  • Data → Quantitative (Integers: signed/unsigned, Non-integers: signed/unsigned) / Qualitative (ตัวอักษร สัญลักษณ์)
  • ระบบเลข: Decimal 0–9 | Binary 0,1 | Octal 0–7 | Hexadecimal 0–9, A–F

2. Signed Integers — 3 วิธี

(1) Sign & Magnitude (2) Complement method (3) Bias / Excess notation

Sign & Magnitude

  • magnitude n บิต + sign bit S (S=0 บวก/ศูนย์, S=1 ลบ/ศูนย์) | Range: −(2ⁿ−1) ถึง +(2ⁿ−1) | 8 บิต → −127 ถึง +127
  • 0000 0000 = +0, 1000 0000 = −0 → ศูนย์ไม่ unique
✅ ข้อดี ❌ ข้อเสีย
กลับเครื่องหมายง่าย, หา |a| ง่าย (พลิก sign bit) บวกกับค่าลบ ≠ การลบ (ต้องใช้ operation ต่างกัน), ศูนย์ไม่ unique

3. Complement Method ⭐

Base = Radix | ฐาน r มี 2 ชนิด: r's complement และ (r−1)'s complement (ฐาน 10 → 9's/10's, ฐาน 2 → 1's/2's)

(r−1)'s complement of m = (rⁿ − 1) − m
r's complement of m     = (rⁿ − 1) − m + 1 = rⁿ − m

ตัวอย่างฐาน 10: m = 382, n = 3 → 9's = 999−382 = 617 / 10's = 618 → เรียก complementary pair

1's Complement

  • = กลับทุกบิต | 0101 (4 บิต) → 1010 = −5 | 00101011 → 11010100
  • 00000000 = 0, 11111111 = −0 (ศูนย์ 2 แบบ) | Range 8 บิต: −127 ถึง +127
  • การบวก: ถ้ามี carry ต้องเอาไปบวกที่ LSB = end-around carry 6 + (−3) บน 3 บิต: 110 + 100 = 1010 → 010 + 1 = 011 = 3 ✅

2's Complement

  • = 1's complement + 1 | ไม่ต้องทำ end-around carry | Range 8 บิต: −128 ถึง +127 (ได้ −128 เพิ่มเพราะ +1)
  • ตัวอย่าง: 0101011 → กลับบิต 1010100 → +1 = 1010101
  • Short-cut: หาบิต 1 ตัวแรกจาก LSB (ขวาสุด) แล้วกลับทุกบิตที่อยู่ซ้ายของมัน
  • การบวก: ทิ้ง carry | 6 + (−5) บน 4 บิต: 0110 + 1011 = 10001 → 0001 = 1 ✅
1's complement 2's complement
ศูนย์ 2 แบบ (+0, −0) ศูนย์แบบเดียว
ช่วงค่าน้อยกว่า ช่วงไม่สมมาตร (ลบมากกว่าบวก 1)

ข้อดีร่วมของ complement: ไม่ต้องมีวงจรลบแยก (ลบ = บวกค่าลบ), NOT ต้นทุนวงจรถูกมาก — แต่คูณและหารช้า

5. Bias Notation (Excess Notation)

  • บวก bias B เข้าไปให้ค่า unsigned ต่ำสุดกลายเป็น −B และค่า B กลายเป็นศูนย์ | ค่าจริง = Σbᵢ2ⁱ − B
  • bias 127, 8 บิต: ช่วง −127 (0−127) ถึง +128 (255−127) | 0111 1111 = +0, 1000 0000 = +1, 1111 1111 = +128
  • อ่านค่า biased = unsigned − bias — ใช้ใน exponent ของ floating point

6. Floating Point ⭐

  • ต้องแทนทศนิยมและค่าที่ใหญ่กว่า 2ⁿ−1 | −0.000321 = −3.21 × 10⁻⁴ ประกอบด้วย Sign, Mantissa (3.21), Radix (10), Exponent (−4)
  • รูปแบบทั่วไป: N = (−1)ˢ × m × 2ᵉ เก็บเป็น sign | exponent | mantissa
Single precision Double precision
รวม 32 bits 64 bits
Sign 1 (บิต 31) 1 (บิต 63)
Exponent 8 (บิต 30–23) 11 (บิต 62–52)
Mantissa 23 (บิต 22–0) 52 (บิต 51–0)

N = (−1)ˢ × [1.m] × 2^(E−127) โดย E = e + 127 (bias 127) — สิ่งที่เก็บจริงคือ E | mantissa เก็บเฉพาะหลังจุด เพราะหน้าจุดเป็น 1 เสมอ (normalized) Single precision: m = 1 ถึง (2 − 2⁻²³) | E = 1 ถึง 254 (0 และ 255 สงวนไว้แทน −∞, +∞, NaN) | e = −126 ถึง +127 | ค่าสูงสุด ≈ 2 × 2¹²⁷ = 2¹²⁸

Binary Fractions

101.1101₂ = 4+0+1+0.5+0.25+0+0.0625 = 5.8125 5.8125₁₀ → ฐานสอง: จำนวนเต็ม 5 = 101 / ทศนิยมคูณ 2 เก็บเลขหน้าจุด: 0.8125×2=1.625 → 0.625×2=1.25 → 0.25×2=0.5 → 0.5×2=1.0 → .1101 → 101.1101₂

7. Character Representation

  • ข้อมูล qualitative: Letters a-z A-Z, Digits 0-9, Symbols (! @ * / & # $), Control characters (<CR> <BEL> <ESC> <LF>) | 1 byte = 256 ตัวอักษร
  • มาตรฐาน: ASCII, EBCDIC, Unicode
  • ASCII: มาตรฐานโดยพฤตินัยทั่วโลก, 128 รหัส, 7 บิต (000 0000–111 1111) + parity bit 1 บิต
  • ช่วงสำคัญ: 0–31 control (BEL=7, BS=8, TAB=9, LF=10, CR=13) | 32 = space | 48–57 = '0'–'9' | 65–90 = 'A'–'Z' | 97–122 = 'a'–'z'
  • ⭐ ต้องจำ: รหัส ASCII ของตัวเลข ไม่เท่ากับค่าตัวเลขจริง ('0' = 48) | ตัวใหญ่-เล็กต่างกัน 0x20 (Shift key เคลียร์บิตที่ 5): A = 65 = 0100 0001, a = 97 = 0110 0001 | ภาษาส่วนใหญ่ต้องการมากกว่า 128 ตัว → จึงมี Unicode

9. Instruction Set & RISC-V

  • คอมพิวเตอร์แต่ละเครื่องมี instruction set ต่างกัน | ยุคแรกชุดคำสั่งเรียบง่ายมาก → implement ง่าย | สมัยใหม่หลายรุ่นก็เรียบง่าย
  • RISC-V: พัฒนาที่ UC Berkeley, เป็น open ISA, ดูแลโดย RISC-V Foundation (riscv.org), เป็นแบบฉบับของ ISA สมัยใหม่, ISA คล้ายกันมีส่วนแบ่งตลาด embedded core ใหญ่ (consumer electronics, network/storage, cameras, printers)

10. Arithmetic Operations & Registers

  • add/sub มี 3 operands: 2 sources + 1 destination — add a, b, c // a = b + c ทุก arithmetic operation เป็นรูปแบบนี้
  • Design Principle 1: Simplicity favours regularity (ความสม่ำเสมอ → implement ง่าย, เรียบง่าย → ประสิทธิภาพสูงในต้นทุนต่ำ)
  • Design Principle 2: Smaller is faster — register file 32 × 64-bit (เทียบ main memory หลายล้านตำแหน่ง) | doubleword = 64 บิต, word = 32 บิต, general purpose registers x0–x31
Register หน้าที่
x0 ค่าคงที่ 0 (เปลี่ยนไม่ได้)
x1 return address
x2 stack pointer
x3 global pointer
x4 thread pointer
x5–x7, x28–x31 temporaries
x8 frame pointer
x9, x18–x27 saved registers
x10–x11 function arguments / results
x12–x17 function arguments

ตัวอย่าง f = (g+h) - (i+j); (f…j อยู่ x19–x23):

add x5, x20, x21    // x5 = g + h
add x6, x22, x23    // x6 = i + j
sub x19, x5, x6     // f = x5 - x6

11. Memory Operands, Endianness, Immediate

  • main memory ใช้กับ composite data (arrays, structures, dynamic data) | ทำ arithmetic ต้อง load เข้า register → คำนวณ → store กลับ
  • Memory เป็น byte addressed (1 address = 8 บิต) | RISC-V เป็น Little Endian (byte นัยสำคัญน้อยสุดอยู่ address ต่ำสุด) c.f. Big Endian (นัยสำคัญมากสุดอยู่ address ต่ำสุด) | RISC-V ไม่บังคับให้ word align
  • ตัวอย่าง ⭐ A[12] = h + A[8]; (h ใน x21, base ของ A ใน x22) — offset = index × 8
ld  x9, 64(x22)     // x9 = A[8]   (8 × 8 = 64)
add x9, x21, x9
sd  x9, 96(x22)     // A[12] = x9  (12 × 8 = 96)
  • Registers vs Memory: register เร็วกว่า, ใช้ memory ต้อง load/store → คำสั่งมากขึ้น → compiler ต้องใช้ register ให้มากที่สุด เก็บลง memory เฉพาะตัวแปรที่ใช้ไม่บ่อย — register optimization สำคัญมาก
  • Immediate operands: ค่าคงที่ในคำสั่งเลย addi x22, x22, 4 → make the common case fast (ค่าคงที่เล็กพบบ่อย, ไม่ต้องโหลดจาก memory)

12. Numbers ใน RISC-V

  • Unsigned: 0 ถึง 2ⁿ−1 | 2's complement signed: −2ⁿ⁻¹ ถึง +2ⁿ⁻¹−1
  • Signed negation = complement and add 1 (+2 = …0010 → …1101 + 1 = …1110 = −2)
  • Sign extension: lb = sign-extend (คัดลอก sign bit เติมซ้าย) | lbu = zero-extend (เติม 0)

13. Representing Instructions ⭐⭐

คำสั่งเข้ารหัสเป็นเลขฐานสอง = machine code | RISC-V = instruction word 32 บิต มี format จำนวนน้อย → Regularity!

R-format (arithmetic)

funct7 rs2 rs1 funct3 rd opcode
7 5 5 3 5 7 bits

rd = destination, rs1 = first source, rs2 = second source, funct3/funct7 = additional opcode ตัวอย่าง add x9, x20, x21: funct7=0, rs2=21, rs1=20, funct3=0, rd=9, opcode=51 → 0000000 10101 10100 000 01001 0110011 = 015A04B3₁₆ ⚠️ ลำดับ field กลับกับลำดับในคำสั่ง (add rd, rs1, rs2 แต่เก็บ rs2 | rs1 | … | rd)

I-format (immediate arithmetic & loads)

immediate (12) rs1 (5) funct3 (3) rd (5) opcode (7)

rs1 = source หรือ base address / immediate = constant หรือ offset ที่บวกกับ base — 2's complement, sign extended Design Principle 3: Good design demands good compromises — format ต่างกันทำให้ decode ซับซ้อน แต่ทำให้ทุกคำสั่งยาว 32 บิตเท่ากัน → ทำให้ format คล้ายกันมากที่สุด

S-format (stores)

imm[11:5] rs2 rs1 funct3 imm[4:0] opcode

rs1 = base address, rs2 = source operand — แยก immediate 2 ส่วน เพื่อให้ rs1 และ rs2 อยู่ตำแหน่งเดิมเสมอ (store ไม่มี rd จึงเอาช่อง rd มาใส่ immediate ส่วนล่าง → decode ง่าย)

14. Stored Program & Logical Operations

  • Stored Program (BIG Picture): คำสั่งแทนเป็นเลขฐานสองเหมือนข้อมูล / คำสั่งและข้อมูลเก็บใน memory / โปรแกรมทำงานกับโปรแกรมได้ (compilers, linkers) / binary compatibility ทำให้รันข้ามเครื่องได้ → standardized ISAs
Operation C Java RISC-V
Shift left << << slli
Shift right >> >>> srli
AND & & and, andi
OR | | or, ori
XOR ^ ^ xor, xori
NOT ~ ~ (xor กับ 1 ทั้งหมด)
  • Shift format: funct6(6) | immed(6) | rs1(5) | funct3(3) | rd(5) | opcode(7) — immed = เลื่อนกี่ตำแหน่ง
  • slli i บิต = คูณ 2ⁱ (เติม 0) | srli i บิต = หาร 2ⁱ (unsigned เท่านั้น)
  • AND = mask bits (เลือกบางบิต เคลียร์ที่เหลือ) | OR = include bits (ตั้งบางบิตเป็น 1) | XOR กับ 1 ทั้งหมด = NOT (differencing)

15. Conditional Operations ⭐

  • beq rs1,rs2,L1 (เท่ากันกระโดด) | bne (ไม่เท่า) | blt (rs1 < rs2) | bge (rs1 ≥ rs2) | unsigned: bltu, bgeu

If statement if (i==j) f=g+h; else f=g-h;

      bne x22, x23, Else     // ทดสอบเงื่อนไขกลับด้าน
      add x19, x20, x21
      beq x0, x0, Exit       // unconditional (0==0 เสมอ)
Else: sub x19, x20, x21
Exit:                        // Assembler calculates addresses

While loop while (save[i]==k) i+=1;

Loop: slli x10, x22, 3     // i * 8
      add  x10, x10, x25   // address ของ save[i]
      ld   x9, 0(x10)
      bne  x9, x24, Exit
      addi x22, x22, 1
      beq  x0, x0, Loop
Exit:

if (a>b) a+=1; → bge x23, x22, Exit (branch if b ≥ a) แล้ว addi x22,x22,1

  • Basic block = ลำดับคำสั่งที่ไม่มี branch ฝังอยู่ (ยกเว้นท้าย) และไม่มี branch target (ยกเว้นต้น) — compiler ใช้หาเพื่อ optimize, processor ขั้นสูงเร่งได้
  • Signed vs Unsigned ⚠️: x22 = 1111…1111, x23 = 0000…0001 → signed: x22 < x23 (−1 < +1) / unsigned: x22 > x23 (4,294,967,295 > 1) — บิตชุดเดียวกันแต่ผลต่างกัน

16. Procedure Calling ⭐⭐

6 ขั้น: 1. วาง parameters ใน x10–x17 2. ส่งการควบคุมไป procedure 3. จองพื้นที่เก็บข้อมูล 4. ทำงาน 5. วางผลลัพธ์ใน register 6. กลับจุดที่เรียก (address ใน x1)

  • Call: jal x1, ProcedureLabel — เก็บ address คำสั่งถัดไปใน x1 แล้วกระโดด
  • Return: jalr x0, 0(x1) — กระโดดไป 0 + address ใน x1, ใช้ x0 เป็น rd (= ทิ้ง return address) | ใช้ทำ computed jumps ได้ เช่น case/switch

Leaf procedure (ไม่เรียกฟังก์ชันอื่น)

leaf_example:
    addi sp, sp, -24     // จอง stack 3 × 8 bytes
    sd   x5, 16(sp)      // save x5, x6, x20
    sd   x6, 8(sp)
    sd   x20, 0(sp)
    add  x5, x10, x11    // g + h
    add  x6, x12, x13    // i + j
    sub  x20, x5, x6     // f
    addi x10, x20, 0     // copy f to return register
    ld   x20, 0(sp)      // restore
    ld   x6, 8(sp)
    ld   x5, 16(sp)
    addi sp, sp, 24      // คืนพื้นที่
    jalr x0, 0(x1)
  • Stack โตจาก high address ลงไป low address (จึง addi sp, sp, -24)
  • Register usage: x5–x7, x28–x31 = temporary (callee ไม่ต้องรักษาค่า) | x8–x9, x18–x27 = saved (ถ้า callee ใช้ต้อง save และ restore)

Non-leaf procedure (เรียก procedure อื่น) — Factorial

caller ต้อง save ลง stack: return address ของตัวเอง + arguments/temporaries ที่ยังต้องใช้หลัง call แล้ว restore หลัง call

fact:
    addi sp, sp, -16
    sd   x1, 8(sp)       // save return address
    sd   x10, 0(sp)      // save n
    addi x5, x10, -1
    bge  x5, x0, L1      // if n >= 1 go to L1
    addi x10, x0, 1      // return 1
    addi sp, sp, 16
    jalr x0, 0(x1)
L1: addi x10, x10, -1    // n - 1
    jal  x1, fact        // fact(n-1)
    addi x6, x10, 0      // ย้ายผลไป x6
    ld   x10, 0(sp)      // restore n
    ld   x1, 8(sp)       // restore return address
    addi sp, sp, 16
    mul  x10, x10, x6    // n * fact(n-1)
    jalr x0, 0(x1)

💡 ต้อง save x1 เพราะ jal x1, fact เขียนทับ x1 | ต้อง save x10 (n) เพราะหลังเรียกยังต้องใช้ n มาคูณ

18. String Copy (strcpy)

strcpy:
    addi sp, sp, -8
    sd   x19, 0(sp)      // push x19 (saved register)
    add  x19, x0, x0     // i = 0
L1: add  x5, x19, x11    // addr ของ y[i]
    lbu  x6, 0(x5)       // y[i]
    add  x7, x19, x10    // addr ของ x[i]
    sb   x6, 0(x7)       // x[i] = y[i]
    beq  x6, x0, L2      // ถ้า y[i] == 0 ออก (null-terminated)
    addi x19, x19, 1
    jal  x0, L1
L2: ld   x19, 0(sp)
    addi sp, sp, 8
    jalr x0, 0(x1)

char = 1 byte จึงไม่ต้องคูณ 8 และใช้ lbu/sb

19. Wide Immediates & Addressing

  • ค่าคงที่ส่วนใหญ่เล็ก → immediate 12 บิตพอ | สำหรับ 32 บิต: lui rd, constant = คัดลอกค่าคงที่ 20 บิตไปบิต [31:12], ขยายบิต 31 ไป [63:32], เคลียร์ [11:0] เป็น 0 → แล้วตามด้วย addi
  • Branch addressing (SB format): imm[12] | imm[10:5] | rs2 | rs1 | funct3 | imm[4:1] | imm[11] | opcode — PC-relative: target = PC + immediate × 2 (branch target ส่วนใหญ่อยู่ใกล้)
  • Jump addressing (UJ format): imm[20] | imm[10:1] | imm[11] | imm[19:12] | rd | opcode — jal ใช้ immediate 20 บิต | กระโดดไกลมาก: lui โหลด address[31:12] → jalr บวก address[11:0]

20. Synchronization

  • 2 processors ใช้ memory ร่วมกัน → ถ้าไม่ synchronize เกิด data race (ผลขึ้นกับลำดับการเข้าถึง)
  • ต้องมี hardware support: atomic read/write memory operation (ไม่มีใครเข้าถึงได้ระหว่างอ่านกับเขียน) — เป็นคำสั่งเดียว (atomic swap) หรือคู่คำสั่งแบบ atomic
  • lr.d rd, (rs1) = load reserved (โหลด + จอง address นั้น) | sc.d rd, (rs1), rs2 = store conditional — สำเร็จ (ตำแหน่งไม่ถูกเปลี่ยนตั้งแต่ lr.d) → คืน 0 / ล้มเหลว → คืนค่าไม่ใช่ศูนย์
// atomic swap
again: lr.d x10, (x20)
       sc.d x11, (x20), x23
       bne  x11, x0, again
       addi x23, x10, 0
// lock
       addi x12, x0, 1
again: lr.d x10, (x20)
       bne  x10, x0, again
       sc.d x11, (x20), x12
       bne  x11, x0, again
Unlock: sd x0, 0(x20)

21. Translation and Startup

C program → Compiler → Assembly → Assembler → Object module (+ library routine) → Linker → Executable → Loader → Memory (compiler หลายตัวสร้าง object module ได้โดยตรง | static linking = รวม library ตอน link)

Object module 6 ส่วน: Header (อธิบายเนื้อหา) | Text segment (คำสั่งที่แปลแล้ว) | Static data segment | Relocation info | Symbol table (global definitions + external references) | Debug info

Linking 3 ขั้น: 1. รวม segments 2. Resolve labels (หา address จริง) 3. Patch การอ้างอิงที่ขึ้นกับตำแหน่งและ external refs — อาจปล่อยให้ relocating loader แก้ (แต่ถ้ามี virtual memory ไม่จำเป็น)

Loading 6 ขั้น: 1. อ่าน header หาขนาด segment 2. สร้าง virtual address space 3. คัดลอก text + initialized data ลง memory 4. ตั้ง arguments บน stack 5. ตั้งค่า registers (sp, fp, gp) 6. กระโดดไป startup routine → คัดลอก arguments ไป x10… → เรียก main → main return แล้ว exit syscall

Dynamic linking: link/load library procedure เฉพาะตอนถูกเรียก / ต้องให้โค้ด relocatable / หลีกเลี่ยง image บวม / ได้ library เวอร์ชันใหม่อัตโนมัติ Lazy linkage: เรียกครั้งแรกผ่าน Indirection table → Stub → Linker/loader → DLL routine / ครั้งต่อ ๆ ไป indirection table ชี้ไป DLL โดยตรง Java: Java program → Compiler → Class files (bytecodes) → JVM แปลความ (interprets) + Java library routines | JIT compiler คอมไพล์ method ที่ "hot" เป็น native code

22. C Sort Example

swap (leaf): slli x6,x11,3 (k×8) → add x6,x10,x6 → ld x5,0(x6) (temp=v[k]) → ld x7,8(x6) → sd x7,0(x6) → sd x5,8(x6) → jalr x0,0(x1) sort (non-leaf): outer loop bge x19,x11,exit1 (i ≥ n ออก) / inner loop blt x20,x0,exit2 (j < 0 ออก), ble x6,x7,exit2, ย้าย x10→x21, x11→x22 ก่อนเรียก jal x1, swap 💡 ย้าย x10, x11 ไปเก็บ x21, x22 เพราะต้องส่งค่าใหม่ให้ swap ทาง x10, x11 แต่ sort ยังต้องใช้ v, n เดิม Preserving registers: addi sp,sp,-40 → save x1, x22, x21, x20, x19 → (ตอนจบ) restore ด้วย ld ทั้ง 5 ตัว → addi sp,sp,40 → jalr x0,0(x1)

23. Compiler Optimization & Language/Algorithm

  • เทียบ gcc none/O1/O2/O3 ใน 4 กราฟ (relative performance, clock cycles, instruction count, CPI): optimization เพิ่ม performance ลด cycles/IC ได้ แต่ CPI ไม่ได้ลดตามเสมอ
  • Quicksort เร็วกว่า Bubblesort หลักพันเท่า (~3000×)
  • Lessons Learnt ⭐: IC และ CPI ไม่ใช่ตัวชี้วัด performance ที่ดีถ้าดูแยกกัน / compiler optimizations ไวต่อ algorithm / Java/JIT เร็วกว่า JVM interpreted มาก เทียบได้กับ optimized C / Nothing can fix a dumb algorithm!

24. Arrays vs Pointers

  • Array indexing ต้องคูณ index ด้วยขนาด element + บวก base address | Pointers ตรงกับ memory address โดยตรง → เลี่ยงความซับซ้อนของ indexing
  • clear1 (array): มี slli อยู่ในลูปทุกรอบ | clear2 (pointer): addi x5,x5,8 เพิ่ม pointer ตรง ๆ + bltu
  • การคูณถูก "strength reduced" เป็น shift | compiler ทำได้ผลเท่ากับการใช้ pointer เองด้วย induction variable elimination → ควรเขียนให้อ่านง่ายและปลอดภัยกว่า ปล่อยให้ compiler optimize

25. MIPS & Extensions

  • MIPS = รุ่นก่อนเชิงพาณิชย์ของ RISC-V — คล้ายกัน: คำสั่ง 32 บิต, GP registers 32 ตัว (reg 0 = 0 เสมอ), FP registers 32 ตัว, เข้า memory ด้วย load/store เท่านั้น, addressing mode สม่ำเสมอทุกขนาด
  • ต่างที่ conditional branch: RISC-V ใช้ blt/bge/bltu/bgeu / MIPS ใช้ slt, sltu (ได้ 0 หรือ 1) แล้วตามด้วย beq/bne
  • Encoding: RISC-V วาง opcode ไว้บิตล่าง และ rs1/rs2 อยู่ตำแหน่งเดิมทุก format / MIPS วาง opcode บิตบนและ immediate 16 บิต
  • Other RV64I: auipc rd, immed (rd = (imm<<12) + pc, ตามด้วย jalr สำหรับ long jump) | slt, sltu, slti, sltui | addw, subw, addiw (32 บิต) | sllw, srlw, sraw, slliw, srliw, sraiw | RV32I = variant 32 บิต
  • Extensions: M = multiply/divide/remainder | A = atomic | F = single-precision FP | D = double-precision FP | C = compressed (encoding 16 บิตสำหรับคำสั่งที่ใช้บ่อย)
