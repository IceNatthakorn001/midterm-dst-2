ส่วน A — Data Representation

1. ภาพรวม

1.1 Data Representation Outline

  • Representing numbers: Unsigned, Signed, Floating point
  • Representing characters & Symbols: ASCII, Unicode

1.2 Data Representation in Computers

  • ข้อมูลถูกเก็บใน registers
  • registers มีจำนวนและขนาดจำกัด
  • register n บิต (บิต n−1 ถึง 0) เก็บ unsigned ได้:
    • Min value = 0
    • Max value = 2ⁿ − 1

💡 8 บิต → 0 ถึง 255 / 16 บิต → 0 ถึง 65,535

1.3 การแบ่งประเภทข้อมูล

  • Data
    • Quantitative (เชิงปริมาณ = ตัวเลข)
      • Integers: Signed / Unsigned
      • Non-integers: Signed / Unsigned
    • Qualitative (เชิงคุณภาพ = ตัวอักษร สัญลักษณ์)

2. Number Systems และ Quantitative Numbers

ระบบ สัญลักษณ์
Decimal (ฐาน 10) 0–9
Binary (ฐาน 2) 0, 1
Octal (ฐาน 8) 0–7
Hexadecimal (ฐาน 16) 0–9, A, B, C, D, E, F

Quantitative Numbers

  • Integers: Unsigned (เช่น 20), Signed (เช่น +20, −20)
  • Non-integers: Floating point numbers เช่น 10.25, 3.33333…, 1/8 = 0.125

3. Signed Integers

ปัญหา: ต้องมีวิธีแทนค่าลบ มี 3 วิธี:

  1. Sign & Magnitude (S&M)
  2. Complement method
  3. Bias notation / Excess notation

3.1 Sign & Magnitude Representation

  • ใช้ magnitude n บิตแบบ unsigned + sign bit (S) 1 บิตหน้าสุด
  • S = 0 → จำนวนบวกหรือศูนย์ / S = 1 → จำนวนลบหรือศูนย์
  • Range: −(2ⁿ − 1) ถึง +(2ⁿ − 1) (n = จำนวนบิต magnitude)

3.2 Example — Sign & Magnitude

  • register 8 บิต มี min และ max เท่าไร? → magnitude 7 บิต → −127 ถึง +127 (คำตอบเสริม)
  • 0000 0000 และ 1000 0000 เป็นเลขอะไร? → +0 และ −0
    • การแทนศูนย์ไม่ unique (มีสองแบบ)

3.3 ข้อดีข้อเสีย S&M

✅ Advantages ❌ Disadvantages
กลับเครื่องหมายง่าย (sign reversal) บวกกับค่าลบไม่เหมือนการลบ — เช่น บวก 2 กับ −3 ต้อง ใช้ operation ต่างกัน
หาค่าสัมบูรณ์ |a| ง่าย — แค่พลิก sign bit ศูนย์ไม่ unique

4. Complement Method ⭐

4.1 แนวคิด

  • Base = Radix — ระบบฐาน r มีสัญลักษณ์ r ตัว (ฐาน 2 มี 0, 1)
  • 2 ชนิด: r's complement และ (r − 1)'s complement
  • ตัวอย่าง: Decimal → 9's และ 10's complement / Binary → 1's และ 2's complement

4.2 Definition

ให้เลข m ในฐาน r มี n หลัก:

$$(r-1)\text{'s complement of } m = (r^n - 1) - m$$

$$r\text{'s complement of } m = (r^n - 1) - m + 1 = r^n - m$$

4.3 Example (ฐาน 10)

m = 382, n = 3 (3 หลัก) หา −382:

  • 9's complement: 999 − 382 = 617
  • 10's complement: 617 + 1 = 618
  • −382 = 617 หรือ 618 ขึ้นกับว่าใช้ complement แบบไหน
  • เรียกว่า complementary pair

4.4 1's Complement

  • คำนวณจาก (2ⁿ − 1) − m = กลับทุกบิต (invert each bit) ของ m
  • ตัวอย่าง: m = 0101 ในระบบ 4 บิต → 1111 − 0101 = 1010 → แทนค่า −5 ใน 1's complement
  • ตัวอย่าง: m = 00101011 → 1's complement = 11010100
  • m = 00000000 = 0 → 1's complement = 11111111 = −0 (ศูนย์สองแบบ)
  • Range (8 บิต): −127 ถึง +127

4.5 Addition with 1's Complement

  • ถ้าผลมี carry (ตัวทด) ให้เอาไปบวกที่ LSB — เรียกว่า end-around carry
  • ตัวอย่าง: บวก 6 กับ −3 ในระบบ 3 บิต
    • 6 = 110
    • −3 = 100 (1's complement ของ 011)
    • 110 + 100 = 1010 → carry 1 วนมาบวก → 010 + 1 = 011 = 3 ✅

4.6 2's Complement

  • ไม่ต้องทำ end-around carry แบบ 1's complement
  • วิธีสร้าง: หา 1's complement แล้ว บวก 1 ที่ LSB
  • Range (8 บิต): −128 ถึง +127
    • ได้ −128 เพิ่มมาเพราะการ +1 ทำให้ฝั่งลบมีเพิ่ม 1 ค่า

4.7 Example — 2's Complement

หา 2's complement ของ 0101011

  • m = 0101011
  • กลับบิต = 1010100
  • +1 = 1010101

Short-cut:

  1. หาบิตที่เป็น 1 ตัวแรก โดยเริ่มจาก LSB (ขวาสุด)
  2. กลับทุกบิตที่อยู่หลัง (ซ้ายของ) 1 ตัวแรกนั้น

💡 0101011 → 1 ตัวแรกจากขวาคือบิต 0 คงไว้ แล้วกลับบิตที่เหลือด้านซ้าย: 1010101 ✅

บวก 6 กับ −5 ในระบบ 4 บิต

  • 5 = 0101 → −5 = 1011
  • 6 = 0110
  • 0110 + 1011 = 10001 → ทิ้ง (discard) carry ด้านซ้าย → 0001 = 1 ✅

4.8 1's vs 2's Complement

1's complement 2's complement
มีศูนย์สองแบบ (+0, −0) มีศูนย์แบบเดียว
ช่วงค่าน้อยกว่า 2's complement ช่วงค่าไม่สมมาตร (ลบมากกว่าบวก 1)

ข้อดีร่วมของ complement:

  • ไม่ต้องมีวงจรลบแยก — ลบ = บวกกับค่าลบ
  • การทำ NOT มี ต้นทุนวงจรถูกกว่ามาก
  • แต่ การคูณและหารช้า

6. Bias Notation (Excess Notation)

  • ช่วงเลขที่ต้องการแทน ถูกบวก bias B (ค่าบวก) เพื่อให้ค่า unsigned ที่เล็กที่สุดมีค่าเท่ากับ −B
  • ค่า B ในช่วงตัวเลขจะกลายเป็นศูนย์
  • ค่าที่แทน:

$$\sum_{i=0}^{n} b_i 2^i - B$$

  • ถ้า bias = 127 กับ 8 บิต: ช่วงคือ −127 (0 − 127) ถึง 128 (255 − 127)

Bit pattern Unsigned Biased-127
0000 0000 +0 −127
0000 0001 +1 −126
0000 0010 +2 −125
0111 1110 +126 −1
0111 1111 +127 +0
1000 0000 +128 +1
1111 1111 +255 +128

💡 อ่านค่า biased = ค่า unsigned − bias เช่น 1000 0000 = 128 − 127 = +1 — ใช้ใน exponent ของ floating point

7. Floating Point ⭐

7.1 ทำไมต้องมี

  • ต้องแทน ค่าทศนิยม และ ค่าที่ใหญ่กว่า 2ⁿ − 1
  • +3207.23 = 3.20723 × 10³
  • −0.000321 = −3.21 × 10⁻⁴ → ประกอบด้วย Sign, Mantissa (3.21), Radix/base (10), Exponent (−4)

7.2 รูปแบบทั่วไป

$$N = (-1)^s \times m \times 2^e$$

  • s = sign, m = mantissa, 2 = radix, e = exponent
  • เก็บเป็นบิต: sign | exponent (e_{n−1}…e₀) | mantissa (m_{n−1}…m₀)

7.3 IEEE Floating Point Standard

Single precision Double precision
ขนาดรวม 32 bits 64 bits
Sign 1 bit (บิต 31) 1 bit (บิต 63)
Exponent 8 bits (บิต 30–23) 11 bits (บิต 62–52)
Mantissa 23 bits (บิต 22–0) 52 bits (บิต 51–0)

$$N = (-1)^s \times [1.m] \times 2^{E-127}$$

  • E − 127 = e และ E = e + 127 (bias 127)
  • สิ่งที่เก็บจริงคือ E (exponent ที่บวก bias แล้ว)
  • mantissa เก็บเฉพาะส่วนหลังจุด เพราะหน้าจุดเป็น 1 เสมอ (normalized)

7.4 Single Precision

  • 23-bit mantissa: m มีค่าตั้งแต่ 1 ถึง (2 − 2⁻²³)
  • 8-bit exponent:
    • E มีค่า 1 ถึง 254
    • 0 และ 255 สงวนไว้ แทน −∞, +∞, NaN
    • e มีค่า −126 ถึง +127
  • ค่าสูงสุดที่แทนได้ ≈ 2 × 2¹²⁷ = 2¹²⁸

7.5 Review — Binary Fractions

101.1101₂ เป็นฐานสิบ = 2²×1 + 2¹×0 + 2⁰×1 + 2⁻¹×1 + 2⁻²×1 + 2⁻³×0 + 2⁻⁴×1 = 4 + 0 + 1 + 0.5 + 0.25 + 0 + 0.0625 = 5.8125

5.8125₁₀ เป็นฐานสอง

  • ส่วนจำนวนเต็ม: 5 = 101
  • ส่วนทศนิยม: คูณ 2 ไปเรื่อย ๆ จนได้ 1 แล้วเก็บเลขหน้าจุด
    • 0.8125 × 2 = 1.625
    • 0.625 × 2 = 1.25
    • 0.25 × 2 = 0.5
    • 0.5 × 2 = 1.0
    • → 0.8125₁₀ = .1101₂
  • 5.8125₁₀ = 101.1101₂

7.6 Example — Single Precision ของ 17.15₁₀ ⭐

  1. แปลงเป็นฐานสอง: 17.15₁₀ = 10001.0010011…₂ (17 = 10001, 0.15 = .001001100110… วนซ้ำ)
  2. Normalize: = 1.00010010011… × 2⁴ → e = 4
  3. หา E: E = e + 127 = 4 + 127 = 131 = 1000 0011
  4. Mantissa: ตัด "1." ออก เหลือ 0001 0010 0110 0000… (ตามสไลด์)
  5. ผลลัพธ์:
Sign Exponent Mantissa
0 1000 0011 0001 0010 0110 0000 ……

⚠️ 0.15 ในฐานสองเป็น ทศนิยมไม่รู้จบ (.0010011001100…) จึงเก็บได้แค่ค่าประมาณ — นี่คือเหตุผลที่ 0.1 + 0.2 ในคอมพิวเตอร์ไม่เท่ากับ 0.3 พอดี (คำอธิบายเสริม)

8. Character Representation

8.1 ภาพรวม

  • เป็นข้อมูล เชิงคุณภาพ (qualitative) — แทนคุณภาพหรือคุณลักษณะ
  • ประกอบด้วย:
    • Letters: a-z, A-Z
    • Digits: 0-9
    • Symbols: !, @, *, /, &, #, $
    • Control characters: , , ,
  • 1 byte (8 บิต) แทนได้ 256 ตัวอักษร
  • มาตรฐาน:
    • ASCII — American Standard Code for Information Interchange
    • EBCDIC — Extended Binary-Coded Decimal Interchange Code
    • Unicode

8.2 ASCII

  • มาตรฐานโดยพฤตินัยทั่วโลก
  • ใช้แทน: ตัวอักษรละตินพิมพ์ใหญ่-เล็ก, ตัวเลข, เครื่องหมายวรรคตอน, control characters
  • มี 128 รหัสมาตรฐาน
    • แทนด้วย เลขฐานสอง 7 บิต (000 0000 ถึง 111 1111)
    • บวก parity bit 1 บิต

10. Instruction Set Overview และ RISC-V

10.1 Instruction Set Overview

  • คอมพิวเตอร์แต่ละเครื่องมี instruction set ต่างกัน
  • คอมพิวเตอร์ยุคแรกมีชุดคำสั่งเรียบง่ายมาก → implement ง่าย
  • คอมพิวเตอร์สมัยใหม่หลายรุ่นก็มีชุดคำสั่งเรียบง่าย

10.2 RISC-V Instruction Set

  • พัฒนาที่ UC Berkeley เป็น open ISA
  • ปัจจุบันดูแลโดย RISC-V Foundation (riscv.org)
  • เป็นแบบฉบับของ ISA สมัยใหม่หลายตัว (ดู RISC-V Reference Data tear-out card)
  • ISA คล้าย ๆ กันมีส่วนแบ่งตลาด embedded core ขนาดใหญ่
    • ใช้ใน consumer electronics, network/storage equipment, cameras, printers, …

11. Arithmetic Operations และ Registers

11.1 Arithmetic Operations

  • Add และ subtract มี 3 operands: 2 sources + 1 destination
    • add a, b, c // a gets b + c
  • ทุก arithmetic operation มีรูปแบบนี้
  • Design Principle 1: Simplicity favours regularity
    • ความสม่ำเสมอทำให้ implement ง่าย
    • ความเรียบง่ายทำให้ได้ประสิทธิภาพสูงในต้นทุนต่ำ

11.2 Arithmetic Example

C code:  f = (g + h) - (i + j);

add t0, g, h    // temp t0 = g + h
add t1, i, j    // temp t1 = i + j
sub f, t0, t1   // f = t0 - t1

(สไลด์เขียนบรรทัดสุดท้ายเป็น add f, t0, t1 แต่ comment บอก f = t0 − t1 ที่ถูกต้องคือ sub)

11.3 Register Operands

  • arithmetic instructions ใช้ register เป็น operand
  • RISC-V มี register file ขนาด 32 × 64-bit
    • ใช้กับ ข้อมูลที่เข้าถึงบ่อย
    • ข้อมูล 64 บิต เรียกว่า "doubleword"
      • มี general purpose registers 32 ตัว: x0 ถึง x31 (สไลด์เขียน "x0 to x30")
    • ข้อมูล 32 บิต เรียกว่า "word"
  • Design Principle 2: Smaller is faster — เทียบกับ main memory ที่มีหลายล้านตำแหน่ง

11.5 Register Operand Example

12. Memory Operands, Endianness, Immediate

12.1 Endian Support

  • Big-endian: byte ที่มีนัยสำคัญมากที่สุดอยู่ที่ address ต่ำสุด (byte address 00–07 เรียงซ้ายไปขวาตรงกับค่า 11 12 13 14 …)
  • Little-endian: byte ที่มีนัยสำคัญน้อยที่สุดอยู่ที่ address ต่ำสุด (เรียงกลับกัน)

12.2 Memory Operands

  • Main memory ใช้กับข้อมูลประกอบ (composite data): arrays, structures, dynamic data
  • การทำ arithmetic:
    • โหลดค่าจาก memory เข้า register
    • เก็บผลจาก register กลับลง memory
  • Memory เป็น byte addressed — แต่ละ address ระบุข้อมูล 8 บิต (1 byte)
  • RISC-V เป็น Little Endian
    • byte ที่มีนัยสำคัญน้อยสุดอยู่ที่ address ต่ำสุดของ word
    • c.f. Big Endian: byte ที่มีนัยสำคัญมากสุดอยู่ที่ address ต่ำสุด
  • RISC-V ไม่บังคับให้ word ต้อง align ใน memory (ต่างจาก ISA อื่นบางตัว)

💡 เลข 0x12345678: little-endian เก็บ 78 56 34 12 / big-endian เก็บ 12 34 56 78 (อ่านจาก address ต่ำไปสูง) (ตัวอย่างเสริม)

12.3 Memory Operand Example ⭐

C: A[12] = h + A[8]; — h ใน x21, base address ของ A ใน x22

  • Index 8 ต้องใช้ offset 64 เพราะ 8 bytes ต่อ doubleword
ld  x9, 64(x22)     // x9 = A[8]  (8 × 8 = 64)
add x9, x21, x9     // x9 = h + A[8]
sd  x9, 96(x22)     // A[12] = x9 (12 × 8 = 96)

⚠️ offset = index × 8 (doubleword 8 bytes) — ลืมคูณ 8 เป็นข้อผิดพลาดที่พบบ่อย

ld = load doubleword, sd = store doubleword

12.4 Registers vs Memory

  • register เข้าถึงเร็วกว่า memory
  • ทำงานกับข้อมูลใน memory ต้อง load และ store → มีคำสั่งต้องรันมากขึ้น
  • compiler ต้องใช้ register เก็บตัวแปรให้มากที่สุด
    • เก็บลง memory เฉพาะตัวแปรที่ใช้ไม่บ่อย
    • Register optimization สำคัญมาก!

12.5 Immediate Operands

  • ค่าคงที่ระบุในคำสั่งเลย: addi x22, x22, 4
  • Make the common case fast (หนึ่งใน Great Ideas)
    • ค่าคงที่ขนาดเล็กพบบ่อย
    • immediate operand ไม่ต้องโหลดค่าจาก memory

13. RISC-V: Numbers

  • Unsigned Binary Integers: range 0 ถึง +2ⁿ − 1
  • 2s-Complement Signed Integers: range −2ⁿ⁻¹ ถึง +2ⁿ⁻¹ − 1
  • Signed Negation: Complement and add 1
    • ตัวอย่าง negate +2: +2 = 0000 0000 … 0010₂ → −2 = 1111 1111 … 1101₂ + 1 = 1111 1111 … 1110₂
  • Sign Extension (ขยายจำนวนบิตโดยรักษาค่า): ใน RISC-V instruction set
    • lb: sign-extend byte ที่โหลดมา (คัดลอก sign bit ไปเติมด้านซ้าย)
    • lbu: zero-extend byte ที่โหลดมา (เติม 0)

💡 sign extension: −2 แบบ 8 บิต = 1111 1110 → แบบ 16 บิต = 1111 1111 1111 1110 (เติม 1 ตาม sign bit) (ตัวอย่างเสริม)

14.1 หลักการ

    • เข้ารหัสเป็น instruction word ขนาด 32 บิต
    • มี format จำนวนน้อย เข้ารหัส operation code (opcode), หมายเลข register, …

14.2 R-format Instructions

14.4 I-format Instructions

12 bits 5 bits 3 bits 5 bits 7 bits
  • ใช้กับ immediate arithmetic และ load instructions
    • rs1: source หรือ base address register number

      • 2s-complement, sign extended
  • Design Principle 3: Good design demands good compromises
    • format ต่างกันทำให้ decode ซับซ้อน แต่ ทำให้ทุกคำสั่งยาว 32 บิตเท่ากัน
    • ทำให้ format คล้ายกันมากที่สุด

14.5 S-format Instructions

imm[11:5] rs2 rs1 funct3 imm[4:0] opcode
7 bits 5 bits 5 bits 3 bits 5 bits 7 bits
  • immediate format แบบต่างออกไปสำหรับ store instructions
    • rs1: base address register number
    • rs2: source operand register number
    • immediate: offset ที่บวกกับ base address
      • แยก immediate เป็น 2 ส่วน เพื่อให้ rs1 และ rs2 อยู่ตำแหน่งเดิมเสมอ

💡 ทำไม S-format ต้องแยก immediate? store ไม่มี rd (ไม่มีผลลัพธ์ลง register) แต่ต้องมี rs2 จึงเอาช่อง rd มาใส่ immediate ส่วนล่างแทน ทำให้ rs1, rs2 อยู่ที่เดิมเหมือน R-format → decode ง่าย

16. Conditional Operations ⭐

16.1 Branch

  • กระโดดไปคำสั่งที่มี label ถ้าเงื่อนไขจริง ไม่งั้นทำต่อตามลำดับ
  • beq rs1, rs2, L1 — ถ้า rs1 == rs2 กระโดดไป L1
  • bne rs1, rs2, L1 — ถ้า rs1 != rs2 กระโดดไป L1

16.2 Compiling If Statements

if (i==j) f = g+h;
else f = g-h;

f, g, … อยู่ใน x19, x20, …

      bne x22, x23, Else     // ถ้า i != j ไป Else
      add x19, x20, x21      // f = g + h
      beq x0, x0, Exit       // unconditional (0 == 0 เสมอ)
Else: sub x19, x20, x21      // f = g - h
Exit: …                      // Assembler calculates addresses

💡 เทคนิค: ทดสอบเงื่อนไขกลับด้าน (bne แทน ==) เพื่อข้ามส่วน then / beq x0,x0 = กระโดดแน่นอน

16.3 Compiling Loop Statements

while (save[i] == k) i += 1;

i ใน x22, k ใน x24, address ของ save ใน x25

Loop: slli x10, x22, 3     // x10 = i * 8
      add  x10, x10, x25   // x10 = address ของ save[i]
      ld   x9, 0(x10)      // x9 = save[i]
      bne  x9, x24, Exit   // ถ้า save[i] != k ออก
      addi x22, x22, 1     // i += 1
      beq  x0, x0, Loop    // วนกลับ
Exit: …

16.4 Basic Blocks

  • Basic block = ลำดับคำสั่งที่
    • ไม่มี branch ฝังอยู่ (ยกเว้นตอนท้าย)
    • ไม่มี branch target (ยกเว้นตอนต้น)
  • compiler ใช้หา basic block เพื่อ optimize
  • processor ขั้นสูงเร่งการทำงานของ basic block ได้

16.5 More Conditional Operations

  • blt rs1, rs2, L1 — ถ้า rs1 < rs2 กระโดด
  • bge rs1, rs2, L1 — ถ้า rs1 >= rs2 กระโดด
  • ตัวอย่าง: if (a > b) a += 1; (a ใน x22, b ใน x23)
      bge  x23, x22, Exit   // branch if b >= a
      addi x22, x22, 1
Exit:

16.6 Signed vs Unsigned

  • Signed comparison: blt, bge
  • Unsigned comparison: bltu, bgeu
  • ตัวอย่าง:
    • x22 = 1111 1111 1111 1111 1111 1111 1111 1111
    • x23 = 0000 0000 0000 0000 0000 0000 0000 0001

    • x22 > x23 // unsigned → +4,294,967,295 > +1

17. Procedure Calling ⭐⭐

17.1 ขั้นตอนเรียก procedure (6 ขั้น)

  1. วาง parameters ใน registers x10 ถึง x17
  2. ส่งการควบคุมไปที่ procedure
  3. จองพื้นที่เก็บข้อมูล สำหรับ procedure
  4. ทำงานของ procedure
  5. วางผลลัพธ์ใน register ให้ caller
  6. กลับไปจุดที่เรียก (address อยู่ใน x1)

17.2 Procedure Call Instructions

  • Procedure call: jump and link
    • jal x1, ProcedureLabel
    • address ของคำสั่งถัดไปถูกเก็บใน x1
    • กระโดดไป target address
  • Procedure return: jump and link register
    • jalr x0, 0(x1)
    • เหมือน jal แต่ กระโดดไป 0 + address ใน x1
    • ใช้ x0 เป็น rd (x0 เปลี่ยนค่าไม่ได้ จึงเท่ากับทิ้ง return address)
    • ใช้ทำ computed jumps ได้ด้วย เช่น case/switch statements

17.3 Leaf Procedure Example

Leaf procedure = ฟังก์ชันที่ไม่มีการ call เรียกออกไปหาฟังก์ชันอื่น

long long int leaf_example (long long int g, long long int h,
                            long long int i, long long int j) {
    long long int f;
    f = (g + h) - (i + j);
    return f;
}
  • Arguments g, …, j ใน x10, …, x13
  • f ใน x20
  • temporaries x5, x6
  • ต้องเก็บ x5, x6, x20 ลง stack
leaf_example:
    addi sp, sp, -24     // จองที่ stack 3 × 8 bytes
    sd   x5, 16(sp)      // Save x5, x6, x20 on stack
    sd   x6, 8(sp)
    sd   x20, 0(sp)
    add  x5, x10, x11    // x5 = g + h
    add  x6, x12, x13    // x6 = i + j
    sub  x20, x5, x6     // f = x5 - x6
    addi x10, x20, 0     // copy f to return register
    ld   x20, 0(sp)      // Restore x5, x6, x20 from stack
    ld   x6, 8(sp)
    ld   x5, 16(sp)
    addi sp, sp, 24      // คืนพื้นที่ stack
    jalr x0, 0(x1)       // Return to caller

(สไลด์พิมพ์บรรทัดที่ 6 เป็น add x6,x12,x1 — ที่ถูกคือ x13 = j)

17.4 Local Data on the Stack

  • (a) ก่อนเรียก: SP ชี้ตำแหน่งเดิม
  • (b) ระหว่างรัน: SP ลดลง 24 มีช่อง Contents of register x5, x6, x20
  • (c) หลังคืน: SP กลับที่เดิม

17.5 Register Usage

17.6 Non-Leaf Procedures

  • สำหรับ nested call caller ต้อง save ลง stack:

17.7 Non-Leaf Procedure Example: Factorial ⭐

long long int fact (long long int n) {
    if (n < 1) return 1;          // สไลด์พิมพ์ return f;
    else return n * fact(n - 1);
}

Argument n ใน x10 / Result ใน x10

fact:
    addi sp, sp, -16     // Save return address and n on stack
    sd   x1, 8(sp)
    sd   x10, 0(sp)
    addi x5, x10, -1     // x5 = n - 1
    bge  x5, x0, L1      // if n >= 1, go to L1
    addi x10, x0, 1      // Else, set return value to 1
    addi sp, sp, 16      // Pop stack, don't bother restoring values
    jalr x0, 0(x1)       // Return
L1: addi x10, x10, -1    // n = n - 1
    jal  x1, fact        // call fact(n-1)
    addi x6, x10, 0      // move result of fact(n-1) to x6
    ld   x10, 0(sp)      // Restore caller's n
    ld   x1, 8(sp)       // Restore caller's return address
    addi sp, sp, 16      // Pop stack
    mul  x10, x10, x6    // return n * fact(n-1)
    jalr x0, 0(x1)       // return

💡 ทำไมต้อง save x1? เพราะ jal x1, fact จะเขียนทับ x1 ด้วย return address ใหม่ ถ้าไม่เก็บไว้ ตัวเองจะกลับไปหาคนเรียกไม่ได้ ทำไมต้อง save x10 (n)? เพราะหลังเรียก fact(n−1) ยังต้องใช้ n มาคูณ แต่ x10 ถูกเปลี่ยนไปแล้ว

lui  x19, 976       // 0x003D0  → x19 = 0000 0000 0011 1101 0000 | 0000 0000 0000

(สไลด์เขียน addi 128 แต่ค่า 0x500 = 1280; ส่วนล่าง 0101 0000 0000 ตามภาพคือ 0x500)

20.2 Branch Addressing

  • branch ระบุ opcode, register 2 ตัว, target address
  • branch target ส่วนใหญ่อยู่ใกล้ (ไปข้างหน้าหรือถอยหลัง)
  • SB format:
imm[12] imm[10:5] rs2 rs1 funct3 imm[4:1] imm[11] opcode
  • PC-relative addressing: Target address = PC + immediate × 2

20.3 Jump Addressing

  • jal ใช้ immediate 20 บิต เพื่อกระโดดได้ไกลกว่า
  • UJ format:
imm[20] imm[10:1] imm[11] imm[19:12] rd opcode
5 bits 7 bits
  • กระโดดไกลมาก เช่น ไป absolute address 32 บิต:
    • lui: โหลด address[31:12] ลง temp register
    • jalr: บวก address[11:0] แล้วกระโดดไป target

20.4 RISC-V Addressing Summary

21. Synchronization

21.1 ปัญหา

  • 2 processors ใช้ memory ร่วมกัน: P1 เขียน แล้ว P2 อ่าน
  • Data race ถ้า P1 และ P2 ไม่ synchronize → ผลลัพธ์ขึ้นกับลำดับการเข้าถึง
  • ต้องมี hardware support:
    • Atomic read/write memory operation — ไม่มีใครเข้าถึงตำแหน่งนั้นได้ระหว่างอ่านกับเขียน
    • เป็น คำสั่งเดียว ได้ เช่น atomic swap ของ register ↔ memory
    • หรือ คู่คำสั่งแบบ atomic

21.2 Synchronization in RISC-V

  • Load reserved: lr.d rd, (rs1)
    • โหลดจาก address ใน rs1 ลง rd
    • จอง (reservation) address นั้นไว้
  • Store conditional: sc.d rd, (rs1), rs2
    • เก็บค่าจาก rs2 ไปที่ address ใน rs1
    • สำเร็จถ้าตำแหน่งนั้นไม่ถูกเปลี่ยนตั้งแต่ lr.d → คืน 0 ใน rd
    • ล้มเหลวถ้าถูกเปลี่ยน → คืน ค่าไม่ใช่ศูนย์ ใน rd

Example 1: atomic swap (test/set lock variable)

again: lr.d x10, (x20)
       sc.d x11, (x20), x23   // x11 = status
       bne  x11, x0, again    // branch if store failed
       addi x23, x10, 0       // x23 = loaded value

Example 2: lock

       addi x12, x0, 1        // copy locked value
again: lr.d x10, (x20)        // read lock
       bne  x10, x0, again    // check if it is 0 yet
       sc.d x11, (x20), x12   // attempt to store
       bne  x11, x0, again    // branch if fails
Unlock:
       sd   x0, 0(x20)        // free lock

💡 เชื่อมกับครึ่ง OS หัวข้อ Synchronization: lock ต้องอาศัยคำสั่งระดับ hardware ที่ atomic แบบนี้

22. Translation and Startup

22.1 ภาพรวม

C program → Compiler → Assembly language program → Assembler → Object (machine language module) + Object (library routine) → Linker → Executable → Loader → Memory

  • compiler หลายตัวสร้าง object module ได้โดยตรง
  • Static linking: รวม library เข้า executable ตอน link

22.2 Producing an Object Module

  • Assembler (หรือ compiler) แปลโปรแกรมเป็นคำสั่งเครื่อง
  • ให้ข้อมูลสำหรับประกอบโปรแกรมสมบูรณ์จากชิ้นส่วน:
ส่วน เก็บอะไร
Header อธิบายเนื้อหาของ object module
Text segment คำสั่งที่แปลแล้ว
Static data segment ข้อมูลที่จองตลอดอายุโปรแกรม
Relocation info สำหรับเนื้อหาที่ขึ้นกับตำแหน่ง absolute ของโปรแกรมที่โหลด
Symbol table global definitions และ external references
Debug info เชื่อมกับ source code

22.3 Linking Object Modules

  • สร้าง executable image
    1. รวม segments
    2. Resolve labels (หา address จริง)
    3. Patch การอ้างอิงที่ขึ้นกับตำแหน่งและ external refs
  • อาจปล่อยการขึ้นกับตำแหน่งไว้ให้ relocating loader แก้
    • แต่ถ้ามี virtual memory ไม่จำเป็น
    • โปรแกรม โหลดที่ตำแหน่ง absolute ใน virtual memory space ได้

22.4 Loading a Program

โหลดจาก image file บน disk เข้า memory:

  1. อ่าน header หาขนาด segment
  2. สร้าง virtual address space
  3. คัดลอก text และ initialized data ลง memory (หรือตั้ง page table entries ให้ fault เข้ามาทีหลัง)
  4. ตั้ง arguments บน stack
  5. ตั้งค่า registers (รวม sp, fp, gp)
  6. กระโดดไป startup routine
    • คัดลอก arguments ไป x10, … แล้ว เรียก main
    • เมื่อ main return ทำ exit syscall

💡 เชื่อมกับ Lecture 2 (OS): นี่คือขั้น "process creation" ในมุมของ loader

22.5 Dynamic Linking

  • link/load library procedure เฉพาะตอนถูกเรียก
  • ต้องให้โค้ด procedure relocatable ได้
  • หลีกเลี่ยง image บวม จาก static linking ของ library ทั้งหมดที่ถูกอ้างถึง
  • ได้ library เวอร์ชันใหม่อัตโนมัติ

22.6 Lazy Linkage

  • (a) First call to DLL routine: โปรแกรมกระโดดผ่าน Indirection table → Stub (Loads routine ID, Jump to linker/loader) → Linker/loader code (Dynamic linker/loader, Remap DLL routine) → Dynamically mapped code (DLL routine)
  • (b) Subsequent calls: indirection table ถูกแก้ให้ชี้ไป DLL routine โดยตรงแล้ว ไม่ต้องผ่าน linker อีก

22.7 Starting Java Applications

  • Java program → Compiler → Class files (Java bytecodes)
  • Java bytecodes = ชุดคำสั่งพกพาได้แบบง่ายสำหรับ JVM
  • Java Virtual Machine ใช้ Class files + Java library routines (machine language) → แปลความ (interprets) bytecodes
  • Just In Time (JIT) compiler: คอมไพล์ bytecodes ของ method ที่ "hot" (ถูกเรียกบ่อย) เป็น native code ของเครื่อง → Compiled Java methods (machine language)

23. C Sort Example

23.1 Swap Procedure (leaf)

void swap(long long int v[], long long int k) {
    long long int temp;
    temp = v[k];
    v[k] = v[k+1];
    v[k+1] = temp;
}

v ใน x10, k ใน x11, temp ใน x5

swap:
    slli x6, x11, 3     // reg x6 = k * 8
    add  x6, x10, x6    // reg x6 = v + (k * 8)
    ld   x5, 0(x6)      // reg x5 (temp) = v[k]
    ld   x7, 8(x6)      // reg x7 = v[k + 1]
    sd   x7, 0(x6)      // v[k] = reg x7
    sd   x5, 8(x6)      // v[k+1] = reg x5 (temp)
    jalr x0, 0(x1)      // return to calling routine

23.2 Sort Procedure in C (non-leaf, เรียก swap)

void sort (long long int v[], size_t n) {
    size_t i, j;
    for (i = 0; i < n; i += 1) {
        for (j = i – 1; j >= 0 && v[j] > v[j + 1]; j -= 1) {
            swap(v,j);
        }
    }
}

v ใน x10, n ใน x11, i ใน x19, j ใน x20

23.3 Outer Loop

        li   x19, 0            // i = 0
for1tst:
        bge  x19, x11, exit1   // go to exit1 if x19 ≥ x11 (i ≥ n)
        (body of outer for-loop)
        addi x19, x19, 1       // i += 1
        j    for1tst           // branch to test of outer loop
exit1:

23.4 Inner Loop

        addi x20, x19, -1      // j = i − 1
for2tst:
        blt  x20, x0, exit2    // go to exit2 if x20 < 0 (j < 0)
        slli x5, x20, 3        // reg x5 = j * 8
        add  x5, x10, x5       // reg x5 = v + (j * 8)
        ld   x6, 0(x5)         // reg x6 = v[j]
        ld   x7, 8(x5)         // reg x7 = v[j + 1]
        ble  x6, x7, exit2     // go to exit2 if x6 ≤ x7
        mv   x21, x10          // copy parameter x10 into x21
        mv   x22, x11          // copy parameter x11 into x22
        mv   x10, x21          // first swap parameter is v
        mv   x11, x20          // second swap parameter is j
        jal  x1, swap          // call swap
        addi x20, x20, -1      // j –= 1
        j    for2tst           // branch to test of inner loop
exit2:

💡 ทำไมต้องย้าย x10, x11 ไปเก็บใน x21, x22? เพราะต้องส่งค่าใหม่ให้ swap ทาง x10, x11 แต่ sort ยังต้องใช้ v และ n เดิมต่อ จึงเก็บสำเนาไว้ใน saved registers

23.5 Preserving Registers

// Preserve saved registers:
    addi sp, sp, -40   // make room on stack for 5 regs
    sd   x1, 32(sp)    // save x1 on stack
    sd   x22, 24(sp)   // save x22 on stack
    sd   x21, 16(sp)   // save x21 on stack
    sd   x20, 8(sp)    // save x20 on stack
    sd   x19, 0(sp)    // save x19 on stack

// Restore saved registers:
exit1:
    ld   x19, 0(sp)    // restore x19 from stack
    ld   x20, 8(sp)    // restore x20 from stack
    ld   x21, 16(sp)   // restore x21 from stack
    ld   x22, 24(sp)   // restore x22 from stack
    ld   x1, 32(sp)    // restore x1 from stack
    addi sp, sp, 40    // restore stack pointer
    jalr x0, 0(x1)

(สไลด์พิมพ์ส่วน restore เป็น sd — การ restore ที่ถูกต้องต้องใช้ ld)

25. Arrays vs Pointers

25.1 หลักการ

  • Array indexing ต้อง: คูณ index ด้วยขนาด element + บวกกับ base address ของ array
  • Pointers ตรงกับ memory address โดยตรง → หลีกเลี่ยงความซับซ้อนของ indexing

25.2 Example: Clearing an Array

clear1 — ใช้ array index clear2 — ใช้ pointer
for (i = 0; i < size; i += 1) array[i] = 0; for (p = &array[0]; p < &array[size]; p = p + 1) *p = 0; 
// clear1
        li   x5, 0          // i = 0
loop1:  slli x6, x5, 3      // x6 = i * 8
        add  x7, x10, x6    // x7 = address of array[i]
        sd   x0, 0(x7)      // array[i] = 0
        addi x5, x5, 1      // i = i + 1
        blt  x5, x11, loop1 // if (i<size) go to loop1

// clear2
        mv   x5, x10        // p = address of array[0]
        slli x6, x11, 3     // x6 = size * 8
        add  x7, x10, x6    // x7 = address of array[size]
loop2:  sd   x0, 0(x5)      // Memory[p] = 0
        addi x5, x5, 8      // p = p + 8
        bltu x5, x7, loop2  // if (p<&array[size]) go to loop2

25.3 Comparison of Array vs Pointer

  • การคูณถูก "strength reduced" เป็น shift
  • เวอร์ชัน array ต้องมี shift อยู่ในลูป (เป็นส่วนของการคำนวณ index ทุกรอบที่ i เพิ่ม) เทียบกับการเพิ่ม pointer ตรง ๆ
  • compiler ทำได้ผลเท่ากับการใช้ pointer เอง ด้วย induction variable elimination
  • ควรเขียนโปรแกรมให้อ่านง่ายและปลอดภัยกว่า (ปล่อยให้ compiler optimize)

26. MIPS, Other RISC-V Instructions, Extensions

26.1 MIPS Instructions

  • MIPS: รุ่นก่อนเชิงพาณิชย์ของ RISC-V
  • ชุดคำสั่งพื้นฐานคล้ายกัน:
    • คำสั่ง 32 บิต
    • general purpose registers 32 ตัว, register 0 เป็น 0 เสมอ
    • floating-point registers 32 ตัว
    • เข้าถึง memory ด้วย load/store เท่านั้น
    • addressing mode สม่ำเสมอ สำหรับข้อมูลทุกขนาด
  • ต่างกันที่ conditional branch สำหรับ <, <=, >, >=
    • RISC-V: blt, bge, bltu, bgeu
    • MIPS: slt, sltu (set less than ได้ผล 0 หรือ 1) แล้วใช้ beq, bne ต่อ

  • 1's complement: กลับบิต, −127 ถึง +127, ศูนย์ 2 แบบ, end-around carry (6 + (−3) บน 3 บิต = 011)
  • 2's complement: กลับบิต + 1 (short-cut: คงบิตจนถึง 1 ตัวแรกจากขวา แล้วกลับที่เหลือ), −128 ถึง +127, ศูนย์เดียว, ทิ้ง carry (6 + (−5) = 0001)
  • ตาราง 8 บิต: 1000 0000 = −0 / −127 / −128; 1111 1111 = −127 / −0 / −1
  • Bias-127: ค่า = unsigned − 127, ช่วง −127 ถึง +128
  • IEEE single: 1 + 8 + 23, N = (−1)ˢ × 1.m × 2^(E−127), E = 1–254, 0/255 สงวน, e = −126 ถึง +127
  • IEEE double: 1 + 11 + 52
  • 17.15 → sign 0, E = 131 = 1000 0011, mantissa 0001 0010 0110…
  • Fraction → binary: คูณ 2 เก็บเลขหน้าจุด (0.8125 = .1101)
  • ASCII: 7 บิต 128 ตัว + parity; '0' ≠ 0; ตัวใหญ่-เล็กต่าง 0x20 (A = 65, a = 97)

RISC-V

  • Design principles 3 ข้อ และ Great Idea "make the common case fast" (immediate)
  • ตาราง register x0–x31 (x0=0, x1=ra, x2=sp, x10–x17 args, temporaries/saved)
  • Memory: byte addressed, little endian, offset = index × 8 (A[8] → 64(x22))
  • Signed range: −2ⁿ⁻¹ ถึง 2ⁿ⁻¹ − 1; negation = complement + 1; lb sign-extend, lbu zero-extend
  • R-format: funct7|rs2|rs1|funct3|rd|opcode (7,5,5,3,5,7); add x9,x20,x21 = 015A04B3₁₆
  • I-format: imm(12)|rs1|funct3|rd|opcode; S-format: imm[11:5]|rs2|rs1|funct3|imm[4:0]|opcode
  • Logical: slli (×2ⁱ), srli (÷2ⁱ unsigned), and (mask), or (include), xor (NOT กับ 1 ทั้งหมด)
  • If/while แปลงด้วย bne/beq; beq x0,x0 = unconditional
  • Signed vs unsigned compare: 111…1 เป็น −1 (signed) แต่เป็น 4,294,967,295 (unsigned)
  • Procedure 6 ขั้น, jal x1 / jalr x0,0(x1), leaf vs non-leaf (save x1 และ argument), stack โตลงล่าง
  • Memory layout: reserved, text, static data (x3 gp), heap, stack
  • Formats 6 แบบ และ addressing 4 แบบ; branch target = PC + imm × 2
  • lr.d / sc.d สำหรับ atomic operations
  • Translation: compiler → assembler → linker → loader; object module 6 ส่วน; linking 3 ขั้น; loading 6 ขั้น; dynamic linking และ lazy linkage; Java JIT
  • Lessons: IC และ CPI ดูแยกไม่ได้, optimization ขึ้นกับ algorithm, JIT เร็วกว่า interpreter มาก, nothing can fix a dumb algorithm
  • Array vs pointer: strength reduction, induction variable elimination → เขียนให้อ่านง่ายดีกว่า
  • MIPS vs RISC-V: slt+beq vs blt/bge; Extensions M, A, F, D, C
