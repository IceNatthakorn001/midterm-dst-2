⭐ Process

  • Process = running program — abstraction พื้นฐานที่สุดของ OS; ผู้ใช้ไม่ต้องสนใจว่า CPU ว่างไหม
  • เปรียบ: Recipe = Program, Ingredient = Input, Baker = OS, Oven = Resources, Baking = Process
  • Program = คำสั่ง + ข้อมูลบน disk → loading เข้า address space ใน memory
  • Address space (0 → max): text (code) → data (global) → heap (dynamic, โตขึ้น) … stack (return addr, parameters, local vars; โตลง)
  • Machine state: memory, registers (general, PC, SP, FP), I/O (open files)
  • Scheduler (ส่วนของ OS) เลือก thread จากตาราง pointers + priority → execute; มี context switch, preemption
  • ดู process: Task Manager, Activity Monitor, top (Linux)

API / Creation

  • API: Create, Destroy (kill), Wait, Misc control (suspend/resume), Status
  • ⭐ Creation: (1) load code + static data จาก disk (2) init I/O: stdin, stdout, stderr (3) ตั้งคำสั่งแรก (main) (4) โอน CPU

⭐ States

  • Running (CPU ทำอยู่) | Ready (พร้อมแต่ OS ยังไม่เลือก) | Blocked (รอ event มัก I/O)
  • Running → Ready: descheduled | Ready → Running: scheduled | Running → Blocked: I/O initiate | Blocked → Ready: I/O done
  • ตัวอย่าง: P0 run t1–3 → I/O → blocked t4–6 (P1 run) → ready t7–8 → run t9–10

⭐ PCB

  • OS เก็บข้อมูล process เป็น struct (C) = Process Control Block
  • Process table: PID → PCB (PC, registers, state, priority, address space, open files, flags)
  • ข้อมูล: process mgmt (regs, PC, PSW, SP, state, priority, PID, parent, signals, CPU time …) | memory mgmt (pointer to text/data/stack) | file mgmt (root/working dir, file descriptors, UID, GID)
  • xv6 struct proc: mem, sz, kstack, state, pid, parent, chan, killed, ofile, cwd, context, tf | states: UNUSED, EMBRYO, SLEEPING, RUNNABLE, RUNNING, ZOMBIE

⭐ UNIX API

fork() wait() exec()
ทำ สร้าง child = สำเนา parent รอ process อื่น (parent รอ child) เปลี่ยนเป็นโปรแกรมอื่น
process ใหม่? ใช่ — ไม่
return child PID ให้ parent, 0 ให้ child สำเร็จไม่ return
  • child มี address space + PCB ของตัวเอง
  • exec 6 แบบ: execl, execv, execlp, execvp, execle, execvpe
  • ตัวอย่าง: parent 2326 → child 2327 (getppid = 2326)

⭐ System calls

  • Direct execution = รันตรงบน CPU แต่ limited (กัน user เข้าถึงทรัพยากรระบบ)
  • Dual mode: user mode (จำกัด) | kernel mode (privileged) → ใช้ system call
  • ตัวอย่าง: open, read, write, close, kill, signal, fork, wait, exec, getpid, link, unlink, mount, chdir, setuid, getuid, chown
  • Library ห่อ system call: open/fopen, close/fclose, read/fread·scanf·gets…, write/fwrite·printf·puts…, lseek/fseek
  • Trap = สัญญาณ software ที่ตั้งใจ สลับ user → kernel mode
  • read(fd, nbytes, buffer): push params → call read → put code ใน register → trap to kernel → dispatch → sys call handler → return → increment SP
  • Boot: trap table บอกที่อยู่ trap handlers
  • Call: trap (เพิ่ม privilege) → kernel stack เก็บข้อมูลผู้เรียก → return-from-trap (ลด privilege)

⭐ Context switching

  • OS ได้ CPU คืนเมื่อ: yield, blocked (I/O), รอ child, terminate — ถ้า infinite loop? → timer interrupt (ทุกไม่กี่ ms; boot ตั้ง handler + start timer)
  • Context switch = save regs ของ process ที่รัน + restore regs ของอีกตัว
  • Detail: timer interrupt → HW save regs(A) → k-stack(A) → kernel mode → trap handler → OS switch(): save regs(A) → proc_t(A), restore regs(B) ← proc_t(B), switch to k-stack(B) → return-from-trap → HW restore regs(B) ← k-stack(B) → user mode → B's PC
