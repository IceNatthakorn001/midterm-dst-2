3 คำถามใหญ่ของบทนี้: (1) Process API หน้าตาเป็นอย่างไร (2) process เข้าถึงทรัพยากรได้อย่างไร (3) OS สลับระหว่าง process ได้อย่างไร

1. Process คืออะไร ⭐

  • รันโปรแกรมด้วยมือเองยาก (โหลดโค้ด จอง memory ตั้ง register) + Multiprogramming และ Virtualization ต้องการหน่วยที่ OS จัดการได้ → Process = abstraction ที่พื้นฐานที่สุดที่ OS ให้ = โปรแกรมที่กำลังรัน (a running program)
  • ผู้ใช้รันหลายโปรแกรมได้โดยไม่ต้องสนใจว่า CPU ว่างหรือไม่

Program vs Process (อุปมาอบเค้ก):

การอบขนม คอมพิวเตอร์
สูตร (Recipe) Program
วัตถุดิบ (Ingredient) Input
คนอบ (Baker) OS
เตาอบ (Oven) Resources
การอบ (Baking) Process

⚠️ Program = static (ลำดับคำสั่ง+ข้อมูลบน disk) / Process = dynamic — โปรแกรมเดียวรันได้หลาย process

2. Address Space & Machine State

ส่วน ตำแหน่ง เก็บอะไร
stack บนสุด โตลงล่าง return address, parameter ของ function call, local variables
(ช่องว่าง) ตรงกลาง ให้ stack กับ heap โตเข้าหากัน
heap โตขึ้นบน memory ที่จองแบบ dynamic (malloc)
data global variables
text ล่างสุด (address 0) instructions (code)

💡 จำจากล่างขึ้นบน: T-D-H-S = Text → Data → Heap → Stack

Machine State = ส่วนของเครื่องที่เกี่ยวข้องกับการรันโปรแกรม:

  • Instructions และ data ใน memory (address space)
  • Registers: general purpose (eax, ebx…), program counter (PC) (ชี้คำสั่งถัดไป), stack pointer (ยอดของ stack), frame pointer (frame ของ function ปัจจุบัน)
  • I/O devices เช่น ไฟล์ที่เปิดอยู่

💡 machine state = "ภาพถ่าย" ของการทำงาน ณ ขณะหนึ่ง → เก็บไว้ได้ = หยุดแล้วกลับมาทำต่อได้ (หัวใจของ context switch)

3. Process Execution

  1. Program (Instruction #1…#N) เก็บบน Disk → 2. OS instantiate เป็น Process ใน RAM → 3. OS เก็บ ตารางของ thread + priority (high/med/low) และ pointers → 4. Scheduler เลือกว่าใครรัน → context switch → execute บน CPU → 5. อาจเกิด preemption (ถูกแย่ง CPU กลางคัน) แล้ววนเลือกใหม่

ดู process จริง: Windows Task Manager / macOS Activity Monitor / Linux คำสั่ง top (tasks: total, running, sleeping, stopped, zombie; PID, USER, PR, NI, VIRT, RES, SHR, S, %CPU, %MEM, TIME+, COMMAND)

4. Process API & Creation

API ทำอะไร
Create เริ่มโปรแกรม → สร้าง process
Destroy process ส่วนใหญ่จบเอง แต่ สั่ง kill ได้
Wait process รอ process อื่น
Miscellaneous Control suspend / resume
Status ดู run time หรือ state

Process Creation 4 ขั้น ⭐:

  1. OS โหลด code และ static data จาก disk เข้า memory (จัดเตรียม code, data, heap, stack)
  2. OS ตั้งค่า I/O เริ่มต้น — Unix มี 3 ตัว: stdin, stdout, stderr
  3. OS ตั้งคำสั่งแรกที่จะรัน เช่น main()
  4. OS ส่งการควบคุม CPU ให้ process

5. Process States ⭐⭐

State ความหมาย
Running CPU กำลังรันคำสั่งของ process นี้
Ready พร้อมรัน แต่ OS ยังไม่เลือกให้ใช้ CPU
Blocked รอ event ส่วนใหญ่คือรอ I/O request ให้เสร็จ
จาก → ไป เกิดเมื่อ
Ready → Running Scheduled
Running → Ready Descheduled
Running → Blocked I/O: initiate
Blocked → Ready I/O: done

⚠️ Blocked → Running ตรง ๆ ไม่ได้ ต้องกลับไป Ready ก่อน 💡 ร้านตัดผม: Running = กำลังนั่งตัด / Ready = นั่งรอคิว / Blocked = รอสีผมแห้ง (ต่อให้ช่างว่างก็ยังตัดต่อไม่ได้)

ตัวอย่างตาราง: t1–3 P₀ Running, P₁ Ready (t3: P₀ initiates I/O) → t4–6 P₀ Blocked, P₁ Running → t7 I/O done → P₀ Ready (ยังต้องรอ P₁) → t8 P₁ done → t9–10 P₀ Running จนจบ ใจความ: ตอน P₀ รอ I/O OS ไม่ปล่อย CPU ว่าง แต่ให้ P₁ รันแทน

6. Process Control Block (PCB) ⭐

  • OS ต้องติดตามข้อมูลหลายอย่างของ process (เช่น state เพื่อ schedule ได้ถูก) → เก็บเป็น struct เรียกว่า PCB
  • Process Table = แถวละ process มี PID + pointer ไปยัง PCB
  • PCB เก็บ: Program counter, Registers, State, Priority, Address space, Open files, Other flags
Process management Memory management File management
Registers, Program counter, Program status word, Stack pointer, Process state, Priority, Scheduling parameters, Process ID, Parent process, Process group, Signals, Time when process started, CPU time used, Children's CPU time, Time of next alarm Pointer to text segment, data segment, stack segment Root directory, Working directory, File descriptors, User ID, Group ID

ตัวอย่าง xv6 struct proc: char *mem / uint sz / char *kstack / enum proc_state state / int pid / struct proc *parent / void *chan / int killed / struct file *ofile[NOFILE] / struct inode *cwd / struct context context (eip=PC, esp=SP, ebx, ecx, edx, esi, edi, ebp — ใช้ตอน context switch) / struct trapframe *tf xv6 states (ละเอียดกว่า 3 state): UNUSED (ช่องว่าง), EMBRYO (กำลังสร้าง), SLEEPING (≈blocked), RUNNABLE (≈ready), RUNNING, ZOMBIE (จบแล้วแต่ parent ยังไม่เก็บผล)

7. UNIX Process API ⭐⭐

fork()

  • สร้าง process ใหม่ — ตัวที่เรียก = parent, ตัวที่ถูกสร้าง = child
  • ⚠️ child เริ่มต้นเป็นสำเนาเหมือน parent ทุกประการ!
  • ค่าที่คืน: คืน PID ของ child ให้ parent / คืน 0 ให้ child → จึงแยกทางได้ด้วย if (pid > 0) vs else
  • getpid() = PID ตัวเอง, getppid() = PID ของ parent
  • child มี address space และ PCB เป็นของตัวเอง (stack, heap, data, text แยก) → child แก้ตัวแปร ค่าใน parent ไม่เปลี่ยน
pid = fork();
if (pid > 0) { printf("parent PID=%d of child %d\n", getpid(), pid); wait(NULL); exit(0); }
else { printf("child PID=%d, parent=%d\n", getpid(), getppid()); exit(0); }

wait()

  • ทำให้ process รอ process อื่น — มีประโยชน์เมื่ออยากให้ parent รอ child จบก่อน (เช่นบังคับให้ child พิมพ์ก่อนเสมอ ไม่งั้นลำดับขึ้นกับ scheduler)
  • โจทย์นับ process: ทุก fork ทำให้จำนวน process เป็น 2 เท่า → fork 1 ครั้งก่อน loop + fork 2 ครั้งใน loop = 2 × 2 × 2 = 8 process (ทุก process ที่ fork ออกมารันโค้ดส่วนที่เหลือต่อด้วย)

exec()

  • เปลี่ยน process ให้กลายเป็นโปรแกรมอื่น
  • ⚠️ ไม่ได้สร้าง process ใหม่ (PID เดิม เนื้อในเปลี่ยน) | ⚠️ ถ้าเรียกสำเร็จ จะไม่ return กลับมา (โค้ดเดิมถูกแทนที่หมดแล้ว) → บรรทัดหลัง exec ไม่ถูกรัน
  • 6 รูปแบบ: execl, execv, execlp, execvp, execle, execvpe 💡 l = argument เป็น list, v = เป็น vector (array), p = ค้นใน PATH, e = ส่ง environment เอง
  • 💡 fork + exec = วิธีที่ shell รันคำสั่ง — shell fork ตัวเองเป็น child → child exec เป็นคำสั่งที่พิมพ์ → shell (parent) wait รอ

8. Limited Direct Execution & System Calls ⭐⭐

  • OS ให้ process รันตรงบน CPU (natively) เพื่อความเร็ว = "Direct Execution" แต่ OS + hardware ป้องกันไม่ให้ user process เข้าถึงทรัพยากรระบบโดยตรง → จึงเป็น "Limited" → process ขอทรัพยากรเพิ่มผ่าน system call

Dual Mode:

User mode Kernel mode
จำกัดสิทธิ์ (mode bit = 1) OS (kernel) รัน ทำ privileged operation ได้ (mode bit = 0)

ลำดับ: user process executing → calls system call → trap (mode bit = 0) → kernel execute system call → return (mode bit = 1) → return from system call 💡 ลูกค้าธนาคารเดินเข้าห้องนิรภัยเองไม่ได้ (user mode) ต้องยื่นคำขอที่เคาน์เตอร์ (system call) ให้พนักงานที่มีกุญแจ (kernel mode) ไปหยิบให้

ตัวอย่าง system call: open, read, write, close, kill, signal, fork, wait, exec, getpid, link, unlink, mount, chdir, setuid, getuid, chown Standard library เปิด system call ออกมาเป็น function ภาษา C → เรียกได้ด้วย procedure call ธรรมดา (printf("Greetings") → standard C library → write() system call)

System calls Library calls
open fopen
close fclose
read fread, getchar, scanf, fscanf, getc, fgetc, gets, fgets
write fwrite, putchar, **printf**, fprintf, putc, fputc, puts, fputs
lseek fseek

⚠️ printf ไม่ใช่ system call แต่เป็น library call ที่ข้างในเรียก write

ขั้นตอนของ read(fd, nbytes, buffer) — 11 ขั้น

Trap = สัญญาณซอฟต์แวร์ที่ตั้งใจสร้างโดยโปรแกรมผู้ใช้ เพื่อสลับ CPU จาก user mode ไป kernel mode

ขั้น ที่ไหน ทำอะไร
1–3 User program Push parameter ลง stack: nbytes, &buffer, fd
4 User program Call read (library procedure)
5 Library read ใส่รหัสของ read ลงใน register
6 Library Trap to the kernel
7 Kernel Dispatch — ดูรหัสแล้วเลือก handler จากตาราง
8 Kernel Sys call handler ทำงาน
9 Kernel → Library คืนการควบคุมกลับ user space
10 Library Return to caller
11 User program Increment SP (ล้าง parameter ออกจาก stack)

Limited Direct Execution Protocol

@ Boot (kernel mode): Trap table บอก hardware ว่า trap handler อยู่ที่ไหน สำหรับแต่ละ event (system call, keyboard interrupt) | Trap handlers = function พิเศษใน memory | hardware จำ address ของ syscall handler @ Run: Trap เข้า OS (raise privilege) → Kernel stack เก็บข้อมูลของ process ที่เรียก → return-from-trap = คำสั่งพิเศษที่ใช้กลับไปยัง process ที่เรียก (lower privilege)

OS (kernel mode) Hardware Program (user mode)
create entry for process list, allocate memory, load program, setup user stack with argv, fill kernel stack with reg/PC, return-from-trap
restore regs (from kernel stack), move to user mode, jump to main
Run main() … Call system call, trap into OS
save regs (to kernel stack), move to kernel mode, jump to trap handler
Handle trap: do work of syscall, return-from-trap
restore regs, move to user mode, jump to PC after trap
return from main, trap (via exit())
free memory of process, remove from process list

9. Context Switching ⭐⭐

เมื่อไหร่ OS จะได้ CPU คืน? process yields เอง / process ถูก block (รอ I/O) / process สร้าง child แล้วรอ / process terminated ⚠️ แต่ถ้า process วน infinite loop? ไม่ yield ไม่ block ไม่จบ → OS ไม่มีทางได้ CPU คืน → ต้องมี timer interrupt

Timer Interrupt: Timer device สร้าง interrupt ทุก ๆ ไม่กี่มิลลิวินาที → Interrupt handler ใน OS ทำงาน → OS ได้ CPU คืน ตอน boot: OS บอก hardware ว่าเมื่อ timer interrupt ให้รันโค้ดไหน + เริ่มจับเวลา (starts the timer)

Context switching = routine ของ OS ตอนสลับ process ที่กำลังรัน

  1. บันทึก context (registers) ของ process ที่กำลังรัน
  2. คืน context (registers) ของอีก process หนึ่ง (ค่า SP/PC ของ CPU ถูกเก็บลง Prog1 State → OS suspends Prog1 / ค่าจาก Prog2 State ถูกโหลดเข้า CPU → OS resumes Prog2)

ขั้นตอนละเอียด:

OS @ boot Hardware
initialize trap table remember addresses of syscall handler, timer handler
start interrupt timer start timer, interrupt CPU in X ms
OS @ run (kernel mode) Hardware Program (user mode)
Process A …
timer interrupt: save regs(A) → k-stack(A), move to kernel mode, jump to trap handler
Handle the trap: call switch() — save regs(A) → proc_t(A), restore regs(B) ← proc_t(B), switch to k-stack(B), return-from-trap (into B)
restore regs(B) ← k-stack(B), move to user mode, jump to B's PC
Process B …

⚠️ มีการเก็บ register 2 ครั้ง: ครั้งแรก hardware เก็บลง kernel stack ตอน interrupt / ครั้งที่สอง OS (switch()) เก็บลง PCB (proc_t) ตอนตัดสินใจสลับ

คู่ที่มักสับสน

คู่ ต่างกันที่
Program / Process สูตร (นิ่ง) / การทำตามสูตร (กำลังรัน)
Ready / Blocked รอ CPU / รอ event หรือ I/O
Stack / Heap local ชั่วคราว อัตโนมัติ / จองเองแบบ dynamic
fork() / exec() สร้าง process ใหม่ (สำเนา) / แทนที่โปรแกรมใน process เดิม
fork() return ให้ parent / child PID ของ child / 0
System call / Library call เข้า kernel จริง / function ใน library ที่อาจเรียก system call
User mode / Kernel mode จำกัดสิทธิ์ (bit 1) / สิทธิ์เต็ม (bit 0)
Trap / Timer interrupt โปรแกรมตั้งใจเรียกเอง / hardware ขัดจังหวะตามเวลา

แนวคิดที่ต้องอธิบายได้

  • ทำไมต้องมี dual mode: ถ้าให้ user process เข้าถึง hardware ตรง ๆ โปรแกรมหนึ่งอาจทำลายข้อมูลหรือ process อื่นได้
  • ทำไมต้องมี timer interrupt: ถ้า process วน infinite loop โดยไม่ yield/block OS จะไม่มีทางได้ CPU คืน
  • ทำไม child แก้ตัวแปรแล้ว parent ไม่เปลี่ยน: เพราะ child มี address space แยกเป็นของตัวเอง
  • ทำไมบรรทัดหลัง exec() ไม่ถูกรัน: เพราะโค้ดของ process ถูกแทนที่ด้วยโปรแกรมใหม่แล้ว
