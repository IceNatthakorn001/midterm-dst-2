2. Introduction

เป้าหมาย: ต่อคอมพิวเตอร์หลายเครื่องเข้าด้วยกันเพื่อประสิทธิภาพสูงขึ้น → ได้ scalability, availability, power efficiency

คำ ความหมาย
Task-level (process-level) parallelism throughput สูงสำหรับงานที่ไม่ขึ้นต่อกัน (หลายงานแยกกันรัน)
Parallel processing program โปรแกรมเดียวที่รันบนหลาย processor
Multicore microprocessors ชิปที่มีหลาย processor (core) ในตัว

Hardware/Software: hardware Serial = Pentium 4 / Parallel = quad-core Xeon e5345 | software Sequential = matrix multiplication / Concurrent = operating system

  • software sequential หรือ concurrent รันบน hardware serial หรือ parallel ก็ได้ทุกแบบ — ความท้าทายคือใช้ parallel hardware ให้คุ้ม
  • ⚠️ Concurrent ≠ Parallel: concurrent = software หลายงานดำเนินพร้อมกัน (รันบน CPU ตัวเดียวได้) / parallel = hardware ทำงานพร้อมกันได้จริง

หัวข้อ parallelism ที่ผ่านมาแล้ว: §2.11 Synchronization | §3.6 Subword Parallelism | §4.10 Advanced ILP (pipelining) | §5.10 Cache Coherence

3. Parallel Programming — ทำไมยาก ⭐

  • ปัญหาอยู่ที่ parallel software — ต้องได้ประสิทธิภาพเพิ่มขึ้นอย่างมีนัยสำคัญ ไม่งั้น ใช้ uniprocessor ที่เร็วกว่าเลยดีกว่า เพราะง่ายกว่า!
  • ความยาก 3 ข้อ: Partitioning (แบ่งงานให้เท่า ๆ กัน) | Coordination (จัดลำดับและประสานงาน) | Communications overhead (เวลาที่เสียไปกับการสื่อสาร)

5. Vector Processors & DAXPY

  • function units แบบ pipeline สูง ส่งข้อมูลเป็นสายระหว่าง vector registers กับ units (ดึงจาก memory เข้า register → เก็บผลกลับ memory) — ลด bandwidth ที่ใช้ fetch คำสั่งได้มาก
  • RISC-V vector extension: v0–v31 = register 32 ตัว × 64 elements (element ละ 64 บิต)
  • คำสั่ง: fld.v/fsd.v (load/store vector) | fadd.d.v (บวก vector ของ double) | fadd.d.vs (บวก scalar เข้ากับทุก element)

DAXPY = Double-precision A*X Plus Y — คำสั่ง linear algebra ใน library BLAS: y[i] = a*x[i] + y[i]

Conventional RISC-V Vector RISC-V
fld f0, a(x3) / addi x5, x19, 512 fld f0, a(x3)
loop: fld f1, 0(x19) fld.v v0, 0(x19)
fmul.d f1, f1, f0 fmul.d.vs v0, v0, f0
fld f2, 0(x20) fld.v v1, 0(x20)
fadd.d f2, f2, f1 fadd.d.v v1, v1, v0
fsd f2, 0(x20) fsd.v v1, 0(x20)
addi x19,x19,8 / addi x20,x20,8 / bltu x19,x5,loop —
วนลูป 512/8 = 64 รอบ, มี branch ทุกรอบ 6 คำสั่ง ไม่มีลูป ไม่มี branch

6. Vector vs Scalar / SIMD / Multimedia Extensions

ข้อดีของ vector architectures & compilers:

  • ทำให้เขียนโปรแกรม data-parallel ง่ายขึ้น
  • บอกชัดว่าไม่มี loop-carried dependences → hardware ตรวจสอบน้อยลง
  • รูปแบบการเข้าถึงสม่ำเสมอ → ได้ประโยชน์จาก interleaved และ burst memory
  • เลี่ยง control hazards เพราะไม่มีลูป
  • ใช้ได้กว้างกว่า media extensions แบบเฉพาะกิจ (MMX, SSE) และเข้ากับเทคโนโลยี compiler ได้ดีกว่า

SIMD ⭐: ทำงานกับ vector ของข้อมูลทีละ element พร้อมกัน (MMX, SSE ใน x86 — ข้อมูลหลายตัวอยู่ใน register กว้าง 128 บิต) | ทุก processor ทำคำสั่งเดียวกันในเวลาเดียวกัน แต่ใช้ data address ต่างกัน | ข้อดี: synchronization ง่าย + ใช้ hardware ควบคุมคำสั่งน้อยลง | เหมาะที่สุดกับงานที่ data-parallel สูง

Vector instructions Multimedia extensions (MMX, SSE)
ความกว้าง vector ปรับได้ (variable) คงที่ (fixed)
Strided access รองรับ ไม่รองรับ

vector units ผสม pipelined + arrayed functional units ได้ — ตัวอย่างมี 4 lanes แต่ละ lane มี FP add pipe และ FP mul pipe + vector registers + Vector load/store unit

7. Hardware Multithreading ⭐⭐

ทำหลาย thread พร้อมกัน: ทำสำเนา registers, PC ฯลฯ ต่อ thread + สลับระหว่าง thread ได้เร็ว

แบบ วิธีสลับ ข้อดี/ข้อเสีย
Fine-grain MT สลับ thread ทุก cycle ถ้า thread หนึ่ง stall thread อื่นยังทำงานต่อได้
Coarse-grain MT สลับเฉพาะตอน stall นาน (เช่น L2-cache miss) hardware ง่ายกว่า แต่ ซ่อน stall สั้น ๆ (data hazards) ไม่ได้
SMT (Simultaneous MT) หลาย thread ใช้ issue slots ร่วมกันใน cycle เดียว เต็มช่องที่สุด ใช้เวลาน้อยที่สุด

SMT: ใช้ใน multiple-issue dynamically scheduled processor — จัดคิวคำสั่งจากหลาย thread, คำสั่งจาก thread อิสระทำได้เมื่อ function unit ว่าง, ภายใน thread เดียวกันจัดการ dependency ด้วย scheduling และ register renaming ตัวอย่าง: Intel Pentium-4 HT (Hyper-Threading) — 2 threads, registers ถูกทำสำเนา แต่ function units และ caches ใช้ร่วมกัน อนาคต: เรื่องพลังงานทำให้ microarchitecture ต้องเรียบง่ายขึ้น → multithreading แบบที่ง่ายขึ้น | การสลับ thread อาจได้ผลดีที่สุดในการทนต่อ latency จาก cache miss | core ง่าย ๆ หลายตัวอาจแชร์ทรัพยากรได้มีประสิทธิภาพกว่า

8. Shared Memory Multiprocessors ⭐

SMP: hardware ให้ physical address space เดียวสำหรับทุก processor | ใช้ lock ในการ synchronize ตัวแปรที่แชร์กัน

UMA (uniform) NUMA (nonuniform)
เวลาเข้าถึง memory เท่ากัน ไม่ว่า processor ไหนเข้าถึง address ไหน ไม่เท่ากัน — memory ใกล้ processor ตัวไหน ตัวนั้นเข้าถึงเร็วกว่า

Sum Reduction ⭐ (บวกเลข 64,000 ตัว บน UMA 64 processor)

  • แต่ละ processor มี ID: 0 ≤ Pn ≤ 63 แบ่งให้ processor ละ 1000 ตัว
sum[Pn] = 0;
for (i = 1000*Pn; i < 1000*(Pn+1); i += 1) sum[Pn] += A[i];
  • Reduction: divide and conquer — processor ครึ่งหนึ่งบวกเป็นคู่ แล้วเหลือหนึ่งในสี่ … ต้อง synchronize ระหว่างแต่ละขั้น
half = 64;
do
  synch();
  if (half%2 != 0 && Pn == 0) sum[0] += sum[half-1];  /* half เป็นคี่ → P0 รับตัวที่เหลือ */
  half = half/2;
  if (Pn < half) sum[Pn] += sum[Pn+half];
while (half > 1);

ไล่: half = 32 (P0–P31) → 16 → 8 → 4 → 2 → 1 (P0 บวก sum[1]) = log₂64 = 6 ขั้น → sum[0] คือผลรวมทั้งหมด 💡 นี่คือตัวอย่างของ SPMD — ทุก processor รันโค้ดเดียวกัน แต่ใช้ Pn ตัดสินว่าตัวเองทำอะไร

9. GPUs

History: early video cards (frame buffer memory) → 3D graphics เดิมอยู่ในคอมระดับสูง (SGI) → Moore's Law ทำให้ถูกลง → การ์ด 3D สำหรับ PC และเครื่องเล่นเกม → GPU = processor เน้นงาน 3D graphics: vertex/pixel processing, shading, texture mapping, rasterization Graphics in the system: ยุคเก่า = CPU–Front Side Bus–North Bridge–PCI Bus–VGA Controller + Framebuffer Memory | Intel = North Bridge –x16 PCI-Express– GPU + GPU Memory | AMD = North Bridge อยู่ในตัว CPU, HyperTransport → Chipset → x16 PCI-Express → GPU 💡 GPU สมัยใหม่ มี memory ของตัวเอง และต่อผ่าน PCI-Express x16

GPU Architectures ⭐:

  • งานเป็น data-parallel สูง → GPU เป็น highly multithreaded → ใช้การสลับ thread ซ่อน latency ของ memory จึงพึ่ง multi-level caches น้อยกว่า | graphics memory กว้างและ bandwidth สูง
  • แนวโน้มไปสู่ GPGPU — ระบบ CPU/GPU แบบ heterogeneous (CPU รันโค้ด sequential, GPU รันโค้ด parallel)
  • APIs/ภาษา: DirectX, OpenGL, Cg (C for Graphics), HLSL, CUDA

NVIDIA Fermi: SIMD processor มี 16 SIMD lanes (Thread Processors) แต่ละ lane มี Reg (1K × 32) และ Load store unit + Address coalescing unit + Interconnection network + Local Memory 64 KiB → Global Memory

  • SIMD instruction ทำงานกับ thread กว้าง 32 elements ถูก schedule dynamic บน processor กว้าง 16 lanes ภายใน 2 cycles
  • register 32K × 32-bit กระจายใน lanes, 64 registers ต่อ thread context

GPU Memory Structures: CUDA Thread → Per-CUDA Thread Private Memory | Thread block → Per-Block Local Memory | Grid (รันเป็น Sequence) → GPU Memory ร่วมกัน + มี Inter-Grid Synchronization

Classifying GPUs ⭐: GPU ไม่เข้ากับโมเดล SIMD/MIMD ได้พอดี — conditional execution ใน thread ทำให้ดูเหมือน MIMD แต่ประสิทธิภาพลดลง ต้องเขียนโค้ดอย่างระมัดระวัง

Static (compile time) Dynamic (runtime)
Instruction-Level Parallelism VLIW Superscalar
Data-Level Parallelism SIMD or Vector Tesla Multiprocessor (GPU)

Multicore with SIMD vs GPU ⭐

10. Message Passing, Clusters, Grid

Message passing: แต่ละ processor มี physical address space ของตัวเอง (Processor → Cache → Memory ของใครของมัน) เชื่อมด้วย Interconnection Network — hardware ส่งและรับ message ระหว่าง processor

Shared memory (SMP) Message passing
address space เดียวกันทุก processor ของใครของมัน
การสื่อสาร อ่านเขียนตัวแปรร่วม + lock ส่ง/รับ message

Loosely Coupled Clusters: เครือข่ายของคอมพิวเตอร์อิสระ (แต่ละเครื่องมี memory และ OS ของตัวเอง) เชื่อมด้วย I/O system (Ethernet/switch, Internet) | เหมาะกับงานที่แยกเป็นงานอิสระได้: web servers, databases, simulations | ข้อดี: high availability, scalable, affordable | ปัญหา: ค่าบริหารจัดการสูง (จึงนิยมใช้ virtual machines) + bandwidth ของการเชื่อมต่อต่ำ เทียบกับ bandwidth ระหว่าง processor-memory ใน SMP

Cluster Grid
การเชื่อมต่อ Ethernet/switch ในที่เดียวกัน long-haul network (Internet)
เครื่อง เครื่องที่จัดไว้สำหรับงานนี้ PC ทั่วไปที่ว่างอยู่ (SETI@home, World Community Grid)

11. Interconnection Networks ⭐⭐

Network topologies (การจัดวาง processor, switch, link):

Topology ลักษณะ
Bus ทุก node ต่อสายร่วมเส้นเดียว — ถูกแต่แย่งกันใช้
Ring ต่อเป็นวง แต่ละตัวมีเพื่อนบ้าน 2 ตัว
2D Mesh ตาราง 2 มิติ ต่อกับ node รอบข้าง
N-cube (N = 3) ลูกบาศก์ 3 มิติ = 8 node แต่ละ node ต่อ 3 link
Fully connected ทุก node ต่อตรงกับทุก node — เร็วที่สุด แพงที่สุด

Multistage networks: a. Crossbar = switch แบบตาราง เชื่อมได้ครบทุกคู่แต่ใช้ switch เยอะ | b. Omega network = switch หลายชั้น ใช้ switch น้อยกว่า crossbar แต่บางคู่เชื่อมพร้อมกันไม่ได้ | c. Omega switch box = กล่อง 2×2 (input A,B → output C,D) ต่อตรงหรือสลับไขว้ได้

Network characteristics ⭐:

  • Performance: Latency per message (บน network ที่ไม่มีโหลด) | Throughput = Link bandwidth, Total network bandwidth, Bisection bandwidth (bandwidth ที่ผ่านเส้นแบ่ง network เป็นสองซีกเท่ากัน ในกรณีแย่ที่สุด) | Congestion delays
  • Cost | Power | Routability in silicon

Code or Applications? traditional benchmarks ใช้ code และ data sets ตายตัว แต่การเขียนโปรแกรมขนานยังพัฒนาอยู่ → algorithms, languages, tools ควรเป็นส่วนหนึ่งของระบบที่วัดด้วยไหม? → เปรียบเทียบระบบได้ถ้าทำ application ที่กำหนดได้ (Linpack, Berkeley Design Patterns) → ส่งเสริมนวัตกรรม Modeling Performance: ตัวชี้วัด = GFLOPs/sec (วัดด้วย computational kernels จาก Berkeley Design Patterns) | Arithmetic intensity = FLOPs ต่อ byte ของ memory ที่เข้าถึง | ต้องหา Peak GFLOPS (จาก data sheet) และ Peak memory bytes/sec (ใช้ Stream benchmark) 💡 สองค่านี้ใช้สร้าง Roofline model — arithmetic intensity ต่ำ ถูกจำกัดด้วย memory bandwidth / สูง ถูกจำกัดด้วย peak GFLOPS

13. Concluding Remarks ⭐

  • เป้าหมาย: ประสิทธิภาพสูงขึ้นด้วยหลาย processor | ความยาก: การพัฒนา parallel software + การออกแบบสถาปัตยกรรมที่เหมาะสม
