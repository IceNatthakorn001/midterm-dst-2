🎬 แอนิเมชันของบทนี้▶ Parallel Processors: Flynn · Vector · Multithreading · Reduction

⭐ Taxonomy

  • SISD → uniprocessor | SIMD → vector, array processor | MISD | MIMD → shared memory (tightly coupled: SMP, NUMA) / distributed memory (loosely coupled: clusters)
  • เป้าหมาย: เชื่อมหลายเครื่องให้เร็วขึ้น → scalability, availability, power efficiency
  • Task-level parallelism (งานอิสระ throughput สูง) | parallel processing program (โปรแกรมเดียวหลาย processor) | multicore
  • HW serial (Pentium 4) / parallel (Xeon e5345) × SW sequential (matrix mult.) / concurrent (OS)
  • เคยเรียน: synchronization, subword parallelism, ILP, cache coherence

Parallel programming

  • ปัญหาอยู่ที่ software — ถ้าไม่เร็วขึ้นมากใช้ uniprocessor เร็ว ๆ ง่ายกว่า
  • ⭐ ความยาก: partitioning, coordination, communications overhead

⭐ Flynn

Single data Multiple data
Single instr. SISD: Pentium 4 SIMD: SSE (x86)
Multiple instr. MISD: ไม่มี MIMD: Xeon e5345
  • SPMD = parallel program บน MIMD + conditional code

⭐ Vector

  • function units pipeline สูง, stream ผ่าน vector registers
  • RISC-V vector: v0–v31 = 32 × 64-element (64-bit) | fld.v/fsd.v, fadd.d.v (vector+vector), fadd.d.vs (scalar+vector)
  • ลด instruction-fetch bandwidth
  • DAXPY (Y = aX + Y, BLAS): ปกติวนลูป 8 คำสั่ง/element | vector 6 คำสั่ง ไม่มีลูป
  • Vector vs scalar: data-parallel ง่าย, ไม่มี loop-carried dependence (ลดการเช็กใน HW), ใช้ interleaved/burst memory, เลี่ยง control hazards, ทั่วไปกว่า MMX/SSE, เข้ากับ compiler
  • SIMD: ทุกตัวทำคำสั่งเดียวกันพร้อมกัน (MMX/SSE, register 128-bit), sync ง่าย, เหมาะ data-parallel สูง
  • Vector vs multimedia: width แปรผัน vs คงที่ | strided access มี vs ไม่มี | vector = pipelined + arrayed (lanes)

⭐ Multithreading

สลับเมื่อ ข้อสังเกต
Fine-grain ทุก cycle thread หนึ่ง stall ตัวอื่นทำต่อ
Coarse-grain stall นาน (L2 miss) HW ง่าย แต่ซ่อน stall สั้นไม่ได้
SMT หลาย thread ใน multiple-issue พร้อมกัน Pentium-4 HT: 2 threads, registers ซ้ำ, FU/cache ร่วม
  • อนาคต: power → แบบง่ายลง, thread switch ทน cache miss, simple cores หลายตัว

⭐ Shared Memory

  • SMP: physical address space เดียว, sync ด้วย locks, UMA vs NUMA
  • Sum reduction: 64,000 ตัว / 64 processors (UMA) → ตัวละ 1000 → reduce ครึ่งละครึ่ง (divide and conquer) + synch() ทุกขั้น, half คี่ให้ P0 บวกตัวที่เหลือ

⭐ GPU

  • ประวัติ: video card (frame buffer) → 3D (SGI) → การ์ด 3D PC/console → GPU (vertex/pixel, shading, texture mapping, rasterization)
  • Data-parallel สูง, highly multithreaded, thread switching ซ่อน memory latency, cache น้อย, memory กว้าง bandwidth สูง
  • Heterogeneous: CPU = sequential, GPU = parallel | DirectX, OpenGL, Cg, HLSL, CUDA
  • Fermi: 16 SIMD lanes, SIMD instr. บน thread 32 element ใน 2 cycles, 32K × 32-bit registers, 64 registers/thread, local memory 64 KiB
  • Memory: CUDA thread → private | thread block → per-block local | grid → GPU memory
  • ไม่เข้า SIMD/MIMD พอดี | VLIW (static ILP), Superscalar (dynamic ILP), SIMD/Vector (static DLP), Tesla (dynamic DLP)
  • เทียบ multicore: GPU ไม่มี demand paging, ไม่ cache coherent, ไม่มี integrated scalar, cache 0.75 MB (vs 8 MB), main memory 4–6 GB (vs 8–256 GB)
  • ชื่อ NVIDIA: Vectorizable loop = Grid | body = Thread Block | 1 lane op = CUDA Thread | thread of SIMD = Warp | SIMD instr. = PTX | multithreaded SIMD processor = Streaming Multiprocessor | thread block scheduler = Giga Thread Engine | SIMD thread scheduler = Warp Scheduler | SIMD lane = Thread Processor | GPU memory = Global Memory | local memory = Shared Memory

⭐ Message passing / Clusters / Grid

  • Message passing: private physical address space + HW ส่ง/รับ messages
  • Clusters: เครื่องอิสระ (memory + OS เอง) ผ่าน I/O (Ethernet, Internet) → web, DB, simulation | high availability, scalable, affordable | ปัญหา: admin cost (ใช้ VM), interconnect bandwidth ต่ำ
  • Grid: long-haul network, แจก work units, ใช้เวลาว่าง PC (SETI@home, World Community Grid)

Networks

  • Topologies: bus, ring, 2D mesh, N-cube (N=3), fully connected | Multistage: crossbar, omega (switch box A,B → C,D)
  • Characteristics: latency/message, throughput (link, total, bisection bandwidth), congestion, cost, power, routability in silicon

Benchmarks / Performance

  • Linpack (matrix), SPECrate (job-level), SPLASH (Stanford, strong scaling), NAS (NASA, fluid dynamics), PARSEC (Princeton, Pthreads/OpenMP)
  • Traditional = code + data คงที่ | เสนอให้เทียบด้วย application (Linpack, Berkeley Design Patterns)
  • Metric: achievable GFLOPs/sec | Arithmetic intensity = FLOPs/byte | peak GFLOPS (data sheet), peak memory bytes/sec (Stream)
  • สรุป: ยากที่ software + architecture | SaaS + clusters | performance per dollar / per Joule
