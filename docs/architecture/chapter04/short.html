⚡ สรุปสั้น · Chapter 04 — Memory System Organization, Hierarchy, Cache Memory

📖 อ่านฉบับเต็ม📝 ทำแบบทดสอบ
🎬 แอนิเมชันของบทนี้▶ Cache: แบ่ง address · Direct mapped · Associativity▶ Virtual Memory: แปล address ผ่าน TLB และ Page table

Locality / Hierarchy

  • ⭐ Temporal = ใช้ซ้ำเร็ว ๆ นี้ (ลูป, induction var.) | Spatial = ใช้ตัวใกล้ ๆ (คำสั่งตามลำดับ, array)
  • Disk → copy ไป DRAM (main memory) → copy ไป SRAM (cache)
  • Pyramid: registers, cache, main memory (inboard) → disk/CD/DVD/Blu-Ray (outboard) → tape (off-line)
  • Block (line) = หน่วย copy | Hit ratio = hits/accesses | Miss ratio = 1 − hit ratio | miss penalty = เวลาที่เสียเมื่อ miss

Memory Technology

Access $/GB
SRAM 0.5–2.5ns $2000–5000
DRAM 50–70ns $20–75
Disk 5–20ms $0.20–2
  • DRAM: ประจุใน capacitor + 1 transistor, ต้อง refresh ทีละ row | burst mode, DDR (ขอบขึ้น+ลง), QDR (แยก in/out) | row buffer, synchronous DRAM, banking
  • DRAM gen: 1980 64Kbit $1.5M/GB → 2007 1Gbit $50/GB
  • Flash: nonvolatile, เร็วกว่า disk 100–1000×, $/GB ระหว่าง disk กับ DRAM | NOR random access (embedded instr. memory) | NAND หนาแน่นถูก ทีละ block (USB) | สึก → wear leveling
  • Disk sector: ID, data 512B (เสนอ 4096), ECC, sync | access = queuing + seek + rotational + transfer + controller
  • ⭐ Disk example: 4 + 2 (½/(15000/60)) + 0.005 + 0.2 = 6.2ms (seek จริง 1ms → 3.2ms)
  • ค่า seek ของผู้ผลิตคิดจากทุก seek; ของจริงน้อยกว่า | disk มี cache prefetch

⭐ Cache basics

  • Elements: addresses (logical/physical), size, mapping (direct/associative/set assoc.), replacement (LRU/FIFO/LFU/Random), write policy (through/back), line size, #caches (1–2 level, unified/split)
  • Direct mapped: index = block addr mod #blocks (low-order bits) | tag = high-order bits | valid bit เริ่ม 0
  • ตัวอย่าง 8 blocks: 22 M, 26 M, 22 H, 26 H, 16 M, 3 M, 16 H, 18 M (แทน tag 11 ที่ 010)
  • ⭐ 64 blocks × 16 B: address 1200 → block addr ⌊1200/16⌋ = 75 → 75 mod 64 = 11 | offset 4, index 6, tag 22
  • Block ใหญ่: ลด miss (spatial) แต่ block น้อยลง แย่งกัน, pollution, miss penalty สูง → early restart / critical-word-first
  • Miss → stall pipeline, fetch block; I-miss restart fetch, D-miss complete access

⭐ Write policy

Write-through Write-back
Write hit แก้ cache + memory แก้ cache, ตั้ง dirty
ปัญหา write ช้า (CPI = 1 + 0.1×100 = 11) เขียนกลับเมื่อ dirty block ถูกแทน
แก้ write buffer (stall เมื่อเต็ม) write buffer ให้อ่านก่อน
Write miss allocate on miss / write around ปกติ fetch
  • FastMATH: 12-stage, split I/D 16KB (256 × 16 words) | miss I 0.4%, D 11.4%, avg 3.2%

⭐ Bandwidth (block 4 words; 1 addr + 15 DRAM + 1 transfer)

Miss penalty B/cycle
1-word wide 1 + 4×15 + 4×1 = 65 0.25
4-word wide 1 + 15 + 1 = 17 0.94
4-bank interleaved 1 + 15 + 4×1 = 20 0.8

⭐ Performance

  • Memory stall cycles = accesses/program × miss rate × miss penalty
  • Example: CPI 2 + I (0.02×100 = 2) + D (0.36×0.04×100 = 1.44) = 5.44 → ideal เร็วกว่า 2.72×
  • AMAT = Hit time + Miss rate × Miss penalty = 1 + 0.05×20 = 2ns
  • CPU เร็วขึ้น → miss penalty มีผลมากขึ้น ห้ามมองข้าม cache

⭐ Associativity

วางได้ comparators
Direct 1 ที่ 1
n-way n ที่ใน set (block mod #sets) n
Fully ที่ไหนก็ได้ ทุก entry (แพง)
  • 8 entries: 1-way 8 blocks / 2-way 4 sets / 4-way 2 sets / 8-way = fully
  • ลำดับ 0, 8, 0, 6, 8 (4 blocks): direct 5 miss | 2-way 4 miss 1 hit | fully 3 miss 2 hit
  • 1-way 10.3% → 2-way 8.6% → 4-way 8.3% → 8-way 8.1% (diminishing returns)
  • Replacement: invalid ก่อน → LRU (ง่ายที่ 2-way, ยากเกิน 4-way) หรือ Random (ใกล้ LRU เมื่อ assoc. สูง)

⭐ Multilevel

  • L1 เล็กเร็ว → L2 ใหญ่กว่า ช้ากว่า → main memory (บางระบบมี L3)
  • 4GHz, miss 2%, mem 100ns: penalty 400 → CPI = 9
    • L2 (5ns = 20 cycles, global miss 0.5%): CPI = 1 + 0.02×20 + 0.005×400 = 3.4 → 2.6× (⚠️ สไลด์เขียน extra penalty 500 แต่สูตรใช้ 400)
  • L1 เน้น hit time ต่ำ | L2 เน้น miss rate ต่ำ | L1 block < L2 block
  • Out-of-order: ทำคำสั่งอื่นระหว่าง miss → วิเคราะห์ยาก ใช้ simulation
  • Software: algorithm + compiler กระทบ miss | Blocking (DGEMM, BLOCKSIZE 32) → unoptimized 1.7→0.8 GFLOPS, blocked 1.7→1.5

Dependability

  • Fault อาจหรือไม่ทำให้ระบบล้ม | service accomplishment ↔ interruption
  • MTBF = MTTF + MTTR | Availability = MTTF / (MTTF + MTTR)
  • เพิ่ม MTTF: fault avoidance / tolerance / forecasting | ลด MTTR: เครื่องมือวินิจฉัย/ซ่อม
  • Hamming distance 2 = detect 1 bit (parity) | 3 = SEC + detect 2 bit | 4 = SEC/DED
  • Parity bits อยู่ตำแหน่ง 1, 2, 4, 8 (นับจาก 1 ทางซ้าย) | parity = 0000 ไม่มี error, 1010 → bit 10 ผิด
  • SEC/DED: H even pn even = OK | H odd pn odd = แก้ได้ | H even pn odd = pn ผิด | H odd pn even = double error
  • ECC DRAM: 8 bits ต่อ 64 bits

Virtual Machines

  • Host emulate guest OS → isolation, security, reliability, sharing | ตัวอย่าง IBM VM/370, VMWare, MS Virtual PC
  • VMM: map virtual → physical resources; guest รันใน user mode, trap ไป VMM เมื่อใช้ privileged instructions
  • Timer: VMM พัก VM, emulate virtual timer | ISA ต้องมี user/system mode, privileged instr.

⭐ Virtual Memory

  • Main memory = "cache" ของ disk; CPU + OS จัดการ; แต่ละโปรแกรมมี private virtual address space
  • block = page, miss = page fault (หลายล้าน cycles → fully associative + smart replacement)
  • VA = virtual page number + page offset (4K → 12 bit) → แปลเฉพาะ page number
  • Page table: array PTE indexed by VPN, page table register ชี้; PTE = physical page no. + status (ref, dirty) หรือ swap location
  • LRU ผ่าน reference bit (OS clear เป็นระยะ) | write-back เท่านั้น + dirty bit
  • TLB = cache ของ PTE: 16–512 PTEs, hit 0.5–1 cycle, miss 10–100 cycles, miss rate 0.01–1%
  • TLB miss: page อยู่ → โหลด PTE แล้ว retry (HW หรือ SW exception) | ไม่อยู่ → page fault
  • Page fault handler: หา PTE → หาบน disk → เลือก page แทน (dirty เขียนก่อน) → อ่านเข้า + update → restart
  • Physical tag ต้องแปลก่อน lookup | virtual tag มีปัญหา aliasing
  • Protection: supervisor (kernel) mode, privileged instr., system call (ecall)

⭐ Common framework

  • 4 คำถาม: placement, finding, replacement, write policy
  • Tag comparisons: direct 1 | n-way n | fully #entries | full lookup table 0
  • VM: full table lookup → fully associative ได้ | LRU approx. | write-back
  • 3C misses: Compulsory (ครั้งแรก) → เพิ่ม block size | Capacity (ขนาดจำกัด) → เพิ่ม cache size | Conflict (แย่ง set) → เพิ่ม associativity (ทุกทางอาจเพิ่ม access time / miss penalty)

Cache Control FSM

  • Direct-mapped, write-back, write allocate, block 16B, 16KB (1024 blocks), offset 4 / index 10 / tag 18, blocking cache
  • CPU↔Cache 32-bit data | Cache↔Memory 128-bit data, หลาย cycle
  • Next state = fn(state, inputs) | output = fo(state)
  • Idle → Compare Tag → (hit) Idle | (miss, clean) Allocate | (miss, dirty) Write-Back → Allocate → Compare Tag

Coherence / Consistency

  • ปัญหา: A เขียน X = 1 แต่ cache B ยังเป็น 0
  • Coherence: อ่านได้ค่าที่เขียนล่าสุด; ทุกตัวเห็นลำดับ write เดียวกัน
  • Protocols: migration, replication | snooping (เฝ้า bus) vs directory-based
  • Invalidating snooping: เขียน → broadcast invalidate → อีก cache miss แล้วได้ค่าใหม่
  • Consistency: write เสร็จเมื่อทุกตัวเห็น; reorder read ได้ แต่ write ไม่ได้

ระบบจริง / Pitfalls

  • A53: L1 2/4-way, random, 2 cycles; L2 16-way 128KiB–2MiB 12 cycles | i7: L1 4/8-way, 4 cycles; L2 8-way 256KiB 10 cycles; L3 8MiB 16-way 35 cycles
  • Multi-banked caches, non-blocking (hit under miss, miss under miss), prefetching
  • RISC-V system instr.: fence.i, fence, sfence.vm, csrr*, ecall, ebreak, sret, wfi
  • Pitfalls: byte 36 → block 1, word 36 → block 4; stride ใหญ่ = locality แย่; associativity < cores → conflict; AMAT ใช้กับ OoO ไม่ได้; segments (80286); VMM บน ISA ที่ไม่รองรับ
  • สรุป: fast = small, large = slow → caching ให้ภาพลวงว่าเร็วและใหญ่
