1. Principle of Locality ⭐

โปรแกรมเข้าถึงพื้นที่ address space ส่วนเล็ก ๆ ในแต่ละช่วงเวลา

แบบ ความหมาย ตัวอย่าง
Temporal locality ของที่เพิ่งใช้ มีแนวโน้มถูกใช้อีกเร็ว ๆ นี้ คำสั่งในลูป, induction variables
Spatial locality ของที่อยู่ใกล้ของที่เพิ่งใช้ มีแนวโน้มถูกใช้เร็ว ๆ นี้ รันคำสั่งเรียงกัน, ข้อมูลใน array

ใช้ประโยชน์: เก็บทุกอย่างบน disk → คัดลอกของที่เพิ่งใช้ (และใกล้เคียง) ไป DRAM (main memory) → คัดลอกของที่ใช้ล่าสุดยิ่งกว่าไป SRAM (cache ติด CPU)

2. Memory Hierarchy

กลุ่ม ประกอบด้วย
Inboard memory (เร็ว แพง เล็ก) Registers, Cache, Main memory
Outboard storage Magnetic disk, CD-ROM/RW, DVD-RW/RAM, Blu-Ray
Off-line storage (ช้า ถูก ใหญ่) Magnetic tape

ลงล่าง: ราคา/บิตลด, ความจุเพิ่ม, เวลาเข้าถึงนานขึ้น, CPU เข้าถึงน้อยลง

  • (a) Single cache: CPU ⇄ Cache (Word Transfer, Fast) ⇄ Main Memory (Block Transfer, Slow) | (b) 3-level: CPU ⇄ L1 (fastest) ⇄ L2 (fast) ⇄ L3 (less fast) ⇄ Main memory (slow)
  • Block (line) = หน่วยของการคัดลอก | Hit = ระดับบนตอบได้, Hit ratio = hits/accesses | Miss = คัดลอก block จากระดับล่างขึ้นมา, Miss penalty = เวลาที่ใช้, Miss ratio = 1 − hit ratio

3. Memory Technology ⭐

เทคโนโลยี Access time $/GB
SRAM 0.5–2.5 ns $2,000–5,000
DRAM 50–70 ns $20–75
Magnetic disk 5–20 ms $0.20–2

Ideal memory = access time ของ SRAM + ความจุ/ราคาของ disk (ทำไม่ได้ → ใช้ hierarchy)

  • DRAM: เก็บข้อมูลเป็น ประจุใน capacitor ใช้ transistor ตัวเดียว → ต้อง refresh เป็นระยะ (อ่านแล้วเขียนกลับ ทีละ row) | SRAM ไม่ต้อง refresh จึงเร็วแต่แพง
  • Advanced DRAM: บิตจัดเป็น array สี่เหลี่ยม เข้าถึงทั้ง row | Burst mode = ส่ง word ถัดไปใน row เดียวกัน latency ลด | DDR = ส่งทั้งขอบขาขึ้นและขาลงของ clock | QDR = แยก input/output ของ DDR
  • DRAM generations: 1980 64Kbit $1,500,000/GB → 2007 1Gbit $50/GB | Trac/Tcac ลดช้ากว่าความจุที่เพิ่ม
  • Performance factors: Row buffer (อ่าน+refresh หลาย word พร้อมกัน) | Synchronous DRAM (burst ไม่ต้องส่ง address ทุกครั้ง) | DRAM banking (เข้าถึงหลาย DRAM พร้อมกัน) — ทั้งหมดเพิ่ม bandwidth

เพิ่ม Memory Bandwidth

แบบ Miss penalty Bandwidth
1-word-wide DRAM (4-word block) 1 + 4×15 + 4×1 = 65 cycles 0.25 B/cycle
4-word wide memory 1 + 15 + 1 = 17 cycles 0.94 B/cycle
4-bank interleaved 1 + 15 + 4×1 = 20 cycles 0.8 B/cycle

(สมมติ: 1 bus cycle ส่ง address, 15 cycles เข้าถึง DRAM, 1 cycle ส่งข้อมูล)

Flash & Disk

  • Flash: nonvolatile semiconductor, เร็วกว่า disk 100–1000×, เล็กกว่า ใช้ไฟน้อยกว่า ทนกว่า, แต่ $/GB แพงกว่า disk | ⚠️ บิตสึกหลังเขียนหลายพันครั้ง → ใช้ wear leveling (ย้ายข้อมูลไป block ที่ใช้น้อย)
NOR flash NAND flash
Random read/write ทีละ block แต่ หนาแน่นกว่า และ ถูกกว่า/GB
instruction memory ใน embedded USB keys, media storage
  • Disk: nonvolatile rotating magnetic — track (วงรอบ), sector (ส่วนย่อยของ track), cylinder (track ตำแหน่งเดียวกันทุกแผ่น)
  • แต่ละ sector บันทึก: Sector ID, Data (512 bytes, เสนอ 4096), ECC, synchronization fields & gaps
  • การเข้าถึง 5 ส่วน: Queuing delay → Seek → Rotational latency → Data transfer → Controller overhead

ตัวอย่างคำนวณ ⭐ 512B sector, 15,000rpm, seek 4ms, 100MB/s, controller 0.2ms: seek 4ms + rotational ½ ÷ (15000/60) = 2ms + transfer 512/100MB/s = 0.005ms + controller 0.2ms = 6.2ms | ถ้า actual seek = 1ms → 3.2ms rotational latency เฉลี่ย = ครึ่งรอบ

  • Disk issues: average seek ที่ผู้ผลิตบอกมาจาก seek ทุกแบบ แต่ locality + OS scheduling ทำให้จริงน้อยกว่า | Smart disk controller จัดวาง physical sectors แล้วแสดง logical sector interface (SCSI, ATA, SATA) | disk drive มี cache → prefetch sectors, เลี่ยง seek/rotational delay

5. Direct Mapped Cache ⭐⭐

  • มีที่เดียวให้วาง: (Block address) modulo (#Blocks in cache) | #Blocks เป็นกำลังของ 2 → ใช้บิตล่างของ address เป็น index ได้เลย
  • Tag = เก็บบิตบนของ block address ไว้ด้วย เพื่อรู้ว่า block ไหนอยู่ในช่อง | Valid bit = 1 มี / 0 ไม่มี (เริ่มต้น 0)

ตัวอย่าง 8 blocks, 1 word/block → address 5 บิต = tag 2 + index 3

Word addr tag index ผล
22 10 110 Miss
26 11 010 Miss
22 10 110 Hit
26 11 010 Hit
16 10 000 Miss
3 00 011 Miss
16 10 000 Hit
18 10 010 Miss → แทนที่ Mem[11010]

⚠️ 18 (10 010) ตก index เดียวกับ 26 (11 010) แต่ tag ไม่ตรง → miss + แทนที่ = จุดอ่อนของ direct mapped (conflict)

6. Address Subdivision & Block Size

  • address 64 บิต: Tag (52) | Index (10) | Byte offset (2) — cache 1024 entries, แต่ละ entry มี Valid, Tag, Data — Hit = Valid AND (Tag ตรง)
  • สูตร: offset = log₂(bytes/block), index = log₂(#blocks), tag = บิตที่เหลือ

ตัวอย่าง ⭐ 64 blocks, 16 bytes/block, address 1200: Block address = ⌊1200/16⌋ = 75 → Block number = 75 mod 64 = 11 Tag = บิต 31–10 (22 บิต) | Index = บิต 9–4 (6 บิต) | Offset = บิต 3–0 (4 บิต)

Block size considerations: ใหญ่ควรลด miss rate (spatial locality) แต่ ใน cache ขนาดคงที่ → จำนวน block น้อยลง แย่งกันมากขึ้น miss rate เพิ่ม + pollution (ดึงข้อมูลที่ไม่ใช้) + miss penalty สูงขึ้น — บรรเทาด้วย early restart และ critical-word-first

7. Cache Misses & Write Policy ⭐

  • Hit: CPU ทำงานต่อปกติ | Miss: stall CPU pipeline → ดึง block จากระดับถัดไป → (I-cache miss) เริ่ม fetch ใหม่ / (D-cache miss) ทำ data access ให้เสร็จ
Write-through Write-back
แก้อะไร cache และ memory cache อย่างเดียว แล้วเขียนกลับตอนถูกแทนที่
ข้อดี ข้อมูลตรงกันเสมอ, replacement ง่าย เขียนเร็ว
ข้อเสีย เขียนช้า (ต้องมี write buffer) ต้องเก็บ state เพิ่ม (dirty bit)

ตัวอย่าง write-through: base CPI = 1, store 10%, เขียน memory 100 cycles → Effective CPI = 1 + 0.1 × 100 = 11 → แก้ด้วย write buffer (CPU ทำงานต่อได้ทันที, stall เฉพาะเมื่อ buffer เต็ม) Write allocation (ตอน write miss): write-through → allocate on miss (ดึง block) หรือ write around (ไม่ดึง เพราะโปรแกรมมักเขียนทั้ง block ก่อนอ่าน เช่น initialization) | write-back → มักดึง block มา

8. Intrinsity FastMATH

  • Embedded MIPS, 12-stage pipeline, เข้าถึง instruction และ data ทุก cycle | Split cache (I-cache + D-cache) แต่ละตัว 16KB = 256 blocks × 16 words | D-cache: write-through หรือ write-back
  • SPEC2000 miss rates: I-cache 0.4%, D-cache 11.4%, weighted average 3.2%
  • address 32 บิต: Tag 18 | Index 8 | Block offset 4 | Byte offset 2 → Mux เลือก word ด้วย block offset

9. Measuring Cache Performance ⭐⭐

CPU time = Program execution cycles (รวม hit time) + Memory stall cycles

Memory stall cycles = (Memory accesses / Program) × Miss rate × Miss penalty
                    = (Instructions / Program) × (Misses / Instruction) × Miss penalty
AMAT = Hit time + Miss rate × Miss penalty

ตัวอย่าง CPI ⭐ I-cache miss 2%, D-cache miss 4%, penalty 100 cycles, base CPI 2, load/store 36%:

  • I-cache: 0.02 × 100 = 2 (ทุกคำสั่งต้อง fetch)
  • D-cache: 0.36 × 0.04 × 100 = 1.44 (เฉพาะ load/store)
  • Actual CPI = 2 + 2 + 1.44 = 5.44 → Ideal CPU เร็วกว่า 5.44/2 = 2.72 เท่า

ตัวอย่าง AMAT: clock 1ns, hit time 1 cycle, penalty 20 cycles, miss rate 5% → AMAT = 1 + 0.05×20 = 2ns = 2 cycles/คำสั่ง

Performance summary: CPU ยิ่งเร็ว miss penalty ยิ่งสำคัญ — ลด base CPI → สัดส่วน memory stall สูงขึ้น / เพิ่ม clock rate → memory stall กิน cycles มากขึ้น → ละเลยพฤติกรรม cache ไม่ได้

10. Associative Caches ⭐⭐

Fully associative n-way set associative
วางที่ไหน entry ไหนก็ได้ set มี n entries; (Block number) mod (#Sets)
ค้นหา ค้นทุก entry พร้อมกัน ค้นทุก entry ใน set นั้นพร้อมกัน
comparator ต่อ entry (แพง) n ตัว (ถูกกว่า)

ค้นหา block 12 ใน cache 8 ช่อง: direct mapped → 12 mod 8 = block 4 (ค้น 1 ที่) | 2-way (4 sets) → 12 mod 4 = set 0 (ค้น 2 ที่) | fully → ค้นทั้ง 8 ที่ Spectrum (cache 8 entries): 1-way = 8 sets×1 (direct mapped) | 2-way = 4×2 | 4-way = 2×4 | 8-way = 1×8 (fully associative)

ตัวอย่างเทียบ cache 4 blocks, ลำดับ 0, 8, 0, 6, 8 ⭐

  • Direct mapped (index = addr mod 4): miss ทุกครั้ง → 5 misses
  • 2-way set associative (set = addr mod 2, LRU): 0 miss, 8 miss, 0 hit, 6 miss (แทน 8), 8 miss (แทน 0) → 4 misses
  • Fully associative: 0 miss, 8 miss, 0 hit, 6 miss, 8 hit → 3 misses

How much associativity (64KB D-cache, 16-word blocks, SPEC2000) — diminishing returns: 1-way 10.3% | 2-way 8.6% | 4-way 8.3% | 8-way 8.1% 4-way organization: Tag 22 | Index 8 (256 sets) → เปรียบเทียบ tag 4 ตัวพร้อมกัน → OR = Hit → 4-to-1 multiplexor เลือก data

11. Replacement Policy & Multilevel Caches

  • Direct mapped: ไม่มีทางเลือก | Set associative: เลือก entry ที่ไม่ valid ก่อน ไม่งั้นใช้ LRU (ง่ายกับ 2-way, พอไหวกับ 4-way, ยากเกินไปถ้ามากกว่านั้น) หรือ Random (ใกล้เคียง LRU เมื่อ associativity สูง)
  • L1 ติด CPU เล็กแต่เร็ว → L2 ใหญ่กว่า ช้ากว่า แต่ยังเร็วกว่า main memory → main memory | ระบบสูงบางตัวมี L3

ตัวอย่าง Multilevel ⭐⭐ base CPI 1, clock 4GHz (cycle 0.25ns), miss rate/instr 2%, main memory 100ns

  • มีแค่ L1: penalty = 100/0.25 = 400 cycles → CPI = 1 + 0.02×400 = 9
  • เพิ่ม L2 (access 5ns, global miss rate 0.5%): L2 hit penalty = 5/0.25 = 20 cycles CPI = 1 + 0.02×20 + 0.005×400 = 3.4 → เร็วขึ้น 9/3.4 = 2.6 เท่า
  • Considerations: L1 เน้น hit time น้อยที่สุด / L2 เน้น miss rate ต่ำ (hit time มีผลน้อยกว่า) → L1 มักเล็กกว่า cache ชั้นเดียว และ block size ของ L1 เล็กกว่า L2

12. Interactions with Advanced CPUs & Software

  • Out-of-order CPUs รันคำสั่งอื่นได้ระหว่าง miss (store ค้างอยู่ใน load/store unit, คำสั่งที่พึ่งพารอใน reservation stations, คำสั่งอิสระทำต่อได้) → วิเคราะห์ยากมาก ต้องใช้ system simulation
  • Miss ขึ้นกับ: พฤติกรรมของ algorithm + compiler optimization

Software optimization via Blocking (DGEMM) — เป้าหมาย: ใช้ข้อมูลให้ได้มากที่สุดก่อนถูกแทนที่ออกจาก cache แบบเดิมเข้าถึง B ไล่ทั้ง column ยาว ๆ → ข้อมูลเก่าหลุดจาก cache | Cache blocked: แบ่ง matrix เป็นก้อน 32×32 (BLOCKSIZE) ที่ใส่ cache ได้พอดี แล้วคูณทีละก้อน

13. Dependability ⭐

  • Service accomplishment ⇄ Service interruption ด้วย Failure / Restoration | Fault = ความเสียหายของส่วนประกอบ (อาจหรือไม่อาจทำให้ระบบ failure)
MTBF = MTTF + MTTR
Availability = MTTF / (MTTF + MTTR)

Reliability = MTTF | Service interruption = MTTR | ปรับปรุง: เพิ่ม MTTF (fault avoidance, fault tolerance, fault forecasting) / ลด MTTR (เครื่องมือวินิจฉัยและซ่อม)

Hamming Code

  • Hamming distance = จำนวนบิตที่ต่างกัน | distance 2 → ตรวจจับ single bit error (parity) | distance 3 → แก้ single error + ตรวจจับ 2 bit error
  • Encoding SEC: นับตำแหน่งเริ่มที่ 1 จากซ้าย, ตำแหน่งที่เป็นกำลังของ 2 (1,2,4,8) เป็น parity bits — p_k ตรวจตำแหน่งที่มีบิต k เป็น 1 ในเลขฐานสอง

p1 p2 d1 p4 d2 d3 d4 p8 d5 d6 d7 d8

p2 ตรวจ X X X X X X
p4 ตรวจ X X X X X
p8 ตรวจ X X X X X
  • Decoding: parity bits = 0000 → ไม่มี error | = 1010 → บิต 10 ถูกพลิก
  • SEC/DED: เพิ่ม parity bit อีก 1 บิตสำหรับทั้ง word (pₙ) → Hamming distance = 4

14. Virtual Machines

  • Host จำลอง guest OS และทรัพยากรเครื่อง → แยก guest หลายตัวได้ดีขึ้น, เลี่ยงปัญหาความปลอดภัย/ความน่าเชื่อถือ, ช่วยแบ่งปันทรัพยากร | มีผลต่อ performance บ้าง | ตัวอย่าง IBM VM/370 (ยุค 1970!), VMWare, Microsoft Virtual PC
  • VMM: map ทรัพยากรเสมือน → จริง (memory, I/O, CPUs) | โค้ด guest รันบนเครื่องจริงใน user mode แล้ว trap ไป VMM เมื่อเจอ privileged instructions และการเข้าถึง protected resources | guest OS อาจต่างจาก host OS | VMM จัดการ I/O จริงและจำลอง virtual I/O
  • Timer virtualization: ปกติ timer interrupt → OS หยุด process, จัดการ, เลือก process ถัดไป | มี VMM → VMM หยุด VM, จัดการ, เลือก VM ถัดไป | ถ้า VM ต้องการ timer → VMM จำลอง virtual timer และจำลอง interrupt ให้ VM
  • Instruction set support: User/System modes, privileged instructions ใช้ได้เฉพาะ system mode (รันใน user mode → trap), ทรัพยากรจริงทั้งหมด (page tables, interrupt controls, I/O registers) เข้าถึงได้ด้วย privileged instructions เท่านั้น

15. Virtual Memory ⭐⭐

  • ใช้ main memory เป็น "cache" ของ disk จัดการร่วมกันโดย CPU hardware + OS | แต่ละโปรแกรมมี virtual address space ส่วนตัว ป้องกันจากโปรแกรมอื่น
  • cache: block / miss ↔ VM: page / page fault
  • Address translation: page ขนาดคงที่ (เช่น 4K) | Virtual address (48 บิต) = VPN | Page offset (12) → แปล VPN → PPN → Physical address (40 บิต) = PPN | Page offset (offset คงเดิม)
  • Page fault penalty: ใช้ หลายล้าน clock cycles, จัดการโดย OS code → ลด page fault rate ด้วย fully associative placement + smart replacement
  • Page table: array ของ PTE ใช้ VPN เป็น index, page table register ใน CPU ชี้ไป page table | อยู่ใน memory → PTE เก็บ PPN + status bits (referenced, dirty) | ไม่อยู่ → ชี้ไป swap space บน disk | Valid = 1 → physical memory / Valid = 0 → disk
  • Replacement & writes: ใช้ LRU ผ่าน reference (use) bit ใน PTE (ตั้ง 1 เมื่อเข้าถึง, OS เคลียร์เป็น 0 เป็นระยะ) | disk write ใช้ล้าน cycles + เขียนทั้ง block → write-through ทำไม่ได้จริง ใช้ write-back + dirty bit

TLB ⭐

  • ปัญหา: การแปล address ต้องเข้าถึง memory 2 ครั้ง (อ่าน PTE + อ่านข้อมูล) → แต่การเข้าถึง page table มี locality ดี → ใช้ cache ของ PTE ใน CPU = Translation Look-aside Buffer
  • Typical: 16–512 PTEs, hit 0.5–1 cycle, miss 10–100 cycles, miss rate 0.01%–1% | miss จัดการได้ทั้ง hardware และ software
  • TLB มีคอลัมน์ Valid, Dirty, Ref, Tag, Physical page address
  • TLB miss: page อยู่ใน memory → โหลด PTE จาก memory แล้วลองใหม่ (hardware หรือ software handler) | page ไม่อยู่ → page fault OS ดึง page + อัปเดต page table แล้ว restart คำสั่งที่ fault
  • TLB miss handler: ต้องรู้ว่า miss ก่อน destination register ถูกเขียนทับ → raise exception → handler คัดลอก PTE จาก memory ไป TLB → restart
  • Page fault handler 5 ขั้น: 1. ใช้ virtual address ที่ fault หา PTE 2. หาตำแหน่ง page บน disk 3. เลือก page ที่จะแทนที่ (ถ้า dirty เขียนลง disk ก่อน) 4. อ่าน page เข้า memory + อัปเดต page table 5. ทำให้ process runnable แล้วเริ่มใหม่จากคำสั่งที่ fault
  • TLB & Cache interaction: cache tag ใช้ physical address → ต้องแปล address ก่อนค้น cache | ทางเลือกใช้ virtual address tag → ซับซ้อนเพราะ aliasing (virtual address ต่างกันชี้ physical เดียวกัน)

19. Cache Coherence ใน Multiprocessor

ปัญหา: 2 cores แชร์ physical address space, write-through — A อ่าน X(0), B อ่าน X(0), A เขียน 1 → B's cache ยังเป็น 0 = ไม่ coherent Coherence (เป็นทางการ): P writes X แล้ว P reads X → ได้ค่าที่เขียน | P1 writes X, P2 reads X (นานพอ) → ได้ค่าที่เขียน | P1, P2 เขียน X → ทุก processor เห็นการเขียนในลำดับเดียวกัน Protocols: Migration ของข้อมูลไป local cache (ลด bandwidth) | Replication ของ read-shared data (ลดการแย่ง) | Snooping (แต่ละ cache เฝ้าดู bus) | Directory-based (บันทึกสถานะการแชร์ใน directory) Invalidating snooping: cache ได้สิทธิ์ exclusive เมื่อจะเขียน → broadcast invalidate บน bus → การอ่านครั้งต่อไปใน cache อื่น miss → cache เจ้าของส่งค่าที่อัปเดตให้ Memory consistency: การเขียนเสร็จเมื่อทุก processor เห็นแล้ว, processor ไม่สลับลำดับการเขียน → P writes X then Y: ทุก processor ที่เห็น Y ใหม่ ก็เห็น X ใหม่ด้วย | สลับลำดับการอ่านได้ แต่สลับการเขียนไม่ได้

21. Pitfalls & Concluding Remarks

  • Byte vs word addressing: cache 32 bytes, block 4 bytes → byte 36 → block 1 (36/4=9, 9 mod 8=1) แต่ word 36 → block 4 (36 mod 8)
  • ละเลยผล memory system ตอนเขียนโค้ด (วนตาม row vs column, stride ใหญ่ → locality แย่)
  • Multiprocessor แชร์ L2/L3: associativity น้อยกว่าจำนวน core → conflict misses → core มากขึ้นต้องเพิ่ม associativity
  • ใช้ AMAT ประเมิน out-of-order processors ไม่ได้ (ไม่นับ non-blocked accesses) → ใช้ simulation
  • ขยาย address range ด้วย segments (Intel 80286): segment ไม่ใหญ่พอ + คำนวณ address ซับซ้อน
  • ทำ VMM บน ISA ที่ไม่ได้ออกแบบมาเพื่อ virtualization → ต้องขยาย ISA หรือห้าม guest OS ใช้คำสั่งที่มีปัญหา
  • ⭐ Fast memories are small, large memories are slow — caching ให้ภาพลวงว่าเร็วและใหญ่พร้อมกัน ผ่าน principle of locality และ hierarchy L1 ↔ L2 ↔ … ↔ DRAM ↔ disk
