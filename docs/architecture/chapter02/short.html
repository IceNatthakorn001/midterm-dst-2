1. Von Neumann vs Harvard ⭐

Von Neumann (John Von Neumann, Princeton) Harvard
Memory รวม program + data แยก instruction memory / data memory
Bus ชุดเดียว แยกกัน
ข้อดี เรียบง่าย ยืดหยุ่น ไม่มีคอขวด ดึงคำสั่ง+ข้อมูลพร้อมกัน
ข้อเสีย Von Neumann bottleneck ซับซ้อนกว่า
ใช้ที่ คอมพิวเตอร์ทั่วไป (ดั้งเดิม/พบมากสุด) DSP, microcontroller

Stored program concept: memory เก็บทั้ง program + data / อ้างด้วย address ไม่ใช่ชนิดข้อมูล / ทำงานและเข้าถึงแบบ sequential (linear) Hybrid: Harvard ที่ระดับ L1 cache + Von Neumann ที่ main memory

2. Bus & Bus Arbitration

  • 2 แบบ: point-to-point (2 อุปกรณ์) / multipoint (หลายอุปกรณ์ใช้ร่วม = shared resource คุมด้วย protocol ในฮาร์ดแวร์)
  • 3 สาย: Data lines = ส่งบิตข้อมูล | Control lines = ทิศทางการไหล + เมื่อไหร่ใครใช้ได้ | Address lines = ตำแหน่งต้นทาง/ปลายทาง
  • Bus arbitration 4 แบบ (เมื่อมี bus master หลายตัว):
แบบ วิธี
Daisy chain ส่งต่อสิทธิ์จาก priority สูงสุด → ต่ำสุด
Centralized parallel แต่ละอุปกรณ์ต่อตรงกับวงจรตัดสิน
Distributed self-detection อุปกรณ์ตกลงกันเอง
Distributed collision-detection ลองส่งเลย ชนแล้วลองใหม่

3. Hardware vs Software Approach

(a) Programming in hardware (b) Programming in software
Data → sequence of arithmetic/logic functions (วงจรเฉพาะ) → Results Instruction codes → instruction interpreter → control signals → general-purpose ALU functions ← Data → Results
เปลี่ยนงาน = เดินสายใหม่ (rewire) เปลี่ยนงาน = เปลี่ยนชุดคำสั่ง

CPU = instruction interpreter + module ของ arithmetic/logic functions แบบอเนกประสงค์ | I/O components = รับข้อมูล/คำสั่งแปลงเป็นสัญญาณ + ช่องทางรายงานผล

4. Registers สำหรับ Memory และ I/O ⭐

Register หน้าที่
MAR (Memory Address Register) ระบุ address สำหรับอ่าน/เขียนครั้งถัดไป
MBR (Memory Buffer Register) เก็บ ข้อมูล ที่จะเขียนลง / อ่านจาก memory
I/OAR ระบุ อุปกรณ์ I/O ที่ต้องการ
I/OBR แลกเปลี่ยนข้อมูลระหว่าง I/O module กับ CPU

⚠️ MAR = "ที่ไหน" / MBR = "อะไร" Top-level view: CPU (PC, IR, MAR, MBR, I/O AR, I/O BR, execution unit) ⇄ System Bus ⇄ Main Memory (0 … n−1, เก็บ instruction + data) และ I/O Module (buffers)

5. Instruction Cycle

START → Fetch Next Instruction → Execute Instruction → วน → HALT Fetch cycle: PC เก็บ address คำสั่งถัดไป → ดึงคำสั่ง → PC เพิ่มค่า → โหลดลง IR → แปลความหมาย → ทำตาม

6. Example of Program Execution ⭐

รูปแบบเครื่องสมมติ 16 บิต: opcode บิต 0–3 (4 บิต) + address บิต 4–15 (12 บิต) | integer: บิต 0 = S (sign), 1–15 = magnitude | registers: PC, IR, AC (Accumulator) Opcodes: 0001 = Load AC from Memory, 0010 = Store AC to Memory, 0101 = Add to AC from Memory

Addr Content ความหมาย
300 1940 Load AC จาก 940
301 5941 Add ค่าที่ 941
302 2941 Store AC ไปที่ 941
940 / 941 0003 / 0002 ข้อมูล

6 ขั้น: fetch 300 (IR=1940, PC=301) → exec Load (AC=0003) → fetch 301 (IR=5941, PC=302) → exec Add (AC=0005) → fetch 302 (IR=2941, PC=303) → exec Store → 941 = 0005 ทุกคำสั่ง = 1 fetch + 1 execute, PC เพิ่มตอน fetch เสมอ

7. Instruction Cycle State Diagram

Instruction address calculation → Instruction fetch → Instruction operation decoding → Operand address calculation → Operand fetch (multiple operands) → Data operation → Operand store (multiple results)

  • ลูกศร "Return for string or vector data" = ข้อมูลชุด วนซ้ำ | "Instruction complete, fetch next instruction" = วนคำสั่งถัดไป
  • แถวบน (instruction fetch, operand fetch, operand store) = ต้องติดต่อ memory/I/O | แถวล่าง = ทำภายใน CPU

8. MARIE — Registers, Architecture, Data Path

MARIE = Machine Architecture that is Really Intuitive and Easy (เครื่องจำลองสอนหลักการ)

Register ขนาด หน้าที่
AC 16-bit conditional operator หรือ operand หนึ่งของคำสั่ง 2 operand
MAR 12-bit memory address ของคำสั่ง/operand
MBR 16-bit ข้อมูลหลังดึงจาก / ก่อนวางลง memory
PC 12-bit address คำสั่งถัดไป
IR 16-bit คำสั่งก่อนถูกรัน
InREG 8-bit ข้อมูลจาก input device
OutREG 8-bit ข้อมูลส่งไป output device

MAR/PC = 12 บิต เพราะ memory มี 2¹² = 4096 ช่อง (0–4095)

  • register + main memory เชื่อมผ่าน common data bus, อุปกรณ์แต่ละตัวมีหมายเลขเฉพาะตั้งบน control lines
  • มี ทางเชื่อมแยก AC↔MBR และ ALU↔AC/MBR → ส่งข้อมูลได้โดยไม่ใช้ main data bus
  • Data path 16-bit bus, bus address: 0 = Main Memory, 1 = MAR, 2 = PC, 3 = MBR, 4 = AC, 5 = InReg, 6 = OutReg, 7 = IR

9. MARIE ISA & Instruction Format ⭐

  • ISA = รูปแบบคำสั่ง + operation พื้นฐานที่เครื่องทำได้ = interface ระหว่าง hardware กับ software | บาง ISA มีหลายร้อยคำสั่ง แต่ MARIE มี 13 คำสั่ง
  • Format: บิต 15–12 = Opcode (4 บิต), บิต 11–0 = Address (12 บิต)
Bin Hex Instruction Meaning
0001 1 Load X โหลดค่าที่ X ลง AC
0010 2 Store X เก็บ AC ไปที่ X
0011 3 Add X บวกค่าที่ X เข้า AC
0100 4 Subt X ลบค่าที่ X ออกจาก AC
0101 5 Input รับค่าจาก keyboard ลง AC
0110 6 Output แสดงค่าใน AC
0111 7 Halt จบโปรแกรม
1000 8 Skipcond ข้ามคำสั่งถัดไปตามเงื่อนไข
1001 9 Jump X PC ← X

ตัวอย่าง bit pattern: 0001 000000000011 = Load address 3 | 1000 100000000000 = Skipcond บิต 11–10 = 10 → ข้ามถ้า AC > 0

10. RTL (Register Transfer Language) ⭐

แต่ละคำสั่งประกอบด้วย microoperations ระบุลำดับด้วย RTL | M[X] = ค่าใน memory ตำแหน่ง X | ← = โอนข้อมูล

LOAD X ADD X
MAR ← X MAR ← X
MBR ← M[MAR] MBR ← M[MAR]
AC ← MBR AC ← AC + MBR

SKIPCOND (ซับซ้อนที่สุด) — "ข้าม" = PC ← PC + 1

IR[11-10] = 00 → ถ้า AC < 0 then PC ← PC + 1
IR[11-10] = 01 → ถ้า AC = 0 then PC ← PC + 1
IR[11-10] = 11 → ถ้า AC > 0 then PC ← PC + 1

⚠️ สไลด์ไม่ตรงกันเอง: หน้า bit pattern ใช้ 10 = AC > 0 แต่หน้า RTL เขียน 11 (ตำรามาตรฐานใช้ 10) — ควรถามอาจารย์ว่ายึดแบบไหน

11. Fetch-Decode-Execute Flowchart

MAR ← PC → IR ← M[MAR], PC ← PC + 1 → decode + MAR ← IR[11-0] → ต้องใช้ operand? ถ้าใช่ MBR ← M[MAR] → Execute → วนกลับ

12. Interrupts ⭐

  • เกิดเมื่อ: ผู้ใช้กด user break (Ctrl + C) / ผู้ใช้หรือโปรแกรมขอ I/O / เกิด critical error
  • แหล่งที่มา: Hardware interrupt / Software interrupt (เรียก OS system call)
  • ก่อนเริ่มแต่ละรอบถาม "Has an interrupt been issued?" → Yes = process the interrupt / No = ทำ fetch-decode-execute
  • ขั้นตอนประมวลผล (ISR = Interrupt Service Routine):
    1. detect interrupt signal → 2. save variables & registers → 3. ค้น address ของ ISR ใน interrupt vector table → 4. ใส่ address ลง PC → 5. branch to ISR (ทำงานเฉพาะของ interrupt นั้น) → 6. restore registers & variables → 7. กลับไปต้น fetch-decode-execute
  • Maskable = เพิกเฉยได้ระหว่างประมวลผล interrupt (ตั้งบิตใน flags register ปิด interrupt ทั้งหมด) | Nonmaskable = ต้องประมวลผลเสมอ เพื่อให้ระบบเสถียร

13. MARIE I/O & Simple Program

  • interrupt มีประโยชน์มากกับ I/O แต่ interrupt-driven I/O ซับซ้อน อยู่นอกขอบเขตบทนี้ → MARIE ใช้ programmed I/O แบบดัดแปลง: output ใส่ OutREG, CPU poll InREG จนมี input แล้วคัดลอกลง AC
Addr Instruction Hex
100 Load 104 1104
101 Add 105 3105
102 Store 106 4106
103 Halt 7000
104 / 105 / 106 ข้อมูล 0023 / FFE9 / 0000

ทำอะไร: 0023₁₆ = 35 บวก FFE9₁₆ = −23 (two's complement) → เก็บที่ 106 = 000C₁₆ = 12 ⚠️ Store 106 เข้ารหัสเป็น 4106 ทั้งที่ตาราง opcode ให้ Store = 2 (4 = Subt) — สไลด์พิมพ์ตามต้นฉบับ ให้ยึดตาราง opcode

Trace ADD 105: เริ่ม PC=101, IR=1104, MAR=104, MBR=0023, AC=0023 MAR←PC (MAR=101) → IR←M[MAR] (IR=3105) → PC←PC+1 (PC=102) → MAR←IR[11-0] (MAR=105) → decode IR[15-12] → MBR←M[MAR] (MBR=FFE9) → AC←AC+MBR (AC=000C)

14. Classes of Interrupts & Program Flow

Class เกิดจาก
Program arithmetic overflow, division by zero, คำสั่งไม่ถูกต้อง, อ้าง memory นอกพื้นที่
Timer timer ใน processor ให้ OS ทำงานเป็นระยะ
I/O I/O controller แจ้งเสร็จปกติ / ขอบริการ / แจ้ง error
Hardware failure power failure, memory parity error

Flow of control: (a) No interrupts = CPU รอจน I/O จบ | (b) short I/O wait = สั่ง I/O แล้วทำงานต่อได้เลย เสร็จแล้วค่อย interrupt ไป handler | (c) long I/O wait = ถึง WRITE ถัดไปแล้ว I/O ก่อนยังไม่เสร็จ ต้องรอ Transfer of control: ถูกขัดหลังคำสั่ง i → ทำ Interrupt Handler → กลับมาที่ คำสั่ง i + 1 Instruction cycle with interrupts: Fetch → Execute → Interrupt Cycle (check + process) → วน | Interrupts Disabled = ข้ามกลับไป fetch เลย Program timing: ไม่มี interrupt = "I/O operation; processor waits" (CPU รอเปล่า) / มี interrupt = "I/O operation concurrent with processor executing" → เสร็จเร็วกว่า (แบบ long I/O ยังต้องรอบางส่วนแต่ยังเร็วกว่า) State diagram with interrupts: หลัง Operand store → Interrupt check → (No) กลับ Instruction address calculation / (มี) → Interrupt → แล้วกลับ

15. Multiple Interrupts ⭐

(a) Sequential (b) Nested
ระหว่างทำ handler X ปิด interrupt เปิดให้ priority สูงกว่าเข้าได้
Y ต้องรอจน X จบ Y ขัด X ได้ทันที เสร็จแล้วกลับไปทำ X ต่อ
ง่าย ไม่สนความเร่งด่วน ตอบสนองงานเร่งด่วน แต่ซับซ้อน

Timeline ตัวอย่าง (priority: communication > disk > printer): t=0 user program → t=10 printer interrupt → t=15 communication ขัด printer ISR → (t=20 disk เข้ามารอ) → t=25 communication จบ → ทำ disk ISR → t=35 disk จบ → กลับทำ printer ISR → t=40 จบ กลับ user program

คู่ ต่างกันที่
Von Neumann / Harvard memory รวม / แยก
MAR / MBR address / data
PC / IR ที่อยู่คำสั่งถัดไป / คำสั่งที่กำลังรัน
LOAD / ADD (RTL) AC ← MBR / AC ← AC + MBR
Hardware / Software interrupt จากอุปกรณ์ / จาก system call
