⭐ Von Neumann vs Harvard

Von Neumann Harvard
Memory เดียว เก็บ program + data (stored program) แยก instruction / data
Bus ร่วมกัน แยก
อื่น ๆ ดั้งเดิม พบมากสุด, อ้างด้วย address, sequential DSP, microcontroller, ลด bottleneck แต่ซับซ้อน
  • Hybrid: Harvard ที่ L1 cache, Von Neumann ที่ main memory

Bus

  • 2 ประเภท: point-to-point, multipoint | multipoint = shared resource คุมด้วย protocol ใน hardware
  • Data lines ส่ง bits | Control lines ทิศทาง + เมื่อไรใช้ bus ได้ | Address lines ตำแหน่งต้นทาง/ปลายทาง
  • ⭐ Bus arbitration (master-slave หลาย master):
    • Daisy chain — ส่งสิทธิ์จาก priority สูง → ต่ำ
    • Centralized parallel — ทุกตัวต่อตรงกับ arbitration circuit
    • Distributed self-detection — ตกลงกันเอง
    • Distributed collision-detection — ลองใช้ ถ้าชนก็ลองใหม่

Hardware vs Software approach

  • Hardware: Data → sequence of arithmetic/logic functions → Results
  • Software: Instruction codes → instruction interpreter → control signals → general-purpose functions → Results; โปรแกรมใหม่ = code ใหม่ ไม่ต้องเดินสายใหม่
  • CPU = interpreter + general-purpose arithmetic/logic | I/O = รับเข้า แปลงสัญญาณ รายงานผล

Registers
MAR address ใน memory สำหรับ read/write ถัดไป
MBR ข้อมูลที่จะเขียน / ที่อ่านมา
I/OAR ระบุ I/O device
I/OBR แลกข้อมูล I/O module ↔ CPU
PC / IR / AC address คำสั่งถัดไป / คำสั่งที่ทำ / ที่เก็บชั่วคราว

Instruction cycle

  • Basic: START → Fetch → Execute → วน → HALT
  • ⭐ Fetch: PC = address คำสั่งถัดไป → fetch → PC + 1 → โหลดเข้า IR → ตีความ/ทำ
  • ตัวอย่าง (opcode 0001 Load, 0010 Store, 0101 Add): 300:1940, 301:5941, 302:2941, 940:3, 941:2 → AC = 3 → 3+2 = 5 → store ลง 941 = 0005
  • State diagram: instruction address calc → instruction fetch → decoding → operand address calc ↔ operand fetch (multiple operands) → data operation → operand address calc ↔ operand store (multiple results) → กลับ (หรือ return for string/vector data)

⭐ MARIE

Reg bit หน้าที่
AC 16 operand / conditional operator
MAR 12 address
MBR 16 ข้อมูลเข้า/ออก memory
PC 12 address คำสั่งถัดไป
IR — คำสั่งที่จะ execute
InREG 8 ข้อมูลจาก input
OutREG 8 ข้อมูลไป output
  • Memory 0–4095 | common data bus 16-bit | bus no.: 0 Mem, 1 MAR, 2 PC, 3 MBR, 4 AC, 5 InReg, 6 OutReg, 7 IR
  • ทางเชื่อมแยก AC↔MBR, ALU↔AC/MBR (ไม่ต้องใช้ main bus)
  • ISA = interface hardware/software | MARIE มี 13 คำสั่ง | opcode bit 15–12, address bit 11–0
  • คำสั่ง: 1 Load, 2 Store, 3 Add, 4 Subt, 5 Input, 6 Output, 7 Halt, 8 Skipcond, 9 Jump
  • LOAD ใน IR 0001 000000000011 = Load จาก address 3 | SKIPCOND 1000 10... = skip ถ้า AC > 0
  • RTL: M[X] = ค่าใน memory X, ← = โอน
    • LOAD: MAR←X, MBR←M[MAR], AC←MBR | ADD: MAR←X, MBR←M[MAR], AC←AC+MBR
    • SKIPCOND: 00 → AC<0, 01 → AC=0, 11 → AC>0 (⚠️ สไลด์ 24 บอก 10 = AC>0 — สไลด์ขัดกัน)

⭐ Fetch-decode-execute (MARIE)

MAR←PC → IR←M[MAR], PC+1 → MAR←IR[11-0], decode IR[15-12] → (มี operand?) MBR←M[MAR] → execute

ADD 105 PC IR MAR MBR AC
initial 101 1104 104 0023 0023
fetch จบ 102 3105 101 0023 0023
decode 102 3105 105 0023 0023
get operand 102 3105 105 FFE9 0023
execute 102 3105 105 FFE9 000C
  • โปรแกรม: 100 Load 104 (1104), 101 Add 105 (3105), 102 Store 106 (4106 ตามสไลด์), 103 Halt (7000), 104 = 0023, 105 = FFE9, 106 = 0000

⭐ Interrupts

  • เกิดเมื่อ: user break (Ctrl+C), ขอ I/O, critical error | จาก hardware หรือ software (OS system call)
  • เพิ่มขั้น "มี interrupt ไหม?" → Yes: process interrupt | No: fetch-decode-execute
  • ISR: detect → save variables/registers → หา ISR address ใน interrupt vector table → ใส่ PC → ทำ ISR → return → restore → กลับ fetch
  • Maskable = ถูกปิดได้ (ตั้ง bit ใน flags register) | Nonmaskable = ต้องจัดการเพื่อความเสถียร
  • MARIE: programmed I/O แบบดัดแปลง — output ใส่ OutREG, CPU poll InREG แล้ว copy เข้า AC
Class ตัวอย่าง
Program overflow, หารศูนย์, illegal instruction, อ้าง memory นอกสิทธิ์
Timer timer ใน processor ให้ OS ทำงานเป็นระยะ
I/O I/O controller แจ้งเสร็จ / ขอบริการ / error
Hardware failure power failure, memory parity error
  • Instruction cycle with interrupts: Fetch → Execute → (enabled) Interrupt cycle / (disabled) กลับ fetch
  • Transfer of control: interrupt หลังคำสั่ง i → handler → กลับที่ i+1
  • Timing: ไม่มี interrupt = processor รอ I/O | มี interrupt = I/O ทำพร้อมกับ processor (long wait ยังต้องรอบ้าง)
  • Multiple: sequential (ทีละตัว) vs nested (ขัดซ้อน) | ตัวอย่าง t=0 → 10 printer → 15 comm → 25 กลับ printer/ไป disk → 35 กลับ printer → 40 กลับ user
