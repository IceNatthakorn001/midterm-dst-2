0. ตารางเรียน / Outline (สไลด์ 2–3)

  • OS#1 Intro → OS#2 Process Concept → OS#3 Process Scheduling → OS#4 Memory Management → OS#5 File Systems → OS#6 Disk & I/O → OS#7 Synchronization & Deadlock

1. Memory hierarchy & memory manager (สไลด์ 5–6)

  • แก่น: เร็ว = เล็ก+แพง, ใหญ่ = ช้า+ถูก | memory manager = manage, keep track, allocate, deallocate
ชั้น ขนาด ลักษณะ
Cache few MB very fast, expensive, volatile
RAM few GB medium, volatile
Disk / SSD few TB slow, cheap, non-volatile
  • พีระมิด L0 Registers → L1 Cache → L2 Main memory → L3 Disk cache → L4 Magnetic disk → L5 Optical/tapes | ขึ้นบน cost/bit แพง | ลงล่าง capacity + access time มากขึ้น

2. No Memory Abstraction (สไลด์ 7–9)

  • แก่น: address absolute → process เดียว, ทับ OS ได้, รันหลายตัวยาก
  • abstraction = ชั้นคั่นระหว่าง 2 ระบบ ไม่ต้องรู้การทำงานของอีกฝั่ง
  • 3 layout: (a) user บน / OS in RAM ล่าง | (b) OS in ROM บน / user ล่าง | (c) drivers in ROM บน / user กลาง / OS in RAM ล่าง
  • รูป (c): โปรแกรม 2 ถูกวางที่ 16384 แต่ JMP 28 ยังกระโดดไป absolute 28 (ADD ของโปรแกรม 1) ไม่ใช่ CMP ที่ 16412

3. Address space (สไลด์ 10)

  • แก่น: ชุด address ที่ process ใช้ได้ แยกของใครของมัน — address 28 ของแต่ละโปรแกรมต้องเป็นคนละที่จริง

4. Base & Limit (สไลด์ 11–12)

  • ⭐ Base = จุดเริ่ม physical | Limit = ความยาวโปรแกรม | physical = addr + base | addr ≥ limit → fault
  • ⭐ ตัวอย่าง base = limit = 16384: JMP 28 → 28 + 16384 = 16412 (CMP)
  • ข้อเสีย: บวก + เทียบทุก reference | เทียบเร็ว | บวกช้า (carry-propagation)

5. Swapping (สไลด์ 13–15)

  • แก่น: เอา process ทั้งตัวเข้า รัน แล้วกลับไป disk | idle อยู่บน disk ไม่กิน memory
  • (a)A → (b)A,B → (c)A,B,C → (d)A ออก → (e)D เข้า → (f)B ออก → (g)A กลับมาคนละที่
  • ⭐ เกิด holes → compaction (ย้ายลงล่างรวม hole) แต่ไม่ค่อยทำ เพราะ เปลือง CPU time
  • fixed & static → จัดพอดี | data segment (dynamic var) + stack (local var, return addr) โตได้ → เผื่อ room for growth (stack กับ data โตเข้าหากัน)

6. Bitmap vs Linked list (สไลด์ 16–17)

  • ⭐ แบ่ง memory เป็น allocation units | bitmap 1 บิต/unit (1 = ใช้, 0 = ว่าง)
  • ตัวอย่าง: A 0–4, hole 5–7, B 8–13, C 14–17, hole 18–19, D 20–25, E 26–28, hole 29–31
    • bitmap 11111000 | 11111111 | 11001111 | 11111000
    • list P0 5 → H5 3 → P8 6 → P14 4 → H18 2 → P20 6 → P26 3 → H29 3
  • ⭐ Bitmap: หา 0 ติดกัน k ตัว ช้า | List: process จบต้องอัปเดต + รวม hole
  • 4 กรณีเพื่อนบ้าน X: A X B → A hole B | A X hole → A hole ใหญ่ | hole X B → hole ใหญ่ B | hole X hole → hole ก้อนเดียว

7. Allocation algorithms (สไลด์ 18–22)

วิธี หมายเหตุ
⭐ First fit hole แรกที่พอ แบ่งเป็น 2 ส่วน —
Next fit เหมือน first แต่เริ่มจากที่ค้างไว้ —
⭐ Best fit hole เล็กสุดที่พอ ค้นทั้ง list → ช้ากว่า first
Worst fit hole ใหญ่สุด hole ที่เหลือยังใช้ได้
Quick fit list แยกตามขนาด (4 KB, 8 KB, …) หาเร็วมาก แต่ merge เพื่อนบ้านแพง
  • แยก list process/hole → 4 ตัวแรกเร็วขึ้น | hole list เรียงตามขนาด → ⭐ first = best เร็วเท่ากัน, next fit pointless | เก็บข้อมูลใน hole เองได้

8. Virtual memory & MMU (สไลด์ 23–25)

  • base/limit มีปัญหา bloatware (preloaded software ที่ไม่จำเป็น) → virtual memory = มี process ใน memory ได้มากขึ้น
  • ⭐ address space แบ่งเป็น pages (ช่วงต่อเนื่อง) | ไม่ต้องอยู่ RAM ครบ | ไม่อยู่ → OS ไปดึงมา แล้ว re-execute
  • ⭐ virtual address → MMU (อยู่ใน CPU package) → physical address → bus → memory / disk controller

9. Paging (สไลด์ 26–27)

  • ⭐ page = virtual, page frame = physical, ขนาดเท่ากัน จำนวนไม่เท่ากัน
  • map (4 KB): 0→2, 1→1, 2→6, 3→0, 4→4, 5→3, 9→5, 11→7, ที่เหลือ X
  • ⭐ physical = frame × 4096 + (addr mod 4096)
    • 8192 → page 2 → frame 6 → 24576
    • 20500 → page 5, offset 20 → frame 3 → 12308
    • 32780 → page 8 = X → ⭐ page fault → trap OS → เลือก frame little-used เขียนกลับ disk → ดึง page → แก้ map → restart

10. Page table (สไลด์ 28–30)

  • ⭐ 8196 = 0010 000000000100 → page 2, offset 4 → frame 110 → 110000000000100 = 24580 | offset 12 บิต copy ตรง
  • ⭐ entry 6 fields: frame # | present (1 = อยู่) | protection (1 = read only, 0 = R/W) | modified/dirty (1 = ต้องเขียน disk) | referenced | caching disabled (1 = disabled)
  • ขั้นตอน: get VA → convert → 4 บิตแรก = page # → ไปแถว → present 0 = re-execute | 1 = frame + offset

11. TLB (สไลด์ 31–33)

  • ปัญหา: map ต้องเร็ว + table ใหญ่ | register = เร็วแต่แพงมาก | ใน memory = ช้า (อ่าน 2 ครั้ง) | → TLB
  • ⭐ TLB = small H/W, associative memory, อยู่ใน MMU | entry: virtual page, modified, protection, page frame, valid
  • ⭐ เทียบ parallel ทุก entry: hit + ไม่ผิด → frame จาก TLB | hit + ผิด → protection fault | miss → lookup page table แล้ว evict/แทน entry ใน TLB

12. Page table สำหรับ memory ใหญ่ (สไลด์ 34–38)

  • ⭐ Multilevel: 32 บิต = PT1 10 | PT2 10 | Offset 12 | process 12 MB (text / data / stack อย่างละ 4 MB) | memory 4 GB | table ละ K = 2^10 = 1024
  • PT1 → top-level (entry 0 = text, 1 = data, 1023 = stack, อื่นไม่ใช้) → PT2 → page frame
  • ⭐ Physical = PT1 × 4M + PT2 × 4K + offset (K = 2^10, M = 2^20; 4K = 2^12 จาก offset, 4M = 2^10 × 2^12)
  • ⭐ 0x00403004 → PT1 = 1, PT2 = 3, offset = 4 → 4194304 + 12288 + 4 = 4206596
  • Inverted: 1 entry ต่อ frame จริง (1 GB / 4 KB = 2^18 vs traditional 2^52) | index ด้วย hash ของ virtual page | ⭐ ข้อเสีย: ต้องค้น ทั้งตาราง

13. Page replacement (สไลด์ 39–40)

  • ⭐ เป้าหมาย lowest page fault rate | เลือก page ที่ไม่ถูกใช้หนัก | ถูกแก้ → อัปเดต disk | local (process เดียวกัน) vs global (process อื่น)
  • ⭐ string 7 0 1 2 0 3 0 4 2 3 0 3 2 1 2 0 1 7 0 1, 3 frames: Optimal 9 | LRU 12 | FIFO 15 faults (สไลด์แสดง 11 ครั้งแรก: Optimal 7F/4H, FIFO 10F/1H)

14–22. อัลกอริทึม (สไลด์ 41–53)

หลักการ จุดจำ
⭐ Optimal evict label สูงสุด (ใช้อีกช้าสุด) ไม่ realistic
⭐ NRU 4 class จาก R,M → evict class ต่ำสุด class 0 = R0M0 … 3 = R1M1
⭐ FIFO evict ตัวอยู่นานสุด (head) ง่ายมาก แต่ไม่สนการใช้
Second-chance FIFO + R: 0 → แทนที่, 1 → clear + ไปท้าย list ตัวอย่าง: fault t = 20, A(R = 1) → B…H, A(20)
Clock วงกลม + เข็ม: 0 → evict ใส่ที่เดิม เลื่อนเข็ม 1 → clear + เลื่อนเข็ม
⭐ LRU evict ไม่ได้ใช้นานสุด ทำยาก (อัปเดต list ทุก reference)
NFU counter += R ทุก tick, evict ต่ำสุด never forgets
⭐ Aging shift ขวา 1 แล้วใส่ R ซ้ายสุด tick 4: page 3 = 00100000 ต่ำสุด
⭐ Working set R = 1 → time = CVT R = 0 & age > τ → out
  • Aging R bits: t0 101011 | t1 110010 | t2 110101 | t3 100010 | t4 011000 → t4: p0 01111000, p1 10110000, p2 10001000, p3 00100000, p4 01011000, p5 00101000
  • WS คำศัพท์: working set | demand paging (เริ่ม 0 page) | locality of reference | ⭐ thrashing (fault ทุกไม่กี่คำสั่ง) | prepaging (โหลดก่อนรัน) | ws(k, t) = page ที่ถูกอ้างใน k references ล่าสุด
  • WS เลือก: มี candidate → age สูงสุด | ไม่มี (R = 1 หมด) → เก่าสุดใน WS, สุ่ม ควร clean M = 0
  • ⭐ ตัวอย่าง CVT 2204, τ 700: 1213 (R0) age 991 → remove | 2014/2020/2032 (R1) → 2204 | 1620 (R0) age 584 → อยู่ต่อ

23. Summary (สไลด์ 54)

  • Optimal = benchmark | NRU = very crude ≈ LRU | FIFO = might throw out important | Second chance = big improvement over FIFO | Clock = realistic | LRU = excellent แต่ทำยาก | NFU = fairly crude ≈ LRU | ⭐ Aging = efficient ≈ LRU well | Working set = somewhat expensive | WSClock = good efficient

Base Limit จุดเริ่ม (บวก) vs ความยาว (เทียบ)

Bitmap Linked list หา k units ช้า vs ต้องรวม hole
First fit Next fit เริ่มต้น list vs เริ่มที่ค้างไว้

Swapping Paging ทั้ง process vs ทีละ page
Multilevel Inverted PT1 → PT2 vs 1 entry/frame ค้นทั้งตาราง

NFU Aging บวก R (ไม่ลืม) vs shift + R ซ้ายสุด
