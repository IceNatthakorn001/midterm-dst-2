3. สามเทคนิคของ I/O ⭐⭐

  1. Programmed I/O — ข้อมูลแลกกันระหว่าง processor กับ I/O module / processor รันโปรแกรมควบคุม I/O โดยตรง / สั่งแล้วต้องรอจน I/O ทำเสร็จ / ถ้า processor เร็วกว่ามาก เสียเวลาเปล่า
  2. Interrupt-driven I/O — processor สั่งแล้วไปทำคำสั่งอื่นต่อ / I/O module interrupt เมื่อเสร็จ
  3. DMA — I/O module กับ main memory แลกเปลี่ยนข้อมูลกันโดยตรง processor ไม่เกี่ยว
No Interrupts Use of Interrupts
I/O-to-memory ผ่าน processor Programmed I/O Interrupt-driven I/O
Direct I/O-to-memory – DMA

⚠️ DMA ก็ใช้ interrupt (แจ้งตอนเสร็จ) แต่ข้อมูลไม่วิ่งผ่าน processor 💡 เปรียบ: programmed = ยืนเฝ้าหน้าบ้าน / interrupt-driven = ทำงานอื่นรอกริ่ง / DMA = จ้างคนรับของแล้วเอาไปเก็บให้เลย

7. Interrupt-Driven I/O

แนวคิด: programmed I/O ทำให้ processor รอนาน → สั่ง command แล้วไปทำงานอื่นที่มีประโยชน์ → I/O module interrupt เมื่อพร้อม → processor โอนข้อมูลแล้วกลับไปทำงานเดิม

Simple Interrupt Processing ⭐ Hardware: 1. device controller ส่ง interrupt 2. processor ทำคำสั่งปัจจุบันให้เสร็จก่อน 3. ส่ง acknowledgment 4. push PSW และ PC ลง control stack 5. โหลด PC ใหม่ตาม interrupt Software: 6. save remainder of process state (register อื่น) 7. process interrupt 8. restore process state 9. restore old PSW and PC ⚠️ PC กับ PSW เก็บโดย hardware / register อื่นเก็บโดย software (ISR)

Changes in memory & registers: interrupt หลังคำสั่งที่ N → push N+1 + registers ลง control stack, SP ลดจาก T → T−M, PC = Y (จุดเริ่ม ISR) | ISR จบที่ Y+L (Return) → pop คืน PC = N+1, SP กลับเป็น T

9. Intel 82C59A & 8255A

  • 82C59A = interrupt controller รับ interrupt 8 เส้น (IR0–IR7) ต่อแบบ cascade: slave หลายตัวรับอุปกรณ์ตัวละ 8 (00–07, …, 56–63) → INT ของ slave ต่อเข้า IR0–IR7 ของ master → master INT → INTR ของ 80386 → รองรับ 64 อุปกรณ์
  • 8255A = Programmable Peripheral Interface: data bus D7–D0 ⇄ data bus buffer ⇄ 8-bit internal bus / read-write control logic (RD, WR, A1, A0, Reset, CS) / Group A: Port A (8 บิต) + Port C upper (4) / Group B: Port C lower (4) + Port B (8) / ชิป 40 ขา

Control Word ⭐ — D7 เป็นตัวแยกสองแบบ

(a) Mode definition (D7 = 1 Active) (b) Bit set/reset ของ Port C (D7 = 0 Active)
D6,D5 = Group A mode (00 = Mode 0, 01 = Mode 1, 1X = Mode 2) D6–D4 = Don't care
D4 = Port A (1 = Input, 0 = Output) D3–D1 = เลือกบิตของ Port C (000 = bit 0 … 111 = bit 7)
D3 = Port C upper (1 = In, 0 = Out) D0 = 1 set / 0 reset
D2 = Group B mode (0 = Mode 0, 1 = Mode 1)
D1 = Port B, D0 = Port C lower

Keyboard/Display interface: INPUT PORT A0–A7 ← keyboard (R0–R5, Shift, Control), C4/C5 = data ready/acknowledge, C3 = interrupt request | OUTPUT PORT B0–B7 → display (S0–S5, Backspace, Clear), C1/C2/C6/C7 = data ready/ack/blanking/clear line, C0 = interrupt request

10. DMA ⭐⭐

ข้อเสีย 2 ข้อของ programmed และ interrupt-driven I/O:

  1. อัตราการโอนถูกจำกัดด้วยความเร็วที่ processor ตรวจและให้บริการอุปกรณ์
  2. processor ต้องผูกติดกับการจัดการ I/O เพราะต้องรันหลายคำสั่งต่อการโอนแต่ละครั้ง → เมื่อต้องย้ายข้อมูลจำนวนมาก ใช้ DMA

ส่วนประกอบ DMA module: Data count (จำนวน word ที่ยังต้องโอน) | Data register (ต่อ data lines) | Address register (ต่อ address lines) | Control logic (Request to DMA, Acknowledge from DMA, Interrupt, Read, Write)

DMA vs Interrupt Breakpoints ⭐

  • Instruction cycle: Fetch Instruction → Decode → Fetch Operand → Execute → Store Result → Process Interrupt
  • DMA breakpoints: แทรกได้ หลายจุด ระหว่าง processor cycle (หลัง fetch, decode, fetch operand, execute, store)
  • Interrupt breakpoint: จุดเดียว ตอนท้าย cycle (หลัง Store Result)
  • ⚠️ DMA ไม่ใช่ interrupt — processor แค่หยุดใช้ bus ชั่วคราว ไม่ต้องเก็บ context จึงหยุดกลางคำสั่งได้

3 รูปแบบการต่อ DMA:

แบบ ลักษณะ
(a) Single-bus, detached DMA Processor, DMA, I/O, Memory ต่อ bus เดียวกันหมด — ถูกแต่ช้า (ข้อมูลข้าม bus 2 ครั้ง)
(b) Single-bus, integrated DMA-I/O DMA ติดกับ I/O (หรือคุม I/O หลายตัว) — ลดการใช้ system bus
(c) I/O bus DMA ต่อ system bus + มี I/O bus แยก — ขยายอุปกรณ์ง่าย

11. Intel 8237 DMA Controller

สัญญาณ: DREQ = DMA request | DACK = DMA acknowledge | HRQ = HOLD request | HLDA = HOLD acknowledge ลำดับ: 1. disk controller ส่ง DREQ → 2. 8237 ส่ง HRQ ขอยึด bus → 3. CPU ตอบ HLDA ปล่อย bus → 4. 8237 ส่ง DACK แล้วโอนข้อมูลกับ main memory (IOR, IOW, MEMR, MEMW) → 5. ยกเลิก HRQ คืน bus Fly-By DMA: ข้อมูลไม่วิ่งผ่านและไม่ถูกเก็บในชิป DMA → ใช้ได้เฉพาะ I/O port ↔ memory (ระหว่าง I/O สองตัว หรือ memory สองตำแหน่งไม่ได้ แต่ memory-to-memory ทำได้ผ่าน register) | 8237 มี 4 channels (0–3) โปรแกรมแยกกันได้ แต่ใช้ได้ทีละ channel Registers (E/D = enable/disable, TC = terminal count): Command (memory-to-memory E/D, channel 0 address hold, controller E/D, normal/compressed timing, fixed/rotating priority, late/extended write, DREQ/DACK sense) | Status (channel 0–3 reached TC + channel requests) | Mode (channel select, verify/write/read transfer, auto-initialization, address increment/decrement, demand/single/block/cascade mode) | Single Mask | All Mask

12. Direct Cache Access (DCA)

ทำไมต้องมี: DMA scale ไม่ทัน ความต้องการ data rate ของ network I/O — จาก Ethernet switch 10-Gbps และ 100-Gbps และ Wi-Fi ระดับ gigabit (3.2 / 6.76 Gbps) Xeon E5-2600/4600: 8 cores, แต่ละ core มี L1 64 KB (32 I + 32 D) + L2 256 KB, L3 ร่วม (บล็อกละ 2.5 MB), เชื่อมนอกชิปด้วย QPI (ไป processor อื่น), PCIe (ไป I/O), Memory Controller Hub (ไป DDR3) พื้นหลัง network: traffic ส่งเป็น packets / protocol data units — ระดับล่างสุดมักเป็น Ethernet ที่มี packet ของ protocol สูงกว่า (IP บน Ethernet, TCP บน IP) เป็น payload | ขาออก packet สร้างใน I/O controller / NIC | ขาเข้า I/O controller ตัดข้อมูล Ethernet ออกแล้วส่ง TCP/IP packet ให้ host CPU ปัญหาในแบบ DMA: แอปวางข้อมูลใน application buffer → core คัดลอกไป system buffer + สร้าง TCP/IP headers → packet ถูก DMA ส่งผ่าน NIC → ใช้ทั้ง main memory และ cache (ขาเข้าก็ต้องคัดลอกกลับทำนองเดียวกัน)

Packet traffic steps ⭐

Incoming (7) Outgoing (6)
1. Packet arrives 1. Packet transfer requested
2. DMA 2. Packet created
3. NIC interrupts host 3. Output operation invoked
4. Retrieve descriptors and headers 4. DMA transfer
5. Cache miss occurs 5. NIC signals completion
6. Header is processed 6. Driver frees buffer
7. Payload transferred

2 กลยุทธ์ DCA:

  1. แบบง่าย (prototype บน Intel Xeon ปี 2006–2010): ใช้ได้กับ incoming network traffic เท่านั้น — DCA function ใน memory controller ส่ง prefetch hint ให้ core ทันทีที่ข้อมูลพร้อมใน system memory → core prefetch data packet จาก system buffer ล่วงหน้า
  2. แบบดีกว่ามาก = เลี่ยง system buffer ใน main memory ไปเลย — packet และ descriptor ถูก core เข้าถึงใน system buffer แค่ครั้งเดียว (อ่านแล้วโอน payload ไป application buffer ไม่ต้องกลับมาอีก) = Cache injection ทำจริงใน Intel Xeon เรียกว่า DDIO (Direct Data I/O)
Normal DMA DDIO
ขาเข้า I/O controller → main memory → core ดึงขึ้น last level cache I/O controller → last level cache โดยตรง
ขาออก cache → main memory → I/O controller I/O controller ดึงจาก last level cache โดยตรง

13. Evolution of the I/O Function ⭐ (6 ขั้น)

  1. CPU ควบคุมอุปกรณ์โดยตรง
  2. เพิ่ม controller / I/O module — CPU ใช้ programmed I/O ไม่มี interrupt
  3. เหมือนข้อ 2 แต่ใช้ interrupt — CPU ไม่ต้องเสียเวลารอ
  4. I/O module เข้าถึง memory ได้โดยตรงด้วย DMA — ย้ายเป็น block โดยไม่ใช้ CPU ยกเว้นตอนเริ่มและจบ
  5. I/O module เป็น processor ของตัวเอง มี instruction set เฉพาะสำหรับ I/O
  6. I/O module มี local memory ของตัวเอง = คอมพิวเตอร์อีกเครื่อง คุมอุปกรณ์จำนวนมากโดย CPU แทบไม่ต้องยุ่ง (ขั้น 5–6 คือ I/O channel — แนวโน้มคือย้ายงาน I/O ออกจาก CPU เรื่อย ๆ)

I/O Channel Architecture: (a) Selector channel = ต่อ I/O controller หลายตัวแต่ให้บริการทีละตัว (เหมาะอุปกรณ์เร็ว) | (b) Multiplexor channel = สลับให้บริการหลายตัวพร้อมกัน (เหมาะอุปกรณ์ช้า)

  • ≤ 60 partitions per system, ≤ 15 partitions per channel subsystem, 4 channel subsystems, ≤ 256 channels per channel subsystem, ≤ 1024 partitions per system
  • ตู้ด้านหน้า: internal batteries (optional), power supplies, support elements, I/O cage carried forward, PCIe I/O drawer, FSP controller cards, Processor Books with Memory, HCA- and PCIe-Fanout cards, InfiniBand and PCIe I/O Interconnects, N+1 Water Cooling Units
  • Book 1–4 (Memory, PU, SC1/SC0 + PCIe 8x หรือ HCA2 8x) → PCIe I/O Drawer (PCIe switch → Fibre Channel controller, 10-Gbps Ethernet) และ I/O Cage & Drawer (InfiniBand multiplexor → ESCON, 1-Gbps Ethernet)
