1. Course Logistics

ทำไมต้องเรียน OS: เป็นซอฟต์แวร์ที่ใหญ่และซับซ้อนที่สุด / แนวคิดเอาไปใช้ที่อื่นได้เยอะ (Abstraction, Performance tuning, Resource coordination) / เป็นพื้นฐานของ Computer Security และ Parallel computing

Principles of OS — 4 เรื่อง: Process, Memory, Files, I/O 3 คำถามหลักของวิชา ⭐ (= Virtualization – Concurrency – Persistence)

  1. จะ virtualize ทรัพยากร อย่างไร (ให้แต่ละโปรแกรมรู้สึกเหมือนมีเครื่องของตัวเอง)
  2. จะสร้าง โปรแกรมที่ทำงานพร้อมกัน (concurrent) ให้ถูกต้อง ได้อย่างไร
  3. จะ เก็บข้อมูลให้คงอยู่ถาวร (persistently) ได้อย่างไร

2. Computer Architecture Review

ระบบคอมพิวเตอร์ 4 ชั้น (ล่างขึ้นบน):

# ส่วนประกอบ หน้าที่
1 Hardware ทรัพยากรพื้นฐาน: CPU, memory, I/O devices
2 Operating system ควบคุมและประสาน การใช้ hardware ระหว่างโปรแกรมของผู้ใช้หลายคน
3 Application programs กำหนดว่าจะ ใช้ทรัพยากรแก้ปัญหา อย่างไร (compiler, assembler, text editor, database)
4 Users คน เครื่องจักร หรือคอมพิวเตอร์อื่น

💡 OS อยู่ตรงกลาง — โปรแกรมไม่ได้คุยกับ hardware ตรง ๆ ต้องผ่าน OS เสมอ

Simplified architecture: CPU = Registers + ALU + Control Unit | Memory (RAM) | I/O Controllers เชื่อมไป I/O Devices (HDD, Floppy, CD-ROM, Tape, Mouse, Keyboard, Monitor, Printer, Network, Modem, Robots, Instrumentation) — ทุกส่วนเชื่อมด้วย bus

Fetch-Decode-Execute: Fetch (ดึงคำสั่งจาก memory) → Decode (ถอดความว่าต้องทำอะไร) → Execute (ทำตามคำสั่ง) → วนซ้ำจนโปรแกรมจบ

3. Roles of OS ⭐⭐

Fetch-Decode-Execute ดูง่าย แต่จริง ๆ ต้องจัดการ: รันหลายโปรแกรมพร้อมกัน / แบ่ง memory ให้หลายโปรแกรม / ควบคุมการเข้าถึง I/O ➜ OS ทำให้ระบบทำงาน ถูกต้อง (correctly) + มีประสิทธิภาพ (efficiently) + ใช้งานง่าย (easy-to-use)

บทบาทที่ 1: Virtualization of hardware

  • ทำไมต้อง virtualize: CPU รันได้ทีละไม่กี่คำสั่ง / memory ต้องแบ่งกันใช้ → OS ทำให้ทรัพยากรจริง "ดูเหมือนมีไม่จำกัด" → จึงเรียก OS ว่า virtual machine / extended machine
  • Virtualizing CPU: CPU รันได้ทีละคำสั่ง แต่ OS สลับระหว่างโปรแกรมเร็ว ๆ จนดูเหมือนรันพร้อมกัน → คำถามต่อ: จะสลับ process อย่างไร? โปรแกรมไหนควรได้ CPU ก่อน (scheduling)? (ตอบใน Lecture 2)
  • Virtualizing Memory: แต่ละโปรแกรมมี address space ของตัวเอง ทุกโปรแกรมเห็น address เริ่มที่ 0x00000 (virtual) แต่จริง ๆ อยู่คนละตำแหน่งใน physical memory → คำถามต่อ: map virtual → physical อย่างไร? จัดสรร memory อย่างไร? ถ้า physical memory ไม่พอทำอย่างไร?

บทบาทที่ 2: APIs

OS ให้ APIs (system calls / standard library) เพื่อให้ผู้ใช้บอก OS ได้ว่าต้องการอะไร (รันโปรแกรม, เข้าถึงไฟล์, จอง memory) — APIs ซ่อนความซับซ้อนของ hardware OS as an Interface: ให้ "beautiful interface" กับ application ด้านบน ซ่อน "ugly interface" ของ hardware ด้านล่าง 💡 เขียน open("file.txt") ได้เลย ไม่ต้องรู้ว่าหัวอ่านดิสก์ต้องไป sector ไหน

บทบาทที่ 3: Resource Manager

หลายโปรแกรมที่รัน concurrently ต้องแบ่ง CPU time / Memory space / Disk และ I/O devices → OS แจกทรัพยากรเพื่อ efficiency + fairness ⚠️ Virtualization = ทำให้ "ดูเหมือนมีไม่จำกัด" / Resource manager = "ตัดสินใจว่าใครได้อะไรเมื่อไหร่" — ทำงานคู่กัน

4. Design Goals ของ OS

เป้าหมาย ความหมาย
Abstraction ทำให้ระบบสะดวกและใช้ง่าย
Performance ลด overhead จากการ virtualize และจัดการทรัพยากร
Protection แยก process ออกจากกัน ไม่ให้ตัวหนึ่งทำร้ายตัวอื่น
Others energy-efficient, security, mobility

5. History of Operating Systems — 5 ยุค ⭐

ยุค ชื่อ Hardware / สภาพ แนวคิดสำคัญ
1 Human OS Mainframes คน (operator) คุมเครื่องเอง ทำทีละ job — เวลาเครื่องเสียเปล่าขณะ operator เดินไปมา
2 Batch System Mainframes, punch cards, tape OS ตัวแรก: Automatic job sequencing
3 Multiprogramming Hardware ถูก คนแพง (IBM System/360) โหลดหลาย job ใน memory, spooling
4 Personal Computer Hardware ถูกมาก คนแพงมาก Multitasking, Multiprocessing, GUI
5 Mobile Computers อุปกรณ์เล็ก ประหยัดพลังงาน, UI แบบใหม่, wireless

ยุค 2 — Batch System: operator รับ punch cards มาโหลด | Automatic job sequencing = ส่งต่อการควบคุมจาก job หนึ่งไปอีก job อัตโนมัติ + ลดเวลา setup โดยรวม job คล้ายกันเป็นชุด | ใช้กับงานคำนวณวิทยาศาสตร์/วิศวกรรม ภาษา FORTRAN + Assembly ขั้นตอนเครื่อง 1401/7094: นำ cards ไปเครื่อง 1401 → อ่าน cards ลง tape → นำ tape ไปเครื่อง 7094 ทำการคำนวณ → นำ tape กลับไปเครื่อง 1401 เพื่อพิมพ์ผล (แยกเครื่องเพราะ 7094 แพงและเร็ว ให้ทำแต่การคำนวณ ส่วนงาน I/O ช้า ๆ ให้ 1401 ที่ถูกกว่า)

ยุค 3 — Multiprogramming: โหลดหลาย job ไว้ใน memory แล้วสลับระหว่างกันอย่างรวดเร็ว → เพิ่ม CPU utilization (CPU ไม่ต้องนั่งรอตอน job หนึ่งรอ I/O) | memory แบ่งเป็น partitions (OS, Job 1, Job 2, Job 3) — เครื่องตัวอย่าง IBM System/360 Spooling = Simultaneous Peripheral Operation On Line: ทำ I/O ของ job หนึ่งซ้อนเวลากับการคำนวณของอีก job — ขณะรัน job หนึ่ง OS จะ อ่าน job ถัดไปจาก card reader ไปเก็บใน job queue บน disk และ ส่ง printout ของ job ก่อนหน้าจาก disk ไป printer Job pool (Job queue): โครงสร้างให้ OS เลือกว่าจะรัน job ไหนต่อ เพื่อเพิ่ม CPU utilization โดยเอา job ไปพักใน buffer ⚠️ Multiprogramming = หลาย job ใน memory แล้ว CPU สลับ / Spooling = ใช้ disk เป็นบัฟเฟอร์ให้ I/O ช้า ๆ ทำพร้อมการคำนวณ

ยุค 4 — PC: OS ให้ผู้ใช้คนเดียวทำหลายงานพร้อมกัน | Multitasking = รันหลายโปรแกรมพร้อมกัน (CPU ตัวเดียวก็ทำได้ด้วยการสลับ) | Multiprocessing = ใช้หลาย processor (ทำพร้อมกันจริง) | ใช้ GUI ไทม์ไลน์เด่น: 1975 IBM 5100, 1977 Apple II, 1983 Apple Lisa (GUI แรก), 1985 Atari/Amiga Workbench GUI, 1992 Windows 3.1, 1995 Windows 95, 2001 Mac OS X, 2009 Windows 7

ยุค 5 — Mobile: OS ต้องรองรับ Energy efficiency (แบตจำกัด) / User interface แบบใหม่ (จอสัมผัส) / Wireless network communication | Mobile OS คือ OS ที่ถูกใช้มากที่สุดตั้งแต่ปี 2017 ไทม์ไลน์ HTC: 1997 ก่อตั้ง, 1998 Windows CE PDA เครื่องแรก, 2005 สมาร์ทโฟน Windows 3G, 2007 HTC Touch (จอสัมผัส), 2008 HTC Dream (Android เครื่องแรก), 2009 HTC Sense, 2010 4G Android เครื่องแรกในสหรัฐฯ, 2014–2017 HTC VIVE (VR)

Migration of OS Concepts: แนวคิดเกิดบน mainframes ก่อน (compilers, time shared, batch, resident monitors, multiuser, distributed, multiprocessor, fault tolerant) แล้วค่อย ๆ ย้ายลง minicomputers → microcomputers → network computers | เส้นทแยง MULTICS (1960s, mainframe) → UNIX (1970, mini) → UNIX (1980, micro)

คู่ที่มักสับสน

คู่ ต่างกันที่
Virtualization / Resource manager ทำให้ดูเหมือนมีไม่จำกัด / ตัดสินใจแจกทรัพยากร
Virtual / Physical address ที่โปรแกรมเห็น / ตำแหน่งจริงใน RAM
Batch / Multiprogramming ทำทีละ job ต่อกัน / หลาย job ใน memory แล้วสลับ
Multiprogramming / Spooling CPU สลับหลาย job / ใช้ disk พัก I/O
Multitasking / Multiprocessing หลายโปรแกรม / หลาย processor

แนวคิดที่ต้องอธิบายได้

  • ทำไมต้องมี OS ทั้งที่ fetch-decode-execute ดูง่าย → เพราะต้องรันหลายโปรแกรม แบ่ง memory คุม I/O ให้ถูกต้อง มีประสิทธิภาพ และใช้ง่าย
  • ทำไม OS ถูกเรียกว่า extended machine → เพราะให้เครื่องเสมือนที่ใช้ง่ายกว่าและดูมีทรัพยากรมากกว่าของจริง
  • ทำไม multiprogramming เพิ่ม CPU utilization → CPU ไม่ต้องรอเมื่อ job หนึ่งรอ I/O สลับไปทำ job อื่นได้
  • ทำไมยุค mobile ต้องเน้นพลังงาน → เพราะอุปกรณ์ใช้แบตเตอรี่
