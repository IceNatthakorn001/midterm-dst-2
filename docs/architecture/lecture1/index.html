2. Computer Architecture Review (สไลด์ 10–15)

2.1 Components of Computer Systems (สไลด์ 11–12)

ภาพ: users 1…n → system and application programs (compiler, assembler, text editor, database system) → operating system → computer hardware

  1. Hardware — ให้ทรัพยากรคำนวณพื้นฐาน (CPU, memory, I/O devices)
  2. Operating system — ควบคุมและประสานการใช้ hardware ระหว่าง application programs ต่าง ๆ สำหรับผู้ใช้หลายคน
  3. Application programs — กำหนดวิธีใช้ทรัพยากรระบบเพื่อแก้ปัญหาการคำนวณ
  4. Users — คน เครื่องจักร คอมพิวเตอร์อื่น

2.2 Simplified Computer Architecture (สไลด์ 13)

  • CPU: Registers, Arithmetic & Logic Unit, Control Unit
  • Memory: RAM
  • Input/Output Controllers → I/O Devices: Hard Disk Drive, Floppy Disk Drive, CD Rom Player, Tape Unit | Mouse, Keyboard, Monitor, Printer | Network, Modem | Robots, Instrumentation

2.3 How an instruction is run (สไลด์ 14)

ภาพจากวิดีโอ (youtube.com/watch?v=XM4lGflQFvA) แสดง CPU (registers, ALU, IR, decoder, CU, PC, MAR) เชื่อมกับ memory ผ่าน data bus, control lines, address bus

2.4 Fetch-Decode-Execute (สไลด์ 15)

สำหรับแต่ละคำสั่งในโปรแกรม processor จะ:

  1. Fetch คำสั่งจาก memory
  2. Decode (หาว่าต้องทำอะไร)
  3. Execute (เช่น บวกเลขสองตัว …)

ทำซ้ำจนโปรแกรมจบ

3. Operating Systems (สไลด์ 16–26)

3.1 Ultimate Goal: Easy-to-use System (สไลด์ 17)

  • Fetch-Decode-Execute ดูง่าย แต่มีอีกหลายอย่างที่ทำให้โปรแกรมของผู้ใช้รันได้ราบรื่น เช่น
    • รันหลายโปรแกรมพร้อมกัน (สำหรับผู้ใช้หลายคน)
    • แชร์ memory ระหว่างโปรแกรม
    • ควบคุมการเข้าถึง I/O devices
  • OS ดูแลให้ระบบทำงานถูกต้องและมีประสิทธิภาพ ในแบบที่ใช้ง่าย

3.2 Roles of OS (สไลด์ 18)

เพื่อให้ระบบ ใช้ง่าย มีประสิทธิภาพ และถูกต้อง — OS คือ software ที่มีบทบาทหลัก 3 อย่าง:

  1. Virtualization of physical resources
  2. APIs (standard library)
  3. Resource manager

3.3 บทบาทที่ 1: Virtualization of hardware (สไลด์ 19–22)

  • ทรัพยากรจริงมีจำกัด:
    • CPU รันได้ไม่กี่คำสั่งต่อครั้ง
    • memory ต้องแบ่งกันระหว่างโปรแกรม
  • OS ทำให้ทรัพยากรจริงดูเหมือนมีไม่จำกัด → เรียกเทคนิคนี้ว่า Virtualization
  • บางครั้งเรียก OS ว่า virtual machine หรือ extended machine
  • ภาพ (สไลด์ 20): Program 1–4 แต่ละตัวเห็น Resources ของตัวเอง ทั้งหมดอยู่บน Operating System + Hardware ซึ่งรวมกันเป็น Extended Machine

ตัวอย่าง: Virtualizing CPU (สไลด์ 21) — OS สลับระหว่างโปรแกรม (CPU รันทีละคำสั่ง) คำถามที่เกิด:

  • จะ สลับระหว่างโปรแกรม (processes) อย่างไร?
  • โปรแกรมไหนควรได้ CPU ก่อน?

ตัวอย่าง: Virtualizing Memory (สไลด์ 22) — แต่ละโปรแกรมมี address space ของตัวเอง (virtual address เริ่มที่ 0x00000 ทุกโปรแกรม แต่ map ไปคนละที่ใน physical memory) คำถามที่เกิด:

  • จะ map program address ไป physical address อย่างไร?
  • จะ จัดสรร memory ให้โปรแกรมอย่างไร?
  • ถ้า physical memory ไม่พอ ทำอย่างไร?

3.4 บทบาทที่ 2: APIs (สไลด์ 23–24)

  • ให้ผู้ใช้บอก OS ว่าจะทำอะไร เช่น รันโปรแกรม, เข้าถึงไฟล์, จอง memory
  • OS ให้ APIs (system calls หรือ standard library) ให้ผู้ใช้และ application เรียกใช้บริการของ OS
  • APIs ซ่อนความซับซ้อนของ hardware
  • OS as an Interface to the hardware (สไลด์ 24): Application programs → (Beautiful interface) → Operating system → (Ugly interface) → Hardware

💡 OS เปลี่ยน interface ที่ "น่าเกลียด" ของ hardware ให้เป็น interface ที่ "สวย" สำหรับโปรแกรม

3.5 บทบาทที่ 3: Resource Manager (สไลด์ 25)

  • โปรแกรมที่รันพร้อมกันต้องแชร์ทรัพยากร: CPU time, memory space, disk และ I/O devices อื่น
  • OS จัดสรรทรัพยากรให้โปรแกรมเพื่อให้ได้ high efficiency และ fairness

3.6 Design Goals (สไลด์ 26)

Goal ความหมาย
Abstraction ทำให้ระบบสะดวกและใช้ง่าย
Performance ลด overhead ของการ virtualize และจัดการทรัพยากร
Protection แยก process ออกจากกัน ไม่ให้ทำร้ายกัน
Others Energy-efficient, security, mobility

4. History of Operating Systems (สไลด์ 27–40)

4.1 ยุคที่ 1: Human OS (สไลด์ 28)

  • Hardware: Mainframes
  • OS: human operators
    • ทำ ทีละ job (job = หน่วยของการประมวลผล)
    • เวลาคอมพิวเตอร์สูญเปล่า ขณะ operator เดินไปมาในห้องเครื่อง

4.2 ยุคที่ 2: Batch System (สไลด์ 29–31)

  • มี operator (คน) รับ cards (โปรแกรมจากผู้ใช้) มาโหลดเข้าเครื่อง
  • OS ตัวแรก: Automatic job sequencing
    • ส่งต่อการควบคุมจาก job หนึ่งไปอีก job
    • ลด setup time ด้วยการรวม (batch) jobs ที่คล้ายกัน
  • ใช้ส่วนใหญ่กับการคำนวณทางวิทยาศาสตร์และวิศวกรรม
  • ภาษา: FORTRAN และ Assembly
  • ขั้นตอน (สไลด์ 30):
    1. นำ cards ไปที่ 1401
    2. อ่าน cards ลง tape
    3. นำ tape ไปใส่ 7094 ซึ่งทำการคำนวณ
    4. นำ tape ไปใส่ 1401 ซึ่งพิมพ์ output
  • สไลด์ 31: ภาพ punched cards (FORTRAN statement)

4.3 ยุคที่ 3: Multiprogramming และ Spooling (สไลด์ 32–33)

Multiprogramming (ตัวอย่างเครื่อง IBM System/360):

  • Hardware ถูก คนแพง
  • OS โหลด หลาย jobs เข้า memory และสลับไปมาอย่างรวดเร็ว → เพิ่ม CPU utilization

Spooling = Simultaneous Peripheral Operation On Line:

  • ทำ I/O ของ job หนึ่งซ้อนกับการคำนวณของอีก job
  • ขณะรัน job หนึ่ง OS:
    • อ่าน job ถัดไปจาก card reader ไปเก็บใน disk (job queue)
    • ส่ง printout ของ job ก่อนหน้าจาก disk ไป printer
  • Job pool (Job queue):
    • โครงสร้างที่ให้ OS เลือก job ถัดไปเพื่อเพิ่ม CPU utilization
    • ใส่ jobs ไว้ใน buffer ที่อุปกรณ์เข้าถึงได้เมื่ออุปกรณ์พร้อม

4.4 ยุคที่ 4: Personal Computer (สไลด์ 34–35)

  • Hardware ถูกมาก คนแพงมาก
  • OS ให้ผู้ใช้ทำหลายงานพร้อมกัน
    • Multitasking: รันหลายโปรแกรมบนเครื่องเดียวพร้อมกัน
    • Multiprocessing: ใช้หลาย processor บนเครื่องเดียว
  • ใช้ GUI (Graphic User Interface)
  • History of Personal Computers (สไลด์ 35): timeline ตั้งแต่ปี 1975 (IBM 5100) ถึง Windows 7 (2009) และ Apple MacBook (2006–present) เช่น 1977 Apple II, 1980 IBM 5120, 1981 IBM PC/Apple III, 1983 Apple Lisa (ใช้ GUI ครั้งแรก), 1985 Atari/Amiga, 1986 IBM PC XT, 1991 Macintosh PowerBook, 1992 Windows 3.1, 1993/2009 Windows NT, 1995 Windows 95, 1997 Mac OS 8, 2000 Windows 2000, 2001 Mac OS X

4.5 ยุคที่ 5: Mobile Computers (สไลด์ 36–37)

  • Hardware: อุปกรณ์ขนาดเล็ก
  • ความต้องการเพิ่มจาก OS: energy efficiency, user interface แบบต่าง, wireless network communication
  • Mobile OS เป็น OS ที่ใช้มากที่สุด (ตั้งแต่ปี 2017)
  • History of Mobile Computers (สไลด์ 37): timeline ของ HTC ตั้งแต่ 1997 (HTC founded in Taiwan), 1998 Windows CE PDA, 2005 Windows 3G smartphone, 2007 touch-centric smartphone (HTC Touch), 2008 first Google Android smartphone (HTC Dream), 2010 first 4G Android ใน US, 2013 metal body, 2015, 2016 HTC Vive, 2017 Edge Sense
ยุค Hardware OS / จุดเด่น
1. Human OS Mainframes คน (operator) ทำทีละ job
2. Batch Mainframes + cards/tape automatic job sequencing, batch jobs คล้ายกัน, FORTRAN/Assembly
3. Multiprogramming IBM System/360 (hardware ถูก คนแพง) หลาย jobs ใน memory + spooling
4. Personal Computer hardware ถูกมาก multitasking, multiprocessing, GUI
5. Mobile อุปกรณ์เล็ก energy, UI ใหม่, wireless; ใช้มากสุดตั้งแต่ 2017

4.6 Migration of OS Concepts and Features (สไลด์ 38)

แนวคิดจาก mainframes (1950–1990: no software → compilers → batch, resident monitors → time shared, multiuser (MULTICS) → distributed systems, multiprocessor, fault tolerant) ย้ายลงมาสู่ minicomputers (UNIX ~1970) → microcomputers (UNIX ~1980, interactive, multiuser, multiprocessor) → network computers ตามลำดับ

💡 สิ่งที่ภาพแสดง: ฟีเจอร์ที่เกิดบน mainframe จะปรากฏบนเครื่องเล็กลงในอีกหลายปีต่อมา
