📖 อ่านฉบับเต็ม📝 ทำแบบทดสอบ
🎬 แอนิเมชันของบทนี้▶ CPU Scheduling: FIFO · SJF · STCF · Priority · RR▶ MLFQ: Multi-level Feedback Queue

Intro

  • Process = วงจร CPU burst ↔ I/O burst | ระหว่าง I/O CPU ว่าง = BAD → สลับไป process อื่น = GOOD
  • CPU-bound: burst ยาว น้อยครั้ง | I/O-bound: burst สั้น หลายครั้ง
  • Multiprogramming: deschedule ตัวที่รัน + schedule ตัวที่ ready → ภาพลวงว่ามีหลาย CPU
  • ⭐ ต้อง schedule เมื่อ: yield, blocked (I/O), รอ child, terminate, timer interrupt
  • Queues: ready queue → CPU → (I/O request → I/O queue) / (time slice expired) / (fork child) / (wait for interrupt) → กลับ ready queue
  • ตารางเรียนใน Lecture 3 อัปเดตจาก Lecture 1 (OS#7 Sec1 = อังคาร 24 พ.ย. 10–12 IT311, Sec2 = พฤหัส 26 พ.ย. 14–16 IT323)

⭐ Goals & Metrics

ระบบ เป้าหมาย
All fairness, policy enforcement, balance
Batch throughput, turnaround time, CPU utilization
Interactive response time, proportionality
Real-time meeting deadlines, predictability
  • Turnaround = CPU time + waiting time (= เสร็จ − มาถึง)
  • Waiting = เวลาใน ready queue | Response = first run − arrival (ไม่ใช่ output ทั้งหมด) | Throughput = งานเสร็จ/เวลา
  • ดี: max CPU util., throughput | min turnaround, waiting, response
  • ตัวอย่าง: P1 wait 0 TT 24, P2 wait 24 TT 27, P3 = ? (สไลด์ไม่ให้ burst ของ P3)

⭐ Algorithms + ตัวเลข

Algorithm หลัก ตัวอย่าง (avg)
FIFO/FCFS มาก่อนได้ก่อน 10/10/10 → 20; 100/10/10 → 110 (convoy effect)
SJF งานสั้นก่อน (non-preemptive) 100/10/10 → 50; B,C มา T=10 → 103.3
STCF SJF + preempt A(0–10) → B → C → A → 50
Priority เลขน้อย = สำคัญ → starvation P1..P5 → (คำนวณเอง) P2,P5,P1,P3,P4 → TT 1,6,16,18,19 → 12
RR สลับทุก quantum q q=1: response 1, TT 14
SJF เทียบ RR response 5, TT 10
  • Non-preemptive: FIFO, SJF (ถือ CPU จนจบหรือ waiting) | Preemptive: ถูกแย่งได้ (clock, priority สูงกว่า)
  • RR: q ใหญ่ → FIFO | q เล็ก → context switch overhead | response ดี, fairness เยี่ยม, turnaround แย่
  • Overhead: process 10 → q12 = 0 switch, q6 = 1, q1 = 9 | slice 10 ms + switch 1 ms ≈ 10% เสีย
  • ⚠️ ตัวอย่าง RR สไลด์เขียน "each needs 15s" แต่กราฟ/คำตอบตรงกับงานละ 5s

Incorporating I/O

  • blocked → เลือก process อื่น | I/O เสร็จ → อาจให้ตัวนั้นรันทันที | overlap CPU กับ I/O
  • A, B ใช้ CPU 50; A ทำ I/O 10 ทุก 10 | ไม่ overlap → (90 + 140)/2 = 115
  • STCF แบ่ง A เป็น sub-jobs 10 ms, B ถูก preempt เมื่อ A พร้อม → (90 + 100)/2 = 95

⭐ MLFQ (Corbato et al.)

  • ปัญหา: SJF/STCF ดีต่อ turnaround แต่ OS ไม่รู้ run time | RR ดีต่อ response แต่ turnaround แย่
  • เป้าหมาย: response ต่ำสำหรับ interactive + turnaround ต่ำโดยไม่รู้ความยาวงาน
  • หลาย queue ต่าง priority, แต่ละ queue ใช้ RR, เริ่มบนสุดแล้วเลื่อนลง | Rule | | |---|---| | 1 | Priority(A) > Priority(B) → A รัน | | 2 | เท่ากัน → RR ด้วย quantum ของ queue | | 3 | งานใหม่ → queue บนสุด | | 4 | ใช้ time allotment หมด (ไม่ว่าสละ CPU กี่ครั้ง) → ลง 1 ระดับ — กัน gaming ("Cheater!") | | 5 | ทุกช่วง S → ย้ายทุก job ขึ้นบนสุด (priority boost) — กัน starvation + ปรับเมื่อพฤติกรรมเปลี่ยน |
  • งานสั้นเสร็จเร็วในระดับบน, งานยาวลงไป Q0 | interactive (I/O มาก) อยู่ระดับบน
  • Config ตัวอย่าง: Q0 RR 8 ms → Q1 RR 16 ms → Q2 FCFS

⭐ Real OS

  • Linux 2.6+: real-time (SCHED_FIFO, SCHED_RR, preemptive priority, สูงกว่า) | normal (SCHED_OTHER, SCHED_BATCH) ใช้ CFS
  • CFS: เลือก virtual runtime ต่ำสุด, รัน 1 slice แล้วใส่กลับ runqueue, RB tree
  • nice −20 (สูงสุด) ถึง +19 (ต่ำสุด) | nice 0: physical = virtual | nice ต่ำ: physical > virtual | nice สูง: physical < virtual
  • Windows: priority-based preemptive, thread priority สูงสุดรันก่อน (จน block / หมด slice / ถูก preempt) | 32 ระดับ: variable 1–15, real-time 16–31, 0 = memory-management thread | queue ต่อ priority
  • Priority classes: real-time 16–31, อื่น ๆ 1–15 (เช่น normal/normal = 8, real-time/time-critical = 31)
  • quantum หมด → priority ลด (ไม่ต่ำกว่า base) | wait → boost | foreground window boost 3×
