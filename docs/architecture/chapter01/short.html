⭐ Architecture vs Organization

Architecture Organization
คำถาม WHAT HOW
คือ สิ่งที่ programmer เห็น มีผลต่อ logical execution operational units + interconnections ที่ทำให้ architecture เกิดจริง
ตัวอย่าง instruction set, addressing modes, data types วงจร, cache, pipeline, design, bus width, clock speed
เกี่ยวกับ ผู้ใช้/โปรแกรมเมอร์ วิศวกรฮาร์ดแวร์
  • Old view = ออกแบบ ISA (registers, memory addressing, addressing modes, operands, operations, control flow, encoding)
  • Real = ตาม requirement ของเครื่อง, performance สูงสุดภายใต้ cost, power, availability, รวม ISA + microarchitecture + hardware

Classes of Computers

  • Supercomputers: คำนวณวิทย์/วิศวะระดับสูง, ความสามารถสูงสุด แต่ส่วนแบ่งตลาดเล็ก
  • Embedded: ซ่อนในระบบอื่น, ข้อจำกัด power/performance/cost เข้มงวด

Cloud

  • Cloud computing = เข้าถึง shared pool ของ resources ผ่านเครือข่ายแบบ on demand | Cloud networking = เครือข่ายที่รองรับ cloud | Cloud storage = database storage/app บน cloud server
  • SaaS = application software | PaaS = platform ให้แอปลูกค้ารัน | IaaS = VM + hardware/OS แบบ abstract คุมผ่าน API
Client จัดการ CSP จัดการ
Traditional IT ทั้งหมด —
IaaS Applications → Databases OS → Networking
PaaS Applications Framework → Networking
SaaS — ทั้งหมด
  • ทาง Traditional: complex, upfront cost สูง, scalable น้อย, customizable มาก | ทาง SaaS: ตรงข้าม

Understanding Performance

Algorithm → จำนวน operations | Language/compiler/architecture → machine instructions ต่อ operation | Processor & memory → คำสั่งเร็วแค่ไหน | I/O (รวม OS) → I/O เร็วแค่ไหน

⭐ Eight Great Ideas

Moore's Law · abstraction · common case fast · parallelism · pipelining · prediction · hierarchy of memories · dependability via redundancy

Software layers / Code levels

  • Applications software → Systems software (compiler แปล HLL → machine code; OS: I/O, memory & storage, scheduling & sharing) → Hardware (processor, memory, I/O controllers)
  • HLL (ใกล้ปัญหา, productivity & portability) →Compiler→ Assembly (textual instructions) →Assembler→ Binary (bits, encoded instructions & data)

Components / CPU

  • Components: Input, CPU, Memory (RAM), Storage, Motherboard, Output, Power Supply, GPU
  • CPU: Control Unit (ควบคุม), ALU (ประมวลผลข้อมูล), Registers (ที่เก็บใน CPU), CPU interconnection (เชื่อม 3 ส่วน)
  • ⭐ Machine cycle: Fetch (จาก memory) → Decode (Control Unit) → Execute (ALU) → Store (ลง memory)
  • Registers: PC, IR, Status register (status, flags)

Cache

  • L1 เร็วสุด เล็กสุด, L2 รองลงมา | อยู่ระหว่าง processor กับ main memory, เล็กกว่าและเร็วกว่า
  • เก็บข้อมูลที่น่าจะใช้เร็ว ๆ นี้ | หลายระดับ L1 ใกล้ core สุด → L2, L3 ไกลออกไป
  • WHEN = ใช้ได้เร็วที่สุด | WHERE = อยู่ใกล้ผู้ใช้ที่สุด

⭐ Multi-core vs Multi-thread

Multi-core Multi-thread
hardware จริง virtual (เทคนิคแบ่งงาน)
ประมวลผลงานใหญ่แยกกันแบบ parallel จัดการงานเบื้องหลัง แบ่งงานย่อยป้อน core
= จำนวนเชฟ = จำนวนแขนของเชฟ
Hyper-Threading (Intel), SMT (AMD)

ฮาร์ดแวร์จริง / การผลิต

  • Multicore computer: Motherboard (memory chips, I/O chips, processor chip) → Processor chip (cores + L3) → Core (instruction logic, ALU, load/store, L1 I/D, L2 I/D)
  • ผลิต IC: ingot → slicer → blank wafers → 20–40 steps → patterned wafers → wafer tester → dicer → tested dies → bond to package → part tester → ship
  • ⭐ Yield = proportion of working dies per wafer
  • Core i7 wafer: 300mm, 280 chips, 32nm, ชิปละ 20.7 × 10.5 mm
  • Single processor performance: 25%/yr → 52%/yr → 23%/yr → 12%/yr → 3.5%/yr

RISC vs CISC

  • RISC = Reduced, CISC = Complex Instruction Set Computing
  • RISC: PC → Program Memory → IR → Decoder → CW → Data path | CISC: PC → Program Memory → mPC → mPM → CW → Data path
  • mPC = microprogram counter, mPM = Microprocessor Mode

Embedded / ARM

  • Embedded: electronics+software ในผลิตภัณฑ์, ผลิตหลายพันล้านต่อปี, tightly coupled กับ environment, real-time constraints
  • ARM: มาจากหลัก RISC, ARM Holdings (Cambridge, England), die เล็ก, power ต่ำ, ใช้มากที่สุดในโลก, = Acorn/Advanced RISC Machine
  • Products: Cortex-A/A50, Cortex-R, Cortex-M (M0, M0+, M3, M4)
  • Cortex-M: interrupt เร็ว deterministic, power ต่ำ | M3: 16/32-bit, มี debug & trace

Parallelism / Flynn

  • Applications: DLP, TLP | Architecture: ILP, Vector/GPU, Thread-level, Request-level | | | |---|---| | SISD | single instr., single data | | SIMD | vector, multimedia ext., GPU | | MISD | ⭐ ไม่มีเชิงพาณิชย์ | | MIMD | tightly / loosely coupled |

System-level patterns

Monolithic (ระบบเดียว) · Client-server (ขอ/ให้บริการ) · Distributed (กระจายบนเครือข่าย) · Microservices (โมดูล deploy แยก, เป็น software pattern มากกว่า)

⭐ Performance — สูตร

  • Performance = 1 / Execution Time
  • X เร็วกว่า Y n เท่า: n = Perf_X / Perf_Y = Time_Y / Time_X
  • Elapsed time = ทุกอย่าง (processing, I/O, OS overhead, idle) → system performance | CPU time = เฉพาะงานนั้น (user + system CPU time)
  • Clock period เช่น 250ps = 0.25ns | Clock rate เช่น 4.0GHz = 4.0×10⁹Hz
  • CPU Time = Clock Cycles × Cycle Time = Clock Cycles / Clock Rate
  • Clock Cycles = IC × CPI → CPU Time = IC × CPI × Cycle Time = IC × CPI / Clock Rate
  • ทำให้เร็วขึ้น: ลด cycles หรือเพิ่ม clock rate (ต้อง trade off กัน)
  • IC ขึ้นกับ program, ISA, compiler | CPI ขึ้นกับ CPU hardware และ instruction mix

⭐ โจทย์ในสไลด์

โจทย์ คำตอบ
A 10s, B 15s 15/10 → A เร็วกว่า 1.5×
A: 2GHz 10s; B ต้อง 6s, cycles ×1.2 Cycles_A = 20×10⁹ → Rate_B = 24×10⁹/6 = 4GHz
A: 250ps CPI 2.0; B: 500ps CPI 1.2 A = I×500ps, B = I×600ps → A เร็วกว่า 1.2×

Compiler vs Assembler HLL→assembly vs assembly→binary
