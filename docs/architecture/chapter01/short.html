1. Architecture vs Organization ⭐

Architecture Organization
คำถาม WHAT ทำอะไรได้ HOW ทำให้เกิดจริงอย่างไร
นิยาม คุณลักษณะที่ โปรแกรมเมอร์มองเห็น มีผลต่อการทำงานเชิงตรรกะของโปรแกรม หน่วยปฏิบัติการ + การเชื่อมต่อ ที่ทำให้ architecture เกิดขึ้นจริง
ตัวอย่าง instruction set, addressing modes, data types cache, pipeline, bus width, clock speed
ใครสน ผู้ใช้ / โปรแกรมเมอร์ วิศวกรฮาร์ดแวร์

Defining CA: "Old" view = ออกแบบ ISA อย่างเดียว (registers, memory addressing, addressing modes, instruction operands, available operations, control flow, instruction encoding) / "Real" = ตอบความต้องการของเครื่องเป้าหมาย ให้ performance สูงสุดภายใต้ cost, power, availability = ISA + microarchitecture + hardware

2. Classes of Computers & Cloud

  • Supercomputers = ความสามารถสูงสุด งานวิทย์/วิศวะ แต่เป็นส่วนน้อยของตลาด | Embedded = ซ่อนอยู่ในระบบอื่น ข้อจำกัดเข้มด้าน power / performance / cost
  • Cloud computing = เข้าถึงผ่านเครือข่ายได้ทุกที่ สะดวก on demand ไปยังกลุ่มทรัพยากรที่ใช้ร่วมกันและปรับแต่งได้ | Cloud networking = เครือข่ายที่จำเป็นต่อ cloud | Cloud storage = DB บน server ระยะไกล
  • SaaS = ซอฟต์แวร์ | PaaS = แพลตฟอร์มให้เอาแอปของตัวเองมารัน | IaaS = VM + hardware/OS แบบ abstract คุมผ่าน API
  • Stack 10 ชั้น: Traditional IT (ลูกค้าจัดการทั้งหมด) → IaaS (CSP ดู VM/server/storage/networking) → PaaS (ลูกค้าเหลือ Applications + Framework) → SaaS (CSP ทั้งหมด)
  • ทิศทาง: Traditional ซับซ้อนกว่า ลงทุนแรกสูง scale ยาก แต่ customize ได้มาก ↔ SaaS ง่าย ถูก scale ง่าย แต่ customize ได้น้อย

3. Understanding Performance — อะไรกำหนดอะไร

ส่วน กำหนด
Algorithm จำนวน operation
Language / compiler / architecture จำนวน machine instruction ต่อ operation
Processor & memory system คำสั่งรันเร็วแค่ไหน
I/O system (รวม OS) I/O operation เร็วแค่ไหน

4. Eight Great Ideas ⭐

  1. Design for Moore's Law 2. Use abstraction to simplify design 3. Make the common case fast 4. Performance via parallelism 5. via pipelining 6. via prediction 7. Hierarchy of memories 8. Dependability via redundancy

5. Below Your Program & Levels of Code

  • Application software (เขียนด้วย HLL) → System software (Compiler แปล HLL → machine code; OS จัดการ I/O, memory & storage, schedule งานและแบ่งทรัพยากร) → Hardware (processor, memory, I/O controllers)
  • HLL (ใกล้ problem domain ให้ productivity + portability) →compiler→ Assembly (ข้อความแทนคำสั่ง เช่น RISC-V add x6,x10,x6) →assembler→ Binary (bits)

6. Components & Inside the CPU

  • ภายนอก: Input, CPU, Memory (RAM), Storage, Motherboard, Output, Power Supply, GPU — สไลด์เน้น Processor = Control + Datapath
  • ภายใน CPU: Control Unit (ควบคุม) / ALU (ประมวลผลข้อมูล) / Registers (เก็บข้อมูลใน CPU เร็วที่สุด) / CPU interconnection (สื่อสารระหว่างกัน)
  • Machine cycle 4 ขั้น: Fetch → Decode (Control Unit) → Execute (ALU) → Store (ฝั่ง OS Lecture 1 พูดแค่ 3 ขั้น ไม่มี store)
  • Registers: PC = address คำสั่งถัดไป | IR = คำสั่งที่กำลังรัน | Status register = flags (zero, negative, carry) — เชื่อม memory/I-O ผ่าน Control Bus + Data Bus

7. Cache Memory ⭐

  • หลายชั้นของ memory ระหว่าง processor กับ main memory เล็กกว่า + เร็วกว่า main memory ดึงข้อมูลที่ น่าจะถูกใช้ในอนาคตอันใกล้ มาวางไว้
  • L1 เร็วสุด/เล็กสุด อยู่ใน core → L2 → L3 ไกลออกไปเรื่อย ๆ | ตัวอย่าง: CORE1/CORE2 ต่างมี L1 Data Cache ของตัวเอง แชร์ Smart-Shared L2 ต่อ System Bus
  • WHEN = ให้ใช้ข้อมูลได้เร็ว (early) ที่สุด | WHERE = ให้ข้อมูลอยู่ใกล้ (close) ผู้ใช้ที่สุด

8. Multi-core vs Multi-thread ⭐

Multi-core Multi-thread
hardware มีอยู่จริงทางกายภาพ เสมือนจริง (เทคนิคแบ่งการทำงาน)
รับงานชิ้นใหญ่ประมวลผลแยกกันแบบ parallel จัดการงานเบื้องหลัง แบ่งงานย่อยป้อนให้ core
= จำนวนเชฟในครัว = จำนวนแขนของเชฟ

เทคโนโลยีจริง: Hyper-Threading (Intel), SMT (AMD) มุมมอง 3 ระดับ: MOTHERBOARD (main memory chips, I/O chips, processor chip) → PROCESSOR CHIP (หลาย core + L3 cache) → CORE (instruction logic, ALU, load/store logic, L1 I-cache, L1 data cache, L2 I-cache, L2 data cache)

9. ฮาร์ดแวร์จริง & การผลิต IC

  • ตัวอย่าง: เมนบอร์ด 2× Intel Quad-Core Xeon (DDR3-1333 six channel ถึง 48GB, Intel 3420 chipset, SATA, USB, VGA, BIOS, Ethernet, PCIe) / Apple A5 = ARM cores + CPU/GPU blocks + DDR SDRAM interface รวมในชิปเดียว (SoC)
  • ขั้นตอนผลิต IC: Silicon ingot →slicer→ blank wafers →20–40 processing steps→ patterned wafers →wafer tester→ tested wafer →dicer→ tested dies →bond die to package→ packaged dies →part tester→ ship to customers
  • Yield = สัดส่วนของ die ที่ใช้งานได้ต่อ wafer | Core i7 wafer: 300mm, 280 chips, 32nm, ชิปละ 20.7 × 10.5 mm

10. Single Processor Performance (1978–2018)

25%/ปี (78–86) → 52%/ปี (86–03) → 23% (03–11) → 12% (11–15) → 3.5% (15–18) หลังปี 2003 เร่ง clock ต่อไม่ได้เพราะความร้อน/พลังงาน จึงหันไป multi-core / parallelism

11. RISC vs CISC ⭐

RISC (Reduced Instruction Set Computing) CISC (Complex Instruction Set Computing)
PC → Program Memory → IR → Decoder → CW → Data path PC → Program Memory → mPC → mPM → CW → Data path
คำสั่งน้อย เรียบง่าย ขนาดคงที่ decode ตรงด้วยวงจร (hardwired) คำสั่งมาก ซับซ้อน ขนาดไม่คงที่ แปลผ่าน microprogram
ARM, RISC-V Intel x86

(mPC = microprogram counter, mPM = microprocessor mode, CW = control word)

12. Embedded Systems & ARM

  • Embedded = ใช้อิเล็กทรอนิกส์ + ซอฟต์แวร์ภายในผลิตภัณฑ์ ผลิตหลายพันล้านเครื่อง/ปี อุปกรณ์ที่ใช้ไฟฟ้าส่วนใหญ่มี — ผูกแน่นกับสภาพแวดล้อม: real-time constraints + ต้องจัดการหลายกิจกรรมพร้อมกัน (ทำให้ข้อจำกัด real-time ซับซ้อนขึ้น)
  • ARM = สถาปัตยกรรมที่พัฒนาจากหลักการ RISC โดย ARM Holdings (Cambridge, England) — die เล็ก ใช้พลังงานต่ำ ความเร็วสูง เป็น embedded processor ที่ใช้มากที่สุดและเป็น processor ที่ใช้มากที่สุดในโลก / ย่อจาก Acorn RISC Machine → Advanced RISC Machine
  • ตระกูล: Cortex-A / A50 (งานประยุกต์ทั่วไป) Cortex-R (real-time) Cortex-M (M0, M0+, M3, M4 = microcontroller)
  • Cortex-M: fast, interrupt management แบบ deterministic, ใช้พลังงานต่ำ | M3: งาน 16/32-bit มี debug & trace features

13. Parallelism & Flynn's Taxonomy ⭐

  • ในตัวแอป: DLP (Data-Level Parallelism) / TLP (Task-Level Parallelism)
  • ในฮาร์ดแวร์: ILP (เช่น pipelining) / Vector architectures & GPUs / Thread-Level / Request-Level
ชื่อเต็ม ตัวอย่าง
SISD single instruction, single data processor เดี่ยวแบบดั้งเดิม
SIMD single instruction, multiple data vector architectures, multimedia extensions, GPU
MISD multiple instruction, single data ไม่มีเครื่องเชิงพาณิชย์
MIMD multiple instruction, multiple data tightly-coupled (multicore แชร์ memory) / loosely-coupled (cluster)

จำ: ตัวแรก = instruction, ตัวที่สาม = data; S = single, M = multiple

14. System Level Architecture Patterns

Monolithic (ระบบเดียวรวมทุกอย่าง) | Client-server (ผู้ขอ / ผู้ให้บริการ) | Distributed systems (กระจายการคำนวณหลายเครื่องผ่านเครือข่าย) | Micro services (บริการย่อยแบบโมดูล deploy แยกอิสระ)

15. Performance — สูตรที่ต้องท่อง ⭐⭐

Performance = 1 / Execution Time
Perf_X / Perf_Y = Time_Y / Time_X = n        ("X เร็วกว่า Y n เท่า")
CPU Time = CPU Clock Cycles × Clock Cycle Time = CPU Clock Cycles / Clock Rate
Clock Cycles = Instruction Count × CPI
CPU Time = IC × CPI × Clock Cycle Time = (IC × CPI) / Clock Rate
Clock Rate = 1 / Clock Period
  • Elapsed time = เวลาตอบสนองรวม (processing + I/O + OS overhead + idle) บอกประสิทธิภาพทั้งระบบ | CPU time = เวลาที่ CPU ใช้ทำงานนั้นจริง ไม่นับ I/O และเวลาที่แบ่งให้งานอื่น = user CPU time + system CPU time
  • Clock period เช่น 250ps = 0.25ns = 250×10⁻¹²s | Clock rate เช่น 4.0GHz = 4×10⁹Hz (1/250ps = 4GHz)
  • ปรับปรุง performance: ลดจำนวน clock cycles หรือ เพิ่ม clock rate — แต่ trade off กัน (clock เร็วขึ้นมักต้องใช้ cycle มากขึ้น)
  • Instruction Count กำหนดโดย program + ISA + compiler | CPI กำหนดโดย CPU hardware และขึ้นกับ instruction mix

ตัวอย่างคำนวณที่ออกสอบ

(1) เร็วกว่ากี่เท่า: A ใช้ 10s, B ใช้ 15s → 15/10 = A เร็วกว่า B 1.5 เท่า (เวลาของตัวช้าอยู่บนเศษ) (2) หา clock rate ใหม่: A: 2GHz, 10s → Cycles_A = 10 × 2×10⁹ = 20×10⁹ ; B ต้องการ 6s และ cycles ×1.2 → Rate_B = (1.2 × 20×10⁹)/6 = 4GHz (3) เทียบ CPI: A: 250ps, CPI 2.0 → I×500ps ; B: 500ps, CPI 1.2 → I×600ps → 600/500 = A เร็วกว่า B 1.2 เท่า (ISA เดียวกัน IC จึงตัดกันได้ — ต้องดูทั้ง 3 ปัจจัยรวมกัน)
