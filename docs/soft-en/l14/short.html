Lecture 14 – Agentic Software Engineering

📖 ฉบับเต็ม⚡ สรุปสั้น

1. ASE (สไลด์ 4–5)

  • ⭐ ใช้ AI coding agent plan, implement, test, iterate | เปลี่ยนวิธีจัดงาน ไม่ใช่แค่ tool | dev ยังต้องรักษา standards, quality, oversight
  • Traditional: dev ตัดสินใจ → AI แนะนำโค้ด → dev accept/reject
  • ⭐ Agentic: dev บอก task → agent plan + implement → agent รัน test + iterate → dev review + verify

2. LLM vs Agent (สไลด์ 6–7)

  • ⭐ LLM = ทำนายข้อความต่อ | ไม่มี persistent state | ทำ action จริงไม่ได้ | ไม่รู้ว่าโค้ดรันได้ไหม
  • ⭐ Agent = LLM (reasoning engine) + tools | อ่านโค้ด แก้ไฟล์ รันคำสั่ง รัน test | plan → execute → observe → iterate
  • ตาราง: LLM alone ทำได้แค่ generate code | agent ได้ทั้ง read files, shell, run tests, maintain state, adapt plan, irreversible actions

3. Taxonomy 6 levels (สไลด์ 8–9)

L Name ตัวอย่าง SAE
0 Manual Coding Notepad, vi, Emacs No Automation
1 Token Assistance IntelliSense, tab-completion Driver Assistance
2 Task-Agentic Copilot, CodeWhisperer, Tabnine Partial
3 ⭐ Goal-Agentic Claude Code, Devin, Jules, Codex Conditional
4 Specialised Domain Autonomy GPT-5 (frontend), security agents High
5 General Domain Autonomy ยังไม่มีจริง ณ 2025 Full

4. ประเภท agent (สไลด์ 10–14)

  • ⭐ Terminal (file system + shell): Claude Code (ไม่ต้องเปิด browser/IDE), Gemini CLI
  • ⭐ AI-native IDE: Cursor (เห็นทั้ง codebase, chat panel) | Windsurf (proactive เสนอเองแบบ pair programmer)

5. Components (สไลด์ 15–19)

  • ⭐ Tools (primitive action) | Skills (reusable, หลาย tool call) | Connectors (ระบบภายนอก: DB, API) | Memory (ข้าม step/session/agent)
  • Tools: read_file, write_file, run_command, search_code, fetch_url, create_branch, submit_pr
  • Skills = reusable prompt/template | Claude Code ใช้ slash command (/review, /test) | code-review, write-tests, security-scan (OWASP Top 10), refactor-rename
  • Connectors: LLM สร้างได้แค่ข้อความ → GitHub, files, issue, DB, CI/CD, PR, docs/API
  • ⭐ Memory: In-context (session เดียว, จบ session) | External (ข้าม session, ไม่มีกำหนด, CLAUDE.md, vector DB) | Episodic (ข้าม task, สรุปงานเก่า) | Semantic (ข้าม agent, ข้อเท็จจริงร่วม/conventions)

6. Agentic SDLC (สไลด์ 20–28)

แก่นวน Spec → Generate → Verify → Refine

  • ⭐ Spec 6 ส่วน: context | inputs/outputs | behaviour rules (≥ 5) | constraints (ห้ามทำ) | examples (normal, edge, error) | quality attributes
  • ตัวอย่าง calculate_average(): [80,90,70]→80.0 | [0,100]→50.0 | [75.5,80.5]→78.0 | [] / [-10,60] / [80,"70"] → Error | O(n), validate input
  • ⭐ Generate 3 decisions: which model (เก่ง = security/ซับซ้อน, เร็ว = boilerplate) | which agent (terminal/IDE) | what context
  • ⭐ Verify = ต้องใช้ human judgment มากที่สุด | checklist: functional correctness, edge cases, security, error handling, type correctness, test coverage, conventions, no accidental side effects
  • ⭐ Refine triggers: test fail → เพิ่ม example | deprecated lib → เพิ่ม constraint | เข้าใจ domain ผิด → เพิ่มนิยาม | ผิด convention → เพิ่มใน context | เป้าหมาย = ปรับ spec

7. Key practices (สไลด์ 29–34, Hassan 2025)

⭐ Pattern ⭐ Anti-pattern
Specification-first Prompt-and-pray (prompt คลุมเครือ ship ไม่ verify; test ผ่าน ≠ ตรง spec)
Verification-driven generation Confidence by plausibility (plausible ≠ correct)
Context file discipline (CLAUDE.md, .cursorrules, อัปเดตเสมอ) Context starvation (โค้ดไม่เข้ากับระบบ)
Incremental delegation (เริ่มเล็ก, trust ตามประเภทงาน) Overlong agentic sessions (ผิดตั้งแต่ต้นลามไปหมด)
Commit granularity (เล็ก, review ได้) Ownership transfer (โยนความรับผิดชอบให้ AI)

8. Productivity vs Risk (สไลด์ 35–36)

  • AI เก่ง: routine code, test scaffolding, documentation, boilerplate, code translation
  • ⭐ routine/well-defined → gain มาก | novel logic/architecture/stakeholder decisions → gain จำกัด
  • ⭐ Risks: overreliance & skill loss | responsibility & accountability | intellectual property | increasing impact of mistakes (blast radius → ปรับอิสระตามความย้อนได้) | security (prompt injection)

9. Summary (สไลด์ 37)

  • Review everything (first draft) | ห้าม commit โค้ดที่ไม่เข้าใจ | ตั้ง delegation boundaries
  • ⭐ Reversible (แก้ไฟล์, เขียน test) = มอบได้ + review | Irreversible (DB migration, production deploy) = คนอนุมัติก่อน
