Lecture 13 – Unit Testing, Integration Testing, and System Testing

⏱ อ่านประมาณ 6 นาที · 12 หัวข้อ

📖 ฉบับเต็ม⚡ สรุปสั้น

1. Testing & phases (สไลด์ 4–5)

  • testing = หาว่าโค้ด (method, class, program) ทำงานตามที่ตั้งใจ | ประเมิน correctness, completeness, quality | หา bug เร็ว ลดต้นทุน | เพิ่มความมั่นใจ
⭐ Phase ทดสอบ ต้นทุน / ความถี่
Unit ส่วนเล็กสุดที่ test ได้ เร็วสุด ถูกสุด ทำบ่อย
Integration กลุ่ม module ปานกลาง รันน้อยลง
System ระบบครบ เทียบ requirement แพงสุด รันไม่บ่อย

2. Good unit test (สไลด์ 6)

  • ⭐ ทีละ function (ไม่พึ่งส่วนอื่น) | รันเร็ว | อัตโนมัติใน CI/CD | ผลเหมือนเดิมทุกครั้ง

3. JUnit (สไลด์ 7–14)

  • กลางยุค 90 | มาตรฐาน TDD ใน Java | JAR ตอน compile | annotation + assert + test runners | Eclipse, Ant, Maven
  • tools อื่น: Jmockit, Cactus, Cobertura, Dbunit, dJUnit (> 30)
  • ⭐ Checklist: Initialize → Write test cases → Write test suite → Execute test suite
  • ⭐ @Test = method นี้รันเป็น test ได้
  • ⭐ Assert: assertEquals (ค่าเท่า) | assertTrue | assertFalse | assertNotNull | assertNull | assertSame (object เดียวกัน) | assertNotSame | assertArrayEquals
  • ตัวอย่าง Student: getDisplayName() = first + " " + last → test Space ✓ | test Nospace ✗

4. Integration (สไลด์ 15–17)

  • ⭐ ทดสอบ interaction → หาปัญหา interface, data flow, dependency | เช่น function ที่พึ่ง DB | สะพาน unit ↔ system
Unit Integration System
Spec module interface interface specs, module breakdown requirements spec
Visible coding details architecture none
Scaffolding some often extensive some
Faults in modules interactions, compatibility system functionality
  • ⭐ unit = รากฐาน (controllability + visibility สูงสุด) | integration ทดแทน unit ไม่ได้ | เจอ module fault ตอน integration = unit test ไม่พอ | fault ที่ interface ระหว่าง module ที่ถูก = ปัญหา module breakdown / interface spec

5. System (สไลด์ 18–19)

  • ⭐ ระบบครบ ตรง functional + non-functional req ในสถานการณ์จริง
  • ⭐ Functional | Non-functional (performance, usability, reliability) | Security
  • V&V: Requirements↔Acceptance (validation) | HLD↔System, DD↔Integration, Coding↔Unit (verification)

6. เอกสาร (สไลด์ 20–22)

  • Test case: ID, priority, module, title, description, designed/executed by/date, pre-conditions, dependencies, steps, data, expected, actual, status, post-conditions
  • Test report: passed/failed → executed, pending/in progress/blocked → planned | ต่อ function: % executed, % passed, pending, priority
  • ⭐ RTM: Business Req → Functional Req → Test Case ID (เช่น BR_1 → FR_1 → TC#001, #002)

7. Regression (สไลด์ 23–24)

  • ⭐ เช็กว่าการแก้ล่าสุด ไม่สร้าง bug ใหม่/ไม่ทำของเดิมพัง
  • ⭐ ใช้: after bug fixes | after new features/enhancement | after performance improvements | routine maintenance

8. Quality model & usability (สไลด์ 25–27)

  • ⭐ 8 ด้าน: Functional Suitability | Performance Efficiency | Compatibility | Usability | Reliability | Security | Maintainability | Portability
  • Usability = ใช้ง่ายและมีประสิทธิภาพแค่ไหน → ถูกนำไปใช้มากขึ้น + productivity
  • ⭐ 5 components: Learnability (ทำ task ได้ง่าย) | Efficiency (เร็ว) | Memorability (กลับมาคล่อง) | Errors (ผิดกี่ครั้ง) | Satisfaction (รู้สึกดี)

9. Usability testing (สไลด์ 28–30)

  • ทดสอบกับ ผู้ใช้ในอนาคต → ตรงเป้า/requirement ไหม
  • ⭐ Task-based (หา pain points) | A/B (เทียบ 2 design) | Surveys/Questionnaires
  • Performance measurement (เชิงปริมาณ): เวลาทำ task, จำนวน task ในเวลาจำกัด, success:error, เวลากู้ error, จำนวน error, feature ที่ไม่เคยใช้, การเปิด manual/help

10. Best practices (สไลด์ 31)

  • ⭐ modular & isolated | test ใน CI/CD | test สม่ำเสมอ | simulate dependencies | coverage ที่มีความหมาย ไม่ใช่ไล่ 100%

11. Exercises (สไลด์ 33–40)

  • Ex5 BVA ตั๋ว: reduced −1 Error | 0, 11 Free | 12, 17 → 100 | 18, 60 → 200 | 61 → 100 (⚠️ class "> 61")
  • ⭐ Ex6 ECP ส่วนลด: ≤0 (−5) invalid | 1–500 (450) ไม่ลด | 501–999 (658) 5% | 1,000–4,999 (2,599) 10% | 5,000–100,000 (45,100) 20% | >100,000 (111,111) invalid
  • ⭐ Ex7 BVA ส่วนลด reduced: −1 | 1, 500 | 501, 999 | 1000, 4999 | 5000, 100000 | 100001
  • ⚠️ เฉลย Ex6–7 ขัดโจทย์ที่ 500 (โจทย์ < 500 ไม่ลด, 500–999 ลด 5%) และ 5,000 (โจทย์ > 5,000)
  • Ex8 Zoo get_ticket_price: 4 decision → 5 independent paths (สไลด์ไม่มีเฉลย คิดตามสูตร L12)
