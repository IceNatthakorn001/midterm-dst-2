Lecture 10 – Node.js Part II (Express Framework)

0. Unit + Objective (สไลด์ 2–4)

  • Part I: Hello World, Module System, first server | Part II: Express | Part III: Cookies, Session, Database
  • เป้าหมาย: สร้าง server ด้วย Express | routing | form handling

1. RECAP Node.js + http server (สไลด์ 5–9)

  • ⭐ Node.js = asynchronous JS runtime บน Chrome's V8 | "open-source server environment"
  • ⭐ ไม่มี: DOM, document, window, Cookies | มี: JS code + modules (File system, HTTP, Utilities)
  • server ตอบเป็น plain text / HTML / JSON | localhost port 8081
  • ⭐ http.createServer((req,res)=>{ res.statusCode=200; res.setHeader("Content-Type","text/plain"); res.write("Hello World!"); res.end(); }) → myServer.listen(8081, cb)
  • ผล: console Listening on the port 8081 | browser Hello World! | browser ขอ / และ /favicon.ico
  • ⚠️ สไลด์ 9 log "The new request comming" ไม่มีในโค้ดสไลด์ 8 | URL ที่ถูก http://localhost:8081

2. Routing ด้วย http module (สไลด์ 10–13)

  • routing = ส่ง request ไปโค้ดที่จัดการ | ใช้ req.url
  • ⭐ / → 200 text/plain "Greeting" | /shabu, /bbq → fs.readFile → 200 text/html | อื่น ๆ → 404 text/plain "Invalid requested :("
  • console: Req: /bbq Req: /SOMEPATH Req: / Req: /shabu
  • ⚠️ template สไลด์ 12 ขาด }); ปิด createServer

3. Express (สไลด์ 14–16)

  • ⭐ minimal and flexible Node.js web application framework | robust features for web & mobile
  • ช่วย: routing, สร้าง API, ใช้ template engine (Pug, EJS) — แทนตัวแปรด้วยค่าจริงตอน runtime → แปลงเป็น HTML
  • อันดับต้นของ Node.js frameworks | เปิดตัว 2010 | de facto standard | MIT license | MVC, routing table, 14+ engine templates, debugging

4. ตั้งโปรเจกต์ (สไลด์ 17–24)

  • ⭐ npm init (→ package.json, entry point app.js) → npm install express (→ dependencies) → [optional] npm install nodemon (restart อัตโนมัติ) → สร้าง app.js
  • NPM = package manager | package.json = meta-data + dependencies
  • ⭐ const app = express(); app.get('/', (req,res)=>res.send('Hello World from Root!')); app.listen(3000, ...) → Server listening on port: 3000
  • ⭐ "scripts": { "start": "nodemon app.js" } → npm start
  • โฟลเดอร์: node_modules, package-lock.json, package.json, app.js, html/(bbq, shabu)

5. express.Router() (สไลด์ 25–27)

  • ⭐ Middleware = ฟังก์ชันที่เข้าถึง req และ res
  • ⭐ const router = express.Router(); app.use(router); router.get('/', ...)
  • ตัวอย่าง route: /, /shabu, /bbq, /product/view = GET | /product/add, /user/add = POST
  • nodemon รันใหม่เมื่อแก้ app.js

6. sendFile + 404 (สไลด์ 28–30)

  • ⭐ router.get('/shabu', (req,res)=>res.sendFile(path.join(`${__dirname}/html/shabu.html`)))
  • __dirname = absolute path ของโฟลเดอร์ไฟล์ที่รัน | path.join = รวม path
  • /somewhere ไม่ได้กำหนด → Cannot GET /somewhere
  • ⭐ router.use((req,res,next)=>{ res.status(404).send("Invalid Path") }) วางท้ายสุด | ถูกเรียกทุก HTTP method
  • ⚠️ อย่าตัดบรรทัดใน backtick ของ path (รันจริงได้ ENOENT)

7. Navbar (สไลด์ 31)

  • href="/", "/shabu", "/my-form" | ⭐ href ต้องตรงกับ route ใน app.js

8. Static files (สไลด์ 32–34)

  • relative path ../public/mystyle.css ใช้ไม่ได้ → No CSS or images
  • ⭐ app.use('/', express.static(path.join(__dirname,'public'))) | '/' = mount path
  • ⭐ HTML อ้าง /mystyle.css, /images/sampleImg.png (public ถูก reset เป็นราก) | /public/mystyle.css → 404

9. Modular routes (สไลด์ 35–38)

  • เว็บใหญ่ → แบ่ง router: app / | router1 /product (add, edit, delete) | router2 /user (add, edit, view) | routerN /module
  • ⭐ app.use("/product", router1) + router1.get('/add') = /product/add
URL (port 3030) ผล
/ Homepage
/product Module for product - Root
/product/add Module for product - Add
/user Module for user - Root
/user/add Module for user - Add

10. Form handling (สไลด์ 39–45)

  • validate ที่ client เมื่อทำได้ (JS, HTML5) | ส่งด้วย GET หรือ POST | validate เพิ่มที่ server ถ้าลง database
  • Flow: GET → empty form → user กรอก → POST → validate → ไม่ผ่าน: form + error messages (กรอกใหม่) | ผ่าน: perform actions → redirect to "success" URL
  • ⭐ <form action="ปลายทาง" method="GET/POST"> | server อ่านค่าตาม name
  • router.get('/my-form', ...) sendFile myForm.html (fname=John, lname=Doe)

11. GET (สไลด์ 46–48)

  • ⭐ action="/form-get" method="GET" → URL /form-get?fname=John&lname=Doe
  • ⭐ router.get("/form-get", ...) → req.query.fname (req.query = ค่าหลัง ?)
  • path ตรงกับ action | method ตรงกับ method
  • console: GET + { fname: 'John', lname: 'Doe' } | response: Form submitted by John Doe with GET

12. POST (สไลด์ 49–52)

  • ⭐ action="/form-post" method="POST" → ข้อมูลอยู่ใน body
  • ⭐ ต้องมี middleware (body-parser รวมใน Express ตั้งแต่ 4.16): router.use(express.json()); router.use(express.urlencoded({ extended: true }));
  • express.json() = JSON payload | express.urlencoded() = urlencoded payload
  • ⭐ router.post("/form-post", ...) → req.body.fname (string หรือ JSON object)
  • response: Form submitted by John Doe with POST | ไม่มี middleware → req.body = undefined

คู่ที่มักสับสน

A B ต่างกัน
http module Express if/else + header/write/end เอง vs router.get + res.send
res.send res.sendFile ข้อความ vs ไฟล์ (absolute path)
text/plain text/html ข้อความ/error vs หน้า HTML
router.get router.use GET + path ตรง vs ทุก method (ดัก 404)
app.use(router) app.use("/product", router1) ที่ root vs มี mount path นำหน้า
node app.js npm start (nodemon) รันครั้งเดียว vs restart อัตโนมัติ
__dirname path.join โฟลเดอร์ไฟล์ที่รัน vs รวม path
../public/x.css /x.css ไม่ทำงาน vs ทำงานหลังตั้ง express.static
GET POST URL → req.query vs body → req.body + middleware
express.json() express.urlencoded() JSON vs urlencoded
action method ส่งไปไหน vs ส่งแบบไหน
อ่านจบแล้ว ลองทดสอบความเข้าใจ
