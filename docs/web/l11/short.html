Lecture 11 – Node.js Part III (Cookies, Session, and Database)

⏱ อ่านประมาณ 10 นาที · 17 หัวข้อ

📖 ฉบับเต็ม⚡ สรุปสั้น
🧠 Quiz Pro

โค้ด cookie / session / dotenv รันจริงแล้ว (Node 22, Express 5.3.0) | ส่วน DB ไม่ได้ต่อ MySQL จริง ตรวจเฉพาะฝั่ง Express ด้วย connection จำลอง

0. Unit + Objective (สไลด์ 2–4)

  • Part I: Hello World, Module System, first server | Part II: Express | Part III: Cookies, Session, Database
  • เป้าหมาย: สร้าง cookies/sessions | ต่อ Node.js กับ relational DB
  • Outline: RECAP Express → Env Variables → Cookies + Session → Database + Node.js

1. RECAP Express (สไลด์ 5–7)

  • ⭐ minimal and flexible Node.js web application framework | ช่วย routing, สร้าง API, ใช้ template engine (Pug, EJS) → แทนตัวแปรด้วยค่าจริงตอน runtime → HTML

2. ตั้งโปรเจกต์ (สไลด์ 8–11)

  • ⭐ npm init (ถามตอบ) | npm init -y (default) | npm install (ทั้งหมดใน package.json, หลัง clone/pull) | npm install <pkg> (เพิ่ม library) | npm uninstall <pkg>
  • ขั้นตอน: โฟลเดอร์ → npm init → entry point app.js → ติดตั้ง express + nodemon → "start": "nodemon app.js" → npm start
  • Router: const router = express.Router(); app.use(router); router.get('/', ...) | /my-form → res.sendFile(path.join(...))
  • ⚠️ สไลด์ 10 เขียน npm init <package> → ที่ถูกคือ npm install <package> | ⚠️ เครื่องหมาย ’ ในโค้ดสไลด์ 11, 24, 27, 28 → SyntaxError

3. Environment Variables (สไลด์ 12–14)

  • ⭐ = key-value ของค่าตั้งค่า (PORT, API_KEY, DB_HOST, DB_NAME) นอก source code
  • ทำไม: รันได้หลายเครื่อง/cloud | ไม่ hardcode | โค้ดเดียว deploy ได้ทุกที่ | portable & maintainable
  • ⭐ npm install dotenv → .env ที่ root (PORT=3000) → require("dotenv") + dotenv.config() → process.env.PORT
  • dotenv = zero-dependency module โหลด .env เข้า process.env | VSCode extension: DotENV
  • รันจริง: dotenv พิมพ์ ◇ injected env (N) from .env (N = จำนวนตัวแปร)

4. Stateless (สไลด์ 15–17)

  • ⭐ HTTP stateless = ไม่มีความเชื่อมโยงระหว่าง 2 request | cookies ทำให้เป็น stateful sessions
  • เก็บข้อมูล 2 แบบ: Cookies = client | Session = server

5. Cookie (สไลด์ 18–19)

  • ⭐ ข้อมูลชิ้นเล็กที่ server ส่งให้ browser → browser เก็บ → ส่งกลับกับ request ไป server เดิม
  • ใช้: Session management | Personalization | Tracking (บอกว่า 2 request มาจาก browser เดียวกัน)
  • ⭐ server ส่ง Set-Cookie (response) | browser ส่งกลับใน Cookie header (request) | ใส่ unique identifier → ระบุตัว client ได้

6. ใช้ Cookie (สไลด์ 20–26)

  • ⭐ npm install cookie-parser → const cp = require("cookie-parser"); router.use(cp());
  • ⭐ สร้าง res.cookie('cookie#1','chocolate-chip-cookie') | อ่านทั้งหมด req.cookies | อ่านตัวเดียว req.cookies['cookie#1']
  • /setCookie → console About to create a cookie | ดูใน DevTools > Application > Cookies (Expires = Session)
  • /showCookie → {"cookie#1":"chocolate-chip-cookie","cookie#2":"peanut-butter-cookie"}
  • ⭐ /restrict: มีครบ 2 ตัว → You are allowed to see the content | ขาดตัวใด → 401 Error 401: You need to have our secret cookies
  • ⭐ {expire: 360000 + Date.now()} = วันเวลาหมดอายุ | {maxAge: 360000} = อายุ 360000 ms | res.clearCookie("username") = ลบ
  • ⚠️ รันจริง: expire (ไม่มี s) ไม่มีผล | maxAge: 360000 → Max-Age=360 (วินาที)

7. Login / Logout (สไลด์ 27–28)

  • / → login.html | /login (ฟอร์ม GET) → res.cookie('tokenID','some-random-session-ID') → Login !! (ของจริงต้องตรวจ username/password ก่อน)
  • /restrict → มี tokenID → Valid Only the ones with cookie only | ไม่มี → 401 | console Accessed the restricted page some-random-session-ID
  • ⭐ /logout → res.clearCookie("tokenID") → Logout !! → เข้า /restrict อีกได้ 401

8. Cookie vs Session (สไลด์ 29–30)

  • Cookies (และ URL parameters) ขนข้อมูล client↔server ได้ แต่ อ่านได้ฝั่ง client
  • ⭐ Session = ข้อมูลใช้ได้ ทุกหน้า ในเว็บแอป เก็บ ฝั่ง server (protected from clients)

9. express-session (สไลด์ 31–34)

  • ⭐ npm install express-session | middleware เก็บ session ใน storage — default MemoryStore (dev/debug เท่านั้น ไม่ใช่ production)
  • ⭐ router.use(session({ secret: process.env.SESSION_SECRET, resave: false, saveUninitialized: true }))
  • secret = sign session ID | resave: false = เซฟเมื่อถูกแก้ | saveUninitialized: true = สร้างให้ทุกคน
  • ⭐ /pageview: ไม่มี numviews → =1 + First time visited | มี → ++ + Visited${n} times | ส่ง Session created!!! ทุกครั้ง
  • req.session สร้าง/อ่าน | req.session.<name> ใช้ได้จาก ทุก route
  • รันจริง: console First time visited, Visited2 times, Visited3 times… | restart server → MemoryStore หาย → First time visited ใหม่ | ไม่มี secret → 500 secret option required for sessions
  • ⚠️ สไลด์ 34 แสดง Visited 2 times (โค้ดไม่มีเว้นวรรค → Visited2 times) และหน้าเว็บ Visited 10 times (โค้ดส่ง Session created!!! เสมอ) | ⚠️ สไลด์ 32 บรรทัด const ค้าง

10–11. DB + RECAP (สไลด์ 35–39)

  • ⭐ วิชานี้ใช้ mysql2 (npm install mysql2) → query, insert, update, delete ผ่าน SQL
  • DB หลายแบบ: Relational, Graph, XML | Relational = schemas, tables, queries, reports, views
  • tinycollege 6 ตาราง: Department(🔑dept_code) | Professor(🔑emp_num) | Student(🔑stu_num) | Enroll(🔑class_code+stu_num) | Class(🔑class_code) | Course(🔑course_code)
  • 9 ความสัมพันธ์: (1) prof works in dept | (2) dept head = prof | (3) student in dept | (4) student advisor = prof | (5) class taught by prof | (6) course offered by dept | (7) students enroll many classes | (8) classes enrolled by many students | (9) class belongs to course
  • SQL = ภาษามาตรฐานเก็บ/แก้/ดึงข้อมูล + จัดการ DB ใน DBMS | INSERT, UPDATE, DELETE, SELECT (WHERE, GROUP BY, HAVING, ORDER BY)

12. เตรียม MySQL (สไลด์ 40–44)

  • ติดตั้ง MySQL Server + Workbench | เข้า server ด้วย root account
  • สร้าง DB/tables (GUI หรือ tinycollege.sql) → สร้าง user (Username, Password, Host = localhost) → privilege
  • Workbench: Server > Users and Privileges > Add Account (เช่น tinyCollegeUser, host localhost) → Schema Privileges tinycollege = DELETE, INSERT, SELECT, UPDATE

13. เชื่อม DB (สไลด์ 45–46)

  • npm install express nodemon dotenv mysql2 | .env มี PORT + ค่าต่อ DB
  • ⭐ mysql.createConnection({ host, user, password, database }) (ค่าจาก process.env.MYSQL_*) → connection.connect(err => { if(err) throw err; ... })
  • ผล: Server listening at Port 3000 → Connected DB: tinycollege
  • ⚠️ สไลด์ 45 ยกชื่อ DB_USER/DB_PWD/DB_HOST แต่โค้ดใช้ MYSQL_* → ชื่อต้องตรงกัน

14. SELECT (สไลด์ 47–48)

  • ⭐ SELECT course_code, course_name FROM Course WHERE dept_code='CIS' → 6 rows (CIS-220, CIS-320, CIS-370, CIS-420, QM-261, QM-362)
  • ⭐ connection.query(sql, function(error, results){ if(error) throw error; console.log(`${results.length} rows returned`); return res.send(results); })
  • /cis-courses → JSON array [{"course_code":"CIS-220","course_name":"Intro. to Microcomputing"}, ...]
  • ⚠️ log ในโค้ด "Retrieved CIS courses" แต่ terminal สไลด์ "Retrieved all courses"

15. INSERT (สไลด์ 49)

  • ⭐ ตัวอย่างใช้ GET (/add241) เพื่อความง่าย — ปกติใช้ POST
  • INSERT INTO Course VALUES('CIS-223','Introduction to Web Development',3,'CIS') → results.affectedRows → 1 record inserted → res.redirect(...)
  • terminal: 6 rows → insert → 7 rows returned
  • ⚠️ res.redirect("/cis-course") ขาด s → รันจริงได้ 404 Cannot GET /cis-course | log Adding 223 vs terminal Adding CIS-212, Port 8080

16. Extra (สไลด์ 50)

  • INSERT/UPDATE/DELETE เพิ่มเติมที่ w3schools | mysql2 รองรับ Promise API + async/await (ES7)
