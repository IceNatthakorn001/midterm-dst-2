1. ทบทวน: HTML คืออะไร และเอกสาร HTML มีโครงยังไง? สไลด์ 4–9

แก่นHTML คือ markup language มาตรฐานของเว็บ ไฟล์ .html/.htm เป็นชุด tag ที่บอก browser ว่าจะแสดงเนื้อหายังไง ทุกไฟล์เริ่มด้วย <!DOCTYPE> <html> <head> <title> <body> และ tag ซ้อนกันได้แต่ห้ามเกยกัน

1.1 HTML คืออะไร? สไลด์ 4

  • HTML = HyperText Markup Language — ภาษา markup มาตรฐานสำหรับหน้าเว็บ
  • ไฟล์นามสกุล .html หรือ .htm เรียกว่า HTML documents
  • HTML ประกอบด้วย markup tags ต่อกันเป็นชุด ทำหน้าที่ บอก browser ว่าจะแสดงเนื้อหายังไง

1.2 โครงสร้างหลักของเอกสาร HTML มีอะไร? สไลด์ 5–6

แก่น<!DOCTYPE html> ต้องมาก่อนสุด, <html> ครอบทุกอย่าง, <head> เก็บข้อมูลเกี่ยวกับหน้า (มี <title>), <body> เก็บเนื้อหาที่แสดงจริง

Tag ทำหน้าที่
<!DOCTYPE html> ประกาศว่าเป็นเอกสาร HTML ต้องเป็น สิ่งแรกสุด ในไฟล์ ก่อน <html>
<html> ตัวเอกสาร HTML เป็น container ของทุก element (ยกเว้น <!DOCTYPE>)
<head> ส่วนหัวของเอกสาร ใส่ title, scripts, styles, meta information ฯลฯ
<body> ส่วนเนื้อหาของเอกสาร เช่น ข้อความ ลิงก์ รูป ตาราง list
<title> ชื่อเอกสาร แสดงบน toolbar ของ browser

ตัวอย่างเอกสาร (สไลด์ 6):

<!DOCTYPE html>
<html lang="en">
    <head>
        <title>I Love HTML</title>
    </head>
    <body>
        Everything displayed on your page
        will be in here.
    </body>
</html>
  • Tip 1: เริ่มทุกไฟล์ด้วย tag พื้นฐานชุดนี้เสมอ: <!DOCTYPE>, <html>, <head>, <title>, <body>
  • Tip 2: ย่อหน้า (indent) element ที่ซ้อนอยู่ข้างใน เพื่อให้อ่านง่าย

1.3 กฎการซ้อน tag (Nesting) คืออะไร? สไลด์ 7

แก่นtag เปิด–ปิดกำหนด "ขอบเขต" ที่ tag มีผล ขอบเขตซ้อนกันได้ (nested) แต่ห้ามเกยกัน (not overlap) — tag ที่เปิดทีหลังต้องปิดก่อน

<!-- ✔ ถูก: tag2 อยู่ข้างใน tag1 ทั้งหมด -->
<tag1>Some text <tag2>more text</tag2> and more.</tag1>

<!-- ✘ ผิด: ปิด tag1 ก่อน tag2 ทั้งที่ tag2 เปิดทีหลัง → ขอบเขตเกยกัน -->
<tag1>Some text <tag2>more text</tag1> and more.</tag2>

💡 เปรียบเหมือนกล่องซ้อนกล่อง: กล่องเล็กต้องอยู่ในกล่องใหญ่ทั้งใบ จะให้กล่องเล็กโผล่ทะลุออกมานอกกล่องใหญ่ไม่ได้

1.4 Basic tags ที่เรียนไปแล้วมีอะไรบ้าง? สไลด์ 8–9

แก่นheading, paragraph, line break, link, list 3 แบบ, รูป, comment และ table (table/tr/th/td)

Tag ทำหน้าที่
<h1> ถึง <h6> หัวข้อ — <h1> ใหญ่และสำคัญที่สุด
<p> ย่อหน้า (สไลด์เขียนว่า "No Closing tags" — ดู ⚠️ ข้างล่าง)
<br> ขึ้นบรรทัดใหม่
<a> ไฮเปอร์ลิงก์ ใช้คู่กับ attribute href
<ol> ordered list = list มีเลขลำดับ
<ul> unordered list = list แบบ bullet
<li> รายการใน list (ซ้อนอยู่ใน <ol> และ <ul>)
<dl> definition list ใช้คู่กับ <dt> และ <dd>
<img> รูป ใช้คู่กับ attribute src และ alt
<!-- --> comment (หมายเหตุ ไม่แสดงผล)
<table> ตาราง HTML
<tr> แถวของตาราง
<th> หัวตาราง — ข้อความ ตัวหนา + จัดกลาง
<td> ช่องข้อมูลในตาราง — ข้อความ ปกติ + ชิดซ้าย

⚠️ สไลด์ 8 เขียนว่า <p> เป็น "Paragraph tag (No Closing tags)" แต่ตัวอย่างในสไลด์เดียวกันชุดนี้ (สไลด์ 51, 53, 54, 60) เขียน <p>...</p> มี tag ปิดทุกครั้ง — ถ้าเจอในข้อสอบให้ถามอาจารย์ว่าหมายถึงอะไร (หรืออาจหมายถึง <br> ที่อยู่บรรทัดถัดไป)

2. ใส่เสียง วิดีโอ และ YouTube ในหน้าเว็บยังไง? สไลด์ 10–13

แก่นHTML5 มี <audio> และ <video> ให้ใช้ตรง ๆ (ใส่ไฟล์ผ่าน <source>, เปิดปุ่มควบคุมด้วย controls, เล่นเองด้วย autoplay) ส่วนวิดีโอ YouTube ใช้ <iframe> + YouTube Video Id

2.1 <audio> สไลด์ 11

  • รองรับ 3 format: MP3, WAV, OGG
  • autoplay → เล่นอัตโนมัติ
  • controls → แสดงปุ่มควบคุมเสียง
<audio autoplay controls>
    <source src="LetItGo.mp3" type="audio/mp3">
    Your browser does not support the audio tag.
</audio>
  • <source> บอกไฟล์ (src) และชนิดไฟล์ (type)
  • ข้อความ "Your browser does not support the audio tag." เป็นข้อความสำรองสำหรับ browser ที่ไม่รองรับ tag นี้

⚠️ สไลด์ 11 (หน้า audio) เขียนว่า "use the autoplay attribute to start video automatically" — น่าจะคัดลอกมาจากหน้า video ความหมายในหน้านี้คือเล่น เสียง อัตโนมัติ

2.2 <video> สไลด์ 12

  • ก่อน HTML5 จะเล่นวิดีโอใน browser ได้ต้องมี plug-in (เช่น flash)
  • รองรับ format: MP4, WebM, OGG
  • autoplay → เล่นอัตโนมัติ | controls → มีปุ่ม play, pause, volume
  • กำหนดขนาดด้วย width / height
<video width="320" height="240" autoplay controls>
    <source src="small.mp4" type="video/mp4">
    <source src="small.ogg" type="video/ogg">
    Your browser does not support the video tag.
</video>
  • ใส่ <source> ได้หลายอัน (ตัวอย่างใส่ทั้ง mp4 และ ogg)

2.3 YouTube สไลด์ 13

  • ใช้ <iframe> + YouTube Video Id อ้างถึงวิดีโอ (URL รูปแบบ https://www.youtube.com/embed/<VideoId>)
<iframe width="320" height="240"
  src="https://www.youtube.com/embed/62bIsvRcPv0">
</iframe>
<audio> <video> YouTube
tag <audio> + <source> <video> + <source> <iframe>
format MP3, WAV, OGG MP4, WebM, OGG ใช้ Video Id ใน src
attribute ที่สไลด์สอน autoplay, controls autoplay, controls, width, height width, height, src

3. HTML Form คืออะไร ประกอบด้วยอะไร? สไลด์ 14–17

แก่นHTML form = กลุ่มคำสั่งสำหรับรับ input จากผู้ใช้ สร้างด้วย <form>...</form> แล้วใส่ form elements (<input>, <button> ฯลฯ) ไว้ข้างใน — form element ทุกตัวต้องอยู่ใน <form>

3.1 นิยาม สไลด์ 15

  • HTML form คือกลุ่มของชุดคำสั่งที่สร้างเพื่อ รับ input จากผู้ใช้
  • สร้างด้วย tag <form>...</form>
  • แล้วใส่ form element ไว้ระหว่าง <form> เช่น <input>, <button>

💡 เปรียบเหมือนใบสมัครกระดาษ: <form> คือตัวกระดาษทั้งแผ่น ส่วน form element คือช่องให้กรอก ช่องติ๊ก และปุ่มส่ง

3.2 ตัวอย่างฟอร์มเต็ม 1 ฟอร์ม สไลด์ 16

<!DOCTYPE html>
<html lang="en">
    <head>
        <title>Application Form</title>
    </head>
    <body>
        <form>
            <fieldset>
                <legend>Student Information</legend>
                <label for="txtStudentID">Student ID</label><br>
                <input type="text" id="txtStudentID"><br>
                <label for="txtName">Name</label><br>
                <input type="text" id="txtName"><br>
                <label for="cldBD">Birth Date</label><br>
                <input type="date" id="cldBD">
                <button type="submit">Submit</button>
            </fieldset>
        </form>
    </body>
</html>

  • ทั้งก้อน <form>...</form> = One HTML Form | แต่ละ <input> = a form element
  • ผลบน browser (ตามภาพในสไลด์): กรอบชื่อ "Student Information" มีช่อง Student ID, Name และช่อง Birth Date ที่กดแล้วมี ปฏิทินเด้งให้เลือกวัน + ปุ่ม Submit

3.3 Form elements มีอะไรบ้าง? สไลด์ 17

Tag ทำหน้าที่
<input> ช่องให้ผู้ใช้กรอกข้อมูล
<textarea> ช่องกรอกข้อความ หลายบรรทัด
<select> drop-down list ใช้คู่กับ <option>
<option> ตัวเลือกแต่ละอันใน select list
<button> ปุ่มกดได้ (type: submit, reset, button)
<fieldset> วาด กรอบ รวมกลุ่ม element ที่เกี่ยวข้องกันในฟอร์ม

⚠️ Note: form elements ทั้งหมด ต้องอยู่ภายใน <form>

4. <input> มีกี่ type และแต่ละ type ใช้ทำอะไร? สไลด์ 18–28

แก่น<input> คือคำสั่งรับค่าในฟอร์ม เลือกชนิดด้วย attribute type — text, password, radio, checkbox, email, tel, date (+ month, week, datetime-local, time) บางชนิด (email, tel+pattern, date+min/max) browser ตรวจรูปแบบให้ตอนกด submit

4.1 ภาพรวม สไลด์ 19

  • <input> = ชุดคำสั่งสำหรับ รับค่าใน Form
  • ระบุประเภทด้วย attribute type ได้แก่: text, password, radio, checkbox, email, tel, date (และแบบเพิ่มเติม เช่น month, week, date-time)
type ได้อะไร ใช้เมื่อ สไลด์
text ช่องข้อความบรรทัดเดียว ชื่อ, รหัส 20
password ช่องบรรทัดเดียว ปิดบังตัวอักษร (masked) รหัสผ่าน 21
radio ปุ่มกลม เลือกได้ ข้อเดียว 22
checkbox ช่องติ๊ก เลือกได้ หลายข้อ 23
tel ช่องเบอร์โทร ตรวจตาม pattern ตอน submit เบอร์โทรรูปแบบตายตัว 24–25
email ช่องอีเมล ตรวจ รูปแบบอีเมล ตอน submit อีเมล 26
date date picker จำกัดช่วงด้วย min / max วันเกิด ฯลฯ 27
week / month / datetime-local / time ตัวเลือกวัน-เวลาแบบอื่น สัปดาห์ / เดือน+ปี / วัน+เวลา / เวลา 28

4.2 Text Fields + <label> สไลด์ 20

แก่นtype="text" = ช่องข้อความบรรทัดเดียว และใช้ <label for="..."> จับคู่กับ id ของ input เพื่อบอกว่าช่องนี้คืออะไร (มีประโยชน์มากกับ screen reader)

<label for="txtFN">First name</label>
<input type="text" id="txtFN"><br>
<label for="txtLN">Last name</label>
<input type="text" id="txtLN">
  • ค่าของ for ใน <label> ต้อง ตรงกับ id ของ <input> (txtFN ↔ txtFN)
  • Note: <label> + attribute for ใช้กำหนด label ให้ form element (อ้างผ่าน id) และ มีประโยชน์มากสำหรับ screen readers

4.3 Password สไลด์ 21

  • type="password" = ช่องข้อความบรรทัดเดียวแบบ masked (พิมพ์แล้วเห็นเป็นจุด •••)
<label for="txtLogin">Login</label>
<input type="text" id="txtLogin"><br>
<label for="txtPwd">Password</label>
<input type="password" id="txtPwd">
  • ผลในสไลด์: ช่อง Login แสดง "This is normal text field" ตามที่พิมพ์ ส่วนช่อง Password แสดงเป็นจุดทั้งหมด

4.4 Radio Buttons สไลด์ 22

แก่นradio ใช้เมื่อเลือกได้ข้อเดียว ทุกปุ่มในกลุ่มต้องมี name เดียวกัน และใช้ checked ตั้งค่าเริ่มต้น

Blood Group: <br>
<input type="radio" name="bloodGr" value="A" checked>A<br>
<input type="radio" name="bloodGr" value="B">B<br>
<input type="radio" name="bloodGr" value="AB">AB<br>
<input type="radio" name="bloodGr" value="O">O<br>
  • ค่าของ name ต้องเหมือนกัน เพื่อจัดเป็นกลุ่มเดียวกัน (ทั้ง 4 ปุ่มคือ bloodGr)
  • checked = ปุ่มที่ถูกเลือกไว้ตั้งแต่แรก (ตัวอย่าง: A ถูกเลือกไว้)
  • value = ค่าของตัวเลือกนั้น ๆ

4.5 Checkbox สไลด์ 23

แก่นcheckbox ใช้เมื่อเลือกได้หลายข้อ — กฎเหมือน radio: name เดียวกันเพื่อจัดกลุ่ม, checked ตั้งค่าเริ่มต้นได้ (หลายช่องก็ได้)

What should I have for lunch? <br>
<input type="checkbox" name="food" value="SW">Sandwich<br>
<input type="checkbox" name="food" value="FC">Fried Chicken<br>
<input type="checkbox" name="food" value="HB">Hamburger<br>
  • ผลในสไลด์: ติ๊ก Sandwich และ Hamburger พร้อมกันได้ (2 ช่อง)
  • checked ใช้ตั้ง checkbox (es) เริ่มต้น — มีได้มากกว่า 1 ช่อง

4.6 Tel + attribute pattern สไลด์ 24–25

แก่นtype="tel" = ช่องเบอร์โทรที่ถูกตรวจว่าตรงรูปแบบ pattern ตอนกด submit โดย pattern คือ regular expression (ลำดับตัวอักษรที่เป็นรูปแบบสำหรับค้นหา/จับคู่)

What is your mobile phone?
<input type="tel" name="mobile" pattern="[0-9]{3}-[0-9]{3}-[0-9]{4}">
<!-- Pattern: XXX-XXX-XXXX -->
<button type="submit">Submit</button>
  • [0-9]{3}-[0-9]{3}-[0-9]{4} อ่านว่า: ตัวเลข 3 ตัว – ขีด – ตัวเลข 3 ตัว – ขีด – ตัวเลข 4 ตัว → รูปแบบ XXX-XXX-XXXX
  • ผลในสไลด์: พิมพ์ Nah~~~ แล้วกด Submit → browser ขึ้น "Please match the requested format." (เพราะไม่ใช่ตัวเลขตามรูปแบบ) ✅ รันตรวจแล้วใน Chrome: Nah~~~ ไม่ผ่าน, 055-775-8588 ผ่าน

pattern attribute (สไลด์ 25):

  • pattern กำหนด regular expression ที่ค่าใน <input> จะถูกตรวจ ตอน submit ฟอร์ม
  • Regular expression = ลำดับตัวอักษรที่ประกอบเป็น search pattern
Regular Expression ความหมาย ตัวอย่างที่ผ่าน (valid) อ่านทีละส่วน
[A-Za-z]{3} ตัวอักษร 3 ตัวเท่านั้น THA tha Tha tHA [A-Za-z] = A–Z หรือ a–z, {3} = 3 ตัวพอดี
[A-Z]{5,} ตัวพิมพ์ใหญ่ 5 ตัวขึ้นไป HELLO WORLD {5,} = อย่างน้อย 5 ตัว ไม่จำกัดมากสุด
.{2,4} อักขระอะไรก็ได้ 2–4 ตัว $o Wh@+ T0o . = อักขระใดก็ได้, {2,4} = 2 ถึง 4 ตัว
[0-9]{2}88[0-9]{3} ตัวเลขรูปแบบ ##88### 5088111 6288999 เลข 2 ตัว + "88" ตายตัว + เลข 3 ตัว

✅ รันตรวจด้วย node แล้ว: ตัวอย่าง valid ในตารางทุกตัวผ่าน pattern ของมันจริง

💡 อ่าน regex ให้แยก 2 ส่วน: [...] = อนุญาตตัวอะไร และ {...} = กี่ตัว ({n} พอดี n, {n,} อย่างน้อย n, {n,m} ระหว่าง n–m)

5. Form element อื่น: textarea, select, button, fieldset สไลด์ 29–33

6. [EX2] Sign-Up Form — ทำยังไง? สไลด์ 34

แก่นรวมสิ่งที่เรียนใน 1 ฟอร์ม — text (ชื่อ), email (อีเมล), date + max (วันสิ้นสุด 1 ม.ค. 2565 = 2022-01-01), ปุ่ม submit และ reset

โจทย์: สร้าง Sign-up Form ที่มี

  1. Input box สำหรับ ชื่อนักศึกษา
  2. Input box สำหรับ อีเมล
  3. Input box แบบ ปฏิทิน โดยวันที่สิ้นสุดที่ 1 มกราคม 2565
  4. ปุ่ม submit
  5. ปุ่ม reset (ล้างค่า)

คิดทีละขั้น:

  1. ทุกอย่างต้องอยู่ใน <form> (สไลด์ 17)
  2. ชื่อ → <input type="text"> + <label for> จับคู่ id (สไลด์ 20)
  3. อีเมล → <input type="email"> เพื่อให้ browser ตรวจ @ ให้ (สไลด์ 26)
  4. ปฏิทิน → <input type="date"> และ "วันที่สิ้นสุด" = จำกัดวันสูงสุด → ใช้ max (สไลด์ 27)
    • 2565 เป็น พ.ศ. → แปลงเป็น ค.ศ. = 2565 − 543 = 2022 → max="2022-01-01" (รูปแบบปี-เดือน-วันเหมือน max="2010-01-01" ในสไลด์ 27)
  5. ปุ่ม → <button type="submit"> และ <button type="reset"> (สไลด์ 31–32)
  6. จะครอบด้วย <fieldset> + <legend> ให้เป็นกลุ่มก็ได้ (สไลด์ 33)

7. Form Validation ด้วย HTML5 attributes ทำยังไง? สไลด์ 35–39

แก่นvalidation = browser ตรวจว่าข้อมูลที่กรอกถูกรูปแบบและอยู่ในเงื่อนไขก่อนส่ง ทำฝั่ง client ได้ 2 วิธี คือ HTML5 (form attributes) และ JavaScript — บทนี้เรียนแบบ HTML5 ด้วย min, max, pattern, title, placeholder, required

7.1 Form Validation คืออะไร? สไลด์ 36

  • เมื่อผู้ใช้กรอกข้อมูล browser จะตรวจ ว่าข้อมูล อยู่ในรูปแบบที่ถูกต้อง และ อยู่ในเงื่อนไข (constraints) ที่กำหนด
  • วิธี validate ฟอร์ม ฝั่ง client มี 2 แบบ:
    1. HTML5 (Form Attributes) ← บทนี้
    2. JavaScript
  • ภาพประกอบในสไลด์: ฟอร์มตัวอย่างที่ช่องผิดถูกทำกรอบแดง และมีป้ายเตือนข้างช่อง เช่น "input is not complete", "please put something here"

7.2 Attribute ที่ใช้จำกัดค่า (Restriction attributes) สไลด์ 37

Attribute ทำหน้าที่
min ค่า ต่ำสุด ของ <input>
max ค่า สูงสุด ของ <input>
pattern regular expression ที่ค่าใน input ต้องตรง
title ข้อความอธิบายรูปแบบเพื่อช่วยผู้ใช้ (ใช้คู่กับ pattern)
placeholder คำใบ้ ค่าที่ควรกรอก แสดงจาง ๆ ในช่องว่าง
required ต้องกรอก ก่อนจึงจะ submit ได้

7.3 ตัวอย่างรวม สไลด์ 38–39

<form>
    First name:<br><input type="text" name="fname"><br>
    Last name:<br><input type="text" name="lname"><br>
    Mobile:<br>
    <input type="tel" pattern="[0-9]{3}-[0-9]{3}-[0-9]{4}"
           title="Mobile: XXX-XXX-XXXX"><br>

           title="Required e-mail"><br>
    Country code:<br>

ผลแต่ละ attribute (จากภาพสไลด์ 39):

✅ รันตรวจแล้ว: United States ไม่ผ่าน [A-Z]{3} · ช่อง required ที่ว่างไม่ผ่าน

8. Form Submission: ส่งข้อมูลยังไง GET กับ POST ต่างกันยังไง? สไลด์ 40–44

แก่นกด submit → ฟอร์มผ่าน validation ก่อน → ข้อมูลทั้งหมดถูกส่งไปที่ action ด้วย HTTP method ใน method — GET ส่งผ่าน URL (เห็นเป็นคู่ name=value) ส่วน POST แพ็กไว้ใน packet

8.1 Attribute ของ <form> ที่ใช้ส่ง สไลด์ 41

  • กดปุ่ม submit → ข้อมูลทั้งหมดในฟอร์ม ถูกส่งไปที่ หน้าเป้าหมาย หรือ web server เพื่อประมวลผล
  • action = ส่งข้อมูลไปที่ไหน ตอน submit
  • method = HTTP method ที่ใช้ส่ง (GET / POST)
    • GET: ส่งข้อมูลทั้งหมด ผ่าน URL
    • POST: ส่งข้อมูลทั้งหมด อยู่ข้างใน packet

8.2 ฟอร์มทำงานยังไง? สไลด์ 42

  1. ผู้ใช้กรอก (ตัวอย่าง: First name = Harry, Last name = Potter) แล้วกด Submit
  2. Form Validation ตรวจข้อมูล
    • ถ้าฟอร์มไม่ถูกต้อง (invalid) → กลับไปที่ฟอร์ม ไม่ส่ง
    • ผ่าน validation → ไปยัง Server หรือปลายทางที่กำหนดใน action ด้วย HTTP: GET/POST
  • รายละเอียดเพิ่มจะได้เรียนตอนทำ form handling ฝั่ง server

8.3 GET vs POST สไลด์ 43–44

<form action="somewhere.html" method="GET">   <!-- สไลด์ 44 เปลี่ยนเป็น method="POST" -->
    First name:<input type="text" name="fistname"><br>
    Last name:<input type="text" name="lastname"><br>
    <button type="submit">Submit</button>
</form>

GET (สไลด์ 43) POST (สไลด์ 44)
กด submit แล้วส่งไปไหน ทุก input ไปที่ "somewhere.html" ทุก input ไปที่ "somewhere.html"
ข้อมูลอยู่ตรงไหน โชว์ใน URL เป็นคู่ name=value แพ็กอยู่ใน packet
URL ที่เห็นในสไลด์ (กรอก Jidapa / K.) somewhere.html?fistname=Jidapa&lastname=K. somewhere.html (ไม่มีข้อมูลต่อท้าย)
ชื่อใน URL ชื่อเดียวกับ name ในฟอร์ม ที่ส่ง —

💡 GET เปรียบเหมือนเขียนข้อความไว้บนหน้าซองจดหมาย (มองเห็นได้ใน URL) ส่วน POST คือใส่ข้อความไว้ในซอง

⚠️ คีย์ใน URL คือค่า name ของ input ตามที่เขียนในฟอร์ม (สไลด์ 43: "Same name as ones in the submitted form") ไม่ใช่ id

9. Semantic Elements คืออะไร มีตัวไหนบ้าง? สไลด์ 45–57

แก่นsemantic = "มีความหมาย" — tag HTML5 ที่บอกว่าส่วนนี้ของหน้าคืออะไร (header, nav, section, article, aside, footer) ใช้วางโครง layout ร่วมกับ CSS และช่วยให้ screen reader / search engine เข้าใจเนื้อหาหน้าเว็บ แทนการใช้ <div class="..."> แบบเดิม

9.1 ทำไมต้องมี semantic elements? สไลด์ 46

  • Semantic = มีความหมาย
  • semantic elements ใช้ วางโครงสร้างหน้าเว็บ (layout) ซึ่งจะนำไปใช้ ร่วมกับ CSS
  • มีข้อมูลเชิงความหมายมากขึ้น → screen readers หรือ search engines ระบุได้ว่าเนื้อหาส่วนไหนคืออะไร

9.2 ก่อนมี semantic ทำยังไง? สไลด์ 47

  • ใช้ tag ทั่วไปอย่าง <div> + attribute class แบ่งส่วนเนื้อหา
<body>
    <div class="header">Header</div>
    <div class="menubar">Menu Bar/Navigation Bar</div>
    <div class="section">
        <div class="article">Content Article 1</div>
        <div class="article">Content Article 2</div>
    </div>
    <div class="footer">Document Footer</div>
</body>

💡 เปรียบเหมือนกล่องเก็บของที่ไม่มีป้าย (<div>) ต้องเปิดดูหรือแปะโน้ต (class) เอง ส่วน semantic tag คือกล่องที่พิมพ์ชื่อติดมาเลยว่า "หัวกระดาษ" "เมนู" "ท้ายหน้า"

9.3 Semantic elements ใน HTML5 สไลด์ 48–49

  • Semantic (adj) = related to meaning in language or logic
  • ใช้กำหนด ส่วนต่าง ๆ ของหน้าเว็บ

💡 ข้อความใน <aside> (สไลด์ 56) บอกหลักการของ aside เอง: เนื้อหาใน aside ควรเกี่ยวข้องกับเนื้อหารอบ ๆ

9.5 <article> ซ้อนกันได้ สไลด์ 54

<article>
    <h2>Famous Cities</h2>
    <article>
        <h2>London</h2>
        <p>London is the capital city of England.</p>
    </article>
    <article>
        <h2>Paris</h2>
        <p>Paris is the capital and most populous city of France.</p>
    </article>
    <article>
        <h2>Tokyo</h2>
        <p>Tokyo is the capital of Japan.</p>
    </article>
</article>

  • <article> ใหญ่ (Famous Cities) มี <article> ย่อย 3 อัน — แต่ละอันคือ "One small article" ที่จบในตัวเอง

9.6 <article> หรือ <section>? สไลด์ 55

แก่นarticle = เนื้อหาอิสระที่จบในตัว (ยกไปวางที่อื่นก็ยังเข้าใจ) เช่น forum post, blog post, news feed, comment ส่วน section = ส่วนทั่ว ๆ ไปของเอกสาร/แอป — และซ้อนกันได้ทั้งสองทาง

<article> <section>
เนื้อหา อิสระ จบในตัวเอง (independent, self-contained) ส่วนทั่วไป (generic) ของเอกสารหรือแอปพลิเคชัน
เช่น forum post, blog post, news feeds, comments เช่น ส่วน Lyrics ในสไลด์ 53
  • Note: <article> อยู่ ข้างใน <section> ได้ และ <section> ก็มี <article> อยู่ข้างในได้

9.7 ตัวอย่างจากเว็บจริง สไลด์ 57

ภาพหน้า "ICT My Courses" (หน้ารายวิชา) ที่ตีกรอบแดงบอกว่าแต่ละส่วนเป็น tag อะไร:

  • แถบบนสุดของหน้า (ชื่อเว็บ + ชื่อผู้ใช้) → <header>
  • เมนูด้านซ้าย (Dashboard, ICT Announcements, Calendar, All Courses ฯลฯ) → <nav>
  • กล่อง "Recently accessed courses" → <section>
  • กล่อง "Course overview" → <section>

10. Web Layout หน้าตาแบบไหน และเขียนเป็น HTML ยังไง? สไลด์ 58–62

แก่นlayout พื้นฐาน = Header / Navigation Bar / Content–Main Content–Content / Footer และ layout ควรเปลี่ยนตามอุปกรณ์ (มือถือ 1 คอลัมน์, แท็บเล็ต/โน้ตบุ๊ก 2, เดสก์ท็อป 3) เขียนโครงด้วย semantic tags แล้วใช้ CSS จัดหน้าตา — ไม่มี CSS ทุกอย่างจะเรียงลงมาเป็นแถวเดียว

10.1 Layout ตัวอย่างพื้นฐาน สไลด์ 58

  • layout มีเยอะมาก นี่เป็นแค่ตัวอย่างง่าย ๆ

10.2 Layout ควรเปลี่ยนตามอุปกรณ์ สไลด์ 59

  • "the Web Content Layout should vary by the devices"
อุปกรณ์ จำนวนคอลัมน์ หน้าตา
Mobile Browser 1-column header / เนื้อหา 1 กล่องใหญ่ / footer เรียงลงมา
Tablet/Laptop Browser 2-column เนื้อหาแบ่งซ้าย–ขวา 2 คอลัมน์
Desktop Browser 3-column เนื้อหาแบ่ง 3 คอลัมน์ (คอลัมน์กลางกว้างสุด)

10.3 เขียน layout เป็น HTML สไลด์ 60

<header>
    <h1>Header</h1>
</header>
<nav>
    <a href="#">Link1</a>
    <a href="#">Link2</a>
    <a href="#">Link3</a>
</nav>
<article class="row">
    <article class="column">
        <h2>Column1</h2>
        <p>Lorem ipsum dolor sit amet … </p>
    </article>
    <article class="column">
        <h2>Column2</h2>
        <p>Lorem ipsum dolor sit amet … </p>
    </article>
    <article class="column">
        <h2>Column3</h2>
        <p>Lorem ipsum dolor sit amet … </p>
    </article>
</article>
<footer>
    <h1>Footer</h1>
</footer>

(ทั้งหมดนี้อยู่ใน <body>)

  • <article class="row"> ครอบ <article class="column"> 3 อัน → ได้ Column1, Column2, Column3

10.4 ไม่มี CSS vs มี CSS สไลด์ 61–62

ไม่มี CSS (สไลด์ 61) มี CSS (สไลด์ 62)
หน้าตาบน browser ทุกอย่าง เรียงลงมาแนวตั้ง: Header → ลิงก์ Link1 Link2 Link3 → Column1 → Column2 → Column3 → Footer Header/Footer พื้นเทาอ่อน จัดกลาง, nav เป็น แถบสีน้ำเงินเข้ม มีลิงก์อยู่ชิดขวา, 3 คอลัมน์วางเคียงกัน

CSS ที่โชว์ในสไลด์ 62 (CSS File — ตัดมาบางส่วน มี ...):

header, footer {
    background-color: #f1f1f1;
    padding: 3px;
    text-align: center;
}
/* Navigation bar */
nav {
    overflow: hidden;
    background-color: darkblue;
}
...
  • header, footer → พื้นสี #f1f1f1 (เทาอ่อน), padding: 3px, ข้อความจัดกลาง
  • nav → overflow: hidden, พื้นสี darkblue
  • ส่วนที่ทำให้ 3 คอลัมน์อยู่ข้างกันอยู่ในส่วน ... ที่สไลด์ไม่ได้แสดง

💡 HTML = โครง (กล่องอะไรอยู่ตรงไหน) ส่วน CSS = การจัดวางและตกแต่ง — semantic tags ทำให้ CSS เลือกส่วนต่าง ๆ ได้ตรง ๆ (header, nav, footer)

คำศัพท์ ความหมาย จำง่าย ๆ ว่า
HTML HyperText Markup Language ภาษา markup มาตรฐานของเว็บ ชุด tag บอก browser ว่าแสดงยังไง
Nesting tag ซ้อนอยู่ใน tag อื่น ซ้อนได้ ห้ามเกย
controls attribute แสดงปุ่มควบคุมของ audio/video มีปุ่ม play/pause/volume
autoplay attribute เล่นอัตโนมัติ เปิดหน้าแล้วเล่นเลย
<iframe> ใช้ฝัง YouTube ด้วย Video Id หน้าต่างย่อยในหน้าเว็บ
HTML form กลุ่มคำสั่งรับ input จากผู้ใช้ ใบสมัครบนเว็บ
Form element ช่อง/ปุ่มที่อยู่ในฟอร์ม (input, textarea, select, button, fieldset) ต้องอยู่ใน <form>

value ค่าของตัวเลือก (radio/checkbox/option) CS, CE... ต่างจากข้อความที่ผู้ใช้เห็น
checked ตั้งค่าเริ่มต้นของ radio/checkbox ติ๊กไว้ก่อน
selected ตั้งค่าเริ่มต้นของ <option> เลือกไว้ก่อนใน drop-down
Regular expression ลำดับตัวอักษรที่เป็น search pattern [อะไร]{กี่ตัว}
pattern regex ที่ค่าใน input ต้องตรง ตรวจตอน submit ใช้กับ tel / text
title ข้อความอธิบายรูปแบบ ใช้คู่กับ pattern โผล่ในป้ายเตือน
placeholder คำใบ้จาง ๆ ในช่องว่าง ตัวอย่างที่ควรกรอก

action ปลายทางที่ส่งข้อมูลไป ส่งไปไหน

GET ส่งข้อมูลผ่าน URL เป็น name=value เขียนบนซอง
POST ส่งข้อมูลอยู่ใน packet ใส่ในซอง

สรุปท้ายบท / จุดที่มักออกสอบ

  • <!DOCTYPE html> ต้องเป็นสิ่งแรกสุด · <html> ครอบทุก element ยกเว้น <!DOCTYPE> · <title> แสดงบน toolbar
  • tag ซ้อนได้ แต่ห้าม overlap
  • <th> = ตัวหนา+กลาง | <td> = ปกติ+ชิดซ้าย
  • audio: MP3, WAV, OGG | video: MP4, WebM, OGG | ก่อน HTML5 ต้องใช้ plug-in (flash) | YouTube ใช้ <iframe> + Video Id
  • form element ทั้งหมดต้องอยู่ใน <form>
  • radio = เลือก 1 | checkbox = เลือก หลาย | ทั้งคู่ต้อง name เหมือนกัน ในกลุ่ม + checked เป็นค่าเริ่มต้น
  • <label for="x"> ต้องตรงกับ id="x" ของ input — ช่วย screen readers
  • อ่าน regex: [A-Za-z]{3} = ตัวอักษร 3 ตัว | [A-Z]{5,} = พิมพ์ใหญ่ ≥5 | .{2,4} = อะไรก็ได้ 2–4 ตัว | [0-9]{2}88[0-9]{3} = ##88### | [0-9]{3}-[0-9]{3}-[0-9]{4} = XXX-XXX-XXXX
  • <textarea> ใช้ rows/cols | <select>+<option> ใช้ selected
  • button 3 type: button (เรียก function), reset (คืนค่าเริ่มต้น), submit (ส่ง)
  • <fieldset> = กรอบ, <legend> = หัวกรอบ
  • 6 restriction attributes: min, max, pattern, title, placeholder, required
  • validation ฝั่ง client ได้ 2 วิธี: HTML5 attributes และ JavaScript
  • ฟอร์ม invalid → ไม่ส่ง กลับไปแก้ | ผ่าน → ไปที่ action ด้วย GET/POST
  • GET = ข้อมูลใน URL (?name=value&name=value) | POST = ข้อมูลใน packet
  • semantic 6 ตัว: header, nav, section, article, aside, footer — ช่วย screen readers/search engines + ใช้กับ CSS
  • article = self-contained (forum post, blog post, news feed, comment) | section = generic | ซ้อนกันได้ทั้งสองทาง
  • layout ตามอุปกรณ์: Mobile 1 คอลัมน์ | Tablet/Laptop 2 | Desktop 3
