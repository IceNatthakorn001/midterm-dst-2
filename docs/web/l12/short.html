Objectives: อธิบาย JSON · อธิบาย Web Services · เรียก WS ด้วย JavaScript

1. ก่อนมีเว็บ: layer / tier (สไลด์ 4–10)

  • ⭐ 3 layers: Resource Management (database) | Application Logic/Business | Presentation (UI) — tier = physical separation ของ layer
ลักษณะ
⭐ 1-Tier 3 layers บนเครื่องเดียว/software package เดียว · dumb terminals + mainframes · tightly connected · ยาก scalability & portability
⭐ 2-Tier Client-Server · presentation ที่ client, data ที่ server · application layer อยู่ฝั่งไหนก็ได้
⭐ 3-Tier แต่ละ layer เกือบอิสระ แยก tier · front-end (GUI) / middleware / back-end
N-Tier AKA Distributed application · คล้าย 3-tier แต่เพิ่ม application servers เป็น individual tiers เพื่อกระจาย business logic (รูป: Client → WAF → Web Tier → Middle Tier 1/2 (+Messaging) → Cache / Data Tier / Remote Service)
  • Web app architecture (Easyrec): Clients ↔ Web Service API ↔ Application Layer ↔ Database Layer + Generator Server + Administration Tool + 3rd Party Metadata

2. WWW basics + CGI (สไลด์ 11)

  • คลิก URL → server map URL to CGI script → execute (script = normal client ของ middleware เดิม) → ผลกลับทาง stdout (มักเป็น address ของหน้าเว็บ) → server ส่งหน้าให้ browser

3. HTTP (สไลด์ 13–31)

  • แลกเอกสาร คล้าย e-mail (RFC 822 headers + MIME types) · foundation ของ data exchange บนเว็บ · MIME type = บอกชนิดเอกสาร
  • 1 หน้าเว็บ = หลาย GET (html, css, png, mp4, jpg) จากหลาย server · stack: HTML/CSS/JS/Web APIs → HTTP → TLS/TCP, DNS/UDP → IP
  • ⭐ simple & human readable | extensible | stateless but not sessionless
  • ⭐ Request = Request Line (Method · Path(URI/URL) · Version HTTP/1.1, 2.0) + Headers + Body
    • Headers: Host (server ปลายทาง) | User-Agent (browser/OS) | Accept (ชนิดที่อยากได้: application/json, text/html, image/png) | Content-Type (ชนิดของ body ที่ส่ง) | Authorization (credentials/tokens)
    • Body: ใช้กับ POST/PUT/DELETE · รูปแบบตาม Content-Type
    • ตัวอย่าง GET / HTTP/1.1 + Host: developer.mozilla.org + Accept-Language: fr
    • สไลด์ 23 แบ่ง header: Request (Host, User-Agent, Accept, Accept-Language, Accept-Encoding) | General (Connection, Upgrade-Insecure-Requests) | Representation (Content-Type, Content-Length)
  • ⭐ Response = Status Line (Version · Code · Text) + Headers + Body
    • ⭐ 200 OK | 404 Not Found | 500 Internal Server Error
    • Headers: Content-Type | Date | Server | Content-Length (ขนาด body เป็น bytes)
    • ตัวอย่าง HTTP/1.1 200 OK · Server: Apache · Content-Length: 29769 · Content-Type: text/html → body = HTML 29769 bytes
    • สไลด์ 29: Response (Access-Control-Allow-Origin, Etag, Server, Set-Cookie, Vary, X-Frame-Options) | General (Connection, Date, Keep-Alive, Transfer-Encoding) | Representation (Content-Encoding, Content-Type, Last-Modified)
  • HTTP Components (ลิงก์): request methods, headers, response status codes
  • Passing parameter: form → POST /cgi-bin/post-query + Content-type: application/x-www-form-urlencoded + บรรทัดว่าง + &name=…&email=… | GET ได้แต่ parameter ต้องอยู่ใน URL ?name=...&email=...

4. HTML vs XML (สไลด์ 32–36)

  • HTML = บอก วิธีแสดงผล (ก่อนหน้ามี SGML) · ไม่บอก semantics → จึงมี XML
  • ⭐ XML: tag ไม่ pre-defined · โครงสร้างข้อมูลเพื่อ exchange & storage · Schemas support data types · ไม่ได้ทำให้ browser · โปรแกรม/เครื่องประมวลผลอัตโนมัติ · ใช้ marshalling/serializing arguments ตอนเรียก service
  • เอกสาร XML = tree root → leaves | <?xml version encoding?> = XML Declaration | <note> = Root element | <to>… = Child element
  • Schema xs:element university → xs:complexType → xs:sequence (name, address, city, country : xs:string) → เอกสาร <university>Mahidol…Thailand</university>

5. Cookies / LocalStorage / sessionStorage (สไลด์ 37–44)

Cookies LocalStorage sessionStorage
⭐ ขนาด ≤4KB ≥5MB / domain like LocalStorage
⭐ อายุ มี expiry จนผู้ใช้/โปรแกรมลบ tab ปัจจุบัน, refresh แล้วยังอยู่
⭐ เข้าถึง client (JS) + server (HTTP headers) client (JS) เท่านั้น –
⭐ ส่งไป server อัตโนมัติทุก request (domain เดิม) ไม่ส่ง –
อื่น ๆ key/value · session state ข้ามหน้า (login, ตะกร้า) key/value ต้องเป็น string ทั้งคู่ · แชร์ทั้ง domain –
  • Cookie purpose: Session management | Personalization | Tracking · ตัวอย่าง "username=Wudhichart; expires=Thu, 18 Dec 2016 12:00:00 UTC";
  • LocalStorage ทำได้: store / get / set / remove / GUI

6. JSON (สไลด์ 45–54)

  • object → string = ⭐ serialisation / stringifying | string → object = ⭐ deserialisation / parsing (ต้องคงข้อมูล + โครงสร้าง)
  • ⭐ JSON vs object literal: JSON is a String | does not support properties (ตามสไลด์ — ไม่ชัด) | property names in quotes
  • ⭐ 6 types: Number, String, Boolean, Array, Object, null
  • JSON object {"wudhichart": {...}} | JSON array {"people": [{…}, {…}]} → people[1].firstName = "Pawitra"
  • ⭐ JSON.stringify(object) → string (เก็บลง LocalStorage) | JSON.parse(JSON) → object (number/boolean คงเดิม)
  • JSON Editor: jsoneditoronline.org

7. Web Services (สไลด์ 55–58)

  • ⭐ W3C: software system designed to support interoperable machine-to-machine interaction over a network
  • remote machine · standardized integration · encode ให้โปรแกรม decode ง่าย: XML (SOAP / POX), JSON · แบบ SOAP และ RESTful
  • สร้างบน SOAP, WSDL, HTTP (transport, SOAP/HTTP), REST
  • ⭐ All WS are APIs, not all APIs are WS · WS ต้องใช้ network / API ไม่ต้อง · HTTP = protocol ที่ใช้บ่อยสุด

8. REST (สไลด์ 59–76)

  • ⭐ REST = architecture — NOT technology / standard / protocol · ใช้ HTTP, URL, XML/HTML/JSON, MIME types
  • ⭐ 6 constraints: Client/Server | Stateless | Cacheable | Uniform Interface | Layered Systems | Code-On-Demand (optional)
Constraint แก่น
Client/Server evolve แยกกัน · แยก UI กับ data storage → portability UI, scalability server
⭐ Stateless server ไม่เก็บอะไร no session, no history · ทุก request มีข้อมูลครบ → scalability + reliability
Cacheable resource ต้อง declare cacheable · client ใช้ response ซ้ำ · ⚠ stale data → reliability ลด
Uniform Interface one logical URI · generic interface GET/POST/PUT/DELETE · ง่ายขึ้นแต่ degrades efficiency
Layered System client ไม่รู้ว่าต่อ end server หรือ intermediary · load balancing → scalability
Code on demand optional · client ดาวน์โหลด applets/scripts มารัน · ตัวอย่าง "code": "function printSomething(){…}" → พิมพ์ Executing client-side code
  • ⭐ Uniform interface 4 ข้อ: Identifying the resource | Resource representation | Self-descriptive messages | HATEOAS
    • Resource = อะไรก็ได้ที่ตั้งชื่อได้ · nouns not verbs · URI ต่อ resource · 'Nice' URIs · googleapis.com = Company/Owner, customsearch = API Name, v1 = Version
    • Representation = เอกสาร state ปัจจุบัน · มีได้หลายแบบ (HTML, XML, JSON, TXT) · client เลือกผ่าน Accept · มี links
    • Self-descriptive = มี metadata (response code, Host, Content-Type)
    • HATEOAS = ใช้ hypertext นำทาง API · links: [{href: "10/employees", rel: "employees", type: "GET"}]
  • ⭐ Methods: GET retrieve | DELETE remove | POST create (sometimes update) | PUT update (sometimes create) | PATCH update บางส่วน
  • ⭐ POST not idempotent, PUT is | PUT = client กำหนด URI | POST = server กำหนด URI

9. JavaScript เรียก WS (สไลด์ 77–89)

  • 2 วิธี: XMLHttpRequest (XHR) · Fetch
  • XHR = built-in browser object · ยังใช้เพื่อ สคริปต์เดิม + browser เก่า
  • ⭐ new XMLHttpRequest() → open(method, URL, [async, user, password]) (async=false → synchronous; user/password = basic HTTP auth) → send([body]) (GET ไม่มี body, POST มี)
  • ⭐ Events: load (เสร็จ แม้ status 400/500) / error (ส่งไม่ได้) / progress → onload onerror onprogress
  • Properties: status (number) | statusText (string: OK, Not Found, Forbidden) | response (body)
  • responseType: "" / "text" (string) | "arraybuffer" | "blob" | "document" (XML/HTML) | "json" (parse อัตโนมัติ) — ⚠ สไลด์พิมพ์ ”json” (คำพูดโค้ง = SyntaxError)
  • ⭐ readyState: 0 UNSENT · 1 OPENED · 2 HEADERS_RECEIVED · 3 LOADING · 4 DONE · onreadystatechange
  • ⭐ Fetch: fetch(url, [options]) คืน Promise · options เช่น method, header
    • ขั้น 1: resolve เป็น Response เมื่อได้ headers · เช็ก status, ok (true = 200–299) · reject ถ้าส่ง HTTP request ไม่ได้
    • ขั้น 2: body → text() json() formData() blob() arrayBuffer() · body = ReadableStream (ทีละ chunk)
  • ตัวอย่าง Google Custom Search: query จาก #q → URL …/customsearch/v1?key=APi_key&cx=cx&q=query → fetch → .then(res => res.json()) → .then(data => #output.innerHTML = "<p>" + JSON.stringify(data, null, "\t") + "</p>") → .catch(err => console.log(err))
